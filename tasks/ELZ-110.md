GitHub and Azure public status pages report no active incident; no global outage or recovery time is established.

## Required behavior

1. Keep the existing package installation's success path. If its Ubuntu package provisioning fails, perform one bounded fallback using the official archive.ubuntu.com Ubuntu package source, then retry installation of the same runtime libraries. No unbounded loop or repeated workflow dispatch.
2. Preserve apt repository signature verification, Signed-By, suites/components, release/codename selection and package validation. Do not add insecure/trusted overrides, pin IPs or arbitrary third-party mirrors. Preserve unrelated package sources. Require a successful fresh fallback metadata refresh with apt's strict update error mode or an equally small equivalent before retrying installation; ordinary apt-get update exit zero can hide failed downloads and stale indexes. Never fall through to cached installation after failed fallback refresh.
3. A failed fallback exits nonzero and fails the job; tests never run as though installation succeeded. Log the primary failure and fallback decision without secrets.
4. Apply equivalent behavior in all three backend work jobs and the Gleam job, retaining hosted job/runner policy and all pins.
5. Define the supported source configuration explicitly. Observed logs include direct azure.archive.ubuntu.com Ubuntu URIs and mirror+file:/etc/apt/apt-mirrors.txt. Safely identify the applicable Ubuntu source or mirror-list configuration before replacing its official Ubuntu URI with archive.ubuntu.com; unsupported or no matching configuration fails closed without broad arbitrary-source replacement or claiming a fallback occurred. Do not introduce a general source parser or retry framework.
6. Account for the existing pre-checkout installation position, including Gleam's working directory /. Keep minimal inline behavior or explicitly review the smallest necessary checkout-order/guard change if a repository helper is used; do not relax unrelated guard checks.
