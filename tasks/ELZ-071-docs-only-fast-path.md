# ELZ-071 — Documentation-only fast path for pull requests

- Phase: P0 harness (CI; `scripts/ci-change-class.py` (new), `.github/workflows/symbolic-check.yml`, `scripts/merge-queue.py`, `scripts/ci-skip-decision.py`, `scripts/check-ci-runners.py` and the tests of these scripts, `docs/development/10-symbolic-ci.md`, `AGENTS.md`)
- Catalogue IDs: none
- Dependencies: ELZ-059 (#99, part A) merged; ELZ-069 (#127) merged. Starts from the new `main` after ELZ-059.
- Review: independent review required (workflow, guard and queue are protected surfaces; the queue gains a new evidence rule).

## Outcome

A documentation-only pull request (the last ten merged ones were documentation, task bodies and plan views) pays the full 18 to 33 minute `mix check`, although nothing that `mix check` tests changed. The coordinator split this part off ELZ-059 on 2026-11-09 because it adds a new trust decision: a marker that the queue accepts instead of the full-run marker. This task makes documentation-only pull requests pass on a short, separate check, and lets the queue accept that check only when it classifies the change itself.

## Scope

1. **`scripts/ci-change-class.py` and its tests.** One allowlist, used by the workflow and by the queue (the queue loads the file from its own checkout). A change is documentation only when it has at least one changed path and every changed path is a regular file under `docs/` or `tasks/`, or one of the root files `README.md`, `GOAL.md`, `PLAN.md`, **except `docs/consuming.md`** (found while implementing: `lib/elzoo/export.ex` copies it into every export, so the export tests and the copied consumers read it). Never documentation: `.github/`, `scripts/`, `lib/`, `test/`, `pieces/`, `config/`, `registry/`, `mix.*`, `AGENTS.md`, and the generated `LEDGER.md` (`registry_test.exs` and `mix check`'s `ledger` stage read it; this corrects the first idea of "all root `*.md` files"). Renames count both paths (`git diff --raw -z --no-renames`); a symlink or submodule entry on either side is never documentation; an empty list, a failed Git command, malformed output or an odd path (`..`, absolute, backslash, `docs-x/`) means "not documentation only".
2. **Workflow** (`symbolic-check.yml`, job `check-hosted`): a step `Classify the change` runs the script for `pull_request` events (the checkout is the merge of the head into the base: `HEAD^1...HEAD^2` is the change of the head) and sets `docs_only`; the heavy steps (S3 binary restore, start and save, setup-beam, dependency cache, `mix setup`, `mix check`, the roadmap step of ELZ-059) get `steps.skip.outputs.skip != 'true' && steps.class.outputs.docs_only != 'true'`; a step `Docs-only check` (only when `docs_only == 'true'`) runs `python3 scripts/check-claims.py` and `python3 scripts/check-roadmap.py` (link check and generated views included) and prints `ELZOO DOCS-ONLY CHECK PASSED`. The guard scripts and their tests that run before (claims, guard, queue and skip tests) keep running. The Postgres service container still starts in a docs-only run (a job-level `services:` block cannot be conditional); only its use is skipped.
3. **Merge queue.** The queue accepts a run whose `Run mix check` step is skipped and whose `Docs-only check` step succeeded and whose log has the docs-only marker line (not an echoed command) **only when its own `git diff --raw -z --no-renames <main>...<head>` on the fetched refs is documentation only according to its own copy of `scripts/ci-change-class.py`**. Any other path, an empty or failed list or a missing marker requires the full run (`ELZOO CHECK PASSED`, as before). The queue's own copy, not the pull request's script, decides: a pull request that changes `scripts/` is never documentation only.
4. **Push skip decision.** `scripts/ci-skip-decision.py` accepts the docs-only marker as evidence when the merge commit's diff against its first parent is documentation only (same script, same rule), so that a documentation merge does not start a full push run; otherwise it keeps requiring the full-run marker.
5. **Guard and tests** accept exactly the new shape (the classify step, the docs-only step and every new step-level condition, pinned like the others). New tests: the allowlist (each allowed class; each denied class, including `LEDGER.md`, `AGENTS.md`, `.github/`, `scripts/`, `pieces/**/README.md`; renames into and out of the list; symlink and submodule entries; empty, failed, malformed lists; traversal and look-alike prefixes), the workflow classification (pull request merge commit; non-merge `HEAD`; other events), the queue (docs-only marker accepted only with a docs-only path list; refused with one code path; refused when the step or marker is missing, echoed or forged in a non-marker line; the full run still accepted), and the skip decision. **Guard test for the allowlist (coordinator addition):** a test greps `lib/`, `test/`, `config/`, `pieces/*/*/lib`, `pieces/*/*/test` and `mix.exs` for `docs/` and `tasks/` path literals and fails if one appears outside a small, reviewed exception list, so a future test that reads a documentation file cannot silently become unchecked on documentation-only pull requests. Existing tests are not weakened; edits to merged tests are listed in the PR for the owner's approval.
6. **Docs.** `docs/development/10-symbolic-ci.md`: the allowlist, the two markers, why the queue decides itself, the limits below; `AGENTS.md` acceptance wording (a documentation-only change is accepted by the docs-only check plus the queue's own path check).

## Acceptance

- [ ] A documentation-only pull request passes `check-hosted` in a short run (run ID and minutes) and merges through the queue on the docs-only marker (observed once).
- [ ] A pull request that changes one code path in addition to documentation still needs the full run (observed or tested), and a pull request that edits `scripts/ci-change-class.py` itself is never documentation only.
- [ ] The guard test for `docs/` and `tasks/` path literals in tests passes today and fails on a scratch test that reads a documentation file.
- [ ] Guard and tests pass with new negative controls; merged-test edits listed and approved.
- [ ] Independent review of the actual diff (separate agent session, reviewed SHA on the PR); Devin findings dispositioned.
- [ ] No local full `mix check` is needed for workflow, script and docs changes; the hosted pull request run and the queue's exact-head run are the acceptance evidence.

## Limits

A documentation-only pull request is not checked by `mix test`: documentation that tests read must stay out of the allowlist (checked today by a scan of `lib/`, `test/`, `config/` and `pieces/`: `LEDGER.md` and `docs/consuming.md`; the guard test of item 5 now scans `lib/` and the other Elixir sources too), and a future test that reads a file under `docs/` or `tasks/` must move that file out of the allowlist in the same change (the guard test of item 5 fails when a test file contains such a path literal outside the exception list). The marker proves that the docs-only steps ran on the merge of the head into the base; the queue's path check is what decides acceptance. The Postgres service container still costs its start time. Part A (ELZ-059) is a dependency: the queue must already adopt the `pull_request` run.

## Additions of 2026-11-09 from the independent review of PR #135 (recorded by the worker)

- **Verified main.** A short check runs no tests, so it must not hide a red or unfinished push run of `main`. The queue accepts the short check only when the push run with the highest ID on the current `main` commit completed with success (it waits up to 600 s for a run in progress; otherwise it dispatches a full run), checked after the evidence and again right before the merge. The push skip accepts the short check only when the first parent has such a push run (no waiting; otherwise the full check runs).
- **Classifier command.** `git diff --raw -z --no-renames --no-abbrev --ignore-submodules=none --no-relative`: a host setting of `diff.ignoreSubmodules` or `diff.relative` must not hide a gitlink or a path.
- **Guard test for the allowlist** scans every Elixir, Cure, Gleam, Erlang, template, shell and browser-script source of the repository (not the root `docs/` and `tasks/`; comments are scanned too, because no language rule decides what is a comment) for the read forms of this repository's own style (`Path.expand("../../docs", __DIR__)`, `"#{root}/docs/x"`, a quoted `"docs"` on a line of its own, `~w(docs x)`, `README.md` anywhere, `*.md`, `*.MD` and `*.{md,json}`, a `Path.wildcard` that starts at the working directory or over `root`, `File.ls`). The reviewed list is keyed by the line itself, so a new read next to a reviewed line fails. It is a net, not a proof.
- A green short `check-hosted` is evidence for the queue only; branch protection accepts it for a hand merge (documented).
