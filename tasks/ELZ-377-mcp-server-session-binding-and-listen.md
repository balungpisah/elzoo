## Outcome and boundary

Two limits that ELZ-363 states become rules.

- **#888, sessions.** Today ex_mcp's sessions carry no identity (`oauth_enabled: false`, no `principal_id` or `tenant_id`), so any verified caller that holds another caller's session ID can end it with `DELETE`, and a legacy request on another principal's session reaches the handler (where the tool decision refuses it). After this task each session is bound at `initialize` to the verified principal's tenant and identity, and every later request or `DELETE` on it from another principal is refused by ex_mcp's session check before the handler.
- **#889, `subscriptions/listen`.** Today ex_mcp serves a modern `subscriptions/listen` from its own registry after the token check, and the stream stays open up to ex_mcp's default lifetime of one hour, past the token's expiry, receiving nothing from this Piece. The Piece exposes no resources or subscriptions, so it refuses the method in its Plug before ex_mcp. Bounding the stream by the token's expiry would need the expiry, which `integration/token-verify` does not return (facts below); it stays open.

The Piece takes untrusted input and decides authentication per request, so this task keeps the local small gate and gets the full review of the coordinator guide ("Reviewer by risk").

## The Contract change

- **Binding.** `http_opts/1` sets `tenant_id` to a one-arity function of the conn returning the verified principal's `tenant`, and `principal_id` to one returning `Atom.to_string(kind) <> ":" <> id` (unambiguous, since a kind holds no `:`). A legacy `initialize` creates a session bound to both; a later request or `DELETE` that names the session with a token of another tenant or another identity is HTTP 404 `-32600` "Session not found" from ex_mcp, with no handler started and no Need beyond the token check called; the same principal's requests and its `DELETE` (204) work as today. A principal whose token was re-issued (same tenant, kind and id) keeps its sessions. With the identity set, ex_mcp also scopes the cancellation of a modern-era request to the principal (`deps/ex_mcp/lib/ex_mcp/message_processor.ex`, lines 240–253).
- **Listen.** After the token check and before ex_mcp, the Plug refuses a request that has an `mcp-method` header equal to `subscriptions/listen`. It reads no body, so a host that parses the body upstream (the default Phoenix endpoint) keeps working: ex_mcp's own body read and its rebuild from `conn.body_params` (`http_plug.ex`, lines 559–561 and 970–1009) are untouched. The answer is HTTP 200 with the JSON-RPC error `-32601` "Method not found", `"id": null` (the body is not read) and no stream. The header alone decides whether a listen stream can open: ex_mcp opens one only for a modern-era request, which must carry one `Mcp-Method` header equal to the body's `method`, and it rejects a legacy-era body naming the method with `-32602` and no stream. Order: the token check (401) first, then the header check (so a request with the listen header gets `-32601` whatever its body size), then ex_mcp with its `body_limit` (413) for every other request.
- Everything else is today's: the token check and its 401, the tools, the handler timeout, the bounds, and the case-4 rule for a request without a foreign session (`unknown tool`).

`piece.json` (the contract, the `http_opts` list and the limit sentence) and the README (options table, session paragraph, listen paragraph) follow; the README states that sessions are ex_mcp's process-local store (its default 10,000 sessions and one-hour TTL are unchanged and upstream) and that the expiry bound of a stream is kept open.

## Kept open (owner's "no corner" rule)

- *Subscriptions bounded by the token's expiry and a declared maximum*, once `integration/token-verify` returns the expiry (its own task) or the Piece exposes resources.
- *Binding to `auth_epoch`*, so a re-issued token ends older sessions.

## Limits to state

Sessions and their store are ex_mcp's; the binding is ex_mcp's session check on the identity the Piece gives, and with it the principal scope of modern-era cancellation. The listen refusal is by header; a body naming the method is left to ex_mcp's own rejections. A session ID still grants no tool: every request is decided on its own token. No subscription, resource or stream is served. The upstream HTTP 500 observation of ELZ-363 after a handler timeout stays as stated.
