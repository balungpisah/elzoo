# ELZ-438 — assembly/run-host: reap only the incarnation that an observer saw

- Dependencies: ELZ-421

## Outcome and scope

A `run_ref` names a Run across starts and wakes. It does not name the particular reservation on this host. After a terminal or halted observation, a delayed `reap(host, run_ref)` can reach a replacement instead. Add a conditional reap to `assembly/run-host`, under the same Piece ID. Keep the existing unconditional reap for callers that mean the current reservation.

- `status(host, run_ref, :with_incarnation)` returns `{:ok, status, incarnation}` when the engine returns `{:ok, status}`, including terminal and halted status. Errors and exits follow `status/2`. The host selects the engine PID and its incarnation together in one host turn. Read status from that PID only. If the engine goes away, do not pair its status with a replacement's incarnation or retry the read against a replacement. The observation describes the selected engine; it is not a promise that it is still live when the caller receives it.
- The `on_terminal` option accepts either the existing `(run_ref, outcome)` callback or `(run_ref, outcome, incarnation)`. Call the configured callback once per terminal notification under the existing once-per-incarnation rule, with the incarnation of the Run that produced the outcome, not that of a later lookup. `on_lost` is unchanged. Keep `nil` and the existing option validation; any other callback arity is invalid.
- `reap(host, run_ref, incarnation)` compares the supplied incarnation with the current reservation for that ref **in the host turn that admits the reap**. On a match it performs the existing reap with its existing outcomes, phase, release and teardown rules. On no reservation or a mismatch it replies `{:error, :not_running}` and changes nothing. This includes an unrelated or malformed token, an old token for the same ref, and a token of another ref. In particular it does not join teardown, stop a process, change a lease-release decision, free a slot or defer a reap for a later reservation. The comparison and admission cannot be two calls separated by a replacement.
- The incarnation is an opaque local observation reference, stable from reservation to removal, including through lease renewal, and different at each new reservation. Give the reservation its own observation reference, distinct from the private token used to authenticate internal worker notifications. Only the observation reference is returned to callers. It is not a lease revision, Attempt ID, `run_ref`, authority credential, durable identity, or evidence about an in-flight external effect. Keep the stable keys for reconciliation receipts and deferred release handover. No extra Store reads or writes for the comparison, no new journal format, and no changes to `start_run/3`, `wake/2`, `status/2` or `reap/2` results.
- Document both ways to get the reference, when a conditional reap can be retried with it, and why a delayed observer must not fall back to an unconditional reap. This feature does not promise durable callback delivery.

Paths: `pieces/assembly/run-host/**`, its entry in `docs/plans/release-plan.json` (`manifest_sha256`, `note` equal to `contract`, keep the primary `job`), and generated index files. New external dependencies: none.

## Acceptance

- Start a Run and read its tagged status. In the host fixture, check that the public reference differs from the private control token of that reservation and is not accepted by the internal notification check. The Run still admits business input and no terminal callback has run. After a confirmed renewal the observation reference is the same. Complete the Run through the real engine: the three-argument callback reports that reference and the terminal outcome; tagged terminal status agrees. From a separate process, reap with that reference: teardown completes, the reservation is freed, and a second conditional reap gives `{:error, :not_running}`. Existing two-argument callback and untagged status/reap cases stay green. Exercise tagged status on a halted engine too, without interpreting the halt as proof of whether an external effect occurred.
- Keep the old observation reference in a surviving observer. Remove the original reservation and wake the same ref with a fresh attestation that the predecessor processes are gone and none of their submitted writes can still commit. Neither the reference nor teardown alone supplies that evidence. After the replacement is live, deliver the old conditional reap: `{:error, :not_running}`. The replacement answers tagged status with its own, different reference, and still holds its slot and lease. Its own conditional reap succeeds and the lease is free. Exercise the replacement on PostgreSQL and on one shared Memory namespace and Lease backend. A tag from another live ref cannot reap the target either.
- At a lost start's existing `on_lost` barrier, use the observation reference of its predecessor, not a private token or a tag obtained from the starting reservation. The stale reap is refused while the callback is still held; after teardown the lost start did not release the newer claim. Separately, make an ordinary tagged reap return `{:error, :release_unconfirmed}`. Retry with its previously saved reference while its reservation still exists but the engine does not. Confirm that the retry frees the lease without an unconditional reap. Keep the existing deferred-release and reconciliation cases.
- For a successful tagged read, hold the reader after selection of the old engine. Allow that engine's status reply to queue for the reader; establish that the fenced replacement is live before the reader finishes. It must return the old status with the old reference. If instead the selected engine dies before replying, the read may fail as `status/2` does; it must not restart on the replacement. Use positive observations of the order, not a sleep or an independent second `status/2` read as evidence of identity.
- Negative control, recorded and reverted: ignore the comparison at reap admission; the delayed observer test detects the replacement being reaped. Run the Piece tests and `mix check --piece "$(git merge-base origin/main HEAD)"` plus `git diff --check`; report commands and exit codes, or the exact local-service limitation as allowed by `AGENTS.md`. Require a green exact-head hosted check, independent review for durable/concurrent behavior, and the automated pass or its authorized replacement before the merge queue.
