# ELZ-123 — Run resource: a live thing that a Run holds

## Scope and reuse

- Dependencies: ELZ-033, ELZ-023, ELZ-028, ELZ-006, ELZ-022, ELZ-114
- Output: `workflow/run-resource`, for RC-50's Run engine.
- Owned paths: `pieces/workflow/run-resource/**` and its index/generated changes under AGENTS.md section 3.

Own one Run's live resource: one-at-a-time use, bounded waiting, events, deadline, retained usage and close policy. Run identity/outcome are opaque here. Implement the seven acceptance groups below, using OTP serialization/queues/timers and existing Piece APIs. Add no options, layers, behaviours, generic helpers, future hooks, real provider, or ownership-transfer implementation. Ready Pieces, shared runtime, dependencies/pins, root tests and CI remain unchanged. A test provider uses the existing effect-intent Binding/Adapter boundary.

Host Needs: authenticated caller context and outer-node typed grants; current exact-action authorization/approval; canonical intent arguments and binding resolution; retained Run inputs and pure Budget state/generation; authenticated provider results/lifetime timestamps; reconciliation and physical fencing of old provider work. A resource lease is neither authentication nor physical-send fencing. No resource handle or lease map grants authority. No new authorization engine or implementation of RC-50 belongs here.

## Three-call public interface

Only `Elzoo.RunResource.start_link/1`, `command/2`, and `read/2` are public.

### start_link/1

`start_link(%{lease: lease, held: held, clock: clock, resource: resource})` returns `{:ok, pid}` or `{:error, :invalid_input | :unavailable | :ownership_lost | :incompatible_recovery}`. The trusted host supplies an existing Lease value and exclusive current claim on this resource's own stream, separate from the Run log. The owner alone writes it. `clock` is the host's delegated recording clock, returning nonnegative Unix milliseconds; it is not a pattern clock. Lease handles, functions, PIDs and provider contexts are never persisted.

The owner renews through `Lease.renew/4` at startup, before mutations/dispatch, and halfway through its initial TTL, retaining each returned fence. Derive `ttl_ms = div(held.live.until - held.live.at, 1000)` and renewal delay `max(1, div(ttl_ms, 2))`; lease timestamps are microseconds. Renewal must succeed for this key. Expired/refused ownership stops work; indeterminate renewal stops for reconciliation. A revision write alone does not detect lease expiry. Use `Process.send_after` for renewal/deadline delivery, with no new timer abstraction or clock guarantee. Before admitting or dispatching open/use, also sample the delegated clock: if expired, commit the expiry transition first, even if the timer is delayed or the submitted command's time is older. A byte-identical receipt replay performs neither new admission nor dispatch.

`resource` has exactly these fields; only `pause_policy` may be omitted:

- `run_id`, `name`: nonempty UTF-8 text, exact equality.
- `deadline_ms`: nonnegative signed-bigint Unix milliseconds; an already expired resource admits no open/use.
- `rate_per_minute`: positive integer in the budget's declared unit.
- `max_waiting`: required nonnegative integer, no default; excludes the active use, and zero allows no waiter.
- `pause_policy`: `:stay | :close`, default `:stay`; fixed with all settings for this resource lifetime.
- `budget`: exactly `budget_id`, `unit`, `cost_ref`, `generation`, identifying an already admitted reservation in the host's retained pure Budget state.
- `close_intent`: immutable cleanup descriptor, defined below, targeting the stable resource/open reference rather than a volatile handle.

Persist this descriptor before accepting open. Recovery requires exact equality with recorded settings, otherwise `:incompatible_recovery`. The test provider supports cleanup by stable reference. The first real provider is a separate task.

An intent descriptor has exactly `identity`, `arguments`, `binding`, `binding_digest`, `deadline_ms`. Reuse effect-intent's five-text identity, 64-KiB canonical argument binary, binding digest and signed-bigint admission deadline. `binding` is a trusted stable text reference resolved by the host to its existing compiled binding/context; require the recorded digest. Open, each use, and cleanup have distinct intent identities; an identity cannot be rebound to another action. Cleanup's admission deadline must permit cleanup after resource expiry. If it expires, report pending cleanup; never mint a replacement identity automatically.

### command/2

`command(pid, %{id: id, at_ms: at_ms, body: body})` takes nonempty UTF-8 command ID and nonnegative signed-bigint host-recorded Unix-ms time. Exact bodies:

- `{:action, action_map, context, intent}`. Only `resource_open`, `resource_use`, `resource_close`. Validate `action_map` by `PatternStep.decode(%{"type" => "request", "version" => 1, "actions" => [action_map]})`; there is no standalone checked-action API. Use `encode/1` to inspect checked values, never tuple internals. Payload schema `elzoo.run-resource.action`, version 1, has exactly string keys `run_id`, `resource_name`, `data`. `data` is portable provider-owned data, not executable callbacks. Trusted context is exactly `%{run_id: text, scope: :owner | :nested, resource_names: [text]}`. Require owning-Run equality; nested use additionally requires the exact name supplied by the outer node. A child Run is refused even with that name. Payload text cannot supply context. Open/use carry their host-authorized intent descriptor; close carries `nil` and uses recorded cleanup.
- `{:input, checked_input}`. Only a checked `run_ended` input, inspected through `PatternStep.encode/1`. Require schema `elzoo.run-resource.run-ended`, version 1, payload exactly string-keyed `run_id`, `outcome`, and matching Run/time. Outcome is opaque; do not enumerate RC-12 outcomes.
- `:pause | :continue`. Trusted lifecycle commands, not new pattern-step kinds. Stay pauses admission/dequeue, not the active use or deadline; continue resumes the queue. Close-on-pause requests cleanup. Continue never reopens a closed/lost resource.
- `{:dispatch, identity, effect_owner}`. The trusted host starts/recovers this EffectIntent owner from the recorded descriptor with its startup activation decision, then supplies its PID. The host guarantees exact descriptor/owner correspondence. Within this resource owner's serialized command, renew ownership, check the recorded intent is currently dispatchable, persist the dispatch decision, then call the existing `EffectIntent.advance(effect_owner, :dispatch)`. No resource command calls rearm. This closes the former read-then-dispatch race without a new public function. The PID is excluded from the durable command identity; retain the intent identity instead. A resource's accepted dispatch decision is not confirmation of provider execution.
- `{:observed, identity, observation}`. Trusted host evidence after the matching effect-intent/provider boundary accepted it. Observation is `{:completed, data}`, `{:failed, :not_dispatched | :dispatched | :unknown, data}`, or `{:unknown, data}`. Completed open data is exactly `%{opened_at_ms: ms}`; completed close data exactly `%{opened_at_ms: ms, closed_at_ms: ms}`; completed use data is portable provider result data. Require `0 <= opened_at_ms <= closed_at_ms <= at_ms` where applicable and agreement with any recorded opening time. The host authenticates timestamps in this declared clock domain. Close may establish both endpoints after an unknown open. Unknown/conflicting lifetime is never zero.
- `{:event, event_id, data}`. Trusted provider event; event ID survives redelivery. Before Run end it becomes a resource-event input, afterwards it is late.
- `:tick`. Check deadline and advance provisional usage. Runtime deadline/renewal observations use the same transition with the delegated recording clock and an internal command ID; no new pattern-step kind or periodic billing scheduler.

Action IDs are command IDs for actions; event IDs for events. Dedup keys are tagged `{:action, id}`, `{:event, id}`, `{:observation, id}`, `{:dispatch, id}`, `{:control, id}`. Exact committed repeats return their original receipt; changed durable contents/time under the same key are `:id_conflict`. Pre-admission refusals are not committed; an effect-owner refusal after the dispatch decision is retained with that decision. The host preserves the original ID/time on redelivery. Internal control IDs are separate from host IDs. Unknown identities are late. An already-settled action never emits another outcome, but authoritative late completion may release its still-occupied use slot or update cleanup/accounting; that evidence transition is applied, not a second PatternStep settlement. It never reopens the resource.

Command result algebra:

```elixir
{:ok, %{seq: seq, disposition: :accepted | :queued | :applied | :late}}
{:refused, :invalid_input | :id_conflict | :wrong_run | :missing_name_grant |
            :not_open | :paused | :queue_full | :closing | :closed | :read_only}
{:error, :unavailable | :ownership_lost | :incompatible_recovery}
{:unknown, %{command_id: id}}
```

Accepted means an effect request/dispatch decision was recorded, not completed; queued means a FIFO admission; applied means committed lifecycle/evidence change; late changes no live operation. Refusals cause no provider work; the engine records the corresponding refused action outcome. Definite storage failure maps to unavailable; fenced/refused ownership to ownership_lost. Indeterminate writes stop the owner and return unknown, never a success or provider send. A dispatch call whose result is uncertain also returns unknown; its retained intent is reconciled, not resent. A caller timeout is likewise unknown, not cancellation. Read-only dispatch returns refused/read_only and leaves cleanup closing. Persist the post-call receipt where known; if only the pre-call decision survives, recovery classifies it unknown. No success receipt is manufactured from EffectIntent status inspection.

### read/2 and merged pattern-step use

`read(pid, after_seq)` takes a nonnegative Store sequence, initially 0, and returns `{:ok, %{state: view, entries: entries}}` or `{:error, :invalid_input | :unavailable}`. View fields are exactly `phase`, `paused`, `run_ended`, `active_action_id`, `waiting_action_ids`, `opened_at_ms`, `observed_through_ms`, `closed_at_ms`, `accrued_ms`, `final_actual`; absent values are nil. Phases: `:new | :opening | :open | :closing | :closed`. Lost is a report; its cleanup phase remains closing until confirmed closed.

Entries are resource records after the cursor, ordered by Store sequence, skipping lease-only records. Expose `seq`, tagged `command_id`, `receipt`, `effects`, `inputs`, `budget_command`. Effects are recorded immutable descriptors, not dispatch permits; `command/2` rechecks them. Suppress obsolete open/use descriptors, especially after loss/recovery/close. Inputs are **neutral string-keyed maps** validated with `PatternStep.decode/1`; persist `encode(checked)` rather than its opaque tuple. Consumers decode before calling `accept/2`. Budget command is nil, `{:settle, %{cost_ref: ref, generation: gen, actual: n}}`, or `{:release, %{cost_ref: ref, generation: gen}}`. No ack, pruning, pagination or subscription API.

Output maps retain the merged v1 fields: `type`, `version`, `kind`, `at_ms`, `schema_id`, `schema_version`, `payload`; action outcomes additionally have `action_id`, `outcome`. Payload schema `elzoo.run-resource.result`, version 1, has string keys `run_id`, `resource_name`, `reason`, `data`; resource-event payloads also have `event_id`. Resource identity never becomes a new top-level field. Lifecycle events use stable stream/sequence/index-derived IDs and reasons `lost`, `expired`, `closed`, `provider_event`. Use only existing outcome classes: completed/failed/unknown from provider outcomes, refused for dropped queued uses, expired for deadline-dropped uses, resource_lost for unsettled lost operations. No new Run outcome or action kind.

Use `PatternStep.open/1` and `accept/2` for per-action settlement, with one-action requests. An unknown outcome settles that action; later completed/failed outcomes are late. Explicit late does not consume an open action. Persist neutral request and first applied outcome maps; reconstruct the opaque tracker by decode/open/accept on recovery, never by forging its tuple or inventing another protocol. Run-wide action identity uniqueness stays a host Need. PatternStep validates shapes, not this payload schema, authority, storage or time ordering. Its `at_ms` permits zero; RC-49 does too. The host applies accounting at a positive recorded time accepted by Budget, without altering an older input's timestamp.

## State, recovery and accounting

Use one `run_resource_state` record kind, version 1, in the resource lease stream. A fenced Lease write commits the normalized command, receipt, complete next state and delivery entries before acknowledgement/effect exposure. State holds descriptor, phase/pause/end/lost-report flags, receipts, action/intent records, FIFO and active identity, timestamps/usage, and final accounting command. Use existing Jason for version-1 JSON: string-keyed objects, string tags, arrays for tuple fields, and base64 for canonical argument/digest bytes; no arbitrary BEAM handles or checked tuples. Provider `data` must fit this declared JSON payload domain; PatternStep itself still accepts arbitrary payloads. The host configures the existing Store/Lease fold with initial `nil`, versions `[1]`, kinds `Map.merge(%{"run_resource_state" => :state_bearing}, Lease.kinds())`, no destinations, and `reduce: fn _, _, _, payload -> payload end`. The owner validates/decodes that latest payload and reads ordered records for replay; no fourth fold API is needed. Existing Store size/capacity limits fail closed; no truncation, new event framework or checkpoint layer.

New -> opening on admitted open; completed open -> open only before closure/loss. Definitely-not-dispatched failed open -> closed and release. Unknown/possibly-dispatched failed open -> lost report and closing, never another open. Open/unpaused admits one active use and at most `max_waiting` FIFO waiters. Only completed use or not-dispatched failure frees the slot. Unknown/possibly-dispatched failure retains it until authoritative completion/cleanup; no second action outcome accompanies that reconciliation. Pause blocks new/dequeued use, but already reserved external sends may still occur. No total mailbox bound is claimed.

Explicit close, Run end, close-on-pause, or deadline requests the one cleanup intent, stops admission, drops queued uses with the specified outcomes, and enters closing. Cleanup can stop an active use; it is not another ordinary use. A confirmed close freezes accounting, settles still-open ordinary actions as resource_lost and explicit close actions as completed. Previously settled unknown/failed outcomes remain unchanged. New explicit close actions during closing join the same cleanup; after closed they complete without an Effect. Closing never-opened state releases without provider work. New use/open after Run end is refused even if its opaque outcome is unfamiliar.

Recovery reads committed state/receipts first. New without admitted open stays new; closed stays closed. Any admitted opening/open/closing resource emits one retained lost report, enters closing, settles remaining open/use actions as resource_lost, and never replays/requeues them. Repeated restart emits no second loss or close identity. Reuse the original cleanup descriptor. Host startup activation is required even for a fresh effect-intent owner; a read-only owner stays read-only. A recovered dispatched reservation never starts a new local send. Cleanup must fence delayed old sends before claiming resource closure; lease revision and a dispatch acknowledgement do not establish this. Indeterminate appends are confirmed/reconciled through Store/Lease before further commands. Retention, cross-node clock guarantees and a production provider are outside this task.

The host durably consumes `(resource stream, sequence, input index)` once into its Run log and applies settlement to its retained pure Budget state. Persist the consumption cursor with destination updates; where transactions differ, persist destination deduplication before advancing the cursor. Effects go through the dispatch command and the existing EffectIntent owner, never straight from historical read entries. Result delivery repeats the same observation command after lost acknowledgement. A lost result is unknown/lost, not permission to retry. These host obligations are exercised by the test host, not implemented as another framework.

Known opening time plus recorded observations gives provisional `observed_through_ms = max(previous, at_ms)` and `accrued_ms = max(previous, observed_through_ms - opened_at_ms)`, including pause/empty-budget time. Confirmed closing freezes `total_ms = closed_at_ms - opened_at_ms` and `actual = div(total_ms + 59_999, 60_000) * rate_per_minute`. Round the **total once**; do not add rounded intervals. Final lifetime may exclude observation lag after physical closure. No deadline, estimate or budget cap clips actual. Zero duration releases; unknown lifetime never releases as zero. Preserve the original reservation/reference/generation and settle once, including late overage; replay uses the identical actual. No minute-by-minute reservations, increasing re-settlements or Budget.Owner restart/reset. Ready Budget supports this unchanged (README 334–350, 375–380).

## Seven named acceptance groups only

1. **`serial_use_and_bounded_wait`**: with `max_waiting: 1`, hold A active, queue B, refuse C; B starts only after A resolves, not on caller timeout. With zero, refuse every waiter. A second resource operates independently. Exercise duplicate command/id conflict and refuse dispatch of a descriptor made obsolete by pause/closure; an already reserved send is not falsely reported prevented.
2. **`same_run_typed_name_grant`**: same-Run nested use succeeds only with the exact outer-supplied name. Missing/different name, forged payload grant, and child Run carrying the valid name perform no provider use. Mutate the grant check temporarily and observe this named test fail, then restore it.
3. **`open_unknown_never_reopens`**: granted open records intent/call/outcome; unknown settles the action and never reopens on duplicate/recovery or later completed evidence. First startup without activation dispatches nothing. Exercise actual merged PatternStep decode/encode/open/accept, time zero, and late settlement rather than tuple construction.
4. **`run_end_close_and_late_event`**: unequal opaque Run outcomes close, reject new/queued work, and never create another cleanup intent on duplicate end. Distinguish dispatch, unknown/read-only close, and confirmed close. Events before end produce valid resource-event maps; after end are late. Repeat final evidence without a second action outcome.
5. **`orphan_cleanup_requires_host_grant`**: recover retained records, emit lost once, preserve Run ownership, and never replay open/use. A read-only cleanup owner remains closing; a newly granted owner after reconciliation follows the original intent. Test separate lease stream, superseded fence, indeterminate resource append with confirmation/recovery, and no Run-log lease writes. Replay delivery after a host crash without duplicate inputs or settlement.
6. **`pause_stay_close_and_deadline`**: explicit/default stay survives pause; close policy requests cleanup. Check just before/at expiry and delayed/duplicate timer; time continues while paused, cleanup/report occurs once, and continue cannot resurrect closed/lost state. No new pattern-step pause/tick kinds.
7. **`paused_usage_survives_empty_budget`**: consume remaining budget elsewhere after admission; stay keeps usage with no new reservation or budget-triggered close. At rate 3, intervals 10,000 + 50,000 ms cost 3, not 6. Durations 0, 1, 59,999, 60,000, 60,001 ms yield release, 3, 3, 3, 6. Final/expired-reservation settlement may exceed estimate/cap; restored Budget state and repeated final actual do not lose/double cost. Unknown lifetime is not zero.

Use one test provider, existing Store/Lease/EffectIntent facilities and controlled time. Memory-double recovery is finite-test evidence, not production durability. One small checked example reuses these operations. No new root harness or unrelated scenarios. Declare lifetime-static Config, these authorized Controls and truthful Telemetry scope; keep tests, upstream contracts and host assumptions separate. No new universal proof claim.

Run Piece tests and the AGENTS.md Piece gate plus `git diff --check`; one independent review checks exact scope and unchanged ready Contracts.
