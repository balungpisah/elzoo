## Proposed surface and serialization

Modules Elzoo.SearchData, Elzoo.SearchData.Migration (no global Repo/process).
A declaration is `%{index_identity, descriptor, metric: :cosine}`. Descriptor
is exactly Elzoo.AiEmbedding.Descriptor's five-field value, with float32 and
unit_l2_verified normalization. A declaration's dimension is fixed per table;
practical vector(n) dimension ceiling will be set from the server's documented
vector limit, not a guessed ANN limit. Bindings hold trusted Repo, prefix
(default public), and declaration, never a credential.

The migration helper installs a per-prefix index registry and one deterministically
named table per index identity; table names are a fixed prefix plus SHA-256,
not caller SQL. Reusing the same identity with any different descriptor/metric
is refused even if it would hash to another table. PostgreSQL transaction/unique
identity plus lock serialization protects concurrent declarations. The helper
never creates the extension. It can be called by a consumer migration; its
result is schema installation, not a business committed receipt.

Proposed configure/bind is pure shape validation. Runtime operations verify the
recorded declaration on the database, so a stale or forged binding cannot
silently mix vector models. Extension availability is checked before operations.

`put_source(binding, tenant, {source_ref, version, source_digest}, chunks)`
accepts chunk maps preserving ELZ-081 fields, plus `embedding: %{index, vector,
descriptor, provenance}`. This is a caller join: each ELZ-080 completed
`embeddings` item receives the call's shared descriptor/provenance, without
calling a provider. Embedding index is local to its provider batch and is preserved unchanged; it need not agree with source-global chunk index. The caller associates the provider item selected by batch input position with its chunk. Validate the
exact descriptor, shape, finite float32 values, actual unit norm, provenance
(using AiModel.Provenance.validate/1 and provider/model agreement), content
digest, byte offsets/length, dense unique chunk indices and UTF-8 content.
Source digest binds supplied metadata; without the full frozen source this
store cannot re-check every offset or authenticate its origin.

Writes serialize concurrent replacements by a transaction-scoped advisory lock
keyed on index/tenant/source (hash collisions only over-serialize), delete all
old rows of tenant/source and insert the entire new source in one transaction.
Readers use one statement/snapshot: old version or new version, not a mix.
Persist non-null source/version/digests/offsets/embedding descriptor/provenance.
DB primary key enforces tenant/source/version/chunk identity.

A store call inside the caller's Ecto transaction refuses before SQL, following
integration/sql's convention: writes `{:refused, :invalid_request}` and reads
`{:error, :invalid_request}` (the published finite result vocabulary has no
caller_transaction tag). Explicit caller transactions and raw SQL BEGIN have
the same documented detectability limits as integration/sql. No Sandbox reply
is represented as independent durable COMMIT.

`query(binding, request)` requires tenant, query_embedding (the joined embedding
record above), k, allowed_sources, principal and checked_at; optional
max_content_bytes and statement_timeout_ms narrow defaults/ceilings. SQL WHERE
applies tenant and explicit permitted sources before ORDER BY cosine distance,
source_ref, version, chunk_index, LIMIT k. Empty allowed_sources returns no
rows. Exact sequential scan only. Byte accounting is whole-result: if a selected
list exceeds the byte bound, return invalid_request with no rows, not silently
truncate or choose an unrequested alternative ranking.

Retrieved candidate identity is SHA-256 of an unambiguous length-tagged
source_ref/version/chunk-index encoding. Return the issue's candidate fields,
including the caller snapshot restatement and byte/digest provenance; caller
removes retrieval-only auxiliary fields and adds estimate/priority/current
provenance before context-selection. Explicit README/example will show this
adaptation, because select/2 accepts exact candidate keys.

## Proposed bounds and outcomes for early review

Identifiers: 1..1024 UTF-8 bytes (index identity 1..256); item versions 1..2^31-1
for context-selection compatibility; SHA-256 values are raw 32-byte binaries.
Write source: at most 65536 chunks (ELZ-081 ceiling), each at most 1 MiB and
8 MiB total content; oversize refuses source_too_large before any SQL. Query:
k 1..256, at most 256 allowed source refs, per-result bytes 1..8 MiB; each
stored chunk at most 1 MiB. Statement timeout default 5000 ms, 1..60000 ms
ceiling for both reads and writes (fixed binding setting for writes; per-query
setting may narrow). Bounds are validated, no lazy stream inputs.

Read failures return unavailable with no partial candidates; extension absence
returns extension_missing. Writes return committed only after Repo.transaction
reports success outside a caller transaction; unexpected DB/connection/timeout
errors are conservative indeterminate(:unavailable), because commit observation
can be lost. Local refusals: invalid_request, invalid_chunk, source_too_large,
incompatible_embedding; known absent extension is refused extension_missing.
No raw payload, SQL parameters, credentials or exception terms in errors.
