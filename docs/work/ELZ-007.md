## Ownership

Owned by this task: `delivery/request-reply`, `delivery/routing`,
`delivery/transformation` (planned -> ready subsets) and one new additive ID,
`core/selection` (new catalogue entry, P1, own). Reused unchanged: `core/port`,
`core/edge`, `core/envelope` (including the shared result/error/attempt/deadline
maps and `examples/shared.exs`), `core/wiring`, `core/assembly`,
`delivery/stream-combinators` (its ready recipe Contract and files stay as is).
Untouched: `delivery/time` and all ELZ-004 runtime/unit/supervision/host/adapter,
exemplar and Jason sources and their P0 Adapter/Host names. No ready Contract is
broadened under an existing ID; no registry/piece.json schema field is added
(selection metadata is a function input only).

Common rules: pure functions over neutral string-keyed maps; decisions in Cure
where they are pure record comparisons; Elixir only translates shapes and uses
Enum for ordering/lists. No timers, clock reads, processes, telemetry,
file/network/registry lookup or ID generation. Errors use fixed atoms tagged
by phase and may include declaration identifiers or indices, never payload or
metadata values. Callback exceptions remain outside that error contract.
Consumers need no `Elzoo.Application`
and no Cure compiler at runtime.

## delivery/request-reply — `Elzoo.RequestReply`

Stateless only. Identity rules are exactly ELZ-003's: result `message_id` is
the request message ID; result `correlation_id` is the request
`correlation_id`, otherwise its `message_id`; `attempt_id` echoes the request's
(exact Option equality); `deadline_unix_ms` is echoed unchanged data, never
evaluated.

- `reply_endpoint(request)` -> `{:ok, %{"unit_id", "port_id"}}` from
  `reply_to`; `{:error, {:request, reason}}` for an invalid Envelope;
  `{:error, {:correlation, :missing_reply_to}}` when absent. Named endpoint
  only, never a pid.
- `expected_correlation(request)` -> `{:ok, text}`.
- `correlate(request, result)` -> `{:ok, result}` (unchanged map) or
  `{:error, {phase, reason}}`; phases in order `:request`, `:result` (ELZ-003
  decode reasons), then `:correlation`: `:message_mismatch`,
  `:correlation_mismatch`, `:attempt_mismatch` (late/stale attempt),
  `:deadline_mismatch`. Decided by `Cure.Elzoo.RequestReply.correlate/2`.
- `accept_reply(request, reply, arrival_endpoint)` -> `{:ok, result}`. Order:
  request, arrival endpoint shape, reply Envelope (ELZ-003 decode), then
  `:reply` reasons: kind must be `reply` or `error` (`:invalid_reply_kind`;
  kind is **not** required to agree with the result outcome — ELZ-003 does
  not define that mapping), schema `elzoo/delivery-result` v1
  (`:invalid_reply_schema`), arrival equals request `reply_to`
  (`:endpoint_mismatch`; a request without `reply_to` fails
  `:missing_reply_to`), reply `correlation_id` **must be present** and equal
  the expected correlation (`:correlation_mismatch`; this is a stricter
  reply-wrapper policy than the optional Envelope field), `causation_id` is
  optional but when present must equal the request message ID
  (`:causation_mismatch`), then the payload through `correlate/2`.
- Any valid outcome row (all `timed_out` dispatch variants and `unknown`
  included) passes through unchanged: no classification, no timeout result is
  produced or re-labelled, unknown is never "no effect".
- Honest limit: being stateless, a repeated identical result correlates again;
  duplicate/already-completed and multi-attempt tracking are ELZ-006/008
  policy and not implemented here.

## delivery/routing — `Elzoo.Routing`

Routing selects among **declared Wiring edges**; it never invents a target.
Route table, exact shape: `%{"version" => 1, "source" => %{"unit_id",
"port_id"}, "routes" => [%{"edge_id" => text, "match" => match}]}`; `match` is
an exact map with optional `kind`, `schema_id`, `schema_version` (conjunction,
exact equality; empty matches all), decoded to `RoutingMatch` and decided by
`Cure.Elzoo.Routing.matches/2`. Predicates are pure over Envelope metadata;
payloads stay opaque, so payload content-based routing is not claimed.
Because every route shares the table source and Wiring fixes that port's
schema/version, schema predicates are effectively constant per table;
`kind` is the discriminating predicate. Documented, not hidden.

- `validate(wiring, table)`: Wiring, then table shape and declared output
  source (`{:table, :unknown_source | :invalid_source}`), then each route:
  `edge_id` exists (`:unknown_edge`), has the table source
  (`:source_mismatch`), appears once (`:duplicate_route`).
- `route(wiring, table, envelope)`: validate; decode the Envelope; check its
  producer and schema/version against the table's declared source binding
  **before** matching (`{:envelope, reason}` / `{:source, :producer_mismatch |
  :schema_mismatch | :version_mismatch}`), so a wrong-producer message is
  never an empty filter result. Then `{:ok, edge_ids}` sorted by edge ID
  (independent of declaration order); `[]` is an explicit filtered result
  returned to the caller. Each matched edge is checked with unchanged
  `Elzoo.Wiring.accept/3`; the first failure in sorted edge order returns
  `{:error, {:edge, edge_id, reason}}`, never a silent drop.
- `route_one/3` -> `{:ok, edge_id}`, `{:error, {:route, :no_route}}` or
  `{:error, {:route, :ambiguous_route}}`.
- Expiration is **excluded** (ELZ-006 owns expiry); the deadline is preserved,
  never compared with a clock. No execution, delivery, ordering or splitter
  claim.

## delivery/transformation — `Elzoo.Transformation`

- `translate(envelope, target, fun)` where `target` is exact
  `%{"unit_id", "port" => core/port descriptor, "message_id"}`; the port must
  decode and have direction `output` (`{:target, :invalid_direction}`, tested).
  Applies the caller's payload function and returns a new valid Envelope
  with the target producer/schema/version, caller-supplied `message_id`,
  `causation_id` = source message ID; explicitly sets `correlation_id` to
  the source correlation ID when present, otherwise its source message ID,
  preserving effective conversation identity across a new message ID; preserves `kind`,
  `trace_id`, `attempt_id`, `reply_to`, `deadline_unix_ms` and
  `idempotency_key` (ELZ-003 does not make it producer-scoped; downstream
  dedup must survive a fresh message ID); drops producer-stream `sequence`.
  The new payload stays opaque: no target-schema validation. The function's
  purity/correctness are the caller's assumption; its exceptions propagate
  and are outside the fixed-atom error contract.
- Batch/lazy map/filter/scan use `Enum`/`Stream` directly via the unchanged
  `delivery/stream-combinators` recipe; no owned stream implementation.
  Enrichment needing a lookup is a separate request/reply Effect before a
  pure merge, never inline I/O.

## core/selection — `Elzoo.Selection` (new additive ID)

`core/assembly`, `core/port` and `core/edge` stay unchanged; selection consumes
their interface/descriptor/delivery vocabulary without copying fields.
Delivery values are validated through the unchanged Edge decoder
(`Elzoo.Edge.decode_binding/1` with candidate interface input Port,
`unit_id = piece_id`, candidate delivery and `required_route = false`;
requirement delivery uses its downstream Port and constant unit ID
`"requirement"`) with a drift test of the exact accepted set
`{"fused", "volatile"}`; selection performs no placement
(fused/hop/same-unit) check — Edge/Wiring still own placement.

- Candidate: exact `%{"piece_id" => nonempty text, "interface" =>
  core/assembly interface, "delivery" => core/edge delivery value, "rank" =>
  nonneg int}`; lower rank = higher explicit priority.
- Requirement: exact `%{"upstream" => output descriptor, "downstream" =>
  input descriptor, "delivery" => core/edge delivery value}`; wrong-direction
  descriptors fail `{:requirement, :invalid_upstream | :invalid_downstream}`.
- Phase order: requirement, then candidate shapes, then compatibility.
  Malformed candidates: `{:candidate, index, reason}` for the **first bad
  index** (list-order dependent by design). Duplicate IDs among well-formed
  candidates: `{:candidate, :duplicate_id, smallest_duplicate_id}`.
  Permutation invariance is claimed **only for well-formed, duplicate-free
  sets**.
- Compatible iff both `Port.compatible(upstream, input)` and
  `Port.compatible(output, downstream)` hold and delivery is equal
  (`Cure.Elzoo.Selection.compatible/2`; reasons `{:input, r}`, `{:output, r}`,
  `:delivery_mismatch`). Cure uses `{:delivery, :delivery_mismatch}` for a
  uniform tuple error type; Elixir translates it to the public atom.
- `select(requirement, candidates)` -> `{:ok, piece_id}` only for a unique
  compatible candidate at the best rank; `{:selection, :missing}` (empty),
  `{:selection, {:incompatible, [{piece_id, reason}]}}` sorted by ID,
  `{:selection, {:ambiguous, [piece_id]}}` for a best-rank tie (sorted IDs, no
  ID/list-order tie-break).
- `rank(requirement, candidates)` -> `{:ok, [{rank, [piece_id]}]}` grouped by
  rank ascending over compatible candidates; empty or wholly incompatible
  sets return `{:ok, []}`. Within-group ID order is presentation only.
- No filesystem/registry lookup; selection certifies nothing about the chosen
  implementation, which keeps its own grounding.
