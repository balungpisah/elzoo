# ELZ-007 — request/reply, routing, transformation and candidate selection

Task: [#7](https://github.com/balungpisah/elzoo/issues/7).
Base: `7ce6b96` (ELZ-002 and ELZ-003 merged). Status: **Contract proposal for
independent interface review**; no new ready behavior is frozen until review.

## Ownership

Owned by this task: `delivery/request-reply`, `delivery/routing`,
`delivery/transformation` (planned -> ready subsets) and one new additive ID,
`core/candidate-selection`. Reused unchanged: `core/port`, `core/edge`,
`core/envelope` (including the shared result/error/attempt/deadline maps and
`examples/shared.exs`), `core/wiring`, `core/assembly`, `delivery/stream-combinators`.
Untouched: `delivery/time` and all ELZ-004 runtime/unit/supervision/host/adapter,
exemplar and Jason sources. No ready Contract is broadened under an existing ID.

Common rules for all four: pure functions over neutral string-keyed maps;
decisions in Cure (`Cure.Elzoo.RequestReply`, `Cure.Elzoo.Routing`,
`Cure.Elzoo.Selection`) where they are pure record comparisons; Elixir only
translates shapes and uses Enum for ordering/lists. No timers, clock reads,
processes, telemetry, file/network lookup, registry access or ID generation.
Errors are fixed atoms tagged by phase, never echoing supplied values. Consumers
need no `Elzoo.Application` and no Cure compiler at runtime.

## delivery/request-reply — `Elzoo.RequestReply`

- `reply_endpoint(request)` -> `{:ok, %{"unit_id", "port_id"}}` from the
  request Envelope's `reply_to`; `{:error, {:request, reason}}` for an invalid
  Envelope; `{:error, {:correlation, :missing_reply_to}}` when absent. The
  endpoint is a named Port address, never a pid.
- `expected_correlation(request)` -> `{:ok, text}`: `correlation_id` if present,
  otherwise `message_id` (exactly ELZ-003's echo rule).
- `correlate(request, result)` -> `{:ok, result}` (the unchanged map) or
  `{:error, {phase, reason}}` with phases `:request`, `:result` (ELZ-003
  decode reasons) then `:correlation` in this order:
  `:message_mismatch` (result.message_id != request.message_id),
  `:correlation_mismatch`, `:attempt_mismatch` (exact Option equality of
  `attempt_id`: both absent or equal text), `:deadline_mismatch` (exact Option
  equality of the echoed `deadline_unix_ms`).
- `accept_reply(request, reply, arrival_endpoint)` -> `{:ok, result}` when the
  reply Envelope is valid, kind `reply` or `error`, schema
  `elzoo/delivery-result` v1, arrived at the request's `reply_to`
  (`:endpoint_mismatch`), its own `correlation_id` equals the expected
  correlation (`:correlation_mismatch`, absent counts as mismatch), its
  optional `causation_id` equals the request message ID
  (`:causation_mismatch`), and its payload passes `correlate/2`.
- Every outcome row, including all `timed_out` dispatch variants and
  `unknown`, is passed through unchanged: correlation is not classification,
  a timeout result is never produced, re-labelled or treated as "no effect".
  Late/stale results are rejected only against the one supplied request;
  multi-attempt matching tables, retry and expiry belong to ELZ-006/008.

## delivery/routing — `Elzoo.Routing`

Routing selects among **declared Wiring edges**; it never invents a target.
A route table is exact: `%{"version" => 1, "source" => %{"unit_id", "port_id"},
"routes" => [%{"edge_id" => text, "match" => match}]}` where `match` is an
exact map with optional `kind`, `schema_id`, `schema_version` (conjunction,
exact equality; empty map matches all). Payloads remain opaque: no content
inspection, so content-based routing over payload is not claimed.

- `validate(wiring, table)`: table shape; every `edge_id` exists in the
  validated Wiring (`:unknown_edge`), has the table's source
  (`:source_mismatch`), and appears once (`:duplicate_route`).
- `route(wiring, table, envelope)` -> `{:ok, edge_ids}` sorted by edge ID
  (independent of declaration order); `[]` is an explicit filtered result
  returned to the caller, not a silent drop. Each selected edge is checked
  with unchanged `Elzoo.Wiring.accept/3` (producer/schema/version).
- `route_one(wiring, table, envelope)` -> `{:ok, edge_id}`,
  `{:error, {:route, :no_route}}` or `{:error, {:route, :ambiguous_route}}`.
- Fan-out is bounded by the declared table; no execution, delivery,
  ordering, expiry (deadline is preserved, not evaluated) or splitter claim.

## delivery/transformation — `Elzoo.Transformation`

- `translate(envelope, target, fun)` where `target` is
  `%{"unit_id", "port" => core/port output descriptor, "message_id"}`: applies
  the caller's pure payload function, returns a new valid Envelope with the
  target producer/schema/version, caller-supplied `message_id`,
  `causation_id` = source message ID; preserves `kind`, `correlation_id`,
  `trace_id`, `attempt_id`, `reply_to`, `deadline_unix_ms`; drops
  producer-scoped `sequence` and `idempotency_key`. Target must be a valid
  output descriptor. The function's own correctness and purity are the
  caller's assumption; exceptions are not caught.
- Batch/lazy mapping, filtering and scans use `Enum`/`Stream` directly
  (the unchanged `delivery/stream-combinators` recipe); no owned stream
  implementation. Effectful enrichment is request/reply before merge.

## core/candidate-selection — `Elzoo.Selection` (new additive ID)

`core/assembly` stays unchanged; selection consumes its interface map shape and
`core/port`/`core/edge` vocabulary without copying fields.

- Candidate: exact `%{"piece_id" => text, "interface" => core/assembly
  interface, "delivery" => "fused" | "volatile", "preference" => nonneg int}`.
- Requirement: exact `%{"upstream" => output descriptor, "downstream" =>
  input descriptor, "delivery" => "fused" | "volatile"}`.
- Compatible iff the interface decodes via `Elzoo.Assembly.decode/1`,
  `Elzoo.Port.compatible(upstream, input)` and
  `Elzoo.Port.compatible(output, downstream)` hold, and delivery is equal.
- `select(requirement, candidates)` -> `{:ok, piece_id}` for the unique
  compatible candidate with the lowest `preference`; errors
  `{:selection, :missing}` (no candidates), `{:selection,
  {:incompatible, [{piece_id, reason}]}}` (sorted by piece ID),
  `{:selection, {:ambiguous, [piece_id]}}` (tie at the best preference,
  sorted), `{:candidate, index, reason}` for malformed/duplicate IDs.
- `rank(requirement, candidates)` -> compatible IDs ordered by
  `(preference, piece_id)`. Results are identical for any permutation of the
  candidate list. Selection certifies nothing about the selected
  implementation: that remains the candidate's own grounding.
