# ELZ-094: export task and consumer-directory repair

## Investigation and decision

On main 339c1edb, the documented Mix command fails before export planning, both
in the test environment and in the default environment. The unchanged-source
compiler marker precedes `** (Mix) argument error`, exit 1. Calling the task with
its rescue removed in memory exposes this stack (paths limited to repository source):

```text
** (ArgumentError) argument error
:erlang.not(<destination string>)
lib/mix/tasks/elzoo.take.ex:9: Mix.Tasks.Elzoo.Take.run/1
```

The guard uses strict boolean `not` on the string returned for `--to`. The
coordinator approves replacing it with an explicit nil check; no exporter or
receipt change is needed. Reproduction command: `MIX_ENV=test mix run -e` invoking
`Mix.Tasks.Elzoo.Take.run/1` with `core/envelope`, `--to`, a newly created temporary
project containing only a minimal mix.exs, and `--dry-run`. A fresh-shell default
`mix elzoo.take core/envelope --to <destination> --dry-run` fails identically.
An in-memory module compile with the rescue omitted exposed the stack above;
the source was not changed for that diagnostic.

## Scope and grounding

Keep export bytes and receipts unchanged. Keep the ArgumentError rescue, reporting
Exception.format/3 so the original exception and location remain visible. Consumer
directories use random host-wide names with exclusive File.mkdir/1, refusing any
existing path. Tests exercise the task, dry run, an underlying failure, and
concurrent directory creation. No proof or monitored-behavior claim. Relies on
Elixir/OTP file creation and cryptographic randomness contracts.
