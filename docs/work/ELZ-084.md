## Digest form: index, not the amd64 manifest

The workflow pins the index digest. An index is content addressed and lists each
platform manifest by digest, so it fixes the amd64 manifest as tightly as the
manifest digest itself; GitHub-hosted runners (`ubuntu-24.04`, amd64, checked by
the runner identity gate) resolve the amd64 manifest from it. The former pin was
also an index digest, so the guard keeps one form, and the image stays pullable
by the same reference on an arm64 host for local reproduction. The amd64 manifest
digest is recorded here and in `docs/development/10-symbolic-ci.md` so a reviewer
can match the manifest a runner pulled (the job log's "Initialize containers"
step names the digest it pulled).

## Preparation step

After `createdb`, each step runs
`psql -d elzoo_test -v ON_ERROR_STOP=1 -c 'CREATE EXTENSION vector'` (as
`postgres`: `PGUSER=postgres` is exported at the top of the step), then
`SHOW server_version`, then
`SELECT extname, extversion FROM pg_extension WHERE extname = 'vector'`, and
finally `test "$(... count(*) ...)" = 1`, so the step fails unless exactly one
row exists. The step runs with `set -eu`, before the checkout and `mix setup`.
