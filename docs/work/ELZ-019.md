# ELZ-019 — symbolic-only CI

Task: [#26](https://github.com/balungpisah/elzoo/issues/26).
Baseline: `b53dad7` (includes the independently completed ELZ-002).

The user's CI policy is explicit: use symbolic, never GitHub-hosted compute.
The old workflows used hosted Ubuntu; those historical runs must not be
reported as symbolic checks. Both legacy workflows were disabled before any
migration push, and no active run was found in the inspected recent run list.

## Changes

Registered the repository-scoped `symbolic-elzoo` runner on symbolic under a
new dedicated `elzoo-ci` account and enabled its systemd service. The downloaded
upstream runner 2.338.2 archive passed the published SHA-256 check. Registration
used a short-lived token sent directly over SSH without logging its value or
storing it in the repository. GitHub reports the runner online with self-hosted,
Linux, X64, symbolic and elzoo labels. The account's Docker probe ran the pinned
Ubuntu 24.04 image successfully.

Replacement workflow paths use only that explicit runner selector and a
Docker-image digest for Ubuntu 24.04. This keeps the compiler environment
separate from symbolic's Ubuntu 26.04 host. The legacy hosted workflow paths
are removed and remain disabled. New workflows can run on the migration PR
without re-enabling any hosted definition. Backend cache storage remains
unchanged. No product code, dependency pins or evidence claims are promoted.

AGENTS.md and docs/development/10-symbolic-ci.md state the prohibition, offline
queue behavior, service operations and replacement procedure. A canonical
selector guard rejects ordinary hosted/matrix/fallback changes; it is not an
account-level policy or adversarial YAML parser. Review remains required.

## Evidence and acceptance

Local macOS, using the existing pinned environment and upstream/build caches:

- `mix format` and `mix check`: 19 Ash checks + 55 root checks passed.
- Runner guard: actual workflow selectors pass; negative tests reject hosted,
  matrix/fallback, incomplete labels and absent workflows.
- Ruby YAML parsing: both replacement workflow files parse.
- Direct task DAG audit: 19 task bodies match declared edges.
- `git diff --check` and tracked-claim guard run before PR.

The required remote acceptance is both actual GitHub jobs reporting
`runner_name: symbolic-elzoo`, with passing backend and Gleam/browser checks,
followed by main-commit confirmation. PR/merge/job IDs and independent review
are recorded on #26 and its PR when observed. Host installation and local
checks alone do not establish completed CI migration.

## Lessons and limits

- `runs-on: ubuntu-24.04` selects GitHub compute; it does not name a user-owned
  Ubuntu machine. Explicit self-hosted/custom labels are necessary.
- Disable legacy hosted workflows before testing a replacement. Do not restore
  old hosted definitions just to get a green check.
- Runner identity and test success are separate evidence. A self-hosted job
  may queue when the single runner is busy/offline; never fall back to hosted.
- Job containers are not a hostile-code sandbox. The dedicated runner has
  Docker access and is scoped to this private repository's trusted workflow code.
