## Proposed surface and ownership

All names in this section are proposed, not shipped APIs.

- `Binding.compile!/1`: consumer build-time validation of an explicit finite
  Adapter descriptor and its exhaustive typed-failure mapping. The compiled
  binding includes stable ID/version, input schema ID/version, provider/account
  scope, operation, replay capability and evidence policy. Missing/extra failure
  variants or a mapping outside the unchanged Envelope matrix fail construction.
  A required `use Elzoo.EffectIntent.Binding, ...` macro invokes this checker
  during compilation of the consumer binding module and embeds its descriptor
  digest; owner startup accepts that checked module, not a per-call map.
  The Adapter declares the finite failure-tag vocabulary independently of the
  mapping; tests compile missing/extra/invalid-tag modules and require failure.
  Unknown exceptions still fail closed to `unknown/unknown/unclassified` at
  runtime; declaring a table does not prove foreign code never throws.
- `Owner.start_link/1`: consumer supervises a single owner for the derived
  key, selected Store and compiled binding. Missing storage or unavailable,
  corrupt, oversized, unsupported-version or uncertain recovered state refuses
  active execution. No local fallback Store in production.
- `admit/3`: host-supplied logical identity and bounded portable arguments;
  repeated exact admission reads the existing intent. Same identity/different
  argument digest is a conflict, not an overwrite or new automatic attempt.
- `advance/2`: explicit host command, including first dispatch, poll/reconcile,
  rearm or restricted revision. Cure returns next state/action; the shell first
  validates/binds and durably commits, then may execute an Adapter operation.
- `observe/2`: trusted Adapter observation, matched to intent/revision/attempt
  and schema. Durable CAS settles one eligible result; stale/duplicate evidence
  is retained without changing the accepted state. Host-authenticated input is
  a Need; a caller-provided `confirmed` tag supplies no authenticity.
- `status/1`: redacted phase, operation/attempt references, revision, fixed
  reason/evidence tags, write-uncertainty and next admissible action. No payload,
  exception text or credentials. `stranded` exposes a reconciliation ticket,
  never a dispatch button under the same terminal intent.

Owner calls are synchronous admissions/commit observations, not an end-to-end
completion promise. Caller timeout is unknown; callers inspect by derived key.
The effect Adapter runs in a supervised task; killing it is not evidence that
an already transmitted request cannot later succeed. No automatically repeating
timer or polling scheduler is added. Config is fixed at owner construction,
including injected current time and bounded operation deadlines; no hot update.

## Identity, stored model and finite bounds (proposal)

Host derives identity from the application operation: `(tenant, provider_account,
adapter_id, operation_kind, logical_request_ref)`, all nonempty UTF-8 without
NUL, each at most 256 bytes. The logical reference is a stable application
request identity supplied by the trusted host, not a new UUID minted by this
Piece per call. Derive a key as SHA-256 of a version prefix plus length-prefixed
fields in that exact order; distinguish empty/concatenation and Unicode bytes.
Hash equality is not authentication; retain the identity and compare it too.
Provider idempotency keys use this stable operation key, never an attempt ID.

One stream per key, schema version 1, maximum 256 attempt/revision transitions,
1024 evidence records, 64 KiB argument bytes and 1 MiB total retained encoded
state/checkpoint. These ceilings are **proposed additions**, not current task
guarantees; owner decision D6 must admit them. Capacity exhaustion before a send
refuses it; while dispatched it freezes dispatch and exposes reconciliation.
Reserve space for the attempt's final settlement before sending, so routine
late/duplicate evidence cannot consume its slot. Refused evidence at the
retention bound must be explicitly reported to the host, not called retained.
There is no automatic pruning or retention-expiry redispatch.

Persist identity/key, binding ID/version/provider scope/replay contract,
canonical argument bytes/digest and schema revision, phase, admission deadline,
monotone intent revision, attempt counter, current attempt ID, ground and source
of rearm permission, disarmed reason, settled-attempt receipt, and redacted
observation records. Exact argument canonicalization is owned by a versioned
Adapter codec tested on golden bytes; never use inspect/term ordering as a
portable hash contract. Attempt identity derives from key + intent revision +
counter; replay keeps the provider operation key and argument digest fixed.

The current Adapter schema revalidates persisted arguments immediately before
the dispatch reservation. A schema change is detected, not silently accepted.
Pass the validated schema revision to the Adapter; if it changes after the
reservation, the Adapter must reject before sending. Validation of old bytes
does not prove compatibility with a later hot-loaded implementation.
An explicit revision may change arguments only when every earlier attempt is
durably certified never sent; no possibly-dispatched history can be erased by
revising arguments, changing binding/provider scope, dropping history or minting
a new key automatically. Provider-account and operation identity are immutable.
Replay capability is trusted binding configuration with named provider scope,
same-payload rule and validity horizon; it is never an untrusted per-call flag.
An expired/mismatched capability yields reconciliation, not unsafe replay.

## Transition proposal and ordering

The proposed D1 amendment records **three** distinct rearm grounds:
`adapter_no_send`, `provider_no_effect`, `provider_replay_safe`.
The current two-ground wording is not implemented as if already amended.

| Current phase / event | Proposed next phase | Action and constraint |
| --- | --- | --- |
| none / valid admission | intended | stop; append and checkpoint identity/arguments |
| intended / dispatch, live deadline and valid schema | dispatched | dispatch only after append **and** checkpoint acknowledge; allocate distinct attempt |
| dispatched / nonpermanent rejected/not_dispatched or timed_out/not_dispatched | failed_definite(adapter_no_send) | stop; durable ground first, explicit rearm later |
| dispatched / permanent rejected/not_dispatched | failed_definite(adapter_no_send), disarmed | stop; restricted argument/schema revision required before rearm |
| dispatched / completed, correlated valid provider completion | confirmed | stop; durable settlement |
| dispatched / failed/dispatched, timed_out or unknown with possible dispatch | dispatched | poll/reconcile, even with error_class permanent or retryable |
| dispatched / authoritative final no-effect certificate | failed_definite(provider_no_effect) | stop; certificate rules D3 |
| dispatched / unknown_to_provider, valid replay capability | failed_definite(provider_replay_safe) | stop; same key/arguments, explicit bounded rearm |
| dispatched / unknown_to_provider, no valid replay capability | stranded | reconcile; never interpret absence as no-effect proof |
| dispatched / pending or provider read unavailable | dispatched | poll/reconcile; deadline cannot authorize a send |
| failed_definite / explicit rearm, live deadline, valid ground and not disarmed | intended | stop; a subsequent dispatch gets a new recorded attempt |
| intended or failed_definite / deadline exhausted | same phase, disarmed | stop; no new send |
| dispatched / recovery deadline exhausted | stranded | reconcile; terminal for dispatch |
| confirmed or stranded / any subsequent operational event | unchanged | stop; retain bounded refused observation evidence |

The first dispatch is not rearm. Returning a pure `dispatch` action is not a
receipt or authority to send: only the integrated owner may execute it after
the durable barriers. Checkpoint-before-send is literal, not a synonym for a
mutable in-memory snapshot. No production helper bypass is a supported API.

Recovery reads a healthy authoritative checkpoint plus tail and never replays
effects. A recovered `dispatched` record polls regardless of whether the old
process actually reached its send. Recovery of `intended` may resume the first
dispatch only after it establishes the required checkpoint. A recovered
failed_definite still needs explicit rearm and all guards.

Append and checkpoint are separate Store operations. `committed` is the only
immediate authorization to advance. On conflict, reload/revalidate; do not
reuse the losing command's action. Rejected write means no send. Indeterminate
append/checkpoint stops the active owner; exact fresh-nonce readback can confirm
the write but absence cannot prove rollback. Generic Writer restart without
uncertainty context is not our automatic recovery policy. A fresh startup
cannot send directly from a dispatched state even when its checkpoint was
lost. A checkpoint duplicate is not silently treated as our acknowledged
request; verify the retained model/cursor and resolve under the Store protocol.

Durable CAS prevents competing state commits, but cannot retract an old task's
future network send. The host must enforce one live dispatch owner per key and
fence/deactivate the old owner before replacement; this is an explicit Need,
not a distributed lease implemented here. Even after task death, a provider
no-effect certificate must rule out delayed acceptance of the old attempt (D3).
A read of "not found yet" does not provide that guarantee.

### Store binding proposed for review

The owner accepts the existing `Elzoo.DurableLog.Store` `{module, config}`
behavior rather than introducing an incompatible parallel durability interface.
The Piece's binding layer owns only versioned intent-event encoding, a total
fold and checkpoint model encode/decode. It calls `Store.read/3` for the head,
`Log.read/4` for bounded pages, `Log.preflight/3` and `Store.write/4` for
expected-revision append, `Checkpoint.take/4` for snapshots and
`Checkpoint.recover/5` for recovery. It records complete canonical requested
rows and nonces when a write becomes indeterminate; the existing
`Log.confirm/5` / `Log.confirm_checkpoint/2` contracts govern confirmation.
An effectful public command never exposes a reusable caller-executed send
closure/token. A successful fresh dispatch reservation may issue one local
send; the same recorded reservation recovered after a crash can only poll.

The production fold must replay validated versioned transition inputs through
the actual pure policy, carrying prior revision/attempt identity, rather than
trust arbitrary persisted `next_phase` strings. Replay emits no effects.
Checkpoint decoding checks phase/ground/attempt/history consistency and the
recorded binding/identity; malformed or unsupported state fails closed.
Use closed tag decoding without dynamic atom creation and distinct public
`EffectIntent*` record tags. The tiny probe's string-replacement fold only
exercises the existing storage API and does not establish these production
invariants or checkpoint semantic authenticity.

The Store result union remains exactly committed/conflict/rejected/indeterminate;
do not turn checkpoint conflicts into committed or hide caller_transaction.
Memory supplies the test-double behavior; PostgreSQL supplies the deployed
binding. The new bundle supplies intent-specific conformance fixtures against
both, including model/key corruption, wrong nonce/revision, uncertain append
and uncertain checkpoint. This is a concrete reuse of the task's requested
Store behavior/test double, not a second database engine. The reviewer must
confirm this reading of scope before production starts.

## Decision requests with before/after Contract text

These are recommendations for the reviewer/root, **not applied amendments**.
Preserve the core no-blind-replay invariant; do not solve contradictions by
weakening an existing ready Piece or editing its tests.

### D1 — no-send versus through-failed_definite (blocking textual conflict)

Before (Admission 2): "`rejected/not_dispatched` and `timed_out/not_dispatched`
return to `intended`"; "`failed_definite` is the only state out of `dispatched`
that re-arms dispatch, and it is reached on exactly two grounds".

After (replace the return and ground sentences):
"A correlated `rejected/not_dispatched` or `timed_out/not_dispatched` records
`failed_definite` with ground `adapter_no_send` before rearm; a permanent
rejection additionally disarms it until a permitted argument/schema revision.
The only path from `dispatched` to another dispatch passes through a durably
recorded `failed_definite` with one of three distinct grounds:
`adapter_no_send`, an authoritative final `provider_no_effect` certificate, or
`provider_replay_safe` under the binding's valid same-key/same-arguments replay
contract. Rearm is explicit, bounded and subject to the deadline; no bare
failed/dispatched, timeout, unknown result, crash or deadline supplies a ground."

Before (Admission 5): "`failed_definite` is reachable only on one of its two
recorded grounds". After: "`failed_definite` is reachable only on one of the
three recorded grounds defined above; every rearm from dispatched passes
through that durable state." Add acceptance: "Nonpermanent no-send results
rearm only through adapter_no_send; permanent no-send remains disarmed until a
permitted revision, and a mutation that bypasses the ground fails."

### D2 — retain the exact ready Envelope matrix

Before (Admission 2): "`timed_out` or `unknown` with `dispatch` one of
`not_dispatched`, `dispatched`, `unknown`".
After: "`timed_out` with dispatch `not_dispatched`, `dispatched` or `unknown`,
and `unknown` with dispatch `dispatched` or `unknown`, exactly as accepted by
core/envelope; unknown/not_dispatched is invalid input and never a no-send
certificate." Add acceptance: "Exhaust the accepted result matrix and reject
unknown/not_dispatched before the policy/owner; no ready Envelope change."

### D3 — distinguish final evidence from provider absence/error

Before: "a `reconcile` or poll answer (`failed`, `unknown_to_provider`) by
which the provider confirms that no effect happened" and
"unknown_to_provider without a provider idempotency contract is stranded".
After: "A provider's `failed` is a no-effect ground only when the trusted
Adapter binds an authoritative, final no-effect certificate to the exact
operation/attempt and certifies that delayed processing of that attempt cannot
later produce the effect. Transport failure, an unauthenticated event, a
generic provider error, partial failure and absence at a point in time do not
meet this Need. unknown_to_provider is never that certificate: absent valid
replay capability it is stranded; with that capability it uses only the
provider_replay_safe ground. Capability covers provider/account, same key and
argument digest, and a validity horizon checked at rearm and send."
Add acceptance: "A delayed old request after a not-found poll cannot produce
a second authorized dispatch; expired or scope/payload-mismatched replay
capability refuses replay; a genuine final no-effect certificate can rearm."

### D4 — identity and argument revision cannot bypass uncertainty

Before: "the key is a function of the logical request, not a client-minted id"
and "until its arguments or the Adapter schema change (a new revision of the intent)".
After: "The host supplies stable tenant/provider-account/Adapter/operation and
logical-request identity; the versioned length-framed key derivation excludes
attempt identity. Exact duplicate admission returns the existing intent;
same identity/different argument digest conflicts. Explicit argument revision
is permitted only when all prior attempts are durably certified never sent;
otherwise binding, arguments and provider key remain fixed and require
reconciliation. Schema revalidation alone grants no replay permission."
Add acceptance: "Key golden vectors, tenant/provider separation, duplicate
admission, changed-payload conflict and attempted revision after possible send."

### D5 — define the settlement winner and host/Store Needs

Before: "accept a late result at most once and only while dispatched; the
first of a late result or a reconciliation wins, a refused late result is
retained as evidence, and a late result whose store write is unavailable is unknown".
After: "One eligible decisive settlement per recorded attempt wins by durable
CAS while dispatched; it is a correlated completion or a validated rearm-ground
certificate. Pending, timeout, unknown and poll failures are observations, not
winning settlements. Later/stale/duplicate observations do not overwrite that
decision and their bounded redacted evidence is retained or explicitly
reported as not retained when capacity/storage prevents it. A settlement write
with an indeterminate result is unknown and halts active ownership; readback
absence never authorizes redispatch. The host supplies one fenced live owner
per intent key and trusted authenticated Adapter observations; this Piece
supplies no distributed lock or provider-authenticity proof."
Add acceptance: "Late completion versus definitive reconciliation CAS races
in both orders; pending then late completion; delayed old-attempt result after
rearm; unavailable/indeterminate settlement and checkpoint writes; competing
owner fixture cannot send on a losing CAS; explicit evidence-retention failure."

### D6 — admit finite storage/attempt bounds and deadline termination

Before: "and the deadline", "stranded is a terminal, visible outcome requiring
reconciliation", and no record/argument/evidence bounds.
After: "The initial subset uses Unix-ms nonnegative signed-bigint deadlines
and host-supplied evaluation time; expiry is now >= deadline. It bounds identity
fields to 256 UTF-8 bytes, encoded arguments to 64 KiB, attempts/revisions to 256,
retained evidence records to 1024, and encoded state/checkpoints to 1 MiB.
Exhaustion never grants dispatch; an unresolved dispatched intent becomes
stranded at its recovery deadline. Evidence space for settlement is reserved
before dispatch; inability to retain additional observations is an explicit
host-visible failure, not silent success. No pruning or automatic retry on
retention expiry is provided."
Add acceptance: "Boundary and over-bound tests, deadline-before-first-send,
deadline-after-possible-send, refusal without provider calls, reserved settlement
space and saturation evidence; no deadline changes rearm permission."

The reviewer should challenge whether D1–D6 are sufficient and minimal. In
particular D5/D6 deliberately make the previously unbounded evidence promise
explicit rather than silently dropping records in an implementation.
