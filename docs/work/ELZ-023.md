## Candidate supported surface

These APIs are a proposal, not shipped interfaces.

- `Binding.compile!/1` checks the Adapter's independently declared finite typed
  failure vocabulary against its exhaustive mapping. A consumer
  `use Elzoo.EffectIntent.Binding, ...` macro runs it at compilation and embeds
  a descriptor digest. Missing/extra tags or invalid Envelope pairs fail build.
  Unknown exceptions map to unknown/unknown/unclassified at runtime, not a
  no-send certificate. The descriptor binds provider/account, operation,
  schema/argument codec, replay contract, recovery grace and no-send attestations.
- `Owner.start_link/1` receives Store, checked binding and host recovery callback;
  every activation calls that callback with a fresh activation nonce. Missing
  Store, unacknowledged activation, corrupt/oversized/unsupported/uncertain
  recovered state permits no active operation. No implicit Memory fallback.
- `admit/3` receives trusted stable identity and bounded portable arguments.
  Exact duplicates return the existing intent, including terminal intents;
  changed digest conflicts. No fresh key is silently minted.
- `advance/2` receives explicit first-send, rearm, revision or poll commands.
  Cure decides; only the owner can perform I/O after required durable barriers.
- `observe/2` validates correlation, recorded attempt, binding output schema and
  trusted authenticity. One decisive settlement per attempt wins durable CAS;
  duplicate/old observations follow the explicit table below. Returned statuses
  distinguish retained, counted, not-retained and halted/unknown.
- `status/1` returns redacted phase, identities, revision, reason tags,
  uncertainty and permissible next actions. It never includes stored arguments,
  payment references, credentials or arbitrary exception text.

Synchronous owner calls acknowledge admissions or writes, not external outcome.
A caller timeout remains unknown. The consumer supervises ephemeral owners and
Adapter tasks. Killing an Adapter task is not proof that no request reached
transport. Configuration is fixed at startup/per call as declared, not hot
reconfiguration; polling is host-driven, with no timer/retry loop added.

## Identity, schema and replay (R-A, R-B)

Key preimage: a version byte and five length-framed UTF-8 fields in fixed order:
tenant, provider_account, adapter_id, operation_kind, logical_request_ref.
Fields are nonempty, without NUL, <=256 encoded bytes. Native SHA-256 derives
the provider key; attempt identity is excluded. Keep and compare identity bytes
as well as digest. Hash equality is not authentication.

Arguments are canonical bytes from a versioned binding codec, <=64 KiB.
Revalidate the current schema immediately before reservation and pass its
revision to the Adapter; drift afterward must be refused before transport.
Pre-reservation schema failure leaves intended disarmed, no new attempt.
An argument/schema revision requires every previous attempt durably certified
never sent, plus binding-declared same-key changed-argument semantics.
Cached-result semantics refuse revision. Revision cannot erase uncertain
history, change provider scope or automatically create a new key.

Accept exactly the eight ready Envelope pairs, with mandatory matching
attempt_id, logical request/correlation identity and binding schema. The ready
Envelope itself remains unchanged. Adapter no-send assertions are named
upstream Needs per typed failure variant.

Replay capability is fixed trusted binding configuration: provider/account
scope, same-key/same-argument semantics, named clock, retention horizon anchored
at the earliest possibly-sent dispatched record, maximum in-flight duration
and clock allowance. Every new send must fit its lifetime in that horizon;
the pure policy checks again at rearm and at actual reservation. An unbounded
or expired capability refuses replay. Failed/timeout/unknown/pending/unavailable
observations alone never supply replay authority. Only poll/reconcile
unknown_to_provider under valid capability yields provider_replay_safe.
Unknown_to_provider is never a no-effect certificate.

The host retains the intent or refusal tombstone through both provider-key
and business duplicate-request horizons; absence after deletion is not authority.
Authentication, replay semantics, no-send truth and finality of provider
certificates remain upstream Needs.

## Pure state and transition ordering (R-A, R-C, R-E, R-F)

Carry provenance `Intended(Fresh | After(ground), attempt_count)` and the
attempt history inside the production state. Three grounds only:
adapter_no_send, provider_no_effect, provider_replay_safe.
The first dispatch is not rearm. Every later dispatch must follow a durable
failed_definite with one of those grounds; no exception for expiry or restart.

| Trigger | Result / action |
| --- | --- |
| Fresh valid admission | Intended(Fresh, 0); append and checkpoint |
| Intended, live guards and current schema | New dispatched attempt; send only after acknowledged append AND checkpoint |
| Reservation result rejected/not_dispatched or timed_out/not_dispatched | Failed_definite(adapter_no_send), then separate explicit rearm |
| Permanent no-send rejection | Same ground plus disarm until permitted revision |
| Pre-reservation schema failure / capacity refusal | No new attempt or send; disarm/refuse |
| Correlated authenticated completion | Confirm only if settlement eligibility and CAS succeed |
| Failed/dispatched, possible timeout/unknown, pending/unavailable | Stay dispatched; poll/reconcile even if permanent/retryable |
| Final attempt-bound provider no-effect certificate | Failed_definite(provider_no_effect); separate explicit rearm |
| Unknown_to_provider + valid replay capability | Failed_definite(provider_replay_safe); separate explicit rearm |
| Unknown_to_provider without valid capability | Stranded, reconcile |
| Failed_definite + explicit live permitted rearm | Intended(After(same ground), same count); checkpoint barrier again |
| Admission expiry | Refuse dispatch/rearm; no ground created |
| Dispatched at finite recovery deadline | Stranded; no ground created |
| Confirmed or stranded | No operational reopening; bounded evidence/operator path only |
| Any unavailable/indeterminate evidence write | Halt active ownership, not retained; restart read-only |

Each attempt's intended barrier and its new dispatched reservation require
acknowledged append **and** checkpoint before its local send, not only the
first-ever attempt. Capacity is checked before either append. A committed
dispatched append followed by failed checkpoint does not send; recovery can
only poll. A recovered reservation never authorizes a local send.

`recovery_grace_ms` is trusted binding configuration, default `:none`.
A nonnegative grace uses checked signed-bigint addition to admission deadline;
overflow rejects the binding/request combination. Admission expiry blocks new
send/rearm; recovery expiry strands dispatched. Neither creates a ground.
Time is trusted; no cross-host clock-skew guarantee follows.

## Settlement and restart protocol (R-C)

Validate intent/attempt/key/payload/binding before classifying completion.
Pending, timeout and unknown are observations, not decisive winners.
For an authenticated older completion:

| History/current state | Treatment |
| --- | --- |
| Every intervening rearm replay-safe, matching identity, nonterminal (including intended-after / failed_definite) | Confirm the same logical operation by durable CAS |
| Any no-send/no-effect ground contradicted | Reserve/commit first contradiction, freeze rearm, operator reconciliation |
| Confirmed or stranded, noncontradictory | Terminal stays; bounded refused/operator evidence |
| Mismatched/unrecorded identity | Refuse; never settle another intent |
| Required evidence cannot commit | Halt, unknown/not-retained; never continue rearm |

Contradiction is a separate priority observation, not a second winning decisive
settlement. In a race, the serialized owner and Store CAS re-read the winning
history: completion-first prevents rearm; ground-first makes completion either
same-operation settlement or contradiction. Late completion cannot clear an
uncertain halt by itself. Production tests must exercise both orders.

The exact candidate host interface is deliberately outside a new Piece
storage/lock engine:

1. Every owner startup supplies a fresh 16-byte activation nonce to a trusted
   `activate(key, startup_nonce, mode)` callback. It returns
   `{:active, %{key, generation, nonce}}` only after the host durably CASes
   its activation marker. `:fresh` is an application attestation of a
   never-activated logical key, never inferred from an absent intent row.
   An existing activation, uncertain callback, missing attestation, or any
   recovery startup returns `{:read_only, :host_reconciliation_required}`.
2. The marker is established **before** any intent mutation or Adapter send.
   It survives owner death and host restart. An uncertain evidence write stops
   the process's active work without relying on a second successful write to
   record a quarantine flag: the pre-existing marker already forces recovery
   read-only. No automatic clean-release/reset path is proposed.
3. For deliberate recovery, the host/operator resolves or fences outstanding
   Store operations (including delayed commits), authenticates provider outcome
   and valid ground, and establishes old-owner safety. It invokes
   `reconcile(key, observed_generation, proof, new_startup_nonce)` during the
   new activation. A durable CAS advances the marker and returns
   `{:active, %{key, generation, nonce, intent_revision, intent_digest}}`.
   The snapshot digest/revision binds the exact recovered state; an unexpected
   Store head or digest is a refusal. A stale generation or uncertain write is
   read-only. The proof includes authoritative outcome, resolved writes and
   old-owner safety; a boolean supplied by an untrusted caller is not a proof.
4. Only that synchronous callback response, matched to the current startup
   nonce and recovered snapshot, enables the current owner. No caller-supplied
   cached token can skip the callback. If it crashes immediately, the next
   startup remains read-only again, even if it reuses the same local arguments.
   The callback must not issue two live activations. Host durable storage,
   authorizations, serialization and physical old-owner safety are Needs.

The [recovery probe](ELZ-023-probes/recovery.exs) realizes the callback marker/CAS
using the **existing** Store and Memory on a separate host-owned stream. It
exercises owner-process death, apparently safe intended recovery, absent
recovery state, indeterminate activation, delayed contradiction commits, exact
confirmation, stale generation and explicit reconciliation. Memory survives
the owner process in this test, not machine death; durable host recovery is
**not proved**. The production callback need not use Elzoo storage; a consumer
can bind it to its existing authoritative workflow. If it cannot supply this
Need, the Piece must stay read-only after recovery.

CAS does not retract a paused old owner's future socket call. Pause-after-
reservation/delayed-send tests remain mandatory: provider replay safety within
the bound or a final certificate fencing that attempt must cover it. Without
such authority, recovery strands. A proof flag in a fixture does not establish
real physical fencing. Stranded never rearms; the operator verifies at provider
and host records business resolution, with optional bounded evidence. Only
verified no-effect plus separate authorization permits a new logical request.

## Bounded priority retention and actual encoding (R-D)

The amendment **deliberately replaces unbounded refused-result retention with
bounded priority retention** because finite Store/checkpoint limits cannot hold
unbounded observations. Priority slots are reserved before dispatch for each
attempt's decisive settlement, first contradictory completion and first refused
result. Routine observations cannot consume these. Extras return explicit
host-visible not-retained. A failed priority write halts and is never called
retained. Reservation guarantees space, not availability or durable success.

The [capacity probe](ELZ-023-probes/capacity.exs) defines a concrete candidate
binary encoding and uses the accepted `Codec.checkpoint_bytes/1`,
`Codec.checkpoint_valid?/1`, `Log.canonical_bytes/1`, `Log.preflight/3` and
`Checkpoint.take/4`. No new storage engine or production codec is authored.

| Part | Worst encoded size / bound |
| --- | --- |
| Identity and descriptor references | 8 fields × (4-byte length + 256 bytes); five key fields plus schema, replay-capability reference and clock name |
| Current arguments | 65,536 bytes + 4 framing |
| Attempt/revision table | 256 entries × (426-byte candidate entry + 4 framing) |
| Evidence table | 1,024 × (512-byte complete evidence record + 4 framing) |
| Complete model, including all global header/counts | **706,224 bytes** |
| Existing checkpoint overhead + all 4,096 SHA-256 witnesses + digest | **164,002 bytes** |
| Complete checkpoint | **870,226 bytes**, below 1,048,576 |
| Largest candidate delta payload | **68,568 bytes**; canonical record plus digest also below 131,072 |

Entries encode index/revision/kind/phase/ground/flags, three times, key/argument/
binding digests, schema reference, nonce, three priority indices and two bounded
counters. Revision entries use the same upper bound. Historical large argument
bodies are in delta events; checkpoint keeps current arguments and historical
digests, not 256 copies of 64 KiB. Full compiled binding is supplied by its
matching digest on recovery; never silently select a changed binding.
Attempt identities derive from stable key and recorded indices, with no
unbounded external ID copied into every table entry.

A complete evidence record includes 2-byte attempt index, kind, time, SHA-256
digest, 2-byte length + <=256-byte redacted provider reference, and 2-byte length
+ <=209-byte redacted note: at most 512 bytes. This is a bounded summary/hash,
not the raw full provider response. Binding validation/authentication consumes
the original response before reducing it. The later production codec/fold must
validate every field, persist the same semantics and demonstrate round trips;
this encoder measures layout and limits, not that yet-unwritten fold.

The probe includes max and max+1 for 256-byte identity (including UTF-8),
65,536-byte arguments, 256 entries, 1,024 evidence records, 512-byte evidence,
4,096 events, 131,072-byte append payload, exact checkpoint-size threshold,
and undersized Store startup. Store's max_record_bytes limits **payload**;
our proposed largest canonical record fits 128 KiB including framing/digest too.
Its max_batch_size must be at least 1; the owner writes only one event per call.

Reservations: before an intended/rearm barrier, budget two immediate barrier
events plus three future priority events, three evidence records (1,536 payload
bytes + 12 evidence-framing bytes), the entry and all five witness additions.
All states are bounded by the full model/checkpoint calculation above. At 256
attempts, 512 barrier events and 768 priority events fit; the remaining 256
evidence slots cannot borrow the 768 reserved slots. Every additional append
(including revision, counter persistence or optional evidence) checks
`events + outstanding_reserved_events + new_events <= 4096`; optional
evidence also checks `used + reserved + 1 <= 1024`.
The reservation simulation saturates optional capacity then consumes **all**
priority slots; event-limit saturation is checked independently.
Each priority category is used once per attempt; later duplicates are optional.

Routine pending/unavailable observations use saturating signed-bigint counters,
not per-observation retained evidence. Any counter persistence consumes the
same event budget and must not consume priority reserves. At exhaustion, report
not-retained (and optional volatile count explicitly as volatile); reconciliation
can still commit its reserved priority result. No write failure is concealed.

The provisional public ceilings remain unchanged pending reviewer clearance.
The measured worst layout needs less than the proposed Store limits; the
178,350-byte checkpoint margin is for no implicit extra fields. Production must
re-run sizing if the layout changes. Smaller consumer-specific admission limits
may refuse earlier, never take away an already admitted attempt's reserves.
No demonstrated product workload justifies reducing the proposed 256-attempt
ceiling in this amendment.

The 1 MiB ceiling is **per snapshot**, not cumulative storage. At most one
immutable checkpoint per event: summing the worst-model size with actual witness
growth across 4,096 events gives **3,228,983,296 encoded checkpoint bytes**.
This is an upper bound, not a measured filesystem allocation. Append log, SQL
row/index overhead, replicas and backups are extra; no automatic pruning is
promised. Corrupt/damaged recovery is read-only and does not create further
normal snapshots with unbounded diagnostics.

## Strengthened evidence and remaining implementation gates

The old `policy.cure` / `probe.exs` are unchanged. Their four reduced laws
and 8 passing tests **are not the no-rearm law**: independent review found
silent Pending/Expired/Resume returns that survived. Their result remains
historical feasibility, not upgraded evidence.

New [template](ELZ-023-probes/provenance.template),
[generator](ELZ-023-probes/generate_provenance.py),
[generated source](ELZ-023-probes/provenance.cure) and
[runner](ELZ-023-probes/provenance.exs) carry origin and attempt count in state.
The runtime keeps deadline, disarm, horizon/lifetime/clock and capability guards
in Cure. The generated expected-label relations do not call the runtime.
Seven unconditional one-step laws quantify over well-typed state components,
event and Config:

- empty_never_recreated;
- dispatch_action_only_after_arm;
- definite_only_with_ground;
- dispatch_only_after_arm (origin projection);
- fresh_only_from_empty;
- after_only_from_definite (preserves the exact ground);
- attempt_changes_only_on_send.

Each is established first for a helper for all Boolean guard results, then
instantiated with the actual Cure guard computations in `step`; no caller
supplies a “safe” boolean to the public entry point. This avoids the pinned
compiler's inability in the first attempt to refine a computed guard directly.
The helper is internal to the proposed supported surface; BEAM export/privacy
is not established by these files.

Initial state is Empty/no attempts/not disarmed/not quarantined. A positive
first dispatch and all three ground/rearm paths execute in tests. Together the
step laws yield the rearm provenance argument for reachable traces:
no transition recreates Empty, Fresh is created only from Empty, After(g) only
from Definite(g), and Dispatch only from an armed Intended, with counter
increment only on send. This is a mathematical consequence of checked step
laws plus initial state, **not a separately checked trace-induction theorem**.
Persistence/authentication/Elixir-to-Cure translation are still production gates.

Eleven actual policy mutations fail proof conversion: silent returns on
Pending/Expired/Resume/Lost/TimedOut/Failed, groundless rearm, wrong ground,
reset-to-Empty, skipped attempt increment, and Dispatch from a non-dispatched
terminal state. Always-stop fails the mandatory positive dispatch scenario.
Expected relations share the real arithmetic guard functions, so the laws do
not independently prove those numeric comparisons; explicit boundary tests
cover their named cases and pinned native integer semantics are upstream.
The laws do not yet cover every production history/identity/settlement property.

The new recovery probe separately exercises finite old-completion classifications
and checked recovery-deadline addition. It is not a substitute for the final
production correspondence law or full owner scenarios.

After focused R-A–R-F/evidence clearance, production still needs:

1. Full state/history policy and selected laws over the actual consumed
   transition; decoder validation, trace/provenance connection, real negative
   controls and positive scenarios run by `mix check`.
2. Binding build failures, eight Envelope pairs and correlation refusal;
   schema drift, restricted revision, key/tombstone reuse and transport hidden-
   resend negative control measured by physical sends.
3. Owner and intent fold/codec reusing Store/Checkpoint; both barriers; Memory
   and SQL boundary/restart/indeterminate tests; capacity preflight/reservations;
   real malformed/roundtrip coverage; old-completion races, contradiction,

4. README and metadata with precise Telemetry/Config/Control, host callback

5. Fresh pinned setup/full check, copied/renamed export evidence, independent
