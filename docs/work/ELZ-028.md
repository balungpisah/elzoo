# ELZ-028 — `state/lease`: single-owner leases fenced by record revision

Task: [#45](https://github.com/balungpisah/elzoo/issues/45). Base:
`665d3e07c58fb9a3e7818a037a6910132535fa53` (origin/main; ELZ-009 and ELZ-010
merged). Claim: `57cd1ac22beb1456ec2e852a0355d050d333d84f` on `task/ELZ-028`.
Status: **early review requested** (design record before implementation).
Decision-ready record: `state/lease` in `docs/plans/catalogue-dispositions.md`
on `origin/task/ELZ-050`: WRAP over the ready transactional Store
(`integration/sql`, `state/event-log`) with an explicit revision fence; no
distributed lock, Raft or Horde; depends on `state/event-log` (ready) and
`integration/sql` (ready); callers C2 report lease, C5 claimed task, C6 agent
attempt; invariant: a stale owner's write is rejected by the fence; renewal and
release are explicit.

## 1. Decision: the Piece is needed

The ELZ-010 evidence on #45 shows that Oban 2.24.2's own ownership contract
does not satisfy the ELZ-028 invariants: it fences its ack by the
`attempted_at` timestamp, has no renewal, rescues by node time and uses the
node clock. ELZ-010 itself needs no lease because every Run write is already
fenced by the ELZ-009 revision CAS plus attempt identity. That composed fence
is narrower than the ELZ-028 Contract (no claim/renew/release/seize per key,
no status classification, no store clock). The owner decision of 2026-11-08
opens every catalogue handle for development. So `state/lease` is built as a
WRAP over the ready Store; the provider mechanisms named in the reuse check
(advisory locks, `SKIP LOCKED`) are not adopted, because the Contract requires
the lease to live in the same transactional record as the state it guards.

## 2. Contract reading

### 2.1 Model

A **key** is a Store stream (`Elzoo.DurableLog.Codec.stream?/1`). The lease
for a key is recorded **in that same stream** as ordinary records of the
consumer's fold. The stream's head revision is therefore one fence for both
the lease records and the guarded state records. This is the admission
record's "state owner: the same transactional record as the state it guards".

Lease record kinds (all `schema_version` 1, all declared
`:non_state_bearing`, so ELZ-009 replay advances the cursor and never calls
the consumer's reducer for them; the consumer only merges
`Elzoo.Lease.kinds/0` into `fold.kinds` and keeps `1` in `fold.versions`):

| kind | payload (JSON object, UTF-8) | meaning |
| --- | --- | --- |
| `lease_claimed` | `v, owner, at, ttl_ms, until, from, from_status` | `owner` holds from store time `at` until `until`; `from` names the previous holder (or null) and `from_status` is `free` or `stale`: the attributable release of a stale lease |
| `lease_renewed` | `v, owner, at, ttl_ms, until` | the live holder extended its lease |
| `lease_released` | `v, owner, at, by, reason` | explicit release; `by` is the actor, `reason` ∈ `released`, `stale`, `ambiguous`, `terminal` |
| `lease_seized` | `v, owner, at, ttl_ms, until, from, from_status, reason` | attributable operator takeover from any status, with a free-text reason |

Times are integer microseconds since the Unix epoch in UTC, **read from the
store clock** (PostgreSQL `clock_timestamp()` through the consumer's Repo;
a test-controlled clock for the Memory double). The Piece never reads a node
clock. `until = at + ttl_ms × 1000`.

### 2.2 Status classification (pure)

From the latest lease record below the head revision and the store time
`now`:

| reading | status |
| --- | --- |
| no lease record, or latest is `lease_released` | `free` |
| holder record with `at <= now < until` | `active` |
| holder record with `at <= now` and `until <= now` | `stale` |
| holder record with `at > now` (a stamp in the future) | `ambiguous` |
| latest lease record unreadable (digest/validation failure, malformed payload, unknown version) | `ambiguous` |
| stream `low_water > 0` and no lease record visible above it | `ambiguous` (`pruned_prefix`, see open question Q3) |

`ambiguous` and `stale` fail closed: `claim`/`claim_expired` admit `free` and
`stale` only; `renew` admits `active` by the holder only; `release` admits the
holder in `active`, `stale` or `ambiguous` and is idempotent on `free`;
`seize` admits any status with a reason. A re-`claim` by the current holder
of an `active` lease is admitted (it writes a fresh `lease_claimed`; the
holder's fence moves with its own write).

### 2.3 Decision table (Cure, `Cure.Elzoo.Lease`)

```
type LeaseStatus   = LeaseFree | LeaseActive | LeaseStale | LeaseAmbiguous
type LeaseActor    = Holder | Other             # is the caller the recorded holder?
type LeaseOp       = OpClaim | OpClaimExpired | OpRenew | OpRelease | OpSeize
type LeaseDecision = Permit | AlreadyFree | RefuseHeld | RefuseStale
                   | RefuseAmbiguous | RefuseNotHolder | RefuseFree
type LeaseReading  = NoHolder | HolderStamp(Int, Int) | Unreadable   # (at, until)

fn classify(reading: LeaseReading, now: Int) -> LeaseStatus      # pickup on Int comparisons; test-grounded
fn decide(op: LeaseOp, status: LeaseStatus, actor: LeaseActor) -> LeaseDecision   # @total @reducible; law-covered
```

`decide` matches on `op`, then `status`, then `actor`, with
`OpClaimExpired` defined as `claim(status, actor)` exactly like `OpClaim`.

Selected laws (each `Equivalent(LeaseDecision, decide(...), <constant>) =
reflexive(...)`, quantified over the variables not fixed):

| law | statement | invariant |
| --- | --- | --- |
| L1 `ambiguous_refuses_claim(actor)` | `decide(OpClaim, LeaseAmbiguous, actor) = RefuseAmbiguous` | ambiguous fails closed |
| L2 `ambiguous_refuses_renew(actor)` | `decide(OpRenew, LeaseAmbiguous, actor) = RefuseAmbiguous` | ambiguous fails closed |
| L3 `stale_refuses_renew(actor)` | `decide(OpRenew, LeaseStale, actor) = RefuseStale` | renew extends only a live lease |
| L4 `free_refuses_renew(actor)` | `decide(OpRenew, LeaseFree, actor) = RefuseFree` | renew never creates a lease |
| L5 `active_other_refuses_claim` | `decide(OpClaim, LeaseActive, Other) = RefuseHeld` | single owner |
| L6 `active_other_refuses_renew` | `decide(OpRenew, LeaseActive, Other) = RefuseNotHolder` | single owner |
| L7 `active_other_refuses_release` | `decide(OpRelease, LeaseActive, Other) = RefuseNotHolder` | release is the holder's |
| L8 `stale_permits_claim(actor)` | `decide(OpClaim, LeaseStale, actor) = Permit` | replacement after expiry |
| L9 `free_permits_claim(actor)` | `decide(OpClaim, LeaseFree, actor) = Permit` | |
| L10 `active_holder_permits_renew` | `decide(OpRenew, LeaseActive, Holder) = Permit` | |
| L11 `seize_permits(status, actor)` | `decide(OpSeize, status, actor) = Permit` | attributable takeover from any status |
| L12 `claim_expired_is_claim(status, actor)` | `decide(OpClaimExpired, status, actor) = decide(OpClaim, status, actor)` | one admission rule for both entry points |
| L13 `release_free_is_idempotent(actor)` | `decide(OpRelease, LeaseFree, actor) = AlreadyFree` | retry after a lost reply |
| L14 `stale_other_refuses_release` | `decide(OpRelease, LeaseStale, Other) = RefuseNotHolder` | stale release is the holder's or a seize |
| L15 `ambiguous_other_refuses_release` | `decide(OpRelease, LeaseAmbiguous, Other) = RefuseNotHolder` | ambiguous fails closed |

Negative controls (bundled test, each must fail to compile and the failing
line must lie in the intended law): `StaleRenews` (`LeaseStale -> Permit` in
the renew arm, breaks L3), `AmbiguousClaims` (breaks L1), `OtherClaimsActive`
(breaks L5), `FalseLaw` (L8 restated with `RefuseStale`).

`classify` uses `pickup` on integer comparisons and is **not** law-covered;
its table is test-grounded (boundary values `now = at`, `now = until`,
`at > now`, unreadable). This is the same split as `Elzoo.JobRun.start_input`.

### 2.4 Atomicity argument (lease condition and record change in one step)

Every lease operation is: read head `r` and the lease rows below `r`; read the
store clock `now`; classify; decide; if permitted, **append the lease record
with `expected = r`** through `Elzoo.DurableLog.Store.write/4`. The Store CAS
commits only if the head is still `r`. Any concurrent record change (a
competing claim, a seize, the holder's own write, a terminal record) moves
the head and makes the CAS fail, which the Piece reports as
`lease_refused{reason: lost_race}`; the caller re-reads. So the lease
condition is evaluated on exactly the state that the write replaces: the
revision, not the timestamp, is the fence.

The clock read and the CAS are two statements. This is sound for the
Contract because:

- expiry is monotone in time: a lease judged `stale` at `now` stays stale at
  the later commit time, so a permitted claim never takes a live lease;
- a lease judged `active` at `now` may expire before the commit of a `renew`;
  that renewal then extends a lease that expired unobserved. It cannot
  **revive** a lease after a handoff, because a handoff is a record change
  and the CAS fails. A renewal issued before a handoff and applied after it
  is exactly this case (scenario LS8);
- the holder's state writes carry only `expected = fence revision`; the Piece
  does not compare timestamps on them. A write from an expired holder commits
  if nobody took over (there is no new owner to protect) and is refused by
  revision as soon as a replacement wrote anything (scenario LS4). This is
  the Contract's "never by timestamp comparison".

### 2.5 Interface (Elixir shell `Elzoo.Lease`)

```elixir
lease = Elzoo.Lease.new(store: store, fold: fold, limits: limits, clock: clock)
# clock :: (-> {:ok, now_us :: integer} | {:error, term})
# Elzoo.Lease.Clock.postgres(repo)   store clock through the consumer's Repo
# Elzoo.Lease.Clock.manual(start_us) test-controlled clock for the Memory double

Elzoo.Lease.kinds/0        # %{"lease_claimed" => :non_state_bearing, ...} to merge into fold.kinds
Elzoo.Lease.claim(lease, key, owner, ttl_ms)
Elzoo.Lease.hold(lease, key, owner)                       # read-only
Elzoo.Lease.renew(lease, owner, keys, ttl_ms)             # per key
Elzoo.Lease.release(lease, key, owner)
Elzoo.Lease.seize(lease, key, owner, ttl_ms, reason)
Elzoo.Lease.claim_expired(lease, owner, ttl_ms, limit, candidates)   # per key, see Q1/Q2
Elzoo.Lease.status(lease, key)                            # read-only classification
Elzoo.Lease.write(lease, held, records, items \\ [], opts \\ [])     # the holder's fenced write
```

Results (complete sets, no raise for domain inputs):

| call | results |
| --- | --- |
| `claim`, `seize` | `{:held, held}`; `{:lease_refused, %{reason: :active \| :ambiguous \| :lost_race, holder: owner \| nil, status, revision}}`; `{:error, {:invalid, field}}`; `{:error, :clock_unavailable}`; `{:error, :unavailable}`; `{:error, :caller_transaction}`; `{:error, {:rejected, reason}}`; `{:indeterminate, info}` |
| `hold`, `status` | `{:held, held}` / `{:free, %{revision}}` / `{:lease_refused, %{reason: :active \| :stale \| :ambiguous, holder}}` for `hold`; `{:ok, %{status, holder, revision, now, until}}` for `status`; read errors as above |
| `renew` | `{:renewed, %{keys: [key], held: %{key => held}, refused: %{key => refusal}, errors: %{key => error}}}`; `{:error, {:invalid, field}}` |
| `release` | `{:free, %{revision}}` (also when already free); `{:lease_refused, %{reason: :not_holder \| :lost_race, holder}}`; errors as `claim` |
| `claim_expired` | `{:claimed, %{held: [held], refused: %{key => refusal}, errors: %{key => error}}}`; stops after `limit` holds; `{:error, {:invalid, field}}` |
| `write` | `{:held, held'}` (revision advanced to the batch target); `{:fenced, %{expected, observed}}`; `{:rejected, reason}`; `{:indeterminate, info}`; with `release: true` the batch ends with a `lease_released{reason: terminal}` record in the same CAS |

`held = %{key, owner, revision, at, until}`; `revision` is the fence value the
holder passes as `expected` through `write/5`. `owner` is UTF-8 text of
1..200 bytes without NUL (owner identifiers only; data classification per
the admission record). `ttl_ms` is an integer in `1..86_400_000`.
`limit` is an integer in `1..1_000`; `candidates` is a list of at most 1_000
distinct keys.

### 2.6 Non-goals and limits (to be recorded in piece.json)

- No distributed lock service, consensus, cross-store agreement,
  authorization (`seize` is attributable, not authorized), TTL policy,
  sweeper cadence, key discovery or job scheduling.
- Lease state is derived by reading the stream from `low_water + 1`; cost
  grows with stream length. Retention that prunes the latest lease record
  makes the key `ambiguous` (fail closed) until a `seize` or the holder's
  `release` (Q3).
- `claim_expired` and `renew` are per-key CAS writes, not one transaction
  over the batch; disjointness across concurrent claimers holds per key.
  A crash between keys leaves the keys already written as committed (Q2).
- Expiry uses the store clock read before the CAS; a long pause between the
  two can extend a lease that expired unobserved, never revive one after a
  handoff.
- The Store's refusal inside the caller's open Ecto transaction (ELZ-032)
  propagates as `{:error, :caller_transaction}`; the clock read is not
  separately guarded.
- Finite tests on two stores; PostgreSQL transaction and clock semantics are
  upstream contracts, not proofs.

## 5. Open questions for the early review

- **Q1 — `claim_expired` candidates.** The issue lists
  `claim_expired{owner, ttl, limit}`. The Store has no cross-stream index, so
  the Piece needs the candidate keys from the caller
  (`claim_expired(lease, owner, ttl_ms, limit, candidates)`); key discovery
  stays the Assembly's (ELZ-010's submission stream, a product table).
  Proposed Contract wording change for the issue, before/after, for the
  main coordinator: before `claim_expired{owner, ttl, limit}`; after
  `claim_expired{owner, ttl, limit, candidates}` (candidate keys supplied by
  the caller; discovery is not a lease responsibility). I will not edit the
  issue without the decision.
- **Q2 — "claim-next-ready under one transaction".** With the Store each key
  claim is one CAS transaction; the batch is not one transaction.
  Disjointness holds per key (LS7). I read the acceptance line
  "Concurrent `claim_expired` never hands one key to two owners" as satisfied
  by per-key CAS and will state the non-atomic batch as a limit. Confirm.
- **Q3 — pruned prefix.** `ambiguous` (fail closed) when `low_water > 0` and
  no lease record is visible, versus `free`. I propose fail closed with
  `seize` as the recovery and a consumer assumption not to retain through a
  live lease's record. Confirm or choose `free`.
- **Q4 — lease kinds as `:non_state_bearing`.** This keeps the consumer's
  reducer untouched (ELZ-009 `admits` never passes them to `reduce`) and keeps
  the consumer's checkpoint model unaffected. Confirm this reading of the
  ELZ-009 Contract.
- **Q5 — Jason directly** for the attributable JSON payloads (as ELZ-010
  did, deviation disclosed) versus `integration/json`. I propose Jason
  directly with the deviation disclosed in piece.json.
