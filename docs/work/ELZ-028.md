## 1. Decision: the Piece is needed

The ELZ-010 evidence on #45 shows that Oban 2.24.2's own ownership contract
does not satisfy the ELZ-028 invariants: it fences its ack by the
`attempted_at` timestamp, has no renewal, rescues by node time and uses the
node clock. ELZ-010 itself needs no lease (every Run write is fenced by the
ELZ-009 revision CAS plus attempt identity) and **does not use this Piece**;
that composed fence is narrower than the ELZ-028 Contract. Oban is comparison
evidence only, not a runtime dependency of `state/lease`. The owner decision
of 2026-11-08 opens every catalogue handle for development. So `state/lease`
is built as a WRAP over the ready Store. The provider mechanisms named in the
reuse check (advisory locks, `SKIP LOCKED`) are not adopted because the
Contract requires the lease to live in the same transactional record as the
state it guards.

Alternative considered and rejected: a separate PostgreSQL adapter in
`state/lease` writing into the `integration/sql` tables under its own
transaction (head lock, `clock_timestamp()`, record insert, revision update in
one transaction). It would evaluate the clock under the row lock, but it
bypasses the ready Store module, duplicates its append path and couples to a
schema another ready Piece owns. That is not a WRAP and would need a
scope/ownership decision; §2.4 shows the WRAP reaches the same observable
guarantee under a stated bound.

## 2. Contract reading

### 2.1 Model

A **key** is a Store stream (`Elzoo.DurableLog.Codec.stream?/1`). The lease
for a key is recorded **in that same stream** as ordinary records of the
consumer's fold. The stream's head revision is therefore one fence for both
the lease records and the guarded state records ("state owner: the same
transactional record as the state it guards").

Lease record kinds (`schema_version` 1; declared `:non_state_bearing`, so the
ELZ-009 replay advances its cursor over them and never calls the consumer's
reducer; they are not part of the consumer's checkpoint model; the consumer
merges `Elzoo.Lease.kinds/0` into `fold.kinds` and keeps `1` in
`fold.versions`):

| kind | payload (JSON object, UTF-8, Jason 1.4.5 as the ready `integration/json` recipe prescribes) | meaning |
| --- | --- | --- |
| `lease_claimed` | `v, owner, at, ttl_ms, until` | `owner` holds from store time `at` until `until` |
| `lease_renewed` | `v, owner, at, ttl_ms, until` | the holder extended its lease (valid only if `at < previous until`, §2.3) |
| `lease_released` | `v, owner, by, at, reason` | explicit attributable release: `owner` is the prior holder (or null when unknowable), `by` the releasing actor, `reason` an enumerated code |
| `lease_seized` | `v, owner, at, ttl_ms, until` | attributable operator takeover; always preceded in the same batch by a `lease_released` naming the prior owner when knowable, `by` the seizer and the seize reason |

`reason` codes (closed set, no free text, so the data classification stays
"owner identifiers only"): `released` (holder release of an active lease),
`stale` (holder release of its own expired lease, or a replacement claim over
an expired lease), `terminal` (release in the same batch as a terminal state
record), and for `seize`: `operator_takeover`, `crashed_owner`,
`pruned_prefix`, `corrupt_record`, `clock_regression`.

Times are integer microseconds since the Unix epoch in UTC, **read from the
store clock**: PostgreSQL `clock_timestamp()` through the same Ecto Repo the
Store uses (the clock is derived from the Store term, never injected
separately; §2.6), or the test-controlled manual clock of the volatile
Memory double. The Piece never reads a node wall clock. `until = at + ttl_ms
× 1000`.

### 2.2 Store-time semantics (B1)

Every lease write records the store-clock reading `at` it used, in the
committed record. **Liveness is defined in store time over the recorded
stamps**: a holder with `(at, until)` is live at store time `t` iff
`at <= t < until`. Readers never trust the writer's decision; the pure fold
(§2.3) re-derives the reading from the stamps, and the pure classifier maps
the reading and the reader's own store-clock value to a status. So the lease
condition that a committed record claims is checkable by every later reader
from the record itself.

Upstream clock interpretation (PostgreSQL 14–17 documentation, named as an
upstream contract, not proved): `now()` and `transaction_timestamp()` return
the **transaction start** time; `clock_timestamp()` returns the wall-clock
time at the call; both are read by a statement and **no SQL statement
observes the commit instant**; wall time may move backwards after an
administrative clock change. Consequently a single-transaction design that
checks `now() < until` under a row lock also checks a time earlier than its
commit; what it adds is that the lock keeps other writers out between its
clock read and its commit. The WRAP obtains the same exclusion through the
revision CAS (§2.4) and bounds the age of its clock reading at commit with the
grace rule below.

### 2.3 Pure part (`Cure.Elzoo.Lease`, B2)

Three reducible, law-covered tables and one primitive comparison:

```
type LeaseStatus   = LeaseFree | LeaseActive | LeaseStale | LeaseAmbiguous
type LeaseActor    = LeaseHolder | LeaseOther
type LeaseOp       = OpClaim | OpClaimExpired | OpRenew | OpRelease | OpSeize
type LeaseDecision = Permit | AlreadyFree | RefuseHeld | RefuseStale | RefuseAmbiguous | RefuseNotHolder | RefuseFree
type StampOrder    = StampBefore | StampSame | StampAfter
type LeaseReading  = NoHolder(Int) | HolderStamp(Int, Int) | Unreadable     # NoHolder(last_at); HolderStamp(at, until)
type LeaseEvent    = EvClaim(Int, Int) | EvRenew(Int, Int) | EvRelease(Int) | EvSeize(Int, Int) | EvUnreadable

fn compare(left: Int, right: Int) -> StampOrder                 # the only integer comparison (pickup); test-grounded
fn classify(reading: LeaseReading, now: Int) -> LeaseStatus      # production classifier = classify_reading(reading, compare(stamp, now), compare(until, now))
fn step(reading: LeaseReading, event: LeaseEvent) -> LeaseReading   # production fold = step_order(reading, event, compare(event_at, last_at), compare(event_at, until))
fn decide(op: LeaseOp, status: LeaseStatus, caller: LeaseActor) -> LeaseDecision
```

**Classification table.** `NoHolder(_) → free`; `Unreadable → ambiguous`;
`HolderStamp(at, until)`: `at > now → ambiguous` (stamp in the future);
otherwise `until > now → active`, `until <= now → stale` (the boundary
`until == now` is stale; `at == now` is admitted).

**Fold table** (reading × event → reading), applied to the lease records
below the head revision in sequence order from `NoHolder(0)`:

- `EvUnreadable` (validation, digest, JSON, version or field failure of a
  lease record) → `Unreadable`, and `Unreadable` is sticky under renew and
  release;
- `EvSeize(at, until)` → `HolderStamp(at, until)` from any reading (the
  attributable recovery path);
- `EvClaim(at, until)` → `HolderStamp(at, until)`, unless `at` is earlier than
  the last recorded stamp (clock regression) → `Unreadable`;
- `EvRelease(at)` → `NoHolder(at)` from a holder or a free reading
  (regression → `Unreadable`);
- `EvRenew(at, until)` from `HolderStamp(a0, u0)`: `at < u0 → HolderStamp(at,
  until)`; `at >= u0` → the reading stays `HolderStamp(a0, u0)` (**a renewal
  stamped at or after expiry never extends the lease**); from `NoHolder` →
  `Unreadable` (a renewal without a holder is a foreign or damaged write).

**Decision table.** `claim`: free/stale → `Permit` (stale carries the
attributable release, §2.5); active by the holder → `Permit` (a fresh
`lease_claimed`); active by another → `RefuseHeld`; ambiguous →
`RefuseAmbiguous`. `claim_expired`: stale → `Permit`; free → `RefuseFree`
(never-held or released keys are not "expired"; R1 asks the Contract to say
so); active → `RefuseHeld`; ambiguous → `RefuseAmbiguous`. `renew`: active by
the holder → `Permit`; active by another → `RefuseNotHolder`; stale →
`RefuseStale`; free → `RefuseFree`; ambiguous → `RefuseAmbiguous`. `release`:
active/stale by the holder → `Permit`, by another → `RefuseNotHolder`; free →
`AlreadyFree` (idempotent, no write); ambiguous → `RefuseAmbiguous` (identity
is not inferred from the caller's owner string; only `seize` recovers).
`seize` → `Permit` from any status.

### 2.4 Atomic condition and change at the serialization point (B1)

Every lease operation on key `k`:

1. read the head `(r, low_water)`; read the lease rows in `(low_water, r]`
   (paged; §2.7); read the head again and restart if `r` or `low_water`
   moved (bounded, then `{:error, :contended}`);
2. read the store clock → `now` (never inside the caller's open Ecto
   transaction: the Repo's `in_transaction?/0` is checked first and the
   operation returns `{:error, :caller_transaction}` without a statement);
3. fold → reading; `classify(reading, now)` → status; `decide` → decision;
4. if permitted, build the lease record(s) with `at = now` and **append with
   `expected = r`** through `Elzoo.DurableLog.Store.write/4`.

The Store CAS commits only if the head is still `r`. Any concurrent record
change (a competing claim or seize, the holder's own write, a terminal
record) moves the head and the CAS fails: `{:lease_refused, %{reason:
:lost_race}}`; the caller re-reads. The condition was evaluated on exactly the
committed state the write replaces, and the committed record carries the
stamp the condition used, so the serialization point (the CAS commit) carries
the condition with it and every reader re-checks it (§2.2, fold law F2/F3).

**Why expiry is valid at the actual atomic point.**

- *Stale → claim/seize.* Expiry in store time is monotone unless the store
  clock regresses; a reading judged stale at `now` is stale at every later
  store time, so a permitted takeover never takes a live lease. A regressed
  clock is detected by the fold (a later record with an earlier stamp →
  `Unreadable`, F8) and by the classifier (a stamp ahead of the reader's
  `now` → ambiguous, C4); both fail closed, and only `seize` with
  `clock_regression` recovers.
- *Active → renew.* The renewal is admitted only if
  `now + renew_grace_us < until` (the **grace rule**), and the clock reading
  is discarded and re-read if more than `clock_age_ms` (default 1_000)
  elapsed on the node's **monotonic** clock between the reading and the Store
  write call. The Store write is bounded by the Store's per-statement timeout
  (`integration/sql` default 30_000 ms; at most five statements for a
  two-record lease batch; the value is read from the Store term, not assumed).
  So the physical commit happens at most `clock_age + 5 × store_timeout` after
  the clock reading, and `renew_grace_ms` defaults to that sum (151_000 ms)
  and may be lowered by the consumer only together with a lower Store
  timeout. Under the assumption that elapsed time measured by the node's
  monotonic clock and by the store clock agree within the grace (rate skew,
  not offset), a renewal that commits does so while the lease is live in
  store time. Without that assumption the fold still guarantees that a
  renewal stamped at or after expiry never extends (F2, F3), and the
  classifier marks a future stamp ambiguous. Consequence recorded as a
  reviewed boundary choice: `ttl_ms` must exceed `renew_grace_ms`, else `renew`
  is always `RefuseStale`-equivalent (`{:lease_refused, %{reason:
  :grace}}`); `claim` and `seize` have no grace because stale is monotone.
- *Handoff.* A renewal issued before a handoff and applied after it cannot
  revive the lease: the handoff moved the head, the CAS fails (LS8). A
  competitor that observed stale and lost the CAS to a renewal that satisfied
  the grace rule lost to a lease that was live at the renewal's commit.
- *The holder's state writes.* They carry only `expected = fence revision`;
  the Piece never compares timestamps on them, and the Store accepts any
  caller that presents the current revision: the fence is a staleness
  detector, not an identity or authorization token (R3). A write from an
  expired holder commits if nobody has written since (no replacement exists
  to protect) and is refused by revision as soon as a replacement wrote
  anything (LS4). The acceptance sentence "A write from an expired lease
  holder is refused by revision" is kept unchanged pending the main
  coordinator's clarification (contract-proposed A4); the control case is
  reported as a control, not as satisfying that sentence.

### 2.5 Attributable release (R2)

- A replacement claim over a **stale** lease appends **two records in one
  CAS batch**: `lease_released{owner: prior, by: claimer, at, reason: stale}`
  then `lease_claimed{owner: claimer, …}`. The consumer's `limits.max_batch_size`
  must be at least 2 (checked at `new/1`).
- A holder's release of its own active or stale lease appends
  `lease_released{owner: holder, by: holder, reason: released | stale}`.
- `seize` appends `lease_released{owner: prior-or-null, by: seizer, reason}`
  then `lease_seized{owner: seizer, …}` in one batch, from any status.
- **Ambiguous** (future stamp, unreadable record, clock regression, pruned
  latest record): `claim`, `claim_expired`, `renew` and `release` are refused
  for every caller; the recorded owner, when readable, is reported in the
  refusal but grants nothing. Only `seize` with a reason recovers the key.
  Tested separately: future-stamped known holder (LS9), malformed JSON,
  unknown version, digest mismatch (LS10), unknown holder (LS10b), pruned
  latest record (LS15), attributable operator seizure (LS5b).
- Terminal state (R3): `complete/4` **always** appends
  `lease_released{reason: terminal}` as the last record of the terminal
  batch; `write/4` never does. The consumer Need: every write to a leased
  stream goes through `write/4` or `complete/4` of the holder (or passes the
  fence revision as `expected`), and the consumer identifies which of its
  record kinds are terminal and routes them through `complete/4`; direct
  Store writers that bypass this are excluded by the consumer. Commit and
  rollback of the terminal batch are shown on both providers (LS11c).

authority). `{:indeterminate, info}` is the Store's unknown-outcome receipt

`owner` is UTF-8 text of 1..200 bytes without NUL; `ttl_ms` in
1..86_400_000 and greater than `renew_grace_ms` for `renew` to be admissible;
`limit` in 1..1_000; `candidates` at most 1_000 distinct keys;
`limits.max_record_bytes >= 1_024` and `limits.max_batch_size >= 2`.

### 2.7 Retention and read consistency (B5)

Facts from the ready Store: `retain/5` locks the head, advances `low_water`,
deletes records at or below `through` and **does not advance `revision`**;
`append` checks `revision` only. Consequences and design:

- Retention never changes the committed lease history; it changes what is
  readable. A lease decision taken from the committed rows at revision `r`
  is taken from the true state; a CAS at `r` that succeeds after a
  concurrent retention wrote a record whose correctness depended only on
  that true state, and the new record (sequence `r+1 > through`) is visible
  to every later reader. So retention cannot make a committed lease write
  unsafe; it can make a later **reading** unavailable (LS16).
- **Pruned latest record:** `low_water > 0` and no lease record visible in
  `(low_water, r]` → `Unreadable`/ambiguous with reason `:pruned_prefix`
  (fail closed); recovery is `seize` with reason `pruned_prefix` (LS15).
  `retention_bound/2` returns the highest `through` that keeps the latest
  lease record (or `low_water` when the stream has none), and the consumer
  Need says: a consumer that retains a leased stream passes
  `min(its through, retention_bound)`; direct `retain` beyond the bound is
  excluded by the consumer, and the Piece's only enforcement is fail closed.
- **Paging consistency:** rows are read in pages (`page`, default 1_000)
  from `low_water + 1`; each page is one Store read (one REPEATABLE READ READ
  ONLY transaction on PostgreSQL, one GenServer call on Memory). After the
  last page the head is read again; if `revision` or `low_water` differ from
  the first head the reading is restarted, at most `max_reads` times, then
  `{:error, :contended}`. Rows above `r` (a staged tail or a concurrent
  append) are ignored. Tests force paging with `page: 2` and interleave a
  retention between pages (LS17) and between the reading and the CAS (LS16)
  on both stores.

### 2.8 Readiness and `claim_expired` (B3, R1)

Readiness predicate: `ready(k) := classify(reading(k), now) = LeaseStale`
(an expired lease; free keys are not ready for `claim_expired`). Selection
and claim for **one key** share one atomic step: the readiness is evaluated
on the committed rows at revision `r` and the claim is the CAS at `r`; a
lost selection race (two claimers evaluate the same key ready at the same
revision) is decided by the CAS: one commits, the other gets `lost_race` and
continues with its next candidate (LS7a deterministic with a barrier before
the CAS on both stores; LS7b free-running on PostgreSQL). Candidate keys are
supplied by the caller (`candidates`), because the Store has no cross-stream
index; key discovery is a caller Need (ELZ-010's submission stream, a
product table). The batch is **not** one transaction: a crash between keys
leaves the keys already claimed as committed, and a later invocation sees
them `active` and skips them; two invocations with overlapping candidate
lists are disjoint per key; a key released and reclaimed while an invocation
runs can appear in both invocations' results only as distinct revisions
(the `held.live.revision` values differ). These statements are the proposed
Contract text in [ELZ-028-contract-proposed.md](ELZ-028-contract-proposed.md)
A1–A2; the existing sentence "claim-next-ready under one transaction" is
kept and the proposed text is appended, as the reviewer asked.

### 2.9 Non-goals and limits (for piece.json)

- No distributed lock service, consensus, cross-store agreement,
  authorization (`seize` is attributable, not authorized; owner strings and
  `held` maps are not security tokens), TTL policy, sweeper cadence, key
  discovery or job scheduling.
- Lease state is derived by reading the stream from `low_water + 1`; cost
  grows with stream length; retention past the latest lease record makes the
  key ambiguous until a `seize`.
- `claim_expired` and `renew` are per-key CAS writes, not one transaction over
  the batch.
- Liveness at the physical commit of a renewal relies on the grace rule and
  the elapsed-time assumption of §2.4; the fold guarantees that a renewal
  stamped at or after expiry never extends regardless.
- The Store's refusal inside the caller's open Ecto transaction (ELZ-032)
  is honoured before the clock statement; a transaction opened outside Ecto
  is not detected (the `integration/sql` limit).
- Finite tests on two stores; PostgreSQL `clock_timestamp()`, transaction and
  locking semantics are upstream contracts, not proofs.

# SPDX-License-Identifier: Apache-2.0
mod Elzoo.Lease
  use Std.Option

  type LeaseStatus = LeaseFree | LeaseActive | LeaseStale | LeaseAmbiguous
  type LeaseActor = LeaseHolder | LeaseOther
  type LeaseOp = OpClaim | OpClaimExpired | OpRenew | OpRelease | OpSeize
  type LeaseDecision = Permit | AlreadyFree | RefuseHeld | RefuseStale | RefuseAmbiguous | RefuseNotHolder | RefuseFree
  type StampOrder = StampBefore | StampSame | StampAfter
  type LeaseReading = NoHolder(Int) | HolderStamp(Int, Int) | Unreadable
  type LeaseEvent = EvClaim(Int, Int) | EvRenew(Int, Int) | EvRelease(Int) | EvSeize(Int, Int) | EvUnreadable

  fn compare(left: Int, right: Int) -> StampOrder =
    pickup
      left < right -> StampBefore()
      left > right -> StampAfter()
      else -> StampSame()

  @total true
  @reducible
  fn by_expiry(until_vs_now: StampOrder) -> LeaseStatus =
    match until_vs_now
      StampAfter() -> LeaseActive()
      StampSame() -> LeaseStale()
      StampBefore() -> LeaseStale()

  @total true
  @reducible
  fn classify_order(at_vs_now: StampOrder, until_vs_now: StampOrder) -> LeaseStatus =
    match at_vs_now
      StampAfter() -> LeaseAmbiguous()
      StampSame() -> by_expiry(until_vs_now)
      StampBefore() -> by_expiry(until_vs_now)

  @total true
  @reducible
  fn classify_reading(reading: LeaseReading, at_vs_now: StampOrder, until_vs_now: StampOrder) -> LeaseStatus =
    match reading
      NoHolder(_) -> LeaseFree()
      Unreadable() -> LeaseAmbiguous()
      HolderStamp(_, _) -> classify_order(at_vs_now, until_vs_now)

  @total true
  @reducible
  fn stamp_of(reading: LeaseReading) -> Int =
    match reading
      NoHolder(last) -> last
      HolderStamp(at, _) -> at
      Unreadable() -> 0

  @total true
  @reducible
  fn until_of(reading: LeaseReading) -> Int =
    match reading
      NoHolder(_) -> 0
      HolderStamp(_, until) -> until
      Unreadable() -> 0

  fn classify(reading: LeaseReading, now: Int) -> LeaseStatus =
    classify_reading(reading, compare(stamp_of(reading), now), compare(until_of(reading), now))

  @total true
  @reducible
  fn regress(order: StampOrder, next: LeaseReading) -> LeaseReading =
    match next
      Unreadable() -> Unreadable()
      NoHolder(last) ->
        match order
          StampBefore() -> Unreadable()
          StampSame() -> NoHolder(last)
          StampAfter() -> NoHolder(last)
      HolderStamp(at, until) ->
        match order
          StampBefore() -> Unreadable()
          StampSame() -> HolderStamp(at, until)
          StampAfter() -> HolderStamp(at, until)

  @total true
  @reducible
  fn renew_reading(reading: LeaseReading, at_vs_until: StampOrder, at: Int, until: Int) -> LeaseReading =
    match reading
      NoHolder(_) -> Unreadable()
      Unreadable() -> Unreadable()
      HolderStamp(held_at, held_until) ->
        match at_vs_until
          StampBefore() -> HolderStamp(at, until)
          StampSame() -> HolderStamp(held_at, held_until)
          StampAfter() -> HolderStamp(held_at, held_until)

  @total true
  @reducible
  fn release_reading(reading: LeaseReading, at: Int) -> LeaseReading =
    match reading
      NoHolder(_) -> NoHolder(at)
      Unreadable() -> Unreadable()
      HolderStamp(_, _) -> NoHolder(at)

  @total true
  @reducible
  fn step_order(reading: LeaseReading, event: LeaseEvent, regression: StampOrder, at_vs_until: StampOrder) -> LeaseReading =
    match event
      EvUnreadable() -> Unreadable()
      EvSeize(at, until) -> HolderStamp(at, until)
      EvClaim(at, until) -> regress(regression, HolderStamp(at, until))
      EvRelease(at) -> regress(regression, release_reading(reading, at))
      EvRenew(at, until) -> regress(regression, renew_reading(reading, at_vs_until, at, until))

  @total true
  @reducible
  fn event_stamp(event: LeaseEvent) -> Int =
    match event
      EvUnreadable() -> 0
      EvSeize(at, _) -> at
      EvClaim(at, _) -> at
      EvRelease(at) -> at
      EvRenew(at, _) -> at

  fn step(reading: LeaseReading, event: LeaseEvent) -> LeaseReading =
    step_order(reading, event, compare(event_stamp(event), stamp_of(reading)), compare(event_stamp(event), until_of(reading)))

  fn initial() -> LeaseReading = NoHolder(0)

  @total true
  @reducible
  fn claim(status: LeaseStatus, caller: LeaseActor) -> LeaseDecision =
    match status
      LeaseFree() -> Permit()
      LeaseStale() -> Permit()
      LeaseAmbiguous() -> RefuseAmbiguous()
      LeaseActive() ->
        match caller
          LeaseHolder() -> Permit()
          LeaseOther() -> RefuseHeld()

  @total true
  @reducible
  fn claim_expired(status: LeaseStatus, caller: LeaseActor) -> LeaseDecision =
    match status
      LeaseFree() -> RefuseFree()
      LeaseStale() -> Permit()
      LeaseAmbiguous() -> RefuseAmbiguous()
      LeaseActive() -> RefuseHeld()

  @total true
  @reducible
  fn renew(status: LeaseStatus, caller: LeaseActor) -> LeaseDecision =
    match status
      LeaseFree() -> RefuseFree()
      LeaseStale() -> RefuseStale()
      LeaseAmbiguous() -> RefuseAmbiguous()
      LeaseActive() ->
        match caller
          LeaseHolder() -> Permit()
          LeaseOther() -> RefuseNotHolder()

  @total true
  @reducible
  fn by_holder(caller: LeaseActor) -> LeaseDecision =
    match caller
      LeaseHolder() -> Permit()
      LeaseOther() -> RefuseNotHolder()

  @total true
  @reducible
  fn release(status: LeaseStatus, caller: LeaseActor) -> LeaseDecision =
    match status
      LeaseFree() -> AlreadyFree()
      LeaseStale() -> by_holder(caller)
      LeaseAmbiguous() -> RefuseAmbiguous()
      LeaseActive() -> by_holder(caller)

  @total true
  @reducible
  fn decide(op: LeaseOp, status: LeaseStatus, caller: LeaseActor) -> LeaseDecision =
    match op
      OpClaim() -> claim(status, caller)
      OpClaimExpired() -> claim_expired(status, caller)
      OpRenew() -> renew(status, caller)
      OpRelease() -> release(status, caller)
      OpSeize() -> Permit()

  fn no_holder_is_free(last: Int, now: Int) -> Equivalent(LeaseStatus, classify(NoHolder(last), now), LeaseFree()) =
    reflexive(LeaseFree())

  fn unreadable_is_ambiguous(now: Int) -> Equivalent(LeaseStatus, classify(Unreadable(), now), LeaseAmbiguous()) =
    reflexive(LeaseAmbiguous())

  fn holder_classifies_by_orders(at: Int, until: Int, now: Int) -> Equivalent(LeaseStatus, classify(HolderStamp(at, until), now), classify_order(compare(at, now), compare(until, now))) =
    reflexive(classify_order(compare(at, now), compare(until, now)))

  fn future_stamp_is_ambiguous(until_vs_now: StampOrder) -> Equivalent(LeaseStatus, classify_order(StampAfter(), until_vs_now), LeaseAmbiguous()) =
    reflexive(LeaseAmbiguous())

  fn stamp_now_classifies_by_expiry(until_vs_now: StampOrder) -> Equivalent(LeaseStatus, classify_order(StampSame(), until_vs_now), by_expiry(until_vs_now)) =
    reflexive(by_expiry(until_vs_now))

  fn past_stamp_classifies_by_expiry(until_vs_now: StampOrder) -> Equivalent(LeaseStatus, classify_order(StampBefore(), until_vs_now), by_expiry(until_vs_now)) =
    reflexive(by_expiry(until_vs_now))

  fn expiry_passed_is_stale() -> Equivalent(LeaseStatus, by_expiry(StampBefore()), LeaseStale()) =
    reflexive(LeaseStale())

  fn expiry_now_is_stale() -> Equivalent(LeaseStatus, by_expiry(StampSame()), LeaseStale()) =
    reflexive(LeaseStale())

  fn expiry_ahead_is_active() -> Equivalent(LeaseStatus, by_expiry(StampAfter()), LeaseActive()) =
    reflexive(LeaseActive())

    reflexive(HolderStamp(at, until))

    reflexive(HolderStamp(held_at, held_until))

  fn renewal_after_expiry_keeps_lease(held_at: Int, held_until: Int, at: Int, until: Int) -> Equivalent(LeaseReading, step_order(HolderStamp(held_at, held_until), EvRenew(at, until), StampAfter(), StampAfter()), HolderStamp(held_at, held_until)) =
    reflexive(HolderStamp(held_at, held_until))

  fn renewal_without_holder_is_ambiguous(last: Int, at: Int, until: Int, regression: StampOrder, at_vs_until: StampOrder) -> Equivalent(LeaseReading, step_order(NoHolder(last), EvRenew(at, until), regression, at_vs_until), Unreadable()) =
    reflexive(Unreadable())
