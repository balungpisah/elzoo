### Configuration and retention (explicit)

- `window` (W): positive integer. For each sender the receiver remembers the
  highest accepted sequence `high` of the current incarnation and the accepted
  sequences in the half-open interval `(high - W, high]`. At most W sequence
  numbers are retained per sender.
- `max_senders` (N): positive integer. At most N `SenderWindow` entries.
- Retention is therefore bounded by N senders × (W sequences + 3 integers);
  it is sequence-count based. **There is no time-based expiry and no clock
  input.** Configuration is fixed at construction inside `WindowedState`
  (no hot reconfiguration; a new configuration means a new state).

### Pure Cure API

    fn initial(window: Int, max_senders: Int) -> WindowedState      # empty senders
    fn classify(state: WindowedState, input: Message) -> WindowDecision
    @total true
    fn step(state: WindowedState, input: Message, decision: WindowDecision) -> Transition(WindowedState, Message)
    fn receiver(state: WindowedState, input: Message) -> Transition(WindowedState, Message)
      = step(state, input, classify(state, input))

`receiver` has the `(s, i) -> Transition(s, m)` shape and composes with the
unchanged `Elzoo.Composition.compose/4` (probe: compiled and executed as the
`first` operator). Output is `Option(Message)`: the accepted input is emitted
unchanged; every non-accepted decision emits `None()` and leaves the state
**exactly unchanged**.

### Decision table (first matching row wins; sender table looked up by `input.sender`)

| # | Condition | Decision | Output | Next state |
| --- | --- | --- | --- | --- |
| 1 | `window < 1` or `max_senders < 1` | `WindowInvalid` | None | unchanged |
| 2 | no entry for sender, `length(senders) >= max_senders` | `WindowFull` | None | unchanged (existing senders unaffected; nothing evicted) |
| 3 | no entry for sender | `WindowFresh` | Some(input) | entry `{sender, incarnation, seq, [seq]}` added |
| 4 | `input.incarnation < entry.incarnation` | `WindowSuperseded` | None | unchanged |
| 5 | `input.incarnation > entry.incarnation` | `WindowNewIncarnation` | Some(input) | entry replaced by `{sender, incarnation, seq, [seq]}` (old incarnation's window discarded) |
| 6 | `seq > high` | `WindowAdvance` | Some(input) | `high := seq`; accepted := `[seq]` ++ old accepted filtered to `> seq - W` |
| 7 | `seq <= high - W` | `WindowStale` | None | unchanged (out of window, deterministic even if never seen) |
| 8 | `seq` in accepted | `WindowDuplicate` | None | unchanged |
| 9 | otherwise (`high - W < seq < high`, not seen) | `WindowReorder` | Some(input) | `seq` added to accepted; `high` unchanged |

Keys are `(sender, incarnation, sequence)`; `value` is ignored for detection
(same as delivery/idempotency). Sequences and incarnations are unbounded BEAM
integers; negative values are ordinary integers (no range claimed). Sender
entry and accepted-list ordering are an internal representation (not part of
the Contract); callers must treat `WindowedState` as opaque and build it only
via `initial`/`new`.

Note the deliberate difference from delivery/idempotency: an out-of-window
message (row 7) is suppressed even if it was never delivered, and a lower
incarnation is suppressed (row 4). This is a stale-input policy, not loss-free
delivery; a sender that needs those messages must not exceed the window.

### Elixir boundary `Elzoo.WindowedIdempotency`

    new(window, max_senders)
      :: {:ok, state} | {:error, :invalid_window | :invalid_max_senders}
    # both must be is_integer and >= 1 (window checked first)

    receive(state, message)
      :: {:ok, {next_state, :none | {:some, message}}, decision}
       | {:error, :invalid_state | :invalid_message}
    decision :: :fresh | :advance | :reorder | :duplicate | :stale
              | :superseded | :new_incarnation | :full

    classify(state, message) :: {:ok, decision} | {:error, :invalid_state | :invalid_message}

- `message` must be `{:Message, s, i, q, v}` with four integers;
  otherwise `:invalid_message`.
- `state` must be a `WindowedState` with positive integer config, a **proper**
  list of `SenderWindow` entries (improper lists rejected before any Enum
  traversal), integer fields, proper `accepted` integer lists, at most
  `max_senders` entries, no duplicate senders, and each accepted list non-empty,
  containing `high`, all within `(high - W, high]`, without duplicates;
  otherwise `:invalid_state`. The boundary never returns `:invalid` decisions:
  `WindowInvalid` is reachable only by direct Cure/BEAM callers with a bad
  `initial`.
- `receive/2` calls the compiled `receiver/2` and reports `classify/2` of the
  same input/state; a test asserts that the reported decision matches the
  transition actually produced (emit iff fresh/advance/reorder/new_incarnation;
  state unchanged otherwise).
- Errors are fixed atoms; no payload/state values are echoed.

### Composability through the typed boundary

Typed composition is the Cure `Transition`/`compose` seam (core/operator):
`receiver` replaces the P0 `Cure.Elzoo.Idempotency.receiver/2` as a `first`
operator over the same `Message` type. No Envelope/Wiring/Adapter/Unit code is
changed; running it inside the existing `Elzoo.Unit` is possible because the
Unit accepts any `(state, input) -> Transition` operator, but no Assembly in
this task adopts it and no runtime claim is made for that placement.

## Delivery, ordering, storage and clock assumptions (external / assembly contracts)

- Per sender, sequences are assigned by the sender and increase within an
  incarnation; the receiver does not verify this. A sender reusing a sequence
  number for different content is suppressed as a duplicate.
- A sender restart must use a strictly greater incarnation; otherwise new
  messages may be suppressed as duplicate/stale.
- No cross-sender ordering, no reordering buffer: accepted messages are emitted
  immediately in arrival order (in-window reorders are emitted late, not held).
- State is a volatile value. Losing it (process restart, no persistence) forgets
  the windows, so duplicates can be emitted again. No durable storage, replay,
  replicated log or network transport.
- No clock: "window" is sequence distance, not time.
- Suppression of output is not an acknowledgement policy; ack/retry/dead-letter
  belong to ELZ-006. No exactly-once Effect claim: an emitted message's
  downstream Effect may still fail or repeat.
- Not the complete historical Zoo receiver.

## Evidence plan (separated)

- **Proof (selected Cure laws, helper/decision scope only).** Over `step` with
  a supplied decision, quantified over every state and input:
  `duplicate_emits_nothing`, `duplicate_keeps_state`,
  `stale_emits_nothing`, `stale_keeps_state`, `superseded_keeps_state`,
  `full_keeps_state` (output None and state unchanged), and
  `reorder_preserves_message`, `advance_preserves_message` (output `Some(input)`).
  Probe: the decision-level `reflexive` proofs compile on the pin and the Cure
  audit reports no axioms/holes/unresolved/not_proven_total. These laws
  **do not** cover `classify` or `receiver`; that gap is disclosed in README,
  piece.json limits and the ledger. A receiver-level replay law
  (`output(receiver(next(receiver(s, m)), m)) == None()`) and Int-equality
  reduction were attempted in the probe and **not** closed (`simplify` residual
  goal / conversion failure), so no receiver-level proof is claimed.
- **Type check.** Pinned Cure compiles the source (including typed composition
  with `compose`); negative controls: a false law (duplicate emitting
  `Some(input)`) and an unfinished hole are rejected; an audit test as in
  delivery/idempotency.
- **Tests (finite named scenarios over the actual compiled `receiver`/`classify`
  and Elixir boundary, not proofs):** first delivery; exact duplicate (same and
  different value); in-window reorder then its duplicate; advance with pruning
  (retained list never exceeds W and stays within the interval); boundary
  sequences `high - W` (stale) and `high - W + 1` (reorder); W = 1; large gap;
  negative sequences; lower/higher incarnation; capacity full for a new sender
  while existing senders continue; invalid config via direct `initial`
  (`WindowInvalid`); every boundary error (non-integers, zero/negative,
  wrong tuple, improper sender/accepted lists, over-capacity, inconsistent
  windows); decision/transition agreement; a seeded deterministic model check
  comparing `receiver` with an independent Elixir reference model over generated
  traces (asserting no duplicate emission within the window and the retention
  bound for those traces); composition with a downstream operator via `compose`;
  delivery/idempotency tests untouched and still passing.
- **Export:** an isolated consumer of `delivery/windowed-idempotency` (with its
  dependencies) compiles and runs without `Elzoo.Application` and without the
  Cure compiler at runtime (`test/export_test.exs` ID list extended).
- **Upstream:** pinned Cure compiler/kernel (commit a004c335), Elixir/OTP.
- **Assumptions (unverified):** the ordering/incarnation/storage/clock items above.
