## Findings that affect selection

1. **The list's framework descriptions lag current package boundaries.** Ash AI 1.5.1 has optional ReqLLM `~> 1.29`, and its README says MCP-only use can omit it. LangChain 0.15.8 also has an optional ReqLLM adapter. Neither needs to be adopted merely to reach an HTTP model provider. An Ash resource consumer may reuse its action/tool machinery directly without introducing Jido.
2. **Ash tool exposure requires explicit access checks.** The release README says only public fields are filterable, but `load` can make private attributes visible in responses. MCP tool annotations are hints, not security guarantees. Preserve authenticated actor/tenant context, current authority, exact-action approval, output allowlists and resource bounds at execution. Do not expose the development MCP surface as a production tool gateway.
3. **ExMCP has a current maintained identity.** The published package remains `ex_mcp 1.8.1`; its repository moved to `trust-arbor/arbor_mcp`, with the 1.x maintenance line distinct from Arbor 2.x release candidates. Its README claims MCP and ACP support, transport/version negotiation and conformance suites. Those are upstream claims, not tests run here. The recorded default-branch activity is repository activity, not necessarily the 1.x branch's last commit. Pin the package and selected protocol/transport explicitly.
4. **PhantomMCP is a focused server alternative.** Its 0.8.0 README describes Plug/stdin/stdout and Streamable HTTP, typed tool declarations and dispatch-time validation. It also describes newer protocol and A2A features while an introductory link names the older 2025-03-26 transport spec. Test the exact negotiated version; do not infer client/ACP-runner coverage from a server framework. The host still owns authentication and per-tool authority.
5. **Structured extraction already has multiple implementations.** InstructorLite supplies Ecto-to-JSON-schema and response casting/validation with retry. ReqLLM already supplies structured output. Choose one at the selected boundary; a malformed output can trigger a bounded new model call, but never automatic replay of tool effects. A schema pass is neither factual correctness nor a Cure proof.
6. **Retrieval preprocessing and context admission differ.** TextChunker records byte offsets and documented overlap/format choices; its release README names Unicode edge cases and says display sanitization remains the caller's responsibility. pgvector 0.4.2 supplies Ecto/Postgrex types/helpers, not an embedding provider or automatic database extension install. Keep model/version/dimension provenance, tenant predicates and result caps explicit; retrieved content still passes ready `workflow/context-selection`.
7. **Package-name collision:** the list's AI `seanmor5/honeycomb` README installs from GitHub. Hex `honeycomb 0.1.1` instead belongs to `Hentioe/honeycomb`, a task scheduler. That version, license declaration and Hex owners must not be attached to the AI inference repository. The register records the collision; no AI Honeycomb Hex release is verified. ExFaiss's matching Hex name returned 404 and its repository is archived without a detected license; Evals's matching Hex name returned 404 and its repository has no detected license. Those results do not prove no other release name exists.
8. **A permissive wrapper does not erase backend licensing.** Anubis MCP 2.2.0 is LGPL-3.0. ClaudeCode 0.36.5 requires Anubis `~> 1.0`; the checked compatible stable 1.14.0 release LICENSE is also LGPL-3.0. Vix is MIT but its libvips backend is identified as LGPL-2.1. YOLO's Apache-2.0 wrapper does not settle the terms of Ultralytics implementations/weights; the Ultralytics repository is AGPL-3.0 and exact selected weight terms remain unverified. No copyleft implementation source was read. Apply the owner's clean-room rule to excluded code; prefer an acceptable existing alternative rather than automatically rebuilding it.
9. **Hosted and native model needs stay visible.** Chatterbex invokes a Python/model stack; Evision/NxImage/Explorer use native numerical/media tooling. Wrapper licensing is not model-weight licensing, a NIF is not an OS sandbox, and local inference still needs capacity, cancellation and memory failure handling. A listed benchmark such as YOLO's “38ms” is not portable evidence and is not adopted as a claim.
10. **Evaluation is separate from correctness.** DeepEvalEx's exact-match and model-judge metrics can support a fixed evaluation corpus, but scores do not prove lack of hallucinations or safe tool execution. Evals, Usage Rules, Cohere, Livebook and Kino are development aids, not substitutes for selected Cure laws, boundary tests or the authoritative task Contract. The listed TWZRD service's advertised trust score cannot replace Elzoo principal/authorization decisions; no call to that service was made.

The owner has resolved Ra/Khepri dual licensing: explicit Apache-2.0 OR MPL-2.0 may use Apache-2.0. The revised source 2 records that chosen option and all exact transitive package licenses. Neither may be forked; adoption still needs a real caller and owner batch selection. This does not relax the copyleft-only/non-commercial rule above.

## Ready-Piece overlaps and admission boundaries

Keep the 17 explicit ready entries unchanged. `domain/authorization` and `workflow/approval` gate tool actions; MCP annotations, model-generated arguments and client allowlists do not replace them. `workflow/budget` owns reservation/settlement, while provider usage and LLM price estimates remain observed/estimated facts. `workflow/context-selection` still owns access/provenance and selected byte/count caps after any retrieval or chunking. `workflow/dependency-graph` and `workflow/state-machine` own their named pure laws; model plans/chains are not those laws.

`integration/jobs` and `assembly/durable-job` retain Oban execution and accepted durable boundaries; `state/event-log`, `state/checkpoint`, `state/outbox` and `integration/sql` are not interchangeable with vector indexes, chat memory or framework checkpoints. `assembly/request-route-retry`, `delivery/retry-timeout`, `delivery/backpressure`, `delivery/dead-letter` and `delivery/windowed-idempotency` must not acquire hidden SDK retries, unbounded queues, raw provider payload logging or durable/exactly-once claims. Reusing schemas or process monitors does not establish reciprocal parent/child settlement or observed cancellation.

Every admitted Adapter needs declared Telemetry/Config/Control, versioned provider/source closure and an independent consumer check. A codec/schema checker is a type/contract check only over its selected inputs; model quality and live provider behavior are finite tests/observations. No runtime checks or `mix setup`/`mix check` were run for this report. Static metadata/license/coverage checks do not imply a compatible installed dependency graph.
