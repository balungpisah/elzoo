## Records and canonical bytes

`%Elzoo.DurableLog.Record{stream, sequence, kind, schema_version, payload,
nonce, digest}`; outbox item `%Elzoo.Outbox.Item{stream, sequence, position,
destination, idempotency_key, payload}`; checkpoint
`%Elzoo.Checkpoint{stream, sequence, fold_version, model, cursor, seen,
nonce, digest}`. `cursor` holds all three Cure cursor fields; `seen` is the
Elixir shell's map of applied sequence to validated record digest (including
non-state-bearing records), needed to check duplicate identity across recovery.

- `stream`: binary, 1..200 bytes, UTF-8. `sequence`: integer ≥ 1, assigned by
  the append (`expected + i`), never by the caller. `kind`: binary from the
  consumer's declared kind table; `schema_version`: positive integer from the
  consumer's declared version set. `payload`: opaque binary ≤ `max_record_bytes`
  (consumer encodes, e.g. Jason; Elzoo does not interpret it). `nonce`: 16
  random bytes from `:crypto.strong_rand_bytes/1`, fresh per append call,
  shared by every record/outbox item of that batch.
- `digest` = SHA-256 (`:crypto.hash/2`) over the canonical encoding
  `<<1::8, byte_size(stream)::32, stream::binary, sequence::64,
  byte_size(kind)::32, kind::binary, schema_version::32, byte_size(nonce)::32,
  nonce::binary, byte_size(payload)::32, payload::binary>>` (format version 1
  prefix; no `term_to_binary`). The digest detects corruption, not tampering.
- Outbox idempotency key is derived, never caller-chosen:
  `"<stream>/<sequence>/<position>"`, stable across restarts and redelivery.
  Sequence and position are positive decimal integers; parse from the right,
  so slashes in the stream do not create ambiguous identities.
- Every write has a fresh 16-byte nonce, including checkpoint, retention, ack
  and test-double torn-tail repair. A maintenance request's canonical digest
  binds its operation tag, stream, expected value, target, nonce and all written
  fields. Checkpoint bytes include the complete model, cursor and `seen` map
  (sorted by sequence); ordered diagnostics are preserved, never truncated.
  Use versioned length-prefixed binary fields and fixed enum encodings, not
  arbitrary Erlang term decoding. `max_checkpoint_bytes` bounds the entire
  checkpoint; oversize is `{:rejected, :checkpoint_too_large}` before writing.
  The digest index grows with the folded prefix: no bounded-memory or compact
  checkpoint claim is made. These are record encodings, not a new WAL format.
- **Untrusted input.** Every row returned by a provider is re-validated
  (types, sizes, digest recomputation, kind/version membership). Strings from
  storage are never converted to atoms; kinds/destinations map through the
  consumer's fixed binary tables. No trust is upgraded from a provider reply,
  and no durability/ack field is guessed: absent or malformed fields are
  `indeterminate` (write) or damaged (read).

## Implementation clarifications

The not-yet-ready Pieces share a portable preflight domain; no ready ID changes.
Revision, sequence, low_water and through are at most `2^63 - 1`;
schema_version, fold_version and outbox position are positive and at most
`2^31 - 1`. Stream, kind and destination are valid UTF-8 without NUL; fixed
kind/destination tables are validated at fold/config construction. Offending
append inputs use the existing static reasons (`invalid_stream`,
`invalid_revision`, `unsupported_version`, `unknown_kind`, `invalid_outbox_item`).
Out-of-domain provider rows are malformed/damaged, never trusted. Canonical
byte layouts are unchanged. This approved clarification preserves the specified
PostgreSQL bigint/int/text schema and applies equally to Memory and the core.

The store form of `Elzoo.Checkpoint.take/4` takes
`{store, replay_state, limits}` as its first argument. `replay_state` is
`%{model, cursor, seen}` produced by replay/recover; `limits` supplies
`max_checkpoint_bytes`. The Writer form supplies its current snapshot through
the same internal path. The store still enforces `sequence <= head` in the
same transaction. This clarifies the snapshot source, not checkpoint semantics.

Writer init refuses **every** damaged cursor with
`{:stop, {:replay_damaged, diagnostics}}`, including gap-only damage. This is
deliberately uniform: `replay/3` and checkpoint recovery still return the damaged
model for read-only inspection; a Writer cannot append to it. Tests cover both
reader results and Writer refusal, including a gap-only checkpoint seed.

When init stops `{:storage, :unfenced}`, operators can inspect read-only, wait for
exact-nonce confirmation, or deliberately propose a **fresh-nonce CAS at the
original expected revision** if they intend that transition and accept either
outcome. A committed competitor fences the earlier transaction; a conflict
requires re-reading. There is no automatic retry, inference of rollback from
absence, or authorization to re-dispatch an external effect.

Concrete Writer options: `checkpoint: %{fold_version: version, decode: decode}`
enables recovery; `Checkpoint.take(writer_pid, stream, version, encode)` uses
the current snapshot and the Writer's limits. These optional calls resolve the
Checkpoint module only at runtime: a standalone event-log consumer does not
need the checkpoint Piece unless it enables this path. Checkpoint witnesses
retain one digest per seen sequence even after retention: complete snapshots
grow O(applied) in contiguous histories. `max_checkpoint_bytes` remains a hard
bound, not compaction; writer-form tests exercise rejection without a provider
call or a changed snapshot.

An append `reconcile:` request retains the result info plus `records` containing
the original canonical Records (reconstructible from the submitted tuples and
the result's expected revision/nonce). Checkpoint reconciliation supplies the
original complete checkpoint as `checkpoint`; other maintenance requests are
their canonical receipts. Missing/malformed evidence stays unfenced. The Writer
does not persist this caller-supplied evidence. Indeterminate owned maintenance
stops just like append.

For staged-tail repair, Writer marks its Store handle with
`repair_owner: self()`. Memory accepts that context only from the matching
calling process and terminally aborts the staged nonce before repair CAS;
ordinary handles still reject an unfenced tail. This is an ownership convention,
not a lease or authentication. Visibility remains fixed adapter configuration.
Only init invokes repair, never readers or conflict refolding.

PR #51 review fixes (user-authorized, for final review). (1) The committed head
is authoritative: after the staged-tail check, a validated row with
`sequence > head.revision` is interior corruption `{:corrupt, seq,
:beyond_head}` (prefix kept, damaged), for atomic stores and for staged-capable
stores without provenance. (2) Writer init and checkpoint recovery fetch the next
page when a 1,000-row page is full and its last sequence is at or below head;
a page ending above head goes straight to replay with its staged-tail
metadata. A staged row at head + 1 is therefore seen and fenced whether it
starts the next page or ends a full one. (3) Deferred, not changed: after an
invalid latest checkpoint, recovery probes earlier sequences one `read_checkpoint`
at a time (cost grows with the gap). An indexed predecessor lookup needs a new
Store callback, which is a Contract change left for a follow-up.

ELZ-032 bug fix (restores the commit-point Contract), 2026-11-06. Inside a
caller's open Ecto transaction, `Repo.transaction/2` joins that transaction and
issues no COMMIT, yet `Postgres` returned `{:committed, n}`; an outer rollback
then erased the write. Reads ran `SET TRANSACTION ...`, which fails after the
outer transaction has run a query and aborts it. Now every `Postgres` callback
checks `repo.in_transaction?()` (Ecto SQL 3.14.0, process-local) before any
statement: writes return `{:rejected, :caller_transaction}` (confirmed nothing
written, no statement issued) and reads return `{:error, :caller_transaction}`
(no statement, so the caller's transaction is not poisoned). `:caller_transaction`
is added to the rejected reasons and the read errors below; the Store shell
accepts it, and `confirm/5` reports `{:unknown, :caller_transaction}`. This
keeps the same Piece IDs (`integration/sql`, `state/event-log`): `committed`
was always defined as "provider `COMMIT` returned ok", so refusing a call that
cannot reach its own COMMIT restores that Contract rather than changing it.
Memory has no caller transactions and never returns the value. No claim is
made about transactions opened outside Ecto on the same connection; savepoint
nesting is out of scope.

The `state/event-log` ID is kept for the same fix. The shell now accepts the
Store reply `{:rejected, :caller_transaction}`, accepts the read error
`:caller_transaction`, and returns the confirm outcome
`{:unknown, :caller_transaction}`. A third-party Store returning that reply was
classed as indeterminate before and is rejected now. The change is strictly
additive: the shell already trusts Store-only rejection reasons
(`:torn_repair_unsupported`, `:unfenced_tail`), the new value adds no new trust
relationship, it is the only way to restore the `integration/sql` Contract
without returning indeterminate, Memory never produces it, and no in-repo
consumer matches the reasons exhaustively.

Ordering: static, I/O-free validation (preflight, batch/checkpoint validation,
ID parsing) runs before the transaction check, so invalid input inside a caller
transaction keeps its existing result (a write's rejection or
`indeterminate(:malformed_reply)`, `{:error, :malformed}` from a read with an I/O-free pre-check such as `read_ack` key parsing or an unknown `read_maintenance` operation; reads that validate input during the query, such as `head`/`read` with an invalid stream, return `{:error, :caller_transaction}` instead). No SQL is issued in either case.

Limits of the refusal: the check is per process (`Repo.in_transaction?/0` sees
only the calling process's checked-out connection). Under
`Ecto.Adapters.SQL.Sandbox`, outside an explicit `Repo.transaction`, `in_transaction?` is false: the Store's transaction
becomes a savepoint, a write can return `{:committed, n}` after only
`RELEASE SAVEPOINT`, and the sandbox rollback erases it, so the refusal does not
apply there (inside an explicit `Repo.transaction` it still refuses); consumer test suites using the Sandbox must not treat `committed`
as a real COMMIT. A raw `BEGIN` inside `Repo.checkout/2` is not detected; writes
then return `indeterminate(:unavailable)` and reads `:unavailable`, and
DBConnection disconnects that connection, so the caller's raw transaction is
aborted (read from the DBConnection source, not tested). Calls from
another process, including every Writer call, are never refused; they commit on
their own connection, independent of the caller's transaction, so this gives no
transaction-scoped atomicity.

`Conformance.checks/0` returns K1–K11's named functions in table order. Each takes
a fresh store factory returning `{store, options}`; the module documents its
adapter-neutral, test-only fault hooks. Memory's reopen hook obtains a fresh
handle to the same volatile server, not durable process-restart evidence.

## Store boundary (`Elzoo.DurableLog.Store` behaviour)

All callbacks take `store :: {module, opts}` and never raise to the caller
(the shell maps raise/exit/throw/timeout itself; see write results).

    capabilities(store) :: %{append_visibility: :atomic | :staged_uncommitted_tail}
    head(store, stream) :: {:ok, %{revision: non_neg_integer, low_water: non_neg_integer}} | {:error, :unavailable | :malformed | :caller_transaction}
    append(store, stream, expected_revision, [record], [outbox_item]) :: write_result
    read(store, stream, from_sequence, limit) :: {:ok, [row], head} | {:error, {:pruned, low_water} | :unavailable | :malformed | :caller_transaction}
    read_at(store, stream, sequence) :: {:ok, row | :absent, head} | {:error, :unavailable | :malformed | :caller_transaction}
    put_checkpoint(store, checkpoint) :: write_result
    latest_checkpoint(store, stream, fold_version) :: {:ok, checkpoint | :none} | {:error, ...}
    retain(store, stream, expected_low_water, through_sequence, nonce) :: write_result
    pending(store, stream, limit) :: {:ok, [outbox_row]} | {:error, ...}
    ack(store, item_id, ack_nonce) :: write_result
    read_ack(store, item_id) :: {:ok, outbox_row | :absent} | {:error, ...}
    read_checkpoint(store, stream, sequence, fold_version) :: {:ok, checkpoint | :absent} | {:error, ...}
    read_maintenance(store, stream, operation) :: {:ok, receipt | :absent} | {:error, ...}
    repair_torn_tail(store, stream, expected_revision, staged_nonce, repair_nonce) :: write_result   # owning-writer-only, capability-gated

`read` also returns explicit staged-tail metadata only for the configured
`:staged_uncommitted_tail` capability (see Read results). Capabilities are
fixed by the selected adapter, not inferred from row contents or accepted
from an arbitrary wire field. `Postgres` declares `:atomic`. No callback in
this proposal implements a non-atomic disk format.

### Write results (R10)

| Result | Meaning | Producer (named) |
| --- | --- | --- |

| `{:rejected, reason}` | Confirmed preflight limit; **nothing written**. | `{:indeterminate, %{operation, stream, expected, target, nonce, digest, cause}}` | Storage may hold either state. `cause` ∈ `:exception :exit :timeout :malformed_reply :unavailable` | any raise/exit/throw, call timeout, `DBConnection.ConnectionError`, error during/after `COMMIT`, any reply outside this table |

A provider reporting "unavailable" is `indeterminate`, never `rejected` or
`conflict`. An exit reason or timeout never establishes non-execution.

Readback confirmation, `Elzoo.DurableLog.confirm(store, stream, expected,
nonce, expected_records)`, reads `read_at(expected + 1 .. expected + n)` and validates
the complete expected canonical bytes as well as nonce/digest. **Fencing rule:
absence is unknown, not rollback.** A plain READ COMMITTED `SELECT` does not
wait for an in-flight writer's head row lock; it may miss a transaction which
commits later. This proposal chooses the review's CAS-fencing option, not a
locking read that asserts non-commit. Memory follows the same rule.

| Observation | Result |
| --- | --- |
| every position holds exactly the expected canonical bytes **and** the nonce/digest | `{:committed, expected + n}` |
| position `expected + 1` absent, even if head = `expected` | `{:unknown, :unfenced}`; an earlier transaction can still commit |
| a complete validated competing batch with a different nonce at `expected + 1` | `:superseded` (ours cannot subsequently commit at that revision; store CAS exclusivity) |
| read error / malformed / partial match | `{:unknown, cause}` (stay down; never guess) |

A mismatched digest with our nonce is corruption/unknown, not proof of a
competing commit. If the row has been pruned, confirmation is unknown, not
negative. `:not_committed` is **not** a result of `confirm/5`. A caller may
explicitly submit a fresh-nonce CAS at the original expected revision only
when it intends that state transition and accepts either outcome: if it
commits, it fences the old transaction out; if it conflicts, re-read. It is
not an automatic retry, repair, or authorization to re-dispatch an Effect.
Positive readback establishes the recorded operation's commit, not a second
commit point or proof of disk behaviour.

Maintenance readback follows the same conservative rule:

| Write | Exact confirmation | Absence / replacement |
| --- | --- | --- |
| checkpoint | immutable `(stream, sequence, fold_version)` row with the request nonce and all canonical bytes | absent → `unknown/unfenced`; validated different nonce at that unique key → `superseded`; malformed → unknown |
| retention | head's `last_retention` receipt binds expected low_water, through, nonce and digest; low_water equals through | absent, changed or overwritten receipt → unknown (a later retention must not be mistaken for this write) |
| ack | item is `acked` with exact `ack_nonce` and request digest | pending or absent → `unknown/unfenced`; another validated ack nonce → `superseded`; pruned → unknown |
| Memory repair | exact `last_repair` receipt binds expected revision, staged nonce and fresh repair nonce | missing/overwritten receipt → unknown; never infer repair from a missing row |

The shell exposes these translations as `confirm_checkpoint(store, request)`,
`confirm_retention(store, request)`, `confirm_ack(store, request)` and
`confirm_repair(store, request)`. Retention receipts are bounded to the latest
operation, not an audit log; once overwritten the old outcome may remain
unknown. No indeterminate maintenance write is blindly retried. Checkpoint
inserts are immutable/unique; retain CASes expected low_water; ack CASes
pending state. Writer-owned maintenance stops the writer on indeterminate
just like append. Direct callers receive indeterminate and must reconcile.

### Writer (`Elzoo.DurableLog.Writer`)

One GenServer per stream, started by the consumer's supervisor (no
`Elzoo.Application`). `start_link(store:, stream:, fold:, limits:, checkpoint:
optional, reconcile: optional_indeterminate_request)`. On init it is the **owning writer**: reads head, optional latest
checkpoint, tail; only a capability-declared uncommitted staged tail may be
repaired (fenced abort plus CAS described below); it then re-reads and folds.
An invalid committed final row is never repaired. `append(writer, [{kind, version,
payload}], [{destination, payload}], timeout)`:

- `committed` → model refolded with the new records, reply `{:committed, rev}`;
- `conflict` → re-reads the tail, refolds, replies `{:conflict, observed}`;
- `rejected` → state unchanged, reply;
- `indeterminate` → replies `{:indeterminate, info}` and **stops**
  `{:shutdown, {:indeterminate_write, info}}`; the next writer's init runs
  `confirm/5` for the recorded nonce only when the caller supplies it (the
  writer never holds durable memory of it); init always rebuilds from the
  authoritative store, so a committed-but-unacknowledged write is folded and an
  uncommitted one is absent in that read. Absence does not settle an outstanding
  transaction; init must obtain the authoritative post-fence state before
  admitting writes if an indeterminate request is supplied. It must return
  `{:stop, {:storage, :unfenced}}` rather than serve a possibly stale model
  when confirmation remains unknown. A caller `GenServer.call` timeout is
  caller-side unknown. With no supplied request, a new writer may read a
  snapshot and propose at its observed revision; CAS, not the snapshot,
  arbitrates any older transaction, and a conflict requires a fresh refold.

The Writer is single-writer by convention; correctness against a second writer
relies on the store CAS (K2), not on process uniqueness. No lease (ELZ-028).

### Read / replay results (R6, R7, R12)

`Elzoo.DurableLog.replay(rows, head, fold)` with `fold = %{initial: model,
reduce: (model, kind, version, payload -> model), kinds: %{binary =>
:state_bearing | :non_state_bearing}, versions: [pos_integer]}` returns
`%{model, cursor: {applied, damaged, diagnostics}, seen: %{sequence => digest},
tail: :intact | :torn}`. The optional `fold.resume = %{model, cursor, seen}`
seeds tail replay from a validated checkpoint; default is the initial
model/cursor/empty map. The public cursor is an Elixir projection: gap/order
diagnostics come from Cure; shell corruption/truncation diagnostics use a
fixed tagged encoding. Do not pass shell diagnostics as Cure ReplayDiagnostic
values. The projection preserves the full diagnostic history across calls.

- **Order backstop:** rows are folded by `sequence`, then provider append
  order (the double keeps insertion order; Postgres orders by the unique
  `(stream, sequence)` key, so equal sequences cannot be returned by a conforming
  Postgres store). Out-of-order arrival arises only when feeding a later read
  batch into an existing cursor/seed or from a faulty provider; it cannot
  arise inside one correctly sorted fresh replay.
- The Elixir shell first validates every row, then compares repeated sequence
  identity with `seen`. A sequence already seen with a different digest
  (including a changed nonce) is **corruption**, even if that row's own digest
  is valid. Stop at that row, preserve the preceding model/cursor and set
  damaged with `{:corrupt, seq, :sequence_identity_mismatch}`. No call to
  `classify` is made for it. An exact repeat of `applied` is ignored only if
  its digest equals the stored witness; earlier identical rows are
  out-of-order diagnostics, not re-applied. An earlier unseen sequence is
  also an out-of-order diagnostic (it can occur after a forward gap).
- After those shell checks, `classify` (Cure) → `ReplayNext` (= applied + 1),
  `ReplayGap` (> applied + 1: record applied, `damaged = true`, diagnostic),
  or `ReplayDuplicate` (= applied, identity already checked). The shell
  supplies `ReplayOutOfOrder` for < applied; `classify` itself never produces
  that constructor. Identity/order translation and `seen` are test-grounded,
  not proved by the supplied-decision Cure laws.
- **Totality over kinds:** every stored kind must be in `kinds`; a
  `:non_state_bearing` kind advances the cursor but never calls `reduce`. A kind
  not in the table, or a version outside `versions`, is treated as interior
  corruption (below), never silently skipped.
- **Interior corruption** (digest mismatch, malformed row, unknown
  kind/version or conflicting sequence identity at any committed sequence,
  **including the last row at head**): fold stops; result is the model of the
  longest valid prefix, `damaged = true`, diagnostic `{:corrupt, seq, reason}`.
  Later rows are not applied.
- **Torn final record** requires configured capability
  `:staged_uncommitted_tail`, explicit store provenance that this is an
  interrupted **uncommitted** append at `sequence = head + 1`, and no later
  staged row. It is not inferred from a bad digest. Tolerated on read:
  prefix model, `tail: :torn`, `damaged` unchanged. A missing provenance or
  invalid committed last row is corruption, even in Memory. Only the owning
  Writer at init may call `repair_torn_tail`; `replay/3`, `read/4`,
  checkpoint recovery and outbox reads never write (audited by a test that
  replays through a store double that fails any mutating call).
- **Repair scope:** only Memory's staged-write fault model supports repair;
  `Postgres` always returns `{:rejected, :torn_repair_unsupported}`. Memory
  first fences/aborts the exact staged nonce so no late completion can commit,
  then atomically checks expected head and staged nonce, removes that staged
  row and its staged outbox items, and records the fresh repair nonce/digest.
  No committed/acked outbox row is touched. Head revision and low_water are
  unchanged, never decremented. The next append may use head + 1 with a fresh
  nonce: the discarded sequence was never committed, and the old operation is
  terminal before repair succeeds. Confirmation of the old nonce stays
  unknown while absent, then superseded after a different nonce commits;
  it cannot be confused with the replacement. If abort/fencing is not
  established, return `{:rejected, :unfenced_tail}` without changing anything.
  Tests pause a late staged completion and verify it cannot resurrect after
  repair. This models repair policy; it does not implement a physical log.
- **Reducer failure:** a raise, throw or catchable exit while reducing a
  state-bearing row at sequence s stops before applying s. Return the longest
  successfully reduced prefix, `damaged = true` and
  `{:corrupt, s, :reducer_failure}` (bounded failure category only, no payload,
  exception message or stack in diagnostics). No later row is applied.
  Consumer reducers must be pure/deterministic: this is not a sandbox against
  side effects, nontermination, OOM or untrappable process death. Checkpoint
  cannot erase this diagnostic; Writer init refuses a damaged model with
  `{:stop, {:replay_damaged, diagnostics}}`. If a post-commit fold fails, the
  write remains committed and the writer stops; never translate that commit
  into a rejected write or re-dispatch its outbox.
- **Truncation:** a head revision greater than the last readable row is a
  forward gap at the tail → `damaged = true`, `{:truncated, head, last}`.
  Reading below `low_water` returns `{:error, {:pruned, low_water}}`.
- **Unavailable:** `{:error, :unavailable}`; the Writer does not start (init
  returns `{:stop, {:storage, :unavailable}}`), no partial model is served.
- **Caller transaction (ELZ-032):** `Postgres` reads called inside the caller's
  open Ecto transaction return `{:error, :caller_transaction}` without issuing a
  statement; no partial model is served.

Postgres row atomicity means a torn row is unobservable through
`integration/sql` (upstream transaction contract). Memory explicitly stages
the interrupted append for its fault model. Both an interior and the **last**
committed Postgres row are corrupted by an out-of-band test UPDATE: both must
yield damaged/prefix results and no application-side repair/delete/update.

### Checkpoint (`state/checkpoint`)

`Elzoo.Checkpoint.take(writer_or_store, stream, fold_version, encode)` writes
`(stream, sequence = applied, fold_version, model_bytes, cursor, seen, nonce,
digest)` via
`put_checkpoint`, which the store accepts only when `sequence ≤ head` in the
same transaction (else `{:rejected, :checkpoint_beyond_tail}` from preflight or
`conflict` from the store). `recover(store, stream, fold, fold_version,
decode)` = latest checkpoint with matching `fold_version` and valid digest,
then tail replay from `sequence + 1`, seeded with the complete cursor and
digest witnesses as well as model. Validate `sequence = cursor.applied`,
all cursor fields/diagnostics, witness entries, and the digest over **all**
checkpoint fields including nonce. Damage and diagnostics survive recovery;
they are not reset at the checkpoint boundary. A snapshot with a terminal
corrupt/truncated diagnostic is returned as the damaged partial result, without
replaying the failing row or duplicating its diagnostic. A gap-only damaged
snapshot can fold later surviving tail rows while retaining its damage. A
checkpoint is not authority to heal or skip a corrupt row. A checkpoint with a different
fold_version, bad digest or undecodable model is ignored (refold from an
earlier checkpoint or from the start), never trusted. If required history was
pruned and no valid checkpoint covers it, recovery fails closed with
`{:error, {:pruned, low_water}}`, not an empty/healthy model.
Duplicate checkpoint insert at the unique key is conflict, never overwrite.
An indeterminate checkpoint is confirmed only by exact nonce/canonical row
readback as specified above. **Equivalence claim:**
`recover` and a full `replay` from sequence 1 yield the same model, cursor and
seen index for the same listed immutable canonical history (test-grounded,
D7/D8). This does not equate a reordered history with an incremental arrival
history, or detect later privileged edits to already-checkpointed rows. A
separate round-trip test preserves seeded out-of-order diagnostics unchanged.
**Tail retention:** `retain(store, stream, expected_low_water, through, nonce)`
requires `0 ≤ expected_low_water < through ≤ head` (else
`:invalid_retention_range`); it deletes records `≤ through` and raises `low_water`
only if a committed checkpoint with `sequence ≥ through` exists, in one
transaction; otherwise `{:rejected, :retention_beyond_checkpoint}`. In that
same transaction, lock the head and require through < minimum pending outbox
sequence (if any); otherwise `{:rejected, :retention_beyond_pending_outbox}`
and rollback with no mutation. Delete acked outbox rows ≤ through **before**
their parent records, then CAS low_water from the supplied expected value to
through and store its nonce/digest receipt. No cascade deletes pending rows.
All outbox/retention mutations share head-first locking, so ack/append cannot
race this bound. Acked rows above through remain; pruned ack evidence is
unknown on later readback. A damaged checkpoint may preserve/report a model
but cannot authorize retention (`:retention_beyond_checkpoint`); only a valid
undamaged checkpoint is a retention anchor. No known damage is hidden by
pruning. An indeterminate retention has the exact receipt rule above, never
inference from low_water alone.

### Outbox (`state/outbox`)

- **Commit:** outbox items are inserted by the same `append` transaction as
  the head CAS and records (R11 "head advance + immutable version record +
  committed change event are one commit"). The in-memory batch passed to
  `append` is transient; only the committed outbox row is a durable source.
- **Offer:** `Elzoo.Outbox.pending(store, stream, limit)` returns committed
  rows with `state = pending` ordered by `(sequence, position)`. Rows are
  validated like records.
- **Ack (commit point):** `Elzoo.Outbox.ack(store, item_id, ack_nonce)` is a
  CAS `pending → acked`; `{:committed, _}` is the only acknowledgement; a
  second ack is `conflict`; error is `indeterminate`. Store fresh `ack_nonce`
  and digest binding the item identity and expected pending state. Pending
  on plain readback stays unknown while the original ack can still commit;
  exact ack nonce confirms, competing ack nonce supersedes. A fresh-nonce ack
  CAS can fence the old ack but never causes dispatch. An acked item is never
  offered again; retention may delete its row only under the bound above.
- **Dispatch failure** is a separate post-commit outcome owned by the caller
  (ELZ-010/011): the item stays pending. No attempt count, deadline or
  dispatcher lives here; no external effect is executed or replayed by this
  task. Delivery to a dispatcher is **at-least-once** (crash between dispatch
  and ack re-offers), deduplicated downstream only by the derived key.
- Replay/refold never creates, re-inserts or re-offers acked outbox items
  ("a committed item is not emitted twice" in the acceptance sense).

### Tiers (R8)

Durable tier: head, records, checkpoints and outbox rows committed by the
provider. Ephemeral tier: the Writer's folded model and cursor, the in-memory
append batch, any caller-side notification. Every ephemeral value is
reconstructable by `recover`. Checkpoint writes explicitly capture the folded
model/cursor/witnesses at an acknowledged revision; their bytes become durable
only at commit. Store CAS/preconditions re-check revisions at commit. No
durable state depends on an optional notification having been observed.

`Elzoo.DurableLog.Postgres.Migration.up/0` (consumer runs it in its own Ecto

| `elzoo_checkpoints` | `stream`, `sequence`, `fold_version int`, `model bytea`, `cursor bytea`, `seen bytea`, `nonce bytea`, `digest bytea`; PK `(stream, sequence, fold_version)`; immutable insert only |

`append` = one `Repo.transaction`: for expected 0, first
`INSERT heads (stream, revision) VALUES ($1, 0) ON CONFLICT DO NOTHING`;
for every expected value, `UPDATE heads SET revision = e + n WHERE stream = $1 AND
revision = e` → 0 rows ⇒ `Repo.rollback(:conflict)`; `INSERT` records; `INSERT`
outbox rows; `COMMIT`. Default READ COMMITTED: a concurrent CAS blocks on the
row lock and re-evaluates the `WHERE` against the committed row (upstream
PostgreSQL contract), yielding 0 rows. The adapter takes the consumer's Repo
module (`{Elzoo.DurableLog.Postgres, repo: MyRepo, prefix: optional}`); no
Repo, config or Application is shipped. Fault-injection hooks
(`:after_head_cas`, `:before_commit`, `:after_commit_reply`, and corresponding
maintenance/ack barriers) are test options only. Checkpoint/retention/ack also
lock the head **first**, then the dependent rows, and validate state-dependent
preflight before mutation. Retention deletes acked children before records;
pending-child bounds are evaluated in the same transaction. Head rows are not
deleted by retention. Plain readback is not a lock or fence, including for a
first append whose head insert is still invisible.

Upstream basis for the uncertainty rule: PostgreSQL 16 [READ COMMITTED](https://www.postgresql.org/docs/16/transaction-iso.html#XACT-READ-COMMITTED)
and [row-level locks](https://www.postgresql.org/docs/16/explicit-locking.html#LOCKING-ROWS).
These documented contracts explain why absence is inconclusive; K6/D15 must
still execute the late-commit interleaving. No concurrency experiment has been
run in this proposal-revision stage.

Test harness: `mix check` requires `ELZOO_TEST_DATABASE_URL` (a disposable
local database) and **fails closed** with an explicit message when it is
absent or unreachable; Postgres scenarios are never silently skipped. CI change
(task-scoped, for independent review): the existing "Prepare Ubuntu job
container" step additionally installs `postgresql` from the pinned
`ubuntu:24.04@sha256:fe8156…` container's apt repository, a new step starts
the cluster with `pg_ctlcluster`, creates a throwaway role/database and exports
the URL. No new runner, label, hosted fallback, Docker image pull or

reported in the log (observed, not pinned — like other apt packages) and the
tests record `server_version`, `fsync` and `synchronous_commit` as monitored
observations of the test cluster.

## Decisions recorded

- **Hash chain (for `state/audit-log`):** not adopted here. Per-record
  SHA-256 detects corruption, not tampering by a party that can write the
  store. An append-time chain over canonical records is needed only if
  `state/audit-log` requires tamper evidence against a store-privileged writer;
  that task decides. No default chain is implemented.
- **Exactly-once:** not claimed. Records commit at most once per nonce under
  CAS; outbox delivery to a dispatcher is at-least-once.
- **Schema evolution:** records carry `schema_version`; only declared versions
  replay; upcasting/golden corpora belong to ELZ-010.

```cure
# SPDX-License-Identifier: Apache-2.0
mod Elzoo.Replay
  use Std.Option

  type ReplayOrder = ReplayNext | ReplayDuplicate | ReplayOutOfOrder | ReplayGap
  type RecordUse = StateBearing | NonStateBearing

  rec ReplayDiagnostic
    sequence: Int
    order: ReplayOrder

  rec ReplayCursor
    applied: Int
    damaged: Bool
    diagnostics: List(ReplayDiagnostic)

  rec ReplayCount
    cursor: ReplayCursor
    total: Int

  fn initial() -> ReplayCursor = ReplayCursor{applied: 0, damaged: False(), diagnostics: []}

  fn classify(cursor: ReplayCursor, sequence: Int) -> ReplayOrder =
    pickup
      sequence == cursor.applied + 1 -> ReplayNext()
      sequence > cursor.applied + 1 -> ReplayGap()
      else -> ReplayDuplicate()

  @total true
  @reducible
  fn admits(order: ReplayOrder, role: RecordUse) -> Bool =
    match order
      ReplayNext() -> bearing(role)
      ReplayGap() -> bearing(role)
      ReplayDuplicate() -> False()
      ReplayOutOfOrder() -> False()

  @total true
  @reducible
  fn bearing(role: RecordUse) -> Bool =
    match role
      StateBearing() -> True()
      NonStateBearing() -> False()

  @total true
  @reducible
  fn track(cursor: ReplayCursor, sequence: Int, order: ReplayOrder) -> ReplayCursor =
    match order
      ReplayNext() -> ReplayCursor{applied: sequence, damaged: cursor.damaged, diagnostics: cursor.diagnostics}
      ReplayGap() -> ReplayCursor{applied: sequence, damaged: True(), diagnostics: [ReplayDiagnostic{sequence: sequence, order: order} | cursor.diagnostics]}
      ReplayDuplicate() -> cursor
      ReplayOutOfOrder() -> ReplayCursor{applied: cursor.applied, damaged: cursor.damaged, diagnostics: [ReplayDiagnostic{sequence: sequence, order: order} | cursor.diagnostics]}

  @total true
  @reducible
  fn count_step(state: ReplayCount, sequence: Int, value: Int, order: ReplayOrder, role: RecordUse) -> ReplayCount =
    ReplayCount{cursor: track(state.cursor, sequence, order), total: add_if(admits(order, role), state.total, value)}

  @total true
  @reducible
  fn add_if(admitted: Bool, total: Int, value: Int) -> Int =
    match admitted
      True() -> total + value
      False() -> total

  @total true
  @reducible
  fn total_of(state: ReplayCount) -> Int = state.total

  @total true
  @reducible
  fn cursor_of(state: ReplayCount) -> ReplayCursor = state.cursor

  @total true
  @reducible
  fn damaged_of(cursor: ReplayCursor) -> Bool = cursor.damaged

  @total true
  @reducible
  fn applied_of(cursor: ReplayCursor) -> Int = cursor.applied

  fn duplicate_keeps_total(state: ReplayCount, sequence: Int, value: Int, role: RecordUse) -> Equivalent(Int, total_of(count_step(state, sequence, value, ReplayDuplicate(), role)), total_of(state)) =
    reflexive(total_of(state))

  fn duplicate_keeps_cursor(state: ReplayCount, sequence: Int, value: Int, role: RecordUse) -> Equivalent(ReplayCursor, cursor_of(count_step(state, sequence, value, ReplayDuplicate(), role)), cursor_of(state)) =
    reflexive(cursor_of(state))

  fn out_of_order_keeps_total(state: ReplayCount, sequence: Int, value: Int, role: RecordUse) -> Equivalent(Int, total_of(count_step(state, sequence, value, ReplayOutOfOrder(), role)), total_of(state)) =
    reflexive(total_of(state))

  fn out_of_order_keeps_applied(state: ReplayCount, sequence: Int, value: Int, role: RecordUse) -> Equivalent(Int, applied_of(cursor_of(count_step(state, sequence, value, ReplayOutOfOrder(), role))), applied_of(cursor_of(state))) =
    reflexive(applied_of(cursor_of(state)))

  fn gap_marks_damaged(state: ReplayCount, sequence: Int, value: Int, role: RecordUse) -> Equivalent(Bool, damaged_of(cursor_of(count_step(state, sequence, value, ReplayGap(), role))), True()) =
    reflexive(True())

  fn non_state_bearing_keeps_total(state: ReplayCount, sequence: Int, value: Int) -> Equivalent(Int, total_of(count_step(state, sequence, value, ReplayNext(), NonStateBearing())), total_of(state)) =
    reflexive(total_of(state))
end
```
