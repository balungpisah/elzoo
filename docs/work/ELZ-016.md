evaluation is independent ELZ-017 and is not a prerequisite or implementation
choice for these interfaces.

  and change timing, authority, revision conflicts, receipts and observer limits.

## Limits and decisions

This tests a serialized volatile admission policy, not running jobs, durable
audit/receipts, arbitrary dynamic rewiring or an autonomous governor. The
GenServer may lose all state on restart; timeouts after dispatch are unknown
outcomes. No control-plane HTTP/MCP server or UI is exposed. Host-provided
actor/context is trusted and internal BEAM calls are not a security sandbox.

The pure policy is kept separate from the effectful host so a future selected
Cure proof would cover the actual decision implementation. For this experiment,
finite tests exercise the proposed semantics before promoting a reusable policy;
they are not universal laws. Upstream Ash, OTP and Telemetry behavior remains
upstream grounding, including synchronous handler latency and handler detachment
on exceptions. No fork was needed.

## Lessons

- Draining is a lifecycle obligation, not a boolean paused flag: pause/resume
  must not silently bypass an unfinished drain.
- Lowering a valid limit can leave active usage above that limit. Preserve
  admitted work and define subsequent admission behavior explicitly.
- A revision versions the declared policy/lifecycle state, not every metric;
  name what increments it, including automatic drain completion.
- Shared tool descriptions are not continuing permission; enforce authority
  again at dispatch and validate host routing to the intended tenant.
- Operational applicability describes the usable subset. Startup arguments and
  an OTP stop do not establish hot reconfiguration or graceful business drain.
