## Contract reading

One shared schema module owns the event family
`[:elzoo, :effect | :job, :start | :stop | :exception]`: fixed event names, a
fixed measurement table with units, and a metadata allowlist with positive
per-field grammars and byte bounds. The Adapters that already hold the
operation identity emit through it. Elzoo authors only the schema, the
redaction function and the emission points; dispatch, handler attachment and
handler-failure detach are `telemetry` 1.4.2's. Events are observations: they
may be missing, they are not audit, metering, billing input or control
receipts, and no exporter, aggregation, tracing or persistence is delivered.

Invariants the implementation is held to (issue, Interface and invariant):

1. Event names and units are fixed and listed in the README.
2. Metadata passes an allowlist; it never contains payload bytes, credentials,
   URLs (with or without credentials) or free-form error messages; errors are
   reduced to a declared reason atom.
3. Handlers are synchronous and may be absent; a handler failure never changes
   the Adapter's result (upstream detach contract plus the named scenarios).
4. Existing behaviour and existing assertions of the edited Adapters are
   unchanged; only new tests are added (main coordinator's decision).

## Schema (finite data, README table)

### Events and measurements

| Event | Emission points | Measurements (all non-negative integers) |
| --- | --- | --- |
| `[:elzoo, :job, :start]` | durable-job worker; http-job runner (and durable-job Relay, if included: [Relay draft](#relay-events-draft-alternative)) | worker/runner: `queue_wait` µs; Relay: none (empty map) |
| `[:elzoo, :job, :stop]` | same | `duration` µs |
| `[:elzoo, :job, :exception]` | same | `duration` µs |
| `[:elzoo, :effect, :start]` | http-job Adapter `send_effect/1`, `poll/1` | `payload_bytes` (byte count of the request arguments) |
| `[:elzoo, :effect, :stop]` | same | `duration` µs |
| `[:elzoo, :effect, :exception]` | same | `duration` µs |

`duration` is measured with `System.monotonic_time/0` in native units and
converted once with `System.convert_time_unit(_, :native, :microsecond)`.
`queue_wait` is `DateTime.diff(job.attempted_at, job.scheduled_at, :microsecond)`
clamped at 0; it is omitted if either field is not a `DateTime`.
`payload_bytes` is `byte_size(arguments)` when the arguments are a binary, else
omitted. No other measurement keys exist. Durable-job emits no `:effect`
event: its handler is pure by its ready Contract and it dispatches no external
Effect (the Acceptance wording is with the main coordinator, review finding 4).

### Metadata: positive grammars

Every value is checked against a positive grammar (what is allowed), never a
blacklist. All strings are ASCII by grammar.

| Key | Grammar and bound | Class |
| --- | --- | --- |
| `adapter` | exactly `"assembly/durable-job"` or `"assembly/http-job"` | constant |
| `operation` | atom: `:perform` (job), `:send` or `:poll` (effect); `:relay` only if the Relay is included | constant |
| `request_ref` | `\A[0-9a-f]{64}\z` (64 bytes) | derived digest |
| `attempt` | integer `1..1_000_000` | counter |
| `queue` | `\A[a-z][a-z0-9_]{0,31}\z` (1..32 bytes; the durable-job queue grammar `Run.queue?/1`) | caller identifier |
| `tenant` | `\A[A-Za-z0-9][A-Za-z0-9_.-]{0,63}\z` (1..64 bytes) | caller identifier |
| `outcome` | atom from the declared per-operation set below | declared tag |
| `reason` | atom in `[:raise, :throw, :exit]` | declared tag |

The grammars exclude JSON punctuation (`{ } [ ] " : ,`), whitespace, controls,
`/`, `@`, `?`, `#`, `=`, `+`, `%` and non-ASCII. A short valid publication JSON
(`{"version":1,"kind":"publication","text":"hi"}`), any URL, any
`user:pw@host`, any header value with a space (`Bearer x`, `Basic x`) and any
base64 with `+`, `/` or `=` fail every string grammar.

`request_ref` is always a 64-hex digest, never caller bytes: for http-job it is
the existing derived intent key (`Wire.hex?/1`); for durable-job it is the
lowercase hex SHA-256 of the `job_key` (the job key itself is caller UTF-8 up
to 160 bytes and is never emitted). A consumer correlates by hashing its own
key.

**Limit stated plainly.** An opaque alphanumeric secret (for example a 40-byte
`[A-Za-z0-9]` token) is lexically indistinguishable from an identifier and
would pass the `tenant` grammar. The mechanism that keeps secrets out is
therefore twofold: (1) source: each key is filled only from one named identity
field the Adapter already holds (table below); credentials, arguments, receipts,
URLs and exceptions are never read at an emission point; (2) grammar: defence
in depth that refuses every structured payload, URL or header shape. A host
that configures a secret as its tenant or queue name is outside this Contract
(recorded assumption). T2/T5 test both parts, including a non-prefixed
token-like secret.

### Required and omitted keys per event

R = required (an invalid value is an instrumentation defect: strict raises,
production omits the key); O = optional identity (emitted only when the source
value already satisfies the telemetry grammar, silently omitted otherwise in
both modes, never raises); — = never present.

| Event (operation) | adapter | operation | request_ref | attempt | queue | tenant | outcome | reason |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| durable-job `job` start (`:perform`) | R | R | R | R | R | — | — | — |
| durable-job `job` stop (`:perform`) | R | R | R | R | R | — | R | — |
| durable-job `job` exception (`:perform`) | R | R | R | R | R | — | — | R |
| http-job `job` start (`:perform`) | R | R | O | R | O | O | — | — |
| http-job `job` stop (`:perform`) | R | R | O | R | O | O | R | — |
| http-job `job` exception (`:perform`) | R | R | O | R | O | O | — | R |
| http-job `effect` start (`:send`/`:poll`) | R | R | O | O | — | O | — | — |
| http-job `effect` stop | R | R | O | O | — | O | R | — |
| http-job `effect` exception | R | R | O | O | — | O | — | R |

Sources: durable-job `queue` = `cfg.queue` (already `Run.queue?/1`), `attempt`
= `job.attempt`, `request_ref` = SHA-256 of `job.args["job_key"]`. http-job
runner `request_ref` = `args["job_key"]` when `Wire.hex?/1` (an invalid job
omits it), `queue` and `tenant` from trusted `Config` (accepted by
`configure/1` up to 128 bytes of text, so they are optional here), `attempt` =
`job.attempt`. http-job effect `request_ref` = `req.key`, `attempt` =
`req.attempt`, `tenant` = `req.context.tenant` only when `req.context` is a
`%Elzoo.HttpJob.Config{}`.

Outcome sets: job `:perform` stop: `:ok | :snooze | :cancel | :error` (the head
of the returned tuple; the reason term is not carried; any other return shape
maps to `:error`). Effect stop: `:completed | :pending | :unavailable` plus the
nine declared `Elzoo.HttpJob.Binding.failures/0` tags (`:preflight_unavailable`,
`:request_rejected`, `:http_4xx`, `:http_5xx`, `:http_redirect`,
`:not_acknowledged`, `:receipt_invalid`, `:transport_timeout`,
`:transport_error`); a returned map is `:completed` when its `"outcome"` is
`"completed"`.

### Redaction function and strict mode

- `Elzoo.Telemetry.metadata(event, operation, map)` — pure; returns
  `{:ok, clean}` or `{:error, {:invalid, keys}}` where `keys` lists required
  keys that are missing or invalid and unknown keys. Optional keys failing
  their grammar are dropped from `clean` and are not errors.
- `Elzoo.Telemetry.emit(event, measurements, metadata, mode)` with `mode` in
  `:strict | :production`; `emit/3` uses the compile-time default
  (`:strict` when `Mix` is loaded at compile time and `Mix.env() in [:dev,
  :test]`, else `:production`; a copied consumer compiled in `:prod` gets
  `:production`). Measurements are checked the same way (declared key,
  non-negative integer).
- `:production`: unknown keys and invalid values are omitted; the event still
  fires with the clean subset; never raises.
- `:strict`: any `{:error, _}` raises `ArgumentError` naming only the key
  names (never values).

Scope of strict mode: invalid emission data is an implementation defect of the
emission point, outside the Adapter's normal result Contract. Emission points
pass only values that satisfy their grammar by construction (R keys) or are
pre-filtered (O keys), so for every valid emission the Adapter result is
unchanged in both modes; strict mode exists to make an instrumentation defect
fail this repository's own tests. It is not a handler-failure guarantee and
not a runtime behaviour of production builds.

## Emission points

All emission happens in the process that already holds the identity, outside
every bounded timer the Adapters use for their own decisions; a slow handler
adds wall time but does not run inside an Adapter timer.

- **durable-job worker** (`Elzoo.DurableJob.perform/2`): `:job :start` before
  `with_writer`; `:job :stop` with the mapped outcome after the result is
  computed; `:job :exception` when the body raises or throws (exits are
  already caught inside `with_writer/3`, so an escaping exit is not expected),
  after which the same kind, reason and stacktrace are re-raised with
  `:erlang.raise/3`, so `Elzoo.Jobs.Worker.trapping/1` and Oban see exactly
  what they see today.
- **http-job runner** (`Elzoo.HttpJob.perform/2`, first clause): `:job :start`
  after `started`; `:job :stop` next to the existing `observe/3` call (the
  existing bounded observer is kept unchanged); `:job :exception` in the
  existing `rescue`/`catch` arms, which still return
  `{:error, :owner_unavailable}`. The second clause (`{:cancel, :invalid_job}`
  for a non-matching job) emits nothing, as it holds no identity.
- **http-job Adapter** (`Elzoo.HttpJob.Adapter.send_effect/1`, `poll/1`):
  `:effect :start` and `:stop` around `request/2` in the owner's task process,
  outside `Call.run(c.transport_supervisor, c.total_ms, …)`, so handler time
  never counts against `total_ms` and cannot turn a response into
  `transport_timeout`. `poll/1`'s stop outcome is the mapped `:pending` /
  `:unavailable` or `:completed`.
- **durable-job Relay**: only if included; see the draft below.

Source anchors that existing mutation tests require verbatim and that the
edits must keep: `"retry: false"`, `"redirect: false"`,
`~s("/publications/" <> req.key)` in `adapter.ex`; `"defp tick(c, key) do"` and
`"act(c, pid, Policy.action(current, c.maximum))"` in `http_job.ex`; `wire.ex`
is untouched. Each anchor is checked by a `String.contains?` assertion in the
existing test, so a lost anchor fails loudly.

## Relay events (draft, alternative)

Ready to implement only if the main coordinator keeps the Relay in the slice
(review finding 2; the reviewer and the pieces orchestrator recommend
inclusion). No change to `integration/jobs`.

- **Point:** `Elzoo.DurableJob.relay/2` (the `handle` function the generic
  `Elzoo.Jobs.Relay` calls once per outbox item). `:job :start` before
  decoding, `:job :stop` with the mapped outcome on return, `:job :exception`
  on an escaping throw or exit (re-raised unchanged; the existing `rescue`
  already maps a raise to `{:skip, :malformed}`, which emits `:stop` with
  `:skip_malformed`).
- **Operation:** `:relay`.
- **Measurements:** start: none (empty map; an outbox item has no scheduling
  timestamp in its ready Contract); stop/exception: `duration` µs.
- **Keys:** `adapter` R, `operation` R, `queue` R (`cfg.queue`), `request_ref`
  O (SHA-256 hex of the decoded `job_key`, omitted when the payload does not
  decode to a valid key), `attempt` — (a Relay pass has no attempt),
  `tenant` —, `outcome` R on stop, `reason` R on exception.
- **Outcome set:** `:done`, `:skip_indeterminate`, `:skip_contended`,
  `:skip_foreign_run`, `:skip_rejected` (`{:rejected, _}`), `:skip_insert`
  (`{:insert, _}`), `:skip_unique_lock_held`, `:skip_malformed`,
  `:skip_damaged`, `:skip_unavailable`, and `:skip_other` for any other
  `{:skip, _}` term. The inner reason term is never carried.
- **Tests (T3r):** a relayed submission fires start/stop `:done` with the
  documented keys; a cancelled-before-relay item fires `:done`; a malformed
  payload fires `:skip_malformed` with `request_ref` omitted; an unreachable
  Store fires `:skip_unavailable`; a foreign item fires `:skip_foreign_run`;
  the existing `Elzoo.Jobs.Relay.run_once/1` acked/skipped lists are
  unchanged against the same scenario without handlers; T5/T6/T7 cover the
  Relay events too.

### Slow-handler disposition

`telemetry` dispatches synchronously in the emitting process. A slow handler
adds its run time to the Oban job execution (durable-job worker and Relay pass,
http-job runner) and to the owner's send/poll task (http-job Adapter).
Placement outside every Adapter timer keeps the Adapter's *result* unchanged
**for the named T7 scenario (200 ms per event) only**; this is a finite
scenario, not a timing guarantee. It does not bound wall-clock impact: a
handler slower than Oban Lifeline `rescue_after` can let Lifeline rescue a live
execution (an existing durable-job limit), and handler time in the owner task
delays the owner's result, so a runner `call_ms` (default 35 000 ms) around an
owner call can expire and turn that wake into `{:error, :owner_unavailable}`
(the Adapter's existing fail-closed path, not a send). Handler failure and
detach are `telemetry`'s upstream contract. Moving work out of the handler is
the host's job (`docs/operational-contracts.md`, Telemetry contract). The
README of each edited Piece states these limits.
