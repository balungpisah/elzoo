## Boundary and initial evidence

The prior `.agents/setup` block explicitly set fsync, synchronous_commit and
full_page_writes off. ELZ-107's first full check failed because its test
connection returned off/off where the data-stream identity guard required
on/on; that log's SHA-256 is
`cfd30461c3dd7d165c859a1365e81504d8716176b2ad1db8d4b8067ed5ddbaa3`.
That is distinct from separate reported connection exhaustion and the later
unresolved aggregate ordering failure. No production durability or general
capacity claim follows.

The changed block retains the existing unrelated-database guard. On a cluster
without unrelated databases it checks all four settings, applies drifted values,
restarts only for max_connections drift and otherwise reloads changed settings.
It checks a fresh actual test-user/database connection, including effective role
and database overrides, without silently changing those overrides. A mismatched
connection fails rather than claiming readiness.

The unrelated-database check is a point-in-time guard, not a lock: concurrent
database creation or other cluster administration can race the check and
configuration. The setup assumes exclusive administration of its disposable
cluster during this operation; it does not establish isolation from other
administrators.
