## Authority and reconciliation

The live issue #8 body is authoritative. At `850abca` it is identical to
`tasks/ELZ-008-request-route-retry-assembly.md` apart from trailing whitespace
and the issue-only "Repository references" footer. ELZ-021 (PR #34) and ELZ-025

durable-write (`committed/conflict/rejected/indeterminate`), replay, version
and untrusted-input requirements bind ELZ-009/010/011, not this Assembly, which
performs **no durable write**. Consistency with them is kept deliberately:

- the only externally persisted artefact is the dead-letter record handed to a
  caller sink; a non-`:ok`, raising or exiting sink is already `unsettled` in
  the unchanged ELZ-006 runner (never acknowledged), the volatile analogue of
  ELZ-009's `indeterminate`; no committed/acknowledged claim is made;
- untrusted payloads are validated by an exact codec (fixed keys, integers
  only), no atom is minted from wire strings (decision labels map through a
  fixed table), no trust upgrade or guessed ack/durability field;
- no retry budget survives restart: bounded attempts hold within one runner
  lifetime only (the ELZ-010 restart scenario is listed as a limit here).

ELZ-022/023/024/026–031 are not implemented, adopted or pre-empted. In
particular ELZ-023 (`delivery/effect-intent`) is not used; possibly-dispatched
work is dead-lettered as `dispatched_unresolved`, never blindly replayed.

### New Cure declarations (labelled worker)

The windowed receiver returns `None()` for duplicate/stale/superseded/full, and
the unchanged Adapter maps `:none` to completed with nil value, so a full-window
refusal would be indistinguishable from success. The worker therefore emits a
labelled answer for **every** input, using the unchanged `classify`/`step`:

| Declaration | Erased form (probe before implementation) |
| --- | --- |
| `rec DedupOutcome` (decision: WindowDecision, accepted: Option(Message)) | `{:DedupOutcome, decision_atom, :none \| {:some, message}}` |
| `rec RouteRetryOutput` (decision: WindowDecision, total: Option(Int)) | `{:RouteRetryOutput, decision_atom, :none \| {:some, int}}` |

Tags are distinct from every existing `rec`/`type` name (`CapacityState`,
`DeadLetterRecord`, `DeliveryResult`, `Descriptor`, `EdgeDeclaration`,
`EnvelopeMessage`, `Interface`, `Joined`, `Message`, `PortBinding`,
`ReplyEndpoint`, `RetryPolicy`, `RouteReference`, `RoutingMatch`,
`SelectionCandidate`, `SelectionRequirement`, `SenderWindow`, `Transition`,
`WindowedState`, `AdmissionDecision`, `RedispatchMode`, `ReleaseDecision`,
`ResultClass`, `RetryDecision`, `WindowDecision`); the existing duplicate-`rec`
test stays.

    fn label_step(state: WindowedState, input: Message, decision: WindowDecision) -> Transition(WindowedState, DedupOutcome)
        # t = Elzoo.WindowedIdempotency.step(state, input, decision);
        # Transition{state: t.state, output: Some(DedupOutcome{decision, t.output})}
    fn labelled_dedup(state: WindowedState, input: Message) -> Transition(WindowedState, DedupOutcome)
        # label_step(state, input, Elzoo.WindowedIdempotency.classify(state, input))
    fn worker_empty(window: Int, max_senders: Int) -> Joined(WindowedState, Int)
        # Joined{left: Elzoo.WindowedIdempotency.initial(window, max_senders), right: 0}
    fn worker(state: Joined(WindowedState, Int), input: Message) -> Transition(Joined(WindowedState, Int), RouteRetryOutput)
        # d = labelled_dedup(left); accepted None -> right unchanged, total None;
        # accepted Some(m) -> Elzoo.Core.accumulate(right, m), total = its output

`worker` is the fused placement (one transition); hop placement runs the same
`labelled_dedup` in a dedup Unit and the unchanged `Elzoo.Core.accumulate` in
an accumulate Unit, so both placements execute the same decision code.
`WindowInvalid` is unreachable through the Elixir boundary (window/max_senders
are validated by unchanged `Elzoo.WindowedIdempotency.new/2` at start); if it
appears the output codec rejects it (Adapter: failed/dispatched/unclassified).

## Topology (visible, checked)

`Elzoo.RequestRouteRetry.topology(placement)` (`placement` ∈ `:fused | :hop`)
returns the exact declaration data `%{"wiring" => ..., "routes" => ...,
"requirement" => ..., "candidates" => [...], "interfaces" => ...}`.
`check_topology(placement)` runs, in order, unchanged `Elzoo.Wiring.validate/1`
(every edge through `Elzoo.Edge.connect/3` → core/port), `Elzoo.Routing.validate/2`,
`Elzoo.Assembly.connect/2` on the worker interface chain and
`Elzoo.Selection.select/2`, returning `{:ok, %{"selected" => piece_id}}` or the
first dependency error unchanged, tagged `{:topology, phase, reason}`.

Schemas (Assembly-owned example IDs, version 1): `example/rr-request`
(client request payload), `example/rr-work` (worker input), `example/rr-accepted`
(accepted Message only, dedup→accumulate), `example/rr-dedup-outcome`
(intermediate labelled dedup result), `example/rr-total` (intermediate integer),
`example/rr-result` (final worker value). None changes a shared ELZ-003 schema.

| Unit / port | direction | schema | delivery |
| --- | --- | --- | --- |
| `client/request` | output | rr-request | volatile |
| `gateway/request.in` | input | rr-request | volatile |
| `gateway/work` | output | rr-work | volatile |
| `gateway/result.in` | input | rr-result | volatile |
| `gateway/reply`; `client/reply.in` | output; input | elzoo/delivery-result v1 | volatile |
| fused: `worker/input`; `worker/dedup.accepted` → `worker/accumulate.input` | in / out→in | rr-work; rr-accepted | volatile; fused |
| fused: `worker/result` | output | rr-result | volatile |
| hop: `dedup/input`, `dedup/accepted`; `accumulate/input` | in, out; in | rr-work, rr-accepted; rr-accepted | volatile |
| hop: `dedup/outcome`; `accumulate/total` | output; output | rr-dedup-outcome; rr-total | volatile |
| hop: `hop-worker/result` (Assembly-owned combination of the two Units) | output | rr-result | volatile |

Edges: `ingress` client/request → gateway/request.in (hop); `work`
gateway/work → worker/input or dedup/input (hop); fused `dedup-accumulate`
inside `worker` or hop `dedup-accumulate` dedup/accepted → accumulate/input.
The GenServer.call into the worker is Adapter/Host entry over the `work` hop;
the fused `dedup-accumulate` edge is an intra-transition seam (ingest-json-unit
precedent), not a mailbox crossing.

The worker candidate's outer output descriptor is `worker/result` (fused) or
`hop-worker/result` (hop). It connects to the declared `gateway/result.in`
descriptor through `Assembly.connect/2`. This is the gateway's logical receipt
of the decoded **value** returned by the attempt callback, not an extra Unit or
mailbox delivery. The UnitAdapter returns a DeliveryResult; only its checked
`rr-result` value occupies this interface. `gateway/reply` → `client/reply.in`
is the declared volatile reply edge; `reply/3` builds the Envelope, and the
caller owns sending it to the request's named `reply_to`. The client receives
`elzoo/delivery-result` v1, not a bare `rr-result`.

Routing table (source `client/request`): one route `ingress` matching
`kind = command`. Any other kind is filtered (`{:route, :no_route}`), a
**synchronous refusal** (see totality).

Selection: requirement upstream `gateway/work` (output), downstream input
`gateway/result.in` (rr-result), using those exact descriptors declared in
`topology/1`. Requirement delivery is derived from the caller's `placement`
option: `:fused` → `fused`, `:hop` → `volatile`. Selection checks interface
and delivery compatibility; it does **not** choose placement. Candidates
(data, rank 0 unless noted):
`request-route-retry/fused-worker` (interface rr-work→rr-result, `fused`),
`request-route-retry/hop-worker` (rr-work→rr-result, `volatile`) and a
deliberately incompatible `request-route-retry/legacy-worker` (rr-work **v2**,
`volatile`, rank 0) that must appear in neither result. The selected ID binds
through an Assembly-owned two-entry table to the fused or hop delivery
function; selection does not certify that implementation (core/selection
limit), the bundled tests do. Selection runs at `start_link`; a failed
selection is `{:error, {:topology, :selection, reason}}` and nothing starts.

## API and lifecycle

    start_link(opts) :: {:ok, runner_pid} | {:error, :invalid_options | {:topology, phase, reason}}
      # :placement (:fused | :hop), :units (%{"worker" => lookup} or
      # %{"dedup" => lookup, "accumulate" => lookup}; runtime/adapter lookups),
      # :window, :max_senders (for worker initial state, see initial_state/3),
      # :capacity, :policy, :attempt_timeout_ms, :task_supervisor,
      # :dead_letter, :now_ms -- passed to the unchanged Runner.
    initial_state(placement, window, max_senders) ::
      {:ok, %{"worker" => state} | %{"dedup" => state, "accumulate" => 0}} | {:error, reason}
      # for the caller's Unit supervision: Elzoo.Unit {Cure.Elzoo.RequestRouteRetry, :worker | :labelled_dedup, s}
      # and {Cure.Elzoo.Core, :accumulate, 0}
    submit(runner, request) ::
        {:ok, ref}
      | {:error, {:route, reason}} | {:error, {:route, edge_id, reason}} | {:error, {:source, reason}}
      | {:error, {:envelope, reason}}                                # routing/envelope phase, before admission
      | {:error, {:saturated, result}} | {:error, {:expired, result}}
      | {:error, :operation_in_flight} | {:error, :attempt_id_present}  # unchanged Runner
    reply(request, settlement, reply_message_id) :: {:ok, reply_envelope} | {:error, {phase, reason}}
    direct(state, requests) :: {values, state}   # pure valid-payload trace, no process; rr-result v1 maps

Lifecycle per request:

1. **Route (pure, before admission).** `Routing.route_one(wiring, routes,
   request)` must return `{:ok, "ingress"}`; otherwise its error is returned
   unchanged and nothing is admitted or dispatched.
2. **Admit.** Unchanged `Runner.submit/2` (deadline-before-dispatch → `:expired`,
   capacity → `:saturated`, one open operation per effective correlation).
3. **Attempt n** (the Runner's `attempt` callback built at start):
   `Transformation.translate(attempt_env, %{"unit_id" => "gateway",
   "message_id" => attempt_id <> "/work", "port" => gateway/work}, & &1)`
   (payload unchanged; new message ID; correlation = effective outer
   correlation; attempt_id, deadline, idempotency_key preserved), then the
   selected delivery: fused = one `UnitAdapter.deliver(worker, wiring, "work",
   inner, Codec.Worker)`; hop = `deliver(dedup, ..., "work", inner,
   Codec.Dedup)` then, only for a valid accepted Message, a second inner
   Envelope through `deliver(accumulate, ..., "dedup-accumulate", second,
   Codec.Accumulate)`. The Assembly builds `second` with
   `Transformation.translate/3`: ID `<inner id>/accumulate`, target producer
   `dedup/accepted`, schema `example/rr-accepted` v1, payload the exact accepted
   Message map (not the decision wrapper). Causation is the first inner ID;
   effective correlation, attempt_id, deadline and idempotency_key are kept.
   `Codec.Accumulate` decodes that map by the same exact integer-only rule as
   the first input. `combine_hop/2` below owns the final hop result.
4. **Re-identify.** The inner result (identity of the translated Envelope) is
   mapped to the outer attempt identity: `message_id` = outer, `correlation_id`
   = effective outer correlation (asserted equal to the inner one; mismatch
   → `unknown/unknown/unclassified`), `attempt_id`/`deadline_unix_ms` echoed.
   The Assembly-owned `finalize_result/2` performs this identity mapping and
   calls `Envelope.validate_result/1` on **every** rebuilt final result,
   including both placements' completed results. Validation failure becomes
   `failed/dispatched/unclassified` with the valid outer attempt identity and
   no value/schema fields, never a completed or not_dispatched result. The
   Runner then validates and correlates it (unchanged) and
   classifies/decides/dead-letters (unchanged).
5. **Settle.** The submitter receives the unchanged Runner message
   `{Elzoo.RetryTimeout, ref, {:completed, result} | {:dead_lettered, record} |
   {:unsettled, record}}`.
6. **Reply (pure).** `reply/3` builds a `reply` (completed) or `error`
   (otherwise) Envelope, schema `elzoo/delivery-result` v1, producer
   `gateway/reply`, `causation_id` = request ID, correlation = effective
   request correlation, payload = a DeliveryResult for the **client request**
   identity: request message_id, effective request correlation, **no attempt_id**,
   and the request's `deadline_unix_ms` echoed exactly (including absence;
   never substitute an attempt deadline or the current clock). This applies
   to both the payload result and the reply Envelope's deadline metadata.
   The payload keeps the completed value/schema, or the record's last
   outcome/dispatch/error_class triple, or `unknown/unknown/unclassified`
   if the record has none. Requires `reply_to`; the client checks it with
   unchanged `RequestReply.accept_reply/3`. A reply is not an acknowledgement.

### Codec and hop-result ownership

All three codecs share an exact Message decoder: only the map with precisely
`sender`, `incarnation`, `sequence`, `value` string keys and four BEAM integers
is accepted and converted to `{:Message, sender, incarnation, sequence, value}`.
`Worker` and `Dedup` accept schema `example/rr-work` v1; `Accumulate` accepts
only `example/rr-accepted` v1. Extra/missing keys, floats, strings or a wrapper
instead of a Message are rejected before that Unit is called. Encoders accept
only the indicated `{:some, ...}` form; an unexpected `:none`, malformed tuple,
unknown decision or decision/accepted-total inconsistency is an output error,
not completed nil. No codec is overloaded for a record and a bare integer.

| Codec | Unit output passed to `encode_output/1` | Encoded value; `value_schema/0` |
| --- | --- | --- |
| `Worker` | `{:some, {:RouteRetryOutput, decision, total_option}}` | `%{"decision" => label, "total" => integer_or_nil}`; `{"example/rr-result", 1}` |
| `Dedup` | `{:some, {:DedupOutcome, decision, accepted_option}}` | `%{"decision" => label, "accepted" => message_map_or_nil}`; `{"example/rr-dedup-outcome", 1}` |
| `Accumulate` | `{:some, integer}` from unchanged `Elzoo.Core.accumulate/2` | bare integer; `{"example/rr-total", 1}` |

`Elzoo.RequestRouteRetry.combine_hop/2` is an Assembly-owned private helper,
not another Piece or runtime mechanism. Its inputs are the first Adapter
result and the second result (or `:not_attempted`). It checks intermediate
schema IDs/versions and exact value shapes, including the fixed decision table:
`fresh/advance/reorder/new_incarnation` require an accepted Message;
`duplicate/stale/superseded/full` require nil. It retains the first inner
identity until `finalize_result/2` maps to the outer attempt:

- First result **completed, not accepted**: no second call; build a new
  completed/dispatched DeliveryResult with `rr-result` v1 value
  `%{"decision" => first_label, "total" => nil}`. Never pass through the
  `rr-dedup-outcome` value or schema as the final value.
- First result **completed, accepted**, second **completed** with a valid
  `rr-total` v1 integer: build completed/dispatched with `rr-result` v1 value
  `%{"decision" => first_label, "total" => second_integer}`. The first hop
  supplies the decision; the second supplies only the total.
- First result **non-completed**: no second call; preserve its neutral
  outcome/dispatch/error_class, with no value/schema fields. If the first
  result was completed but had invalid metadata/value, the result is instead
  failed/dispatched/unclassified, since dedup may already have advanced.
- After a completed accepted first hop, a second rejection (even
  not_dispatched) → failed/dispatched/unclassified; timed_out (any dispatch)
  → timed_out/dispatched/unclassified; unknown or failed → that outcome/
  dispatched/unclassified. No value/schema fields survive these failures.
  Failure building/validating the second Envelope also maps to
  failed/dispatched/unclassified. The first hop's state advance is never
  erased by a second-hop refusal.

Both placements' final completed DeliveryResults thus carry only
`example/rr-result` v1. The Assembly validates the final value's exact shape
and decision/total consistency before `finalize_result/2` calls
`Envelope.validate_result/1`; the latter checks the neutral result contract,
not the opaque value's payload schema. No intermediate schema reaches the
Runner as a completed final value. `direct/2` invokes the same Cure worker and
`Codec.Worker` encoding to produce those same final value maps, without OTP.

Completed value (`example/rr-result` v1): `%{"decision" => label, "total" =>
integer | nil}` with label ∈ `fresh | advance | reorder | new_incarnation |
duplicate | stale | superseded | full` from a fixed atom→string table.
`total` is nil exactly when the window did not accept the message. For the
first input, anything outside the exact four-integer Message map → unchanged
Adapter `rejected/not_dispatched/permanent` → Runner dead-letter `permanent`,
attempts 1. A rejection at the second hop instead follows the conservative
post-dedup combination rule above.

**Totality (no silent drop).** Each `submit/2` call yields exactly one of: a
synchronous `{:error, _}` refusal (nothing admitted, nothing dispatched), or
`{:ok, ref}` followed by exactly one settlement while the Runner lives (DOWN
before settlement = unknown, inherited). Every worker input yields a labelled
answer; suppression/refusal by the window is a completed result with an
explicit label, never an absent or unlabelled nil. A caller-side
`GenServer.call` timeout on submit is unknown admission (inherited).

## Delivery class, ordering and failure assumptions

- **Local at-most-once (default `redispatch_forbidden`).** Per admitted
  operation and Runner lifetime, at most one attempt can have reached the
  worker: retries happen only after a reported `not_dispatched`
  (`:restarting`/`:undefined`/`nil` lookup, codec rejection is permanent).
  `timed_out`/`unknown`/`failed` and any exit reason become
  `dispatched_unresolved`; an exit reason or timeout never establishes
  non-execution or authorizes replay.
- **At-least-once attempting (opt-in `redispatch_idempotent`).** Re-dispatch
  after a possibly-dispatched attempt is allowed only under the caller's
  assertion; here the assertion is grounded by the worker's windowed key
  (unchanged payload sender/incarnation/sequence across attempts), **not** by
  `idempotency_key` (the Adapter never dedups on Envelope metadata). If the
  first attempt was applied, the retry reports `duplicate` with nil total: the
  earlier total is lost, not recovered. Holds only while the worker's volatile
  window survives and the sequence stays within W; a Unit restart re-accepts.
- **Not implemented:** durable log, durable dead-letter storage, durable
  attempt count/deadline across restart, at-least-once delivery across
  crashes, exactly-once Effects, broker, network transport.
- **Ordering:** none across operations; up to `capacity` operations
  interleave; each Unit serializes calls in arrival order; window reorders
  within W are accepted late, beyond W are `stale`. Hop partial failure can
  advance dedup without accumulating (no atomicity).
- **Assumptions (unverified):** truthful Adapter observations, sender
  sequence discipline (windowed-idempotency), wall-clock agreement at
  admission, sink durability, caller-supervised Units/Task.Supervisor.
