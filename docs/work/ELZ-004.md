## New Pieces

### `runtime/adapter` (planned → ready, kind `adapter`, owned)

Depends on `core/wiring` (hence envelope/edge/port) and `runtime/unit`.

    Elzoo.UnitAdapter.deliver(unit, wiring, edge_id, envelope, codec)
      :: {:ok, encoded_output} | {:error, {phase, reason}}

    @callback decode_payload(schema_id :: String.t(), schema_version :: pos_integer(), payload :: term())
      :: {:ok, cure_value :: term()} | {:error, atom()}
    @callback encode_output(output :: :none | {:some, term()})
      :: {:ok, term()} | {:error, atom()}

Order and declared errors (first failure wins, nothing after it runs):

1. `Elzoo.Wiring.accept/3` unchanged → `{:wiring | :route | :envelope, reason}`.
2. Runtime payload validation of the *value*, distinct from ELZ-002 descriptor
   compatibility: `codec.decode_payload/3` → `{:payload, reason}`. Only a
   validated value reaches the Unit.
3. `Elzoo.Unit.step/2` (unchanged, trusted transition) inside a caught
   `GenServer.call` exit → `{:unit, :unavailable}` for a dead/absent Unit and
   `{:unit, :exited}` when the step crashes it (e.g. a non-`Transition` return;
   the supervisor then restarts it with fresh state).
4. Output shape check `:none | {:some, _}` → `{:output, :invalid_shape}`.
5. `codec.encode_output/1` → `{:output, reason}`.

Limits: one synchronous call per delivery with OTP's default 5 s call timeout
(not a timeout/retry policy; ELZ-006); unbounded mailbox; no DeliveryResult or
error-class mapping (ELZ-003 schema reused only by later tasks; classification
is ELZ-006); no ack, redelivery, durability or exactly-once.

### `runtime/host` (planned → ready, kind `recipe`)

Depends on `runtime/unit`, `runtime/supervision`. A recipe, not a wrapper:
`examples/elzoo/host.exs` defines a **consumer-owned** `Application` whose
`Supervisor` (one_for_one) starts named `Elzoo.Unit` children. Tests start it
without `Elzoo.Application` and show restart resets volatile state.
No custom engine loop, Registry or DynamicSupervisor.

### `assembly/ingest-json-unit` (new, kind `owned`)

Depends on `assembly/ingest-dedup-accumulate` (unchanged Cure operators),
`runtime/adapter`, `runtime/host`, `core/wiring`, `integration/json`;
providers cure, elixir, otp, jason.

    Elzoo.IngestCodec            # runtime/adapter codec for schema example/ingest-message v1
    Elzoo.IngestBoundary.handle(unit, wiring, edge_id, json :: binary)
      :: {:ok, json :: binary} | {:error, {phase, reason}}
    Elzoo.IngestBoundary.wiring(:fused | :hop)   # declared in this bundle

* JSON Adapter: `Jason.decode/1` → `{:json, :invalid}`; non-object/malformed
  envelope → `{:envelope, :invalid_shape}`; `Jason.encode/1` failure →
  `{:json, :unencodable}`. Jason's behavior is an upstream contract
  (pinned version from mix.lock); our translation is tested.
* Payload value check: exact JSON object
  `{"sender","incarnation","sequence","value"}` of integers (others rejected
  with `{:payload, :invalid_shape}`; schema id/version other than
  `example/ingest-message`/1 → `{:payload, :unsupported_schema}`), then built with
  the compiled Cure constructor `Elzoo.Idempotency.message/4`, so the Unit
  sees the measured `{:Message, ...}` ABI. Output `{"accepted": false}` or
  `{"accepted": true, "total": n}`; schema `example/optional-count` v1.
* Wiring: fused = one Unit `pipeline` running `Cure.Elzoo.Core.assembly`;
  hop = Units `dedup` (receiver) and `accumulate`, one volatile `hop` edge
  between them, validated by `Elzoo.Wiring.validate/1`. Owned by this bundle;
  the shared ELZ-003 maps are untouched.

## Evidence plan

* Proof: existing selected Cure laws in `delivery/idempotency` and
  `core/operator` only ground the pure transition. No new law claimed.
* Type: pinned Cure compiles the reused operators; Envelope/Edge/Port decoders
  are the named checkers for descriptors and envelopes.
* Tests (named scenarios, not proofs): direct `Elzoo.Runtime.fused/1` versus the
  JSON→Adapter→supervised Unit path for named traces and the existing seeded
  model, for fused and hop wiring; Supervisor restart (state reset, duplicate
  re-accepted); each declared Adapter error above, including a crashing step and
  an absent Unit; Jason invalid input and unencodable output; isolated
  consumer export of the new IDs with no `Elzoo.Application`.
* Upstream: Jason, OTP GenServer/Supervisor/Application, Elixir.
* Existing ELZ-002/003 positive/negative boundary checks stay in `mix check`.

## Contract statement for the exemplar

Volatile, single-host, synchronous bootstrap exemplar. Not bounded (history and
mailbox unbounded), not durable (restart forgets keys), not ordered across hosts,
not exactly-once and not a complete old Zoo receiver.
