## New Pieces

### `runtime/adapter` (planned → ready, kind `adapter`, owned)

Depends on `core/wiring` (hence envelope/edge/port) and `runtime/unit`.

    Elzoo.UnitAdapter.deliver(unit_lookup, wiring, edge_id, envelope, codec)
      :: {:ok, delivery_result_map}
       | {:error, {:envelope, reason}}     # Envelope.decode/1 failed
       | {:error, {:wiring, reason}}       # wiring declaration invalid

    unit_lookup :: pid() | (-> pid() | :restarting | :undefined | nil)

    @callback decode_payload(schema_id, schema_version, payload) :: {:ok, value} | {:error, atom()}
    @callback encode_output(:none | {:some, term()}) :: {:ok, term()} | {:error, atom()}
    @callback value_schema() :: {String.t(), pos_integer()}

A `DeliveryResult` is built only after the unchanged `Elzoo.Envelope.decode/1`
accepted the Envelope, so the echoed `message_id`, `correlation_id` (falls back
to `message_id` when absent), `attempt_id` and `deadline_unix_ms` are valid by
construction. Every `{:ok, result}` passes the unchanged
`Elzoo.Envelope.validate_result/1`. A wiring declaration fault
(`Elzoo.Wiring.validate/1`) is a caller error, not a message rejection.

| Step (first failure wins) | outcome / dispatch / error_class |
| --- | --- |
| route check (`Elzoo.Wiring.accept/3` `:route` phase: unknown edge, producer/schema/version mismatch) | rejected / not_dispatched / permanent |
| `codec.decode_payload/3` fails (runtime value validation, distinct from ELZ-002 descriptor checks) | rejected / not_dispatched / permanent |
| lookup returns `:restarting`, `:undefined` or `nil` | rejected / not_dispatched / unavailable |
| `GenServer.call` exits `{:timeout, _}` (OTP default 5000 ms) | timed_out / dispatched / unclassified |
| any other `GenServer.call` exit, **including `{:noproc, _}`** (step crashed the Unit, Unit died, or callback exited) | unknown / dispatched / unclassified |
| output not `:none` or `{:some, _}` | failed / dispatched / unclassified |
| `codec.encode_output/1` fails (state already advanced) | failed / dispatched / unclassified |
| `:none` (duplicate suppressed) | completed / dispatched, `value: nil`, codec value schema (a successful suppression, never rejected) |
| `{:some, v}` | completed / dispatched, `value`: encoded `v`, codec value schema |

Only the explicit pre-call lookup result (`:restarting`/`:undefined`/`nil`) is
known absence. A call exit shape never proves non-execution: on the pinned
OTP 29.1.2/Elixir 1.20.4 a live `handle_call` can perform a side effect and then
`exit(:noproc)`, and the caller sees exactly `{:noproc, {GenServer, :call, _}}`.
So `dispatched` means a submission was attempted, not that the receiver ran or
had no effect; a regression test with a callback side-effect marker followed by
`exit(:noproc)` asserts unknown/dispatched with the outer identity preserved.
No `Process.alive?` pre-check is used to decide a race.
Timeout: the default call timeout is used, not configured; a late reply is
dropped by OTP's call alias mechanism (upstream contract) and the Unit may have
advanced. Envelope metadata (`idempotency_key`, `sequence`) is carried but
never the dedup key. Results and errors never embed payloads or exception data.

Limits: one synchronous call per delivery; unbounded mailbox; no ack,
redelivery, durability, ordering or exactly-once claim.

### `runtime/host` (planned → ready, kind `recipe`)

Depends on `runtime/unit`, `runtime/supervision`. A recipe, not a wrapper:
`examples/elzoo/host.exs` defines a consumer-owned `Application` module whose
`Supervisor` (one_for_one, OTP default intensity 3 restarts in 5 s, beyond which
the Supervisor exits) starts `Elzoo.Unit` children by child id, and
`lookup(supervisor, id)` via `Supervisor.which_children/1` returning the pid, or
`:restarting`/`:undefined` (absent). The example is copied and run by the
isolated export consumer without `Elzoo.Application`. Tests assert that a
killed Unit restarts with fresh state, its dedup history is lost and a
previously delivered key is re-accepted.

### `assembly/ingest-json-unit` (new ID, kind `owned`)

New ID because the exemplar acquires new Needs (Jason, Adapter, Host); the
ready `assembly/ingest-dedup-accumulate` stays unchanged. Depends on
`assembly/ingest-dedup-accumulate` (Cure operators reused, not copied),
`runtime/adapter`, `runtime/host`, `core/wiring`, `integration/json`;
providers cure, elixir, otp, jason.

    Elzoo.IngestBoundary.handle(placement :: :fused | :hop, units, json :: binary, opts \\ [])
      :: {:ok, delivery_result_json :: binary}
       | {:error, :invalid_json | :invalid_envelope}
       | {:error, {:wiring, reason}}
    units :: %{"pipeline" => lookup} | %{"dedup" => lookup, "accumulate" => lookup}
    Elzoo.IngestBoundary.wiring(:fused | :hop) :: wiring_map

**Wiring (bundle-owned; ELZ-003 shared maps untouched).** Both declare the
actual ingress edge:

* fused: Unit `pipeline`, ports `ingress.request` (output) and `dedup.input`
  (input), schema `example/ingest-message` v1, delivery `fused`; edge
  `ingress` (fused). The Unit runs `Cure.Elzoo.Core.assembly/2`.
* hop: Units `client` (`request` output), `dedup` (`input` input,
  `accepted` output, schema `example/accepted-message` v1) and `accumulate`
  (`input` input); delivery `volatile`; edges `ingress` (hop,
  client.request→dedup.input) and `dedup-accumulate` (hop). `dedup` runs
  `Cure.Elzoo.Idempotency.receiver/2`, `accumulate` `Cure.Elzoo.Core.accumulate/2`.

The external JSON producer must name the declared ingress producer
(`pipeline`/`ingress.request` or `client`/`request`); a mismatch is a route
rejection, never rewritten.

**Codecs (one per hop).**

* `Elzoo.IngestCodec.Count` (fused) and `Elzoo.IngestCodec.Accepted` (hop 1)
  decode JSON `example/ingest-message` v1: an object with exactly the keys
  `sender`, `incarnation`, `sequence`, `value`, each `is_integer/1` (unbounded
  BEAM integers; no range claimed). Floats (including `1.0`), booleans, null,
  strings, extra or missing keys → `:invalid_payload`; another schema →
  `:unsupported_schema`. Values are built by the compiled Cure constructor into
  `{:Message, sender, incarnation, sequence, value}`.
* `Count` encodes `{:some, total}` → integer, schema `example/optional-count` v1.
  `Accepted` encodes `{:some, message}` → the BEAM `Message` for the internal
  hop only, schema `example/accepted-message` v1.
* `Elzoo.IngestCodec.Total` (hop 2) decodes an internal `example/accepted-message`
  v1 `{:Message, i, i, i, i}` (integers checked) and encodes like `Count`.

No erased tuple is ever placed in outer JSON: the outer value is an integer or
`nil`.

**Boundary drive (hop).** The Boundary drives both Units: it delivers the
outer Envelope to `dedup` on `ingress`; on a completed fresh result it builds
the inner Envelope deterministically: `message_id` = outer id + `"/dedup-accumulate"`,
kind `event`, producer `dedup`/`accepted`, schema `example/accepted-message` v1,
`causation_id` = outer `message_id`, `correlation_id`/`attempt_id`/`deadline_unix_ms`
echoed, payload = the BEAM Message; then delivers it to `accumulate` on
`dedup-accumulate`. The outer result always carries the outer IDs:

| dedup result | accumulate result | outer result |
| --- | --- | --- |
| rejected / timed_out / unknown / failed | not called | the dedup result |
| completed, `nil` (duplicate) | not called | completed / dispatched, `nil` |
| completed, Message | completed, total | completed / dispatched, total |
| completed, Message | rejected / not_dispatched (any class) | failed / dispatched / unclassified (dedup already advanced) |
| completed, Message | timed_out / dispatched | timed_out / dispatched / unclassified |
| completed, Message | unknown or failed | unknown resp. failed / dispatched / unclassified |
| completed, Message | `{:error, _}` (internal fault) | failed / dispatched / unclassified |

**JSON Adapter.** `Jason.decode/1` failure → `{:error, :invalid_json}`; any
`Elzoo.Envelope.decode/1` failure of the decoded value (including non-objects)
→ `{:error, :invalid_envelope}`; neither carries input bytes or
`Jason.DecodeError` data. If `Jason.encode/1` of a result fails (state may have
advanced), the Boundary encodes instead the fixed fallback
failed/dispatched/unclassified with no value and the outer IDs, which contains
only validated text/integers and always encodes. Tested with an injected
codec (`opts[:codecs]`) whose output is unencodable. Jason behavior is an
upstream contract (version pinned in mix.lock); our translation is tested.

## Evidence plan

* Proof: existing selected Cure laws in `delivery/idempotency` and
  `core/operator` ground only the pure transition. No new law claimed.
* Type: pinned Cure compiles the reused operators; `Elzoo.Envelope`,
  `Elzoo.Wiring`, `Elzoo.Edge`, `Elzoo.Port` are the named checkers for
  envelopes and declarations; codecs are executable Elixir checks, not types.
* Tests (named scenarios, not proofs): `Elzoo.Runtime.fused/1` versus the
  JSON→Boundary→Adapter→supervised Unit path for named crash-free traces and
  the existing seeded model, both placements; every Adapter row (route,
  payload, `:restarting`/`:undefined`, callback-marker-then-`exit(:noproc)`, timeout, crash, bad output,
  encode failure, duplicate, fresh); every composite hop row; Supervisor
  restart reset and duplicate re-acceptance; Jason invalid input,
  invalid envelope and encode fallback; isolated export consumer of the new
  IDs (including host.exs) without `Elzoo.Application`.
* Upstream: Jason, OTP GenServer/Supervisor/Application, Elixir.
* All existing checks, including the ELZ-002/003 positive/negative boundary
  checks and the original `Elzoo.Runtime` traces, stay in `mix check` unchanged.

## Contract statement for the exemplar

Volatile, single-host, synchronous bootstrap exemplar. Not bounded (history and
mailbox unbounded), not durable (restart forgets keys), not ordered across
hosts, not exactly-once and not a complete old Zoo receiver. Direct/OTP
equivalence is claimed only for named crash-free traces. In the hop placement a
failure after `dedup` can record a key as seen and lose the `accumulate`
output (reported failed/timed_out/unknown, never completed); no
partial-failure atomicity.
