## New Pieces

### `runtime/adapter` (planned → ready, kind `adapter`, owned)

Depends on `core/wiring` (hence envelope/edge/port) and `runtime/unit`.

    Elzoo.UnitAdapter.deliver(unit_lookup, wiring, edge_id, envelope, codec)
      :: {:ok, delivery_result_map}

    @callback decode_payload(schema_id :: String.t(), schema_version :: pos_integer(), payload :: term())
      :: {:ok, cure_value :: term()} | {:error, atom()}
    @callback encode_output(output :: :none | {:some, term()})
      :: {:ok, json_value :: term()} | {:error, atom()}
    @callback value_schema() :: {String.t(), pos_integer()}

`unit_lookup` is a pid or a zero-arity function resolving the current child
(needed because `Elzoo.Unit` has no name option and a restarted child has a new
pid; the Host recipe resolves via `Supervisor.which_children/1` by child id).
Every return is an ELZ-003 version-1 `DeliveryResult` map that passes the
unchanged `Elzoo.Envelope.validate_result/1`; `message_id`, `correlation_id`
(falls back to `message_id` when absent) and `attempt_id`/`deadline_unix_ms`
are copied from the envelope. Fixed mapping (a statement of what the exemplar
observed, not a retry/classification policy — ELZ-006 owns that):

| Step (first failure wins) | outcome / dispatch / error_class |
| --- | --- |
| `Elzoo.Wiring.accept/3` (unchanged) fails, envelope invalid | rejected / not_dispatched / permanent |
| `codec.decode_payload/3` fails (runtime value validation, distinct from ELZ-002 descriptor checks) | rejected / not_dispatched / permanent |
| Unit absent/dead before the call | rejected / not_dispatched / unavailable |
| call sent, Unit exits or OTP default 5000 ms call timeout | unknown / unknown / unclassified (state may or may not have advanced) |
| output not `:none \| {:some, _}` | failed / dispatched / unclassified |
| `codec.encode_output/1` fails after state advanced | failed / dispatched / unclassified |
| success, fresh key | completed / dispatched, `value` = encoded output, value schema from codec |
| success, duplicate suppressed | completed / dispatched, `value` = `nil`, same value schema (a successful suppression, never rejected) |

Envelope metadata (`idempotency_key`, `sequence`) is carried but never used as
the dedup key; dedup uses only payload `{sender, incarnation, sequence}` via
the unchanged Cure receiver. Absent-vs-dead is best-effort (`Process.alive?`
then call): a race classifies as unknown, never as rejected.

Limits: one synchronous call per delivery; unbounded mailbox; no ack,
redelivery, durability or exactly-once. Raw payloads/exception data are not
copied into results or logs.

### `runtime/host` (planned → ready, kind `recipe`)

Depends on `runtime/unit`, `runtime/supervision`. A recipe, not a wrapper:
`examples/elzoo/host.exs` defines a **consumer-owned** `Application` whose
`Supervisor` (one_for_one, OTP default intensity 3 restarts / 5 s, beyond which
the Supervisor itself exits) starts `Elzoo.Unit` children by child id, plus a
lookup by child id. Tests run it without `Elzoo.Application` and show: a
killed Unit is restarted with **fresh state**, its dedup history is lost and a
previously delivered key is **re-accepted** (asserted, not hidden).
No custom engine loop, Registry or DynamicSupervisor.

### `assembly/ingest-json-unit` (new, kind `owned`)

Depends on `assembly/ingest-dedup-accumulate` (unchanged Cure operators),
`runtime/adapter`, `runtime/host`, `core/wiring`, `integration/json`;
providers cure, elixir, otp, jason.

    Elzoo.IngestCodec            # runtime/adapter codec for schema example/ingest-message v1
    Elzoo.IngestBoundary.handle(unit, wiring, edge_id, json :: binary)
      :: {:ok, delivery_result_json :: binary}
       | {:error, :invalid_json | :invalid_envelope | :unencodable}
    Elzoo.IngestBoundary.wiring(:fused | :hop)   # declared in this bundle

* JSON Adapter: `Jason.decode/1` failure → `{:error, :invalid_json}`, without
  the input bytes or `Jason.DecodeError` data (redacted everywhere). A decoded
  value from which no valid non-empty `message_id` can be read →
  `{:error, :invalid_envelope}` (a DeliveryResult needs that identity). Any
  other invalid envelope → rejected/not_dispatched/permanent result. `Jason.encode/1` failure of the
  result → `{:error, :unencodable}` (no state can depend on it: the result was
  already computed). Jason's behavior is an upstream contract (version pinned in
  mix.lock); our translation is tested.
* Payload value check (`Elzoo.IngestCodec`): schema must be
  `example/ingest-message` v1 (else `:unsupported_schema`); payload must be an
  object with exactly the keys `sender`, `incarnation`, `sequence`, `value`,
  each a JSON integer (`is_integer/1`); floats (incl. `1.0`), booleans, null,
  strings, extra or missing keys → `:invalid_payload`. Integers are
  unbounded (BEAM bignums; no range limit claimed). Valid values are built with
  the compiled Cure constructor into `{:Message, sender, incarnation, sequence, value}`.
  Output value: `{:some, n}` → `n` (running total), schema `example/optional-count` v1.
* Wiring: fused = one Unit `pipeline` running `Cure.Elzoo.Core.assembly`;
  hop = Units `dedup` (receiver) and `accumulate`, one volatile `hop` edge
  between them, validated by `Elzoo.Wiring.validate/1`. Owned by this bundle;
  the shared ELZ-003 maps are untouched.

## Evidence plan

* Proof: existing selected Cure laws in `delivery/idempotency` and
  `core/operator` only ground the pure transition. No new law claimed.
* Type: pinned Cure compiles the reused operators; Envelope/Edge/Port decoders
  are the named checkers for descriptors and envelopes.
* Tests (named scenarios, not proofs): direct `Elzoo.Runtime.fused/1` versus the
  JSON→Adapter→supervised Unit path for named traces and the existing seeded
  model, for fused and hop wiring; Supervisor restart (state reset, duplicate
  re-accepted); each declared Adapter error above, including a crashing step and
  an absent Unit; Jason invalid input and unencodable output; isolated
  consumer export of the new IDs with no `Elzoo.Application`.
* Upstream: Jason, OTP GenServer/Supervisor/Application, Elixir.
* Existing ELZ-002/003 positive/negative boundary checks stay in `mix check`.

## Contract statement for the exemplar

Volatile, single-host, synchronous bootstrap exemplar. Direct/OTP
equivalence is claimed only for named crash-free traces. In the hop wiring a
failure between Units can record a key as seen in `dedup` and then lose the
`accumulate` output (reported as unknown); no partial-failure atomicity. Not bounded (history and
mailbox unbounded), not durable (restart forgets keys), not ordered across hosts,
not exactly-once and not a complete old Zoo receiver.
