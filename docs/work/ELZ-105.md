## Existing consumers and platform contracts

Inspected accepted injection paths, not just package descriptions:

- ObjectStore.Config resolves a function/MFA per call into an access-key map;
  ReqS3 0.2.5 and Req 0.7.5 (Apache-2.0) have environment fallback paths which
  the accepted Adapter avoids through explicit credentials/endpoint/region.
- Notification.Transport invokes its zero-arity Need for `{username, password}`
  before SMTP. Swoosh 1.29.3 (MIT), `lib/swoosh/adapters/smtp.ex:101–115`,
  passes session config to gen_smtp 1.3.0 (BSD-2-Clause). No adoption is required.
- AiText.Adapter checks the injected key before calling its provider: 1..1024
  printable ASCII bytes, narrower than this Piece's binary Contract. Its existing
  scripted provider proves optional composition and refusal without network calls.
- ReqLLM 1.30.0 (Apache-2.0), `lib/req_llm/keys.ex:59–76`, prefers explicit
  api_key over application/environment fallbacks. `application.ex:27` can load
  dotenv; accepted consumers must retain `config :req_llm, load_dotenv: false`.

Existing provider pins are in mix.lock; the ELZ-105-owned implementation changes
no pins or dependency/configuration files. The separately admitted ELZ-107
provider prerequisite is inherited only through the local stack described below.
Source archives for these comparisons are likewise available at
`https://repo.hex.pm/tarballs/<package>-<version>.tar`.

Elixir 1.20.4 and OTP 29.1.2 are Apache-2.0 platform providers. Relevant actual
Elixir source: [Exception formatting](https://github.com/elixir-lang/elixir/blob/v1.20.4/lib/elixir/lib/exception.ex#L141-L157),
[System.getenv translation](https://github.com/elixir-lang/elixir/blob/v1.20.4/lib/elixir/lib/system.ex#L680-L686),
and [Process introspection](https://github.com/elixir-lang/elixir/blob/v1.20.4/lib/elixir/lib/process.ex).
Formatting exception/throw/exit terms can disclose secrets; this implementation
never invokes those formatters. OTP introspection, trace/debug access, callback
side effects, crash dumps and retained binaries remain outside its protection.
