## Contract reading

One Adapter instance runs one external OS command per request with bounded
concurrency, an absolute deadline, group-scoped staged termination and an
**observed** outcome. Elzoo owns the admission/queue state, the termination
state machine, the reaper handoff and the result schema. Signal delivery and
group semantics are OS behaviour. It is not security isolation: no sandbox,
container, seccomp, path confinement, network isolation, shell parsing or
remote execution. No Elixir SDK, no Jido copy (`jido_shell`/`jido_workspace`
are comparison input only, rejected as dependencies by the record).

### Provider and host tools (reuse check)

- **OTP Port** (`{:spawn_executable, path}`, `args`, `cd`, `env`, `:binary`,
  `:exit_status`, `:stderr_to_stdout`) at OTP 29.1.2 / Elixir 1.20.4 is the
  selected provider; no process library. Implementation observation (not a
  documented API promise): `erts/emulator/sys/unix/erl_child_setup.c`
  `start_new_child` calls `setsid()` (POSIX build) before `exec`, so the child
  is a process-group leader with `pgid == os_pid` (probed on macOS with
  `ps -o pgid=`). The Adapter **observes** this per run with `pgrep -g os_pid`
  before relying on it (see state machine); the test suite also observes it.
- **`pgrep -g <pgid>`** is the group observation: it lists member PIDs from the
  process table; exit 0 = members listed, 1 = no member, 2/3 = usage/fatal
  error = **observation failed**. It is independent of the `kill` utility.
  Present as `/usr/bin/pgrep` on macOS and procps-ng on Ubuntu (probed locally;
  symbolic/macbook-ubuntu are Ubuntu 26.04.1 x86_64 per
  docs/development/10-symbolic-ci.md; exact behaviour there is confirmed by
  the CI run, not assumed).
- **`kill -s TERM|KILL -- -<pgid>`** sends the signal to the group. Its exit
  status is **never** used as evidence of delivery or death: exit 0 means the
  utility accepted the request, nonzero means the request could not be made
  (`signal_failed` observation). Death is established only by `pgrep`.
- Both utilities are located once at Adapter start (`System.find_executable/1`
  or explicit `kill_path`/`pgrep_path` options, which also serve fault
  injection in tests); absence fails `start_link` with
  `{:error, {:tool_unavailable, :kill | :pgrep}}`. They are declared Needs.
- Probed OTP facts: `Port.open` raises `ErlangError{original: :enoent}` for a
  missing file (nothing dispatched → `rejected{spawn_failed}`); a signalled
  child's `exit_status` is `128 + signal` (TERM → 143); with `:exit_status` the
  status is delivered only after the stdout pipe reaches EOF (completion
  condition, finding 9 / Q4 below).

### PGID lifetime and reuse (finding 3)

A process-group ID stays reserved while any member exists (zombies included):
Linux keeps the `struct pid` referenced through `PIDTYPE_PGID` so the number is
not reallocated; XNU/BSD `fork1` skips candidate PIDs in use as a PGID or SID.
These are OS implementation observations, declared as unverified assumptions.
Consequences used by the design:

- A `pgrep -g pgid` listing proves the group is still ours while the Adapter
  has not yet observed it empty.
- The Adapter **never signals after it has observed the group empty**.
- The only hazard is the gap between an "alive" observation and the following
  signal (sub-millisecond to a few ms): reuse there needs the whole PID space
  to wrap in that gap. Declared, not mitigated further.
- The only unconditional signal is the one sent after a **failed** observation
  (see state machine); that path is declared as the single place where the
  hazard is accepted, because leaving a possibly live group is the greater
  Contract violation.

### Inputs

`Elzoo.OsProcess.start_link(opts)` — one Adapter instance = one slot pool with
its own Reaper. Config is fixed at construction; no hot reconfiguration.

| Option | Type / default | Meaning |
| --- | --- | --- |
| `max_concurrent` | positive integer, required | in-flight slots, counted by `Elzoo.Backpressure` (ELZ-006 selected helper laws cover only the counter steps) |
| `queue_limit` | non-negative integer, required | bounded FIFO of waiting requests; Adapter-owned policy, not covered by the backpressure laws |
| `queue_timeout_ms` | positive integer, required | maximum queue residence |
| `grace_ms` | non-negative integer, default 2000 | full wait after TERM before the escalation observation |
| `reap_timeout_ms` | positive integer, default 5000 | bounded wait after KILL for the group to become empty (observation every 50 ms) |
| `max_output_bytes` | positive integer, default 1 MiB | retained output bound |
| `kill_path`, `pgrep_path` | absolute paths, default located | host tools |
| `now_unix_ms` | zero-arity fun, default `System.os_time(:millisecond)` | injected wall clock for tests |
| `name` | optional | |

Per request (`submit/3`; `run/3` = submit + await):

| Field | Type | Meaning |
| --- | --- | --- |
| `spec.executable` | absolute path | run directly; no shell; no PATH search |
| `spec.args` | list of binaries | |
| `spec.cwd` | absolute path or nil | Port `cd` |
| `spec.env` | `%{inherit: [name], set: [{name, value}]}`, default empty | child environment = inherited names present in the VM environment + set names; **every other VM variable is unset** for the child (Port `env` with `false` for each) |
| `deadline_unix_ms` | non-negative integer | absolute wall-clock deadline (same field as `core/envelope`) |
| `max_run_ms` | positive integer, optional | relative cap from dispatch; at least one of the two is required; both → the earlier wins |
| `request` | optional map with `message_id`, `correlation_id`, `attempt_id` | echoed by `to_delivery_result/2`; absent → mapping needs them as arguments |

Malformed input → `{:error, {:invalid_spec, field}}` from `submit/3`
synchronously (caller error; nothing admitted). stdin is the Port pipe and
never carries data (declared limit). stderr is always merged into the bounded
output (`:stderr_to_stdout`); no `:inherit` option (finding 9).

### Deadline semantics (finding 6, G5)

1. At **admission** the Adapter reads `now_unix_ms` once and computes
   `remaining = deadline_unix_ms - now`. `remaining <= 0` → result
   `expired` immediately (`timed_out/not_dispatched`). `remaining` larger than
   the OTP timer bound (4_294_967_295 ms) → `{:error, {:invalid_spec,
   :deadline_too_far}}`. The deadline becomes a **local monotonic target**
   `target = monotonic_now + remaining`; wall clock is not read again.
2. **Queued**: one timer per entry armed for
   `min(queue_timeout_ms, target - monotonic_now)`. When it fires: if
   `monotonic_now >= target` → `expired`; else → `rejected{queue_timeout}`.
   Equal instants resolve to `expired` (the deadline is the caller's law, the
   queue timeout is Adapter policy). Each timer message carries the run ref
   and a generation; a late message for a dispatched or finished ref is ignored.
3. **Dispatch**: recompute `remaining = target - monotonic_now`; `<= 0` →
   `expired` (not dispatched, slot released). Otherwise spawn and arm the
   collector's deadline timer for `min(remaining, max_run_ms)`. Queue residence
   can only shorten the run; it never restarts the deadline. Test: a request
   with `deadline_unix_ms = now + 300` queued behind a 500 ms command ends
   `expired`, never `completed`.
4. A deadline timer that fires after the Port reported exit+EOF is ignored
   (stale generation). A deadline during a running termination (cancel) does
   not start a second sequence (at-most-once).

### Outputs (Adapter result schema)

Atom-keyed maps delivered as `{Elzoo.OsProcess, ref, result}` to the
submitter (or returned by `run/3` as `{:ok, result}`). Rejections are also
delivered this way: `submit/3` returns `{:ok, ref}` as soon as the request is
accepted for admission, so an asynchronous spawn failure is a normal result.

| status | fields | meaning |
| --- | --- | --- |
| `completed` | `exit_code` (0..255, incl. 128+signal), `output`, `truncated`, `group_cleanup` (`nil` or `%{stage: :term \| :kill}`) | leader exited and EOF reached; any exit code; `group_cleanup` records a staged reap of members found alive after the leader exited, **and that reap observed the group empty** |
| `rejected` | `reason: :queue_full \| :queue_timeout \| :spawn_failed \| :cancelled` | nothing dispatched (A1) |
| `expired` | `deadline_unix_ms` | deadline passed before dispatch (A4) |
| `terminated` | `cause: :deadline \| :cancel \| :caller_down \| :collector_exit`, `stage: :none \| :term \| :kill`, `exit_code` (int or nil), `output`, `truncated` | the group was **observed empty** after the stage named; `exit_code` present only when the Port delivered it (A3, A5) |
| `unknown` | `reason: :observation_failed \| :group_alive_after_kill`, `stage: :none \| :term \| :kill`, `exit_code`, `output`, `truncated` | no observation of cleanup; external outcome unknown (A6); the stage names what was sent |

`output` in `terminated`/`unknown` is the bounded bytes collected before
termination; no result ever contains the command line, environment or an
exception message.

### Delivery-result mapping and stage sidecar (finding 4, G5)

`Elzoo.OsProcess.to_delivery_result(result, request)` returns
`{:ok, delivery_result_map, result}`: the first element is an exact
`core/envelope` version-1 map validated by `Elzoo.Envelope.validate_result/1`;
the second is the unchanged Adapter result (the **sidecar** carrying the stage,
exit code and cause). `request` must supply `message_id`; `correlation_id`
falls back to `message_id`; `attempt_id` and `deadline_unix_ms` are echoed when
present. The shared map gains no key.

| Adapter result | outcome / dispatch | error_class / value |
| --- | --- | --- |
| `completed` (any exit code) | completed / dispatched | `value` = `%{"exit_code", "output", "truncated"}`, `value_schema_id` `elzoo/os-process-completed`, version 1 |
| `rejected{queue_full \| queue_timeout}` | rejected / not_dispatched | `unavailable` |
| `rejected{spawn_failed}` | rejected / not_dispatched | `permanent` |
| `rejected{cancelled}` | rejected / not_dispatched | `permanent` |
| `expired` | timed_out / not_dispatched | `unclassified` |
| `terminated{cause: :deadline}` | timed_out / dispatched | `unclassified` (A2) |
| `terminated{cause: :cancel \| :caller_down \| :collector_exit}` | failed / dispatched | `unclassified` (A3) |
| `unknown` | unknown / dispatched | `unclassified` |

Tests check every row with `validate_result/1`, the correlation fallback, the
echo of `attempt_id`/`deadline_unix_ms`, and separately the sidecar fields.
`group_cleanup` is not in the completed `value` (it is cleanup metadata in the
sidecar); `value` carries no payload beyond the three keys.

### Termination state machine (pure Elixir `Elzoo.OsProcess.Termination`; finding 2)

Pure `step(state, observation) -> {actions, state}`; the collector or the
Reaper performs the actions and feeds back observations. Observations:
`:begin`, `{:group, [pid]}`, `{:group, :empty}`, `{:group, :failed}`,
`{:signal, :sent | :failed}`, `:grace_elapsed`, `:port_exit`, `:poll_tick`,
`:reap_elapsed`. Invariants of the machine (unit-tested as a transition table):

1. **Observe first.** `begin → observe`. `{:group, :empty}` before any signal
   → done `terminated{stage: :none}`. `{:group, :failed}` → retry the
   observation once after 100 ms; a second failure → send TERM anyway (the
   declared unconditional signal), then continue as if `{:signal, _}`.
2. **TERM.** `{:group, [_|_]} → send TERM → term_sent`. `{:signal, :sent |
   :failed}` → `grace` with the **full** `grace_ms` timer. The signal status is
   recorded, not interpreted.
3. **Grace is never shortened for escalation.** During `grace`, `:port_exit`
   (exit+EOF arrived) triggers an **early observation**: `{:group, :empty}` →
   done `terminated{stage: :term}`; `{:group, [_|_]}` or `{:group, :failed}` →
   stay in `grace` until `:grace_elapsed`. Only `:grace_elapsed` leads to the
   escalation observation.
4. **Escalation observation.** After `:grace_elapsed`: `{:group, :empty}` →
   done `terminated{stage: :term}`; `{:group, [_|_]}` → send KILL →
   `kill_sent`; `{:group, :failed}` → retry once; second failure → send KILL
   anyway, then `unknown{reason: :observation_failed, stage: :kill}` after
   the reap wait (one more observation attempt at the end; if it succeeds with
   `:empty`, the result is `terminated{stage: :kill}` instead).
5. **Reap wait.** After KILL: observe every 50 ms until `{:group, :empty}` →
   done `terminated{stage: :kill}`; `:reap_elapsed` with members still listed →
   done `unknown{reason: :group_alive_after_kill, stage: :kill}`;
   `{:group, :failed}` twice in a row → `unknown{reason: :observation_failed}`.
6. **At most one sequence per run.** `cancel`, deadline and owner-death
   causes enter the same machine; a second trigger while the machine runs only
   records the first cause and returns `{:ok, :already_requested}`.
7. A `terminated` result is only ever produced by a `{:group, :empty}`
   observation. `unknown` is produced by failed observations or by members
   still listed at `:reap_elapsed`. Nothing is assumed from `kill`'s status.

### Processes, ownership and the reaper handoff (finding 2, G2)

| Process | Owns | Linked / monitored |
| --- | --- | --- |
| **Adapter** (`Elzoo.OsProcess`, GenServer) | validation, admission counter, bounded FIFO and its timers, `from` of every submitter, the single reply point, dispatch of the next queued request | linked to its Reaper; monitors every submitter |
| **Reaper** (`Elzoo.OsProcess.Reaper`, GenServer, traps exits) | **opens every Port** (so it holds `os_pid` before any collector exists), the registry `ref → {pgid, port, collector, stage}`, cleanup on collector death, cleanup of every group on Adapter death | linked to the Adapter; link to its Ports; monitors every collector |
| **Collector** (plain process per run, spawned by the Reaper, not linked) | bounded output, deadline timer, drives the termination machine, reports stage transitions to the Reaper before each signal, closes/drains the Port, sends the final result | monitors its Port |
| **Cleanup worker** (plain process per group, spawned by the Reaper) | runs the same machine for one pgid from the recorded stage, reports the result to the Reaper | monitored by the Reaper |

Spawn handoff: Adapter → `Reaper.spawn(ref, spec, run_opts)` (synchronous
call): the Reaper opens the Port (catching `ErlangError` → `{:error,
:spawn_failed}`), reads `os_pid`, registers `{ref, pgid, port}`, spawns and
monitors the collector, `Port.connect(port, collector)`, then forwards every
`{port, _}` message already in its mailbox to the collector. There is no
window in which a collector can die while holding an unregistered child,
because the collector never exists before registration.

Failure matrix:

| Dies | Effect | Who cleans the group | Reply |
| --- | --- | --- | --- |
| Collector (brutal kill) | Reaper gets DOWN before `{:finished}`; Port still open (owned by Reaper) | Cleanup worker resumes from the recorded stage (`none` → observe, TERM…; `term` → remaining grace, observe, KILL…; `kill` → reap wait); then the Reaper closes the Port and reports `{:reaped, ref, result}` to the Adapter | Adapter replies `terminated{cause: :collector_exit}` or `unknown` **after** the cleanup observation, never before |
| Submitter, while queued | Adapter DOWN handler removes the entry, cancels its timer | nobody (nothing dispatched) | none |
| Submitter, while running | Adapter asks the collector to cancel with cause `:caller_down` | collector; result dropped by the Adapter | none |
| Adapter | Reaper receives `EXIT`; kills every collector; runs one cleanup worker per registered group **in parallel**, waits for all (bounded by grace + reap + 2 observation retries each), closes the Ports, exits with the same reason | Reaper | callers' `GenServer.call` exits with the Adapter's reason (unknown admission) |
| Reaper | its Ports close (OTP link); the Adapter dies (link, not trapping) | each collector observes `{:DOWN, _, :port, _, _}` and runs its own machine (cause `:collector_exit` is not used; the result is dropped) | callers' calls exit |
| Whole VM | OTP does not signal Port children; the child reads EOF on stdin / gets SIGPIPE on write | **nobody** — declared limit, distinct from BEAM-owner death | — |
| Child that leaves the group (`setsid`) | invisible to `pgrep -g` | **nobody** — declared residual; tested as isolated and safely cleaned by the test itself | — |

Normal `GenServer.stop(adapter)` takes the Adapter-death path: running
commands are terminated, not drained (Control contract says so).

### Completion condition (finding 9, Q4)

The Port delivers `exit_status` only after exit **and** EOF on the merged
output pipe. The Adapter does not poll the leader. Three distinct cases:

1. Leader exits, no member holds the pipe → `completed` immediately; then one
   group observation: members listed → cleanup worker (TERM, grace, KILL) →
   `completed{group_cleanup: %{stage}}` if it ends `:empty`, otherwise the
   whole result is `unknown{group_alive_after_kill}` (a completed command with
   an unreaped group is not reported as completed).
2. Leader exits, a **member** still holds the pipe → no `exit_status` until the
   deadline → deadline machine: observation lists the member → TERM … → the
   pipe closes → the Port delivers the leader's status → result
   `terminated{cause: :deadline, exit_code: <leader's>}`.
3. Leader exits, a process that **left the group** holds the pipe → at the
   deadline the observation is `:empty` → `terminated{stage: :none,
   exit_code: nil}` (the Port is closed without delivering the status; the
   holder is a declared residual).

The coordinator accepts this consequence or asks for leader polling (which
costs one `pgrep` per interval); the author does not propose polling.

### Operational declarations for piece.json (finding 8, G7)

- **Telemetry: `planned`.** No event, log or measurement is emitted by the
  Adapter, the Reaper or the collector. A future event family must exclude the
  command line, arguments, environment and output. Test: a run with a
  secret-looking argument under `ExUnit.CaptureLog` produces no log output
  containing it.
- **Config: `supported`.** Construction-time `max_concurrent`, `queue_limit`,
  `queue_timeout_ms`, `grace_ms`, `reap_timeout_ms`, `max_output_bytes`, tool
  paths; per-call `deadline_unix_ms`/`max_run_ms`, `cwd`, `env` allowlist. No
  hot update; a change needs a new Adapter instance. Evidence: tests exercise
  each setting (`test/elzoo/os_process_test.exs`).
- **Control: `supported`** for `cancel(adapter, ref)`. Authority: holding the
  run `ref` (a capability handed to the submitter; the Adapter performs no
  authentication). Precondition: the ref is queued or running. Operation
  identity: the ref. Results: queued → `{:ok, :requested}` and the submitter
  receives `rejected{cancelled}`; running → `{:ok, :requested}` and the
  submitter later receives `terminated{cause: :cancel}` or `unknown`; already
  terminating → `{:ok, :already_requested}` without a second signal sequence;
  finished or foreign → `{:error, :unknown_run}`. `{:ok, :requested}` is
  acceptance, not application; application is observed in the final result.
  No pause, no drain, no business-level stop guarantee; Adapter stop
  terminates running commands. Evidence: cancellation tests.

### Non-goals, limits and residuals (declared)

Security isolation, shell parsing, path confinement, containers, seccomp,
filesystem confinement, remote execution, cross-host claims, stdin data,
separate stderr capture, telemetry, durable receipts, retry policy. Whole-VM
death leaves children (OTP contract). A process that calls `setsid` leaves the
group and is invisible. A group that survives KILL within `reap_timeout_ms`
yields `unknown`. `kill`'s and `pgrep`'s exact behaviour is observed on macOS
(BSD utilities) locally and on Ubuntu (procps-ng) in CI; no other platform is
claimed. Output truncation drops bytes beyond the bound silently except for
the `truncated` flag. Tests are finite observations on the named OSes, not
proofs of universal cleanup.
