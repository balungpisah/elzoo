## Contract reading

One Adapter instance runs one external OS command per request with bounded
concurrency, an absolute deadline, group-scoped staged termination performed by
the provider's port program, and an observed outcome. Elzoo owns admission,
the bounded queue, deadline conversion, output bounds, the result schema, the
delivery-result mapping, the group observation after the exit notification and
the honest labels. Signal delivery, group semantics and escalation are the
provider's and the OS's behaviour. Not security isolation: no sandbox,
container, seccomp, path confinement, network isolation, shell parsing or
remote execution.

### Group identity (observation 2 of the re-reviews)

The Adapter **sends no signal**. Every signal to the group is sent by the port
program that forked the leader and reaps it: the deadline watchdog and the
owner-death stop act immediately after its own `kill(pid, 0)` liveness check
in the same C process, and the at-exit TERM is sent in the `waitpid` handler
while the leader's pid is still reserved. The inherent gap between a liveness
check and a `kill(-pgid)` is the provider's upstream behaviour (declared), not
an Adapter design choice. The Adapter's `pgrep -g OsPid` observations serve
only to **report** (group empty / members listed); a reused group id could at
most make a report wrong, never cause a signal. Absence of an "empty"
observation is never used as a claim.

### Deadline semantics (unchanged from revision 3, mapped to the provider)

1. Admission: `remaining = deadline_unix_ms − now`; `≤ 0` → `expired`;
   `> 4_294_967_295` → `{:error, {:invalid_spec, :deadline_too_far}}`; a
   monotonic target is stored; the wall clock is not read again.
2. Queued: one timer per entry for `min(queue_timeout_ms, target − now)`;
   fired with `now ≥ target` → `expired`, else `rejected{queue_timeout}`;
   equal instants → `expired`; stale generations ignored.
3. Dispatch: `remaining = min(target − now, max_run_ms)`; `≤ 0` → `expired`;
   else `exec:run(…, [{timeout, remaining} …])`. The provider's watchdog is
   the deadline; queue residence can only shorten it.
4. `max_run_ms` alone: target set at dispatch; queue bounded by
   `queue_timeout_ms` only.
5. Every BEAM timer is one `Process.send_after` below the OTP bound; Config
   rejects larger values; the owner also arms a **safety timer** at
   `remaining + grace_s·1000 + observe_timeout_ms` after which a missing DOWN
   yields `unknown{reason: :no_exit_notification}` (row T20).

### Outputs (Adapter result schema)

| status | fields | meaning |
| --- | --- | --- |
| `completed` | `exit_code` (0..255; 128+signal for a self-ended child), `output`, `truncated`, `leftovers: :none \| :reaped` | leader exited; `:reaped` = members were listed after DOWN and the provider's at-exit TERM emptied the group within `observe_timeout_ms` |
| `rejected` | `reason: :queue_full \| :queue_timeout \| :spawn_failed \| :cancelled` | nothing dispatched (A1) |
| `expired` | `deadline_unix_ms` | deadline before dispatch (A4) |
| `terminated` | `cause: :deadline \| :cancel \| :caller_down \| :owner_exit`, `stage: :term \| :kill \| :unobserved`, `signal: :sigterm \| :sigkill \| nil`, `exit_code: nil`, `output`, `truncated` | group observed empty after the provider's staged termination; `stage` is `:term`/`:kill` exactly when the DOWN status carried `sigterm`/`sigkill` (deadline path); `:unobserved` when the provider masked the status (cancel, owner death; A8) |
| `unknown` | `reason: :observation_failed \| :group_alive \| :no_exit_notification \| :port_closed`, `pgid`, `members`, `output`, `truncated`, `exit_code` | cleanup or outcome not established (A6); the result names the group and the last listing |

`stage: :none` (A5) does not occur with this provider: the provider always
sends at least TERM when it terminates; a group already empty at the deadline
means the leader has exited, which is `completed`.

`to_delivery_result(result, request)` → `{:ok, envelope_map, result}`; rows as

### Processes and ownership (observation 1)

| Process | Owns | Links / monitors |
| --- | --- | --- |
| **`exec` server + `exec-port`** (erlexec application; supervisor-level, outside the Piece) | the OS Port, every child's registration (written by the forking process itself), the deadline watchdog, staged signals, reaping, `finalize` on EOF | links to owners that pass `link` |
| **Adapter** (`Elzoo.OsProcess`, GenServer) | validation, admission counter, FIFO + timers, `from` of every submitter, single reply point, dispatch, owner registry `ref → {owner, os_pid}` | monitors owners and submitters |
| **Owner** (`Elzoo.OsProcess.Owner`, one GenServer per run under a `DynamicSupervisor`, `restart: :temporary`, `trap_exit`) | `exec:run` with `[{group,0}, kill_group, link, monitor, stdout, stderr, {timeout, remaining}, {kill_timeout, grace_s}, {env, …}, {cd, …}]`; bounded output; safety timer; the post-exit `pgrep` observation; the result | linked to the erlexec proxy (provider cleanup on owner death); traps exits so the proxy's exit does not kill it |

There is **no `Port.connect`, no Port in the Piece, no BEAM-side registration
gap**: the registration that protects the child is written by the process that
forks it. The owner reports `{ref, os_pid}` to the Adapter after `exec:run`
returns; an owner death before that report still triggers the provider's
owner-death stop (link) and the deadline watchdog bounds the child regardless.
