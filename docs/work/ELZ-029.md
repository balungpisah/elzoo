## Contract reading

One Adapter instance runs one external OS command per request with bounded
concurrency, an absolute deadline, group-scoped staged termination and an
**observed** outcome. Elzoo owns the admission/queue state, the termination
state machine, the watchdog handoff and the result schema. Signal delivery and
group semantics are OS behaviour. It is not security isolation: no sandbox,
container, seccomp, path confinement, network isolation, shell parsing or
remote execution. No Elixir SDK, no Jido copy (`jido_shell`/`jido_workspace`
are comparison input only, rejected as dependencies by the record).

### Provider and host tools (reuse check)

- **OTP Port** at OTP 29.1.2 / Elixir 1.20.4 is the selected provider; no
  process library, no SDK, no Jido copy. Pinned implementation observations
  (not documented API promises): the Port child is a process-group and session
  leader (`setsid()` in `erl_child_setup.c`); `exit_status` arrives after exit
  **and** EOF on the merged output pipe and then OTP closes the Port itself; a
  signalled child reports `128 + signal`.
- **Documented OTP contracts relied on** ([`port_connect/2`](https://www.erlang.org/doc/apps/erts/erlang.html#port_connect/2),
  `open_port/2`, `monitor/2` for ports): after `Port.connect(port, pid)` the
  new process is the port owner **and is linked to the port, while the old
  link stays**; an abnormal exit of any linked process closes the port; a
  closing port sends exit signals to its linked processes. Probe 1 on the
  pinned OTP confirmed: links `[adapter, collector]` after connect; killing the
  collector closed the port; the trapping Adapter received
  `{:EXIT, port, :killed}`; the child survived (no watchdog).
- **In-group watchdog wrapper.** The command runs behind a constant POSIX
  `sh` script executed as `/bin/sh -c SCRIPT elzoo-wrapper TOKEN GRACE_S exe
  args…`; the command is `"$@"`, never parsed (no shell parsing of caller
  data). The wrapper `W` (pid = pgid): starts the command `C` in the
  background (POSIX: a background job in a non-interactive shell has stdin
  `/dev/null`), then ignores TERM/HUP/INT, then starts the watchdog `S`
  (`exec /bin/sh -c '…' elzoo-anchor-TOKEN PGID GRACE_S`, stdout/stderr
  closed, stdin = the Port pipe, TERM ignored), waits for `C` and exits with
  `C`'s status. `S` blocks on `read` until **EOF on the Port pipe**, which
  happens exactly when the Port is closed for any reason (normal `exit_status`
  close, collector/Adapter/VM death, deliberate close); then `S` sends TERM to
  the group, sleeps `GRACE_S` seconds, sends KILL to the group (shell
  builtins, independent of the `kill`/`pgrep` utilities) and dies with it.
  Probe 2 on this macOS: normal exit 7 → `exit_status` 7 and the group empty
  within 300 ms; `sleep 30` + deliberate `Port.close` → group empty within 2 s;
  TERM to the group → `exit_status` 143, anchors survive; TERM-ignoring
  command → survives TERM, dies on KILL, `exit_status` 137; lingering member
  with closed stdout → `exit_status` 0, group empty within 2.5 s after close.
- **`pgrep`** is the group observation: `pgrep -g PGID` lists members (exit 0
  listed, 1 none, 2 usage error, 3 fatal error — only exit 1 is "empty"; 2/3
  are **observation failed**); `pgrep -g PGID -f elzoo-anchor-TOKEN` lists
  the watchdog `S`; `pgrep -P PID` lists children. `pgrep` output is data from
  the process table, independent of `kill`.
- **`kill -s TERM|KILL -- -PGID`** sends a group signal. Its exit status is
  recorded as the **request outcome** (`:sent` = utility exit 0, `:failed`
  otherwise) and is never used as evidence of delivery or death.
- `/bin/sh`, `kill` and `pgrep` are declared Needs (A7, A7′), located at
  Adapter start (`System.find_executable/1` or explicit `kill_path`/`pgrep_path`
  for fault injection); absence fails `start_link` with
  `{:error, {:tool_unavailable, name}}`. Their exact behaviour is observed on
  macOS locally and on Ubuntu in CI; no other platform is claimed.

### Group identity and signal safety (observation 2)

Two **anchors** belong to every run: `W` (pid = pgid, alive while `C` runs)
and `S` (alive until EOF on the Port pipe or KILL). A process-group ID cannot
be reallocated while any member exists (Linux: the `struct pid` stays
referenced through `PIDTYPE_PGID`; XNU/BSD: `fork1` skips PIDs in use as a
PGID or SID — OS implementation observations, declared as assumptions). Rules:

1. **The Adapter sends a signal only while the Port is open** (deadline or
   cancellation). While the Port is open, `S` has not seen EOF and is alive
   unless an external actor killed it, so the group is the original one.
2. **Every signal is preceded by an observation that lists at least one
   anchor** (`W` by pid, or `S` by marker). No anchor listed → no signal →
   `unknown{reason: :anchor_lost}` (the only way to reach it is an external
   kill of both anchors; declared residual). Absence of an "empty" observation
   is **never** used as evidence of ownership.
3. **KILL is sent only after an observation that lists the anchor and at
   least one non-anchor member** after the full grace (A5/A6; live invariant
   "escalates only if the group is still alive").
4. **After the Port is closed the Adapter sends no signal.** Cleanup after
   closure belongs to `S` (observation 4); the Adapter only observes.
5. Check-to-signal gap: a signal can hit a reused group only if both anchors
   die (external actor) and the PID space wraps to the same number inside a
   few milliseconds. Declared, not relied on for correctness of any claim; the
   result never claims more than its observations.

### Inputs

`Elzoo.OsProcess.start_link(opts)` — one Adapter instance = one slot pool with
its own collectors and watchdogs. Config is fixed at construction; no hot reconfiguration.

| `queue_timeout_ms` | positive integer, required | maximum queue residence |

| `reap_timeout_ms` | positive integer, default 5000 | bounded wait for the group to become empty after the Adapter's KILL request, and after Port closure in addition to `watchdog_grace_s` (observation every 50 ms) |
| `max_output_bytes` | positive integer, default 1 MiB | retained output bound |
| `kill_path`, `pgrep_path` | absolute paths, default located | host tools |
| `now_unix_ms` | zero-arity fun, default `System.os_time(:millisecond)` | injected wall clock for tests |
| `name` | optional | |

Per request (`submit/3`; `run/3` = submit + await):

| Field | Type | Meaning |
| --- | --- | --- |
| `spec.executable` | absolute path to a regular file with an execute bit (checked at dispatch, else `rejected{spawn_failed}`) | passed as `$1` to the constant wrapper; never parsed; no PATH search |
| `spec.args` | list of binaries | |
| `spec.cwd` | absolute path or nil | Port `cd` |
| `spec.env` | `%{inherit: [name], set: [{name, value}]}`, default empty | child environment = inherited names present in the VM environment + set names; **every other VM variable is unset** for the child (Port `env` with `false` for each) |

synchronously (caller error; nothing admitted). stdin is the Port pipe and
never carries data (declared limit). stderr is always merged into the bounded
output (`:stderr_to_stdout`); no `:inherit` option (finding 9).

### Deadline semantics (finding 6, G5)

1. At **admission** the Adapter reads `now_unix_ms` once and computes
   `remaining = deadline_unix_ms - now`. `remaining <= 0` → result
   `expired` immediately (`timed_out/not_dispatched`). `remaining` larger than
   the OTP timer bound (4_294_967_295 ms) → `{:error, {:invalid_spec,
   :deadline_too_far}}`. The deadline becomes a **local monotonic target**
   `target = monotonic_now + remaining`; wall clock is not read again.
2. **Queued**: one timer per entry armed for
   `min(queue_timeout_ms, target - monotonic_now)`. When it fires: if
   `monotonic_now >= target` → `expired`; else → `rejected{queue_timeout}`.
   Equal instants resolve to `expired` (the deadline is the caller's law, the
   queue timeout is Adapter policy). Each timer message carries the run ref
   and a generation; a late message for a dispatched or finished ref is ignored.
3. **Dispatch**: recompute `remaining = target - monotonic_now`; `<= 0` →
   `expired` (not dispatched, slot released). Otherwise spawn and arm the
   collector's deadline timer for `min(remaining, max_run_ms)`. Queue residence
   can only shorten the run; it never restarts the deadline. Test: a request
   with `deadline_unix_ms = now + 300` queued behind a 500 ms command ends
   `expired`, never `completed`.
4. A deadline timer that fires after the Port reported exit+EOF is ignored
   (stale generation). A deadline during a running termination (cancel) does
   not start a second sequence (at-most-once).
5. **Bounds.** Every timer (`queue`, `deadline`, `grace`, reap poll) is a
   single `Process.send_after` below the OTP bound 4_294_967_295 ms; Config
   validation rejects larger values (`{:error, {:invalid_config, field}}`),
   and `max_run_ms`/`remaining` are checked the same way. Timer messages carry
   `{ref, generation}`; the collector ignores any message whose generation is
   not its current one.

### Outputs (Adapter result schema)

Atom-keyed maps delivered as `{Elzoo.OsProcess, ref, result}` to the
submitter (or returned by `run/3` as `{:ok, result}`). Rejections are also
delivered this way: `submit/3` returns `{:ok, ref}` as soon as the request is
accepted for admission, so an asynchronous spawn failure is a normal result.

| status | fields | meaning |
| --- | --- | --- |
| `completed` | `exit_code` (0..255, incl. 128+signal), `output`, `truncated`, `leftovers: :none \| :reaped` | wrapper exited with the command's status and EOF reached; any exit code; `leftovers: :reaped` means non-anchor members were still listed after `exit_status`, the watchdog's post-closure cleanup ran and the Adapter then **observed the group empty** |
| `rejected` | `reason: :queue_full \| :queue_timeout \| :spawn_failed \| :cancelled` | nothing dispatched (A1) |
| `expired` | `deadline_unix_ms` | deadline passed before dispatch (A4) |
| `terminated` | `cause: :deadline \| :cancel \| :caller_down \| :collector_exit`, `stage: :none \| :term \| :kill`, `requests: [{:term \| :kill, :sent \| :failed}]`, `cleanup: :adapter \| :watchdog`, `exit_code` (int or nil), `output`, `truncated` | the group was **observed empty** by the Adapter after the sequence; `stage` = highest signal whose request the utility accepted (`:sent`); `requests` lists every request with its utility outcome; `exit_code` only when the Port delivered it (A2, A3, A5) |
| `unknown` | `reason: :observation_failed \| :signal_failed \| :anchor_lost \| :group_alive`, `stage`, `requests`, `pgid`, `members: [pid]` (last listing or `[]`), `exit_code`, `output`, `truncated` | the Adapter could not establish cleanup (A6); the result names the group and the last observed members for the operator; see "Cleanup owner after unknown" |

`output` in `terminated`/`unknown` is the bounded bytes collected before
termination; no result ever contains the command line, environment or an
exception message.

### Delivery-result mapping and stage sidecar (finding 4, G5)

`Elzoo.OsProcess.to_delivery_result(result, request)` returns
`{:ok, delivery_result_map, result}`: the first element is an exact
`core/envelope` version-1 map validated by `Elzoo.Envelope.validate_result/1`;
the second is the unchanged Adapter result (the **sidecar** carrying the stage,
exit code and cause). `request` must supply `message_id`; `correlation_id`
falls back to `message_id`; `attempt_id` and `deadline_unix_ms` are echoed when
present. The shared map gains no key.

| Adapter result | outcome / dispatch | error_class / value |
| --- | --- | --- |
| `completed` (any exit code) | completed / dispatched | `value` = `%{"exit_code", "output", "truncated"}`, `value_schema_id` `elzoo/os-process-completed`, version 1 |
| `rejected{queue_full \| queue_timeout}` | rejected / not_dispatched | `unavailable` |
| `rejected{spawn_failed}` | rejected / not_dispatched | `permanent` |
| `rejected{cancelled}` | rejected / not_dispatched | `permanent` |
| `expired` | timed_out / not_dispatched | `unclassified` |
| `terminated{cause: :deadline}` | timed_out / dispatched | `unclassified` (A2) |
| `terminated{cause: :cancel \| :caller_down \| :collector_exit}` | failed / dispatched | `unclassified` (A3) |
| `unknown` | unknown / dispatched | `unclassified` |

Tests check every row with `validate_result/1`, the correlation fallback, the
echo of `attempt_id`/`deadline_unix_ms`, and separately the sidecar fields.
`group_cleanup` is not in the completed `value` (it is cleanup metadata in the
sidecar); `value` carries no payload beyond the three keys.

### Termination state machine (pure Elixir `Elzoo.OsProcess.Termination`; observations 2 and 3)

Pure `step(state, observation) -> {actions, state}`. Observations:
`:begin`, `{:group, members, anchors}` (two listings: `pgrep -g` and
`pgrep -g -f marker`, plus the known pgid for `W`), `{:group, :failed}`,
`{:request, :term | :kill, :sent | :failed}`, `:grace_elapsed`, `:port_exit`,
`:poll_tick`, `:reap_elapsed`. `leftovers = members − anchors`,
`anchored? = pgid ∈ members or marker pids ≠ []`.

1. `begin → observe`. `{:group, _, _}` with `anchored? and leftovers == []`
   → done `terminated{stage: :none, requests: []}` **after** the Port is closed
   and the post-closure observation confirms empty (rule 7). `not anchored?`
   → done `unknown{reason: :anchor_lost}` (no signal). `{:group, :failed}` →
   one retry after 100 ms; second failure → done `unknown{reason:
   :observation_failed}` (no signal; the watchdog cleans after closure).
2. `anchored? and leftovers ≠ []` → request TERM. `{:request, :term, :sent}`
   → `stage: :term`. `{:request, :term, :failed}` → stage stays `:none`,
   retry the request once; second failure → done `unknown{reason:
   :signal_failed}` (close the Port; the watchdog's builtin `kill` cleans).
   In both cases the full `grace_ms` timer is armed only after a `:sent`.
3. **Grace is never shortened for escalation.** During `grace`, `:port_exit`
   triggers an early observation; `leftovers == []` → leave the machine (the
   Port is already closed by OTP; proceed to rule 7); otherwise stay in
   `grace` until `:grace_elapsed`.
4. After `:grace_elapsed`: observe. `leftovers == []` → rule 7 with `stage:
   :term`. `anchored? and leftovers ≠ []` → request KILL → `{:request,
   :kill, :sent}` → `stage: :kill`; `:failed` → retry once, then
   `unknown{reason: :signal_failed}`. `not anchored?` → `unknown{reason:
   :anchor_lost}`. `{:group, :failed}` twice → `unknown{reason:
   :observation_failed}`.
5. After a KILL `:sent`: observe every 50 ms; the group is expected to become
   **entirely empty** (the anchors die with the group). `members == []` →
   rule 7 with `stage: :kill`. `:reap_elapsed` with members listed → done
   `unknown{reason: :group_alive, members}`.
6. At most one sequence per run: a second trigger (duplicate cancel, deadline
   during cancellation, caller death during either) only records the first
   cause and returns `{:ok, :already_requested}`.
7. **Terminal observation.** Every `terminated` result is produced only after
   (a) the Port is closed (by OTP after `exit_status`, or by the Adapter) and
   (b) `pgrep -g PGID` returned exit 1 (empty) within `watchdog_grace_s · 1000
   + reap_timeout_ms`. The watchdog's own TERM/KILL after closure are not the
   Adapter's requests and never appear in `requests`; `cleanup: :watchdog`
   marks that the final emptiness followed the watchdog's cleanup (members
   were still listed at closure), `cleanup: :adapter` that the group was
   already empty except the anchors when the Port closed. Members still listed
   at the bound → `unknown{reason: :group_alive}`.

What `stage` claims and does not claim (observation 3): `stage` is the highest
signal whose `kill` request the utility accepted; `requests` keeps every
request outcome; `terminated` additionally claims one fact — the group was
observed empty afterwards. Nothing claims that a request caused an exit, that
a signal was delivered, or distinguishes natural exit from another actor's
signal. Injection tests cover failed TERM, failed KILL, and natural exit during
grace (stage stays `:term`, no KILL request, `requests == [{:term, :sent}]`).

### Processes, ownership and the handoff (observation 1)

| Process | Owns | Links / monitors |
| --- | --- | --- |
| **Adapter** (`Elzoo.OsProcess`, GenServer, `trap_exit`) | validation, admission counter (`Elzoo.Backpressure`), bounded FIFO and its timers, `from` of every submitter, the single reply point, **`Port.open` for every run**, the run registry `ref → {pgid, port, collector, requests}`, the post-closure verification | linked to every Port it opened (stays linked after handover); monitors every collector and every submitter |
| **Collector** (plain process per run, spawned by the Adapter) | bounded output, deadline timer, the termination machine while the Port is open, signal requests (reported to the Adapter before and after each request), final result | becomes Port owner and is linked to the Port by `Port.connect/2`; monitors the Port |
| **Watchdog `S`** (OS process inside the group) | cleanup after Port closure (TERM, sleep `watchdog_grace_s`, KILL), independent of every BEAM process and of the `kill`/`pgrep` utilities | none (OS) |

Spawn: in one `handle_call`/continue the Adapter validates the executable and
cwd, opens the Port (catching `ErlangError` → `rejected{spawn_failed}`), reads
`os_pid` (= pgid), stores `{ref, pgid, port}`, spawns and monitors the
collector, calls `Port.connect(port, collector)` and forwards every `{port, _}`
message already in its mailbox. No BEAM process other than the Adapter exists
between `Port.open` and registration; an Adapter death in that gap closes the
Port (link) and the watchdog cleans the group.

Signal accounting protocol: the collector sends `{:request, ref, stage,
:requesting}` to the Adapter **before** calling the `kill` utility and
`{:request, ref, stage, :sent | :failed}` **after**. The Adapter records both.
On collector death the Adapter sends no signal itself (rule 4: the Port is
closed by the collector's exit); the records only decide what the result may
claim: a stage with `:requesting` but no outcome is reported in `requests` as
`{stage, :unknown_outcome}` and does not advance `stage`.

Failure matrix (every BEAM-side death closes the Port → watchdog cleanup):

| Dies | Port | Group cleanup | Adapter verification and reply |
| --- | --- | --- | --- |
| Collector (any reason) while running | closed by OTP (owner link) | watchdog: TERM, `watchdog_grace_s`, KILL | DOWN + `{:EXIT, port, _}` → observe until empty (bound `watchdog_grace_s·1000 + reap_timeout_ms`) → `terminated{cause: :collector_exit, stage/requests from records, cleanup: :watchdog, exit_code: nil}` or `unknown{group_alive}` |
| Collector after sending `{:finished}` (normal exit) | already closed | none needed | reply with the collector's result |
| Submitter while queued | — | — | entry removed, timer cancelled, no reply |
| Submitter while running | open | collector runs the machine (cause `:caller_down`) | result dropped |
| Adapter | all its Ports close (links) | every run's watchdog | none (callers' calls exit with the Adapter's reason); test observes every group empty within `watchdog_grace_s + 1 s` |
| Adapter and collector together | closed | watchdog | none |
| Whole VM | fds close | watchdog (EOF) | none; this is a distinct, now covered case, not a limit |
| Watchdog `S` killed by an external actor while `W` lives | open | Adapter still anchored on `W`; after `W` exits, post-closure cleanup has no owner | if no anchor is listed before a signal → `unknown{anchor_lost}`; leftovers are then outside the bounded-lifetime guarantee (declared residual) |
| Descendant that calls `setsid` | — | not in the group | invisible: declared residual, tested with a nested `elixir` fixture and cleaned by the test |

Normal `GenServer.stop(adapter)` takes the Adapter-death row for running
commands (terminated by watchdogs, not drained; Control contract says so).

### Cleanup owner after `unknown` and bounded lifetime (observation 4)

| `unknown` reason | What was attempted | Owner of further cleanup | Bound |
| --- | --- | --- | --- |
| `observation_failed` | no signal (identity unprovable) | the Adapter closes the Port → watchdog `S` (TERM, sleep, KILL via builtins) | `watchdog_grace_s` + signal delivery |
| `signal_failed` | TERM or KILL request failed twice | same (watchdog uses the shell builtin, not the utility) | same |
| `anchor_lost` | no signal (anchors gone) | none: `S` is dead and `W` is dead; `C` leftovers continue until they finish | **not bounded by the Adapter**: declared residual caused by an external kill of both anchors |
| `group_alive` | the Adapter's KILL `:sent` and/or the watchdog's KILL, members still listed at the bound | the OS: processes that survive KILL are in uninterruptible state or are zombies waiting for PID 1 | OS reaping, not controllable; the result carries `pgid` and `members` for inspection |

Every `unknown` result closes the Port before it is returned, so the watchdog
has run or is running; the Adapter waits the full bound once and reports what
it observed. `unknown` never relaxes the acceptance tests: those tests assert
observed emptiness for every path where a BEAM-side or watchdog cleanup exists.

### Completion condition (finding 9, Q4)

`exit_status` arrives after `W` exits **and** the merged output pipe reaches
EOF; OTP then closes the Port, so the watchdog `S` starts its cleanup at the
same moment. The Adapter does not poll the leader. Cases:

1. `W` exits, no non-anchor member holds the pipe → `exit_status` at once →
   observe: `leftovers == []` → `completed{leftovers: :none}` returned
   immediately (`S` ends its own cycle within `watchdog_grace_s`; the test
   asserts the group empty within `watchdog_grace_s + 1 s`). `leftovers ≠ []`
   (a member that closed stdout) → observe until empty (bound as rule 7) →
   `completed{leftovers: :reaped}`, or `unknown{group_alive}`.
2. `W` exits, a **member** holds the pipe → no `exit_status` until the
   deadline → machine (TERM … KILL) → EOF → `exit_status` = `W`'s status →
   `terminated{cause: :deadline, exit_code: <W's>}`.
3. `W` exits, a process that **left the group** holds the pipe → at the
   deadline `leftovers == []` → the Adapter closes the Port (no `exit_status`
   is delivered) → `terminated{stage: :none, exit_code: nil}`; the holder is a
   residual.

The coordinator accepts this consequence or asks for leader polling (one
`pgrep` per interval); the author does not propose polling.

### Operational declarations for piece.json (finding 8, G7)

- **Telemetry: `planned`.** No event, log or measurement is emitted by the
  Adapter or the collector. A future event family must exclude the
  command line, arguments, environment and output. Test: a run with a
  secret-looking argument under `ExUnit.CaptureLog` produces no log output
  containing it.
- **Config: `supported`.** Construction-time `max_concurrent`, `queue_limit`,
  `queue_timeout_ms`, `grace_ms`, `reap_timeout_ms`, `max_output_bytes`, tool
  paths; per-call `deadline_unix_ms`/`max_run_ms`, `cwd`, `env` allowlist. No
  hot update; a change needs a new Adapter instance. Evidence: tests exercise
  every setting, including the rejection of out-of-bound values
  (`test/elzoo/os_process_test.exs`). Crash behaviour: a collector crash yields
  `terminated{cause: :collector_exit}` after verification; an Adapter crash
  terminates every run through the watchdogs and callers' calls exit.
- **Control: `supported`** for `cancel(adapter, ref)`. Authority: holding the
  run `ref` (a capability handed to the submitter; the Adapter performs no
  authentication). Precondition: the ref is queued or running. Operation
  identity: the ref. Results: queued → `{:ok, :requested}` and the submitter
  receives `rejected{cancelled}`; running → `{:ok, :requested}` and the
  submitter later receives `terminated{cause: :cancel}` or `unknown`; already
  terminating → `{:ok, :already_requested}` without a second signal sequence;
  finished or foreign → `{:error, :unknown_run}`. `{:ok, :requested}` is
  acceptance, not application; application is observed in the final result.
  No pause, no drain, no business-level stop guarantee; Adapter stop
  terminates running commands. Evidence: cancellation tests.

### Non-goals, limits and residuals (declared)

Security isolation, shell parsing, path confinement, containers, seccomp,
filesystem confinement, remote execution, cross-host claims, stdin data,
separate stderr capture, telemetry, durable receipts, retry policy. Whole-VM
death leaves children (OTP contract). A process that calls `setsid` leaves the
group and is invisible. A group that survives KILL within `reap_timeout_ms`
yields `unknown`. `kill`'s and `pgrep`'s exact behaviour is observed on macOS
(BSD utilities) locally and on Ubuntu (procps-ng) in CI; no other platform is
claimed. Output truncation drops bytes beyond the bound silently except for
the `truncated` flag. Tests are finite observations on the named OSes, not
proofs of universal cleanup.
