## Contract reading

One Adapter value (`Elzoo.ObjectStore` configuration) binds one S3-compatible endpoint and one bucket
under a caller-chosen backing-store identity. Each call performs exactly one operation — `put`, `get`,
`head`, `list`, `delete` — as at most one HTTP request (plus one disambiguating bucket `HEAD`, see R4),
or computes a presigned URL locally (`presign`, no I/O). Elzoo owns request translation, local
validation before dispatch, the deadline, the bounded body and list, the typed outcome mapping, the
unknown-outcome rule and the ELZ-011 delivery-result mapping. S3 semantics, MinIO durability, SigV4
signing and HTTP transport are upstream (`req_s3`, `req`, Finch/Mint, MinIO).

### Inputs

Construction (`Elzoo.ObjectStore.new/1`, a validated struct; no process, no application, no global state):

| Setting | Type / default | Meaning |
| --- | --- | --- |
| `store_id` | nonempty UTF-8 ≤ 128 bytes, required | backing-store identity echoed in every result |
| `endpoint` | `http`/`https` URL without user info, query or fragment, required | path-style S3 endpoint; passed explicitly so `req_s3` never consults `AWS_ENDPOINT_URL_S3` |
| `bucket` | S3 bucket name (3–63, lowercase, digits, `-`, `.`), required | the one bucket this binding may touch |
| `region` | nonempty string, required | SigV4 region; passed explicitly so `AWS_REGION` is never read |
| `credentials` | `{module, function, args}` or zero-arity function returning `{:ok, %{access_key_id: binary, secret_access_key: binary}}`, required | the injected credential Need: a **reference** resolved inside the request process at each call, never stored in the struct as a value |
| `max_object_bytes` | positive integer ≤ 5 GiB, default 64 MiB | bound for a put body (bounded or streamed) and for a get body read into memory |
| `max_page_size` | 1..1000, default 1000; per-call `page_size` default 100 | list bound |
| `presign_default_s` / `presign_max_s` | 1..604 800, defaults 900 and 3600 | presign expiry |
| `default_deadline_ms` | 1..4 294 967 295, default 30 000 | used when a call gives no deadline |
| `finch` | optional Finch pool name | default Req's own pool |

`inspect/1` of the struct prints `store_id`, endpoint host, bucket and region only; the credential
reference is shown as `#credentials<redacted>`.

Per call: `key` (UTF-8, 1..1024 bytes, no NUL/control bytes, no empty, `.` or `..` path segment — refused
`invalid_key` before dispatch); `put` body as a binary or as `{:stream, enumerable, length}` with a
required `content_sha256` (32 bytes) for streams and an optional one for binaries (checked against the
bytes before dispatch); `content_type` (declared, default `application/octet-stream`); optional
`if_absent: true` (`If-None-Match: *`); `deadline_ms` (relative budget) or `deadline_unix_ms` (absolute,
with an injected clock); `list` takes `prefix`, `page_size`, `continuation`; `presign` takes `method`
(`:get` or `:put`) and `expires_s`. Optional `declaration`: an ELZ-011 `Elzoo.Effect` declaration that
must validate, name capability `integration/object-store` and the called operation, else
`{:error, :declaration}` before dispatch.

### Outputs (finite table; every result carries `store`, `bucket`, `key` or `prefix`, `operation`)

| Result | When |
| --- | --- |
| `committed{etag, bytes, sha256}` | put: HTTP 200 **and** the response `x-amz-checksum-sha256` equals the value sent (always sent: computed for a binary, caller-supplied for a stream); delete: HTTP 204 (R2) |
| `found{metadata, body}` | get: 200, body ≤ bound, and when the object has a stored SHA-256 (`x-amz-checksum-mode: ENABLED`) it equals the SHA-256 of the received bytes; `metadata` = etag, size, content type, last modified, sha256 or nil |
| `found{metadata}` | head: 200 |
| `absent` | get/head: 404 with error code `NoSuchKey` only |
| `listed{keys, truncated, continuation}` | list: 200; `keys` ≤ page size; `continuation` = `NextContinuationToken` when `truncated` |
| `refused{denied}` | 403 (`AccessDenied`, `SignatureDoesNotMatch`, `InvalidAccessKeyId`, expired) |
| `refused{no_such_bucket}` | 404 `NoSuchBucket` (never `absent`) |
| `refused{precondition_failed}` | 412 (`if_absent` on an existing key) |
| `refused{too_large}` | body or declared stream length > `max_object_bytes` **before dispatch**; 400 `EntityTooLarge`; get whose length exceeds the bound (read stopped) |
| `refused{invalid_key}` | local key check before dispatch; 400 `XMinioInvalidResourceName`/`KeyTooLongError` |
| `refused{checksum_mismatch}` | **proposed (A1)**: 400 `XAmzContentChecksumMismatch`/`BadDigest`, or a caller `content_sha256` that does not match a binary body before dispatch |
| `refused{unavailable}` | **proposed (A2)**: connection refused / DNS failure before a connection existed (no request byte sent) |
| `unknown{reason}` | anything else after dispatch: deadline reached (`deadline`), connection closed or reset mid-request (`transport`), 5xx (`server_error`), 200 without the expected checksum (`unverified`), unexpected status or unparsable body (`unexpected`), get body SHA-256 mismatch (`integrity`) |

Invariants (each with a named scenario): every operation names bucket, key and store; a put is
`committed` only with the matching echoed checksum; a deadline after dispatch is `unknown`, never
`absent` or `committed`; a missing or denied bucket is never `absent`; a list is bounded and its
continuation explicit; no hidden local/remote interchange (one endpoint, no fallback, no cache); the
Adapter never retries (`retry: false`): an `unknown` write is reconciled by an explicit `head`, never
re-sent by the Adapter.

`to_delivery_result(result, request)` maps to the ELZ-011 `Elzoo.Envelope` result (validated by
`Elzoo.Envelope.validate_result/1`, as in `runtime/os-isolation`): committed/found/absent/listed →
`completed/dispatched` with a value schema `elzoo/object-store-*`; `refused{invalid_key | too_large |
checksum_mismatch}` before dispatch → `rejected/not_dispatched/permanent`; `refused{unavailable}` →
`rejected/not_dispatched/unavailable`; refusals the provider returned → `failed/dispatched/permanent`
(`denied`, `no_such_bucket`, `precondition_failed`, provider `too_large`/`invalid_key`/`checksum_mismatch`);
`unknown{deadline}` → `timed_out/unknown/unclassified`; other unknowns → `unknown/dispatched/unclassified`.

### Readings that need the coordinator's confirmation (R) and proposed amendments (A)

- **R1 Deadline.** The call runs in a monitored process started with `spawn_monitor` (no link, no
  proc_lib crash report); the caller waits until the deadline and then kills it with `:kill`. Req's
  `receive_timeout` and connect timeout are set to the remaining budget as an inner bound. The request
  process catches every exception and returns only a sanitized reason atom, so no Req structure (which
  holds the resolved credential) ever leaves it.
- **R2 Delete.** S3 `DELETE` is idempotent: 204 for an existing and for a missing key (probe P9/P9c).
  The Adapter reports `committed{etag: nil, bytes: 0, sha256: nil}`, meaning "no object remains at
  the key after the request", never "an object existed". The task's "a write is committed only when the
  provider response carries the expected ETag or checksum" cannot hold for delete; see A3.
- **R3 Presign is local.** `presign` performs no I/O and returns `presigned{url, method, expires_at}`.
  By S3 design the URL's `X-Amz-Credential` query parameter contains the **access key ID** (probe P8:
  present; the secret: absent). The URL is a bearer capability; the result struct's `inspect` redacts the
  query; the Adapter never logs it. See A4.
- **R4 HEAD 404 disambiguation.** A HEAD 404 has no body. MinIO adds `x-minio-error-code`
  (`NoSuchKey`/`NoSuchBucket`, probe P4/P4b). When the header is absent (other S3 servers) the Adapter
  issues one bucket `HEAD` before answering `absent`; a non-200 there gives `refused{no_such_bucket}` or
  the mapped refusal/unknown. Only MinIO is tested.
- **R5 Streaming body.** `{:stream, enumerable, length}` is the bounded body stream of the task
  (`delivery/data-stream` is deferred; its boundary is not redefined). Req signs a stream with
  `UNSIGNED-PAYLOAD`, so integrity comes from `x-amz-checksum-sha256`, which the server verifies (probe
  P10b: 400, object absent afterwards). A stream that yields more bytes than `length` is cut by the
  Adapter's counting wrapper and reported `unknown{transport}`.
- **R6 Versioning and retention.** Unversioned bucket assumed; a put to an existing key overwrites
  unless `if_absent`. No versioning, lifecycle, retention, ACL or object-lock request is ever sent.

Proposed exact amendments (the main coordinator decides on the issue):

- **A1/A2** (one edit; until decided, a provider checksum rejection is reported
  `refused{precondition_failed}` and a never-established connection `unknown{transport}`, the nearest
  current-Contract outcomes):
  - Before: "`refused{denied | no_such_bucket | precondition_failed | too_large | invalid_key}`"
  - After: "`refused{denied | no_such_bucket | precondition_failed | too_large | invalid_key |
    checksum_mismatch | unavailable}`"
  - Reason: the dangerous path "a checksum mismatch accepted" needs an honest outcome when the provider
    rejects the bytes; a connection that was never established sent no byte, a definite non-dispatch the
    ELZ-011/023 boundary can use (`rejected/not_dispatched/unavailable`) instead of a pessimistic `unknown`.
- **A3** Before: ``a write is committed only when the provider response carries the expected ETag or
  checksum;`` After: ``a put is committed only when the provider response carries the expected checksum;
  a delete is committed on the provider's 204, which states that no object remains at the key, not that
  one existed;``
- **A4** Before: ``credentials never appear in results, logs or events.`` After: ``the secret access key
  never appears in results, logs or events; the access key ID appears only inside a presigned URL, where
  S3 requires it, and the Adapter never logs or emits that URL.``

## Defaults and the first caller (closes the record's open question)

First callers: C8 upload and transform (uploaded bytes and the transform result) and C2 report artifact;
first owned consumer `state/artifact` (deferred). Neither names an object larger than a single PUT can
carry, so: **size bound** 64 MiB default per object, configurable up to 5 GiB (the S3 single-PUT limit);
**multipart not required**, `ex_aws_s3` not added (a later caller above 5 GiB needs a new Piece ID or a
reviewed extension). **Page size** default 100, maximum 1000 (the S3 maximum). **Presign expiry** default
900 s, maximum 3600 s by default configuration (S3 allows 604 800 s). **Versioning and retention**: none;
`state/artifact` owns content identity, retention and deletion policy. These defaults are proposals for
the reviewer and the coordinator.

## Operational applicability

- **Telemetry `planned`.** ELZ-052 (`runtime/telemetry`, #108) is not merged, so nothing is inherited.
  The Adapter emits no event and no log line (S11 checks it). Upstream Finch emits its own telemetry with
  the signed request headers; the `Authorization` header contains the access key ID (not the secret).
  That is upstream behaviour the Adapter cannot suppress; recorded as a limit (see Q2).
- **Config `supported`:** the construction settings above, fixed per struct value (a change is a new
  value; no hot update), and per-call `deadline_ms`, `page_size`, `expires_s`, `if_absent`,
  `content_type`; validated with bounds; evidence the tests above.
- **Control `not_applicable`:** a call-scoped Adapter with no running lifecycle; the caller's deadline is
  the only cancellation; cancelling cannot erase a dispatched write (reported `unknown`).

## ELZ-023 composition

The task names "the ELZ-023 intent record for dispatched writes" as an input. Proposal: the Adapter
does not depend on `delivery/effect-intent` (it would pull `integration/sql` and PostgreSQL into every
copy). Instead `to_delivery_result/2` gives the exact result shape a Binding's `send_effect/1` returns,
and `reconcile_put/3` (a `head` that compares the stored SHA-256 with the intended one) gives the
evidence for a Binding's `poll/1`: matching checksum → completed; `absent` → `:pending` (never
`no_effect`: an absent object after an `unknown` write is not a final no-effect certificate). A
test-only Binding module under the Piece's `test/` exercises `send_effect`/`poll` against MinIO through
the ready `Elzoo.EffectIntent` owner with its explicitly volatile Memory store. See Q1.
