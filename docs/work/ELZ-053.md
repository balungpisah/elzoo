## Contract reading

One Adapter value (`Elzoo.ObjectStore` configuration) binds one S3-compatible endpoint and one bucket
under a caller-chosen backing-store identity. Each call performs exactly one operation — `put`, `get`,
`head`, `list`, `delete` — normally as one HTTP request; `head` may issue one documented bucket-`HEAD`
disambiguation request when the provider omits an error code on a 404 (R4). `presign` computes a URL
locally (no I/O). Key-addressed operations name bucket, key and store; `list` names bucket, store and an
explicit prefix (the empty prefix allowed) (M1). Elzoo owns request translation, local
validation before dispatch, the deadline, the bounded body and list, the typed outcome mapping, the
unknown-outcome rule and the ELZ-011 delivery-result mapping. S3 semantics, MinIO durability, SigV4
signing and HTTP transport are upstream (`req_s3`, `req`, Finch/Mint, MinIO).

### Inputs

Construction (`Elzoo.ObjectStore.new/1`, a validated struct; no process, no application, no global state):

| Setting | Type / default | Meaning |
| --- | --- | --- |
| `store_id` | nonempty UTF-8 ≤ 128 bytes, required | backing-store identity echoed in every result |
| `endpoint` | `http`/`https` URL without user info, query or fragment, required | path-style S3 endpoint; passed explicitly so `req_s3` never consults `AWS_ENDPOINT_URL_S3` |
| `bucket` | S3 bucket name (3–63, lowercase, digits, `-`, `.`), required | the one bucket this binding may touch |
| `region` | nonempty string, required | SigV4 region; passed explicitly so `AWS_REGION` is never read |
| `credentials` | `{module, function, args}` or zero-arity function returning `{:ok, %{access_key_id: binary, secret_access_key: binary}}`, required | the injected credential Need: a **reference** resolved inside the request process at each call, never stored in the struct as a value; the resolved pair, endpoint and region are passed explicitly on every request and every presign (note 9) |
| `max_object_bytes` | positive integer ≤ 5 GiB, default 64 MiB | bound for a put body (bounded or streamed) and for a get body read into memory |
| `max_page_size` | 1..1000, default 1000; per-call `page_size` default 100 | list bound |
| `presign_default_s` / `presign_max_s` | 1..604 800, defaults 900 and 3600 | presign expiry |
| `default_deadline_ms` | 1..4 294 967 295, default 30 000 | used when a call gives no deadline |
| `finch` | optional Finch pool name | default Req's own pool |

`inspect/1` of the struct prints `store_id`, endpoint host, bucket and region only; the credential
reference is shown as `#credentials<redacted>`.

Per call: `key` (UTF-8, 1..1024 bytes, no NUL/control bytes, no empty, `.` or `..` path segment — refused
`invalid_key` before dispatch); `put` body as a binary or as `{:stream, enumerable, length}` with a
required `content_sha256` (32 bytes) for streams and an optional one for binaries (checked against the
bytes before dispatch); `content_type` (declared, default `application/octet-stream`); optional
`if_absent: true` (`If-None-Match: *`); `deadline_ms` (relative budget) or `deadline_unix_ms` (absolute,
with an injected clock); `list` takes `prefix` (UTF-8, 0..1024 bytes, no NUL/control bytes; required,
`""` allowed), `page_size` (1..`max_page_size`) and `continuation` (nil or nonempty printable ASCII ≤ 1024
bytes) — an invalid one is `refused{invalid_request}` before dispatch (M5); `presign` takes `method`
(`:get` or `:put`) and `expires_s`. Optional `declaration`: an ELZ-011 `Elzoo.Effect` declaration that
must validate, name capability `integration/object-store` and the called operation, else
`{:error, :declaration}` before dispatch.

### Outputs (finite table; every result carries `store`, `bucket`, `operation`, and `key` for key-addressed operations or `prefix` for `list`)

| Result | When |
| --- | --- |
| `committed{etag, bytes, sha256}` | put: HTTP 200 **and** the response `x-amz-checksum-sha256` equals the value sent (always sent: computed for a binary, caller-supplied for a stream); delete: HTTP 204 (R2) |
| `found{metadata, body}` | get: 200, body ≤ bound, and when the object has a stored SHA-256 (`x-amz-checksum-mode: ENABLED`) it equals the SHA-256 of the received bytes; `metadata` = etag, size, content type, last modified, sha256 or nil |
| `found{metadata}` | head: 200 |
| `absent` | get/head: 404 with error code `NoSuchKey` only |
| `listed{keys, truncated, continuation}` | list: 200; `keys` ≤ page size; `continuation` = `NextContinuationToken` when `truncated` |
| `refused{denied}` | 403 (`AccessDenied`, `SignatureDoesNotMatch`, `InvalidAccessKeyId`, expired) |
| `refused{no_such_bucket}` | 404 `NoSuchBucket` (never `absent`) |
| `refused{precondition_failed}` | 412 (`if_absent` on an existing key) |
| `refused{too_large}` | body or declared stream length > `max_object_bytes` **before dispatch**; 400 `EntityTooLarge`; get whose length exceeds the bound (read stopped) |
| `refused{invalid_key}` | local key check before dispatch; 400 `XMinioInvalidResourceName`/`KeyTooLongError` |
| `refused{checksum_mismatch}` | **M3**: exactly the provider codes `XAmzContentChecksumMismatch` and `BadDigest` (400), or a caller `content_sha256` that does not match a binary body before dispatch (local, tested separately) |
| `refused{invalid_request}` | **M5**: local argument check before dispatch (page size, prefix, continuation, expiry, deadline, body shape); no request is sent (no-request stub) |
| `refused{credentials_unavailable}` | the credential Need raised, exited or returned another shape; checked before any connection; the credential term is not echoed |
| `unknown{reason}` | anything else after dispatch: deadline reached (`deadline`), connection refused, closed or reset (`transport`; A2 dropped: a connect error is not a general no-send attestation), 5xx (`server_error`), 200 without the expected checksum (`unverified`), unexpected status or unparsable body (`unexpected`), get body SHA-256 mismatch (`integrity`), exception in the request process (`adapter_error`) |

Invariants (each with a named scenario): every key-addressed operation names bucket, key and store and
every list names bucket, store and prefix (M1); a put is
`committed` only with the matching echoed checksum; a deadline after dispatch is `unknown`, never
`absent` or `committed`; a missing or denied bucket is never `absent`; a list is bounded and its
continuation explicit; no hidden local/remote interchange (one endpoint, no fallback, no cache); the
Adapter never retries (`retry: false`): an `unknown` write is reconciled by an explicit `head`, never
re-sent by the Adapter.

`to_delivery_result(result, request)` maps to the ELZ-011 `Elzoo.Envelope` result (validated by
`Elzoo.Envelope.validate_result/1`, as in `runtime/os-isolation`): committed/found/absent/listed →
`completed/dispatched` with a value schema `elzoo/object-store-*`; `refused{invalid_key | too_large |
checksum_mismatch | invalid_request}` decided locally before dispatch → `rejected/not_dispatched/permanent`;
`refused{credentials_unavailable}` → `rejected/not_dispatched/unavailable`; refusals the provider returned → `failed/dispatched/permanent`
(`denied`, `no_such_bucket`, `precondition_failed`, provider `too_large`/`invalid_key`/`checksum_mismatch`);
`unknown{deadline}` → `timed_out/unknown/unclassified`; `unknown{transport | adapter_error}` →
`unknown/unknown/unclassified`; other unknowns (a response was observed) → `unknown/dispatched/unclassified`.
Every local refusal is decided before the request process opens a connection, which is what makes its
`not_dispatched` attestation honest.

### Readings that need the coordinator's confirmation (R) and proposed amendments (A)

- **R1 Deadline.** The call runs in a monitored process started with `spawn_monitor` (no link, no
  proc_lib crash report); the caller waits until the deadline and then kills it with `:kill`. Req's
  `receive_timeout` and connect timeout are set to the remaining budget as an inner bound. The request
  process catches every exception and returns only a sanitized reason atom, so no Req structure (which
  holds the resolved credential) ever leaves it.
- **R2 Delete.** S3 `DELETE` is idempotent: 204 for an existing and for a missing key (probe P9/P9c).
  The Adapter reports `committed{etag: nil, bytes: 0, sha256: nil}` on 204. That acknowledges the
  delete request, not that an object previously existed or that absence persists (concurrent writers,
  provider durability and versioning are outside this Piece; unversioned bucket assumed). See M4.
- **R3 Presign is local.** `presign` performs no I/O and returns `presigned{url, method, expires_at}`.
  By S3 design the URL's `X-Amz-Credential` query parameter contains the **access key ID** (probe P8:
  present; the secret: absent). The URL is a bearer capability; the result struct's `inspect` and every
  error redact it; the Adapter never logs or emits it. See M2.
- **R4 HEAD 404 disambiguation.** A HEAD 404 has no body. MinIO adds `x-minio-error-code`
  (`NoSuchKey`/`NoSuchBucket`, probe P4/P4b). When the header is absent (other S3 servers) the Adapter
  issues one bucket `HEAD` before answering `absent`; a non-200 there gives `refused{no_such_bucket}` or
  the mapped refusal/unknown. Only the pinned MinIO is exercised, which always sends the header, so the
  fallback path is covered by the loopback stub only and other providers' behaviour is an unverified
  assumption (should-fix 7).
- **R5 Streaming body.** `{:stream, enumerable, length}` is the bounded body stream of the task
  (`delivery/data-stream` is deferred; its boundary is not redefined). Req signs a stream with
  `UNSIGNED-PAYLOAD`, so integrity comes from `x-amz-checksum-sha256`, which the server verifies (probe
  P10b: 400, object absent afterwards). A stream that yields more bytes than `length` is cut by the
  Adapter's counting wrapper and reported `unknown{transport}`.
- **R6 Versioning and retention.** Unversioned bucket assumed; a put to an existing key overwrites
  unless `if_absent`. No versioning, lifecycle, retention, ACL or object-lock request is ever sent.

The exact amendments are in "Amendment package for main" at the end of this record.

## Defaults and the first caller (closes the record's open question)

First callers: C8 upload and transform (uploaded bytes and the transform result) and C2 report artifact;
first owned consumer `state/artifact` (deferred). Neither names an object larger than a single PUT can
carry, so: **size bound** 64 MiB default per object, configurable up to 5 GiB (the S3 single-PUT limit);
**multipart not required**, `ex_aws_s3` not added (a later caller above 5 GiB needs a new Piece ID or a
reviewed extension). **Page size** default 100, maximum 1000. **Presign expiry** default 900 s,
maximum 3600 s. These are first-caller Config defaults with tests, not universal S3 limits (the 5 GiB
single-PUT limit and the 604 800 s presign limit remain upstream). **Versioning and retention**: none;
`state/artifact` owns content identity, retention and deletion policy.

## ELZ-023 composition (rev 2: should-fix 8 and the orchestrator's direction)

The live Composition record names `delivery/effect-intent`; the dependency edge is kept (no amendment),
following the ELZ-054 pattern. The Piece ships a consumer-parameterised Binding helper:
`use Elzoo.ObjectStore.Binding, id:, operation: :put | :delete, provider_account:, recovery_grace_ms:`,
compiled through `Elzoo.EffectIntent.Binding.compile!/1` with `replay: :none` and
`revision: :forbidden`. The consumer supplies the concrete account (for example `s3://<store_id>/<bucket>`),
operation, identity and attestation context; the helper fixes the failure table:

| Adapter outcome | failure tag | outcome / dispatch / error class | no-send attested |
| --- | --- | --- | --- |
| local `invalid_key`, `too_large`, `checksum_mismatch`, `invalid_request` | same name | `rejected` / `not_dispatched` / `permanent` | yes (decided before a connection is opened) |
| `credentials_unavailable` | same | `rejected` / `not_dispatched` / `unavailable` | yes |
| provider `denied`, `no_such_bucket`, `precondition_failed`, `too_large`, `invalid_key`, `checksum_mismatch` | `provider_<name>` | `failed` / `dispatched` / `permanent` | no |
| `unknown{deadline}` | `deadline` | `timed_out` / `unknown` / `unclassified` | no |
| `unknown{transport}`, `unknown{adapter_error}` | same | `unknown` / `unknown` / `unclassified` | no |
| `unknown{server_error}`, `unknown{unverified}`, `unknown{unexpected}` | same | `unknown` / `dispatched` / `unclassified` | no |

The EffectIntent argument bound is 64 KiB, so the canonical arguments are the object reference (`key`,
`sha256`, `bytes`, `content_type`), not the body. The consumer supplies the body through the owner's
`adapter_context` (a body source returning the bytes or a bounded stream); `send_effect/1` checks the
supplied bytes against the argument SHA-256 before dispatch (a mismatch is the local `checksum_mismatch`,
attested no-send). `poll/1` calls `reconcile_put/3` (a `head` with checksum mode): matching SHA-256 → a
completed result; `absent`, or a found object with another SHA-256 → `{:pending, evidence}`; never
`:no_effect` or `:unknown_to_provider`, because absence after an unknown write is not a final no-effect
certificate. For a delete binding, `poll/1` returns `{:pending, evidence}` when the object is found and a
completed result when `absent` is observed, its value stating "absent at poll", not "deleted by this

## Implementation notes (where the code is more precise than revision 2)

- An Effect declaration that does not validate, or names another capability or operation, is
  `refused{invalid_request}` (local, before dispatch), not a separate `{:error, :declaration}`: the
  outputs list stays the single table.
- A deadline already passed (or out of range) at the call is `refused{invalid_request}` before dispatch.
- A get whose body exceeds `max_object_bytes` is `refused{too_large}` with `origin: :adapter` (decided
  after dispatch, mapped `failed/dispatched/permanent`), so no local `not_dispatched` attestation is
  claimed for it.
- A streamed body is pulled one element at a time; a failing source, a non-binary element or more bytes
  than declared stops the transfer as `unknown{transport}`. A `Req.TransportError` with reason
  `:timeout` (the inner receive timeout set to the remaining budget) is `unknown{deadline}`.
- A list error body arrives decoded by `req_s3` (a map); its `Error.Code` is read from the map.
- The credential Need is resolved inside the request process, before any connection; that is what
  makes `credentials_unavailable` an attested no-send.
- The Binding's EffectIntent identity must be `[tenant, provider_account, id, operation, ref]` with the
  Binding's own account, id and operation (EffectIntent admission checks it).
