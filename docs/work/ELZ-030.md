## Exact public schemas (B1, B4, M4, M5)

Only `Elzoo.ContextSelection.select(request, context)` is supported. All maps
use exact atom keys; all keys below are required except `updated_at`. No defaults,
coercion or normalization. Unknown fields fail closed. Identities are nonempty,
valid UTF-8 binaries compared byte-for-byte, within the fixed bounds below.
External decoders must reject duplicate object keys before lossy map conversion.

```elixir
request = %{candidates: [candidate]}
context = %{
  principal: id, tenant: id, now: unix_ms, snapshot_at: unix_ms,
  window: window, windows: [window], reservations: [{name, nonnegative_integer}],
  policy: %{
    max_age: nonnegative_ms, allow_derived: boolean,
    priority: :descending | :input, recency: :newest | :input,
    max_selected_count: 0..256, max_selected_bytes: 0..8_388_608
  },
  provenance: [node]
}
window = %{provider_id: id, model_id: id, size: nonnegative_integer,
           unit: :tokens | :bytes, estimator_id: id,
           estimator_version: positive_integer}
candidate = %{
  item_id: id, version: positive_integer, source: id, content: binary,
  estimate: nonnegative_integer, priority: integer,
  access: %{principal: id, checked_at: unix_ms, result: :allowed | :denied},
  derived_from: [ref], content_hash: nil | <<_::256>>
  # updated_at: unix_ms REQUIRED for recency :newest; optional for :input
}
ref = %{item_id: id, version: positive_integer}
node = %{
  item_id: id, version: positive_integer, tenant: id, source: id,
  content_hash: nil | <<_::256>>, derived_from: [ref], check: nil | check
}
check = %{
  item_id: id, version: positive_integer, tenant: id, source: id,
  content_hash: nil | <<_::256>>, principal: id,
  checked_at: unix_ms, result: :allowed | :denied
}
```

Everything in `context` is host-owned, never taken from a tool/model request.
This includes `now`, `snapshot_at`, every policy member, reservations, chosen
window and selected caps. `request` cannot override top-level context fields or
nested policy members; a named test attempts each one, including `max_age`,
`allow_derived`, `priority`, `recency`, `max_selected_count`, `max_selected_bytes`.
A candidate's priority is untrusted ranking data, with no authority effect;
the host controls whether it is used.

One trusted node/check store serves both direct items and non-candidate sources:
**every candidate requires a node**, even a non-derived candidate. There is no
second competing `access_checks` collection. Node identity is `(item_id, version)`
in `context.tenant`; its check is the current check for that same item. Candidate
`source`, hash and exact ordered `derived_from` must match its node. A mismatch
is whole-call `invalid_input/candidate_binding_mismatch`; an absent node is the
per-item `policy/missing_node` drop. Requiring authoritative derivation for every
candidate prevents a model from hiding a denied ancestor by sending `[]`.
All node/check tenants must equal `context.tenant`, and check identity/source/hash
must equal the node. Binding failure is an access drop, including for ancestors.

Only supplied candidate bytes are hashed. Every non-nil candidate digest must
match `:crypto.hash(:sha256, content)` or the whole call fails `:hash_mismatch`.
A nil digest retains reference-based dedupe; the host must ensure immutable
identity/version/content binding. Nodes without candidate bytes rely on that host
integrity Need; no hash of absent content is claimed. For `unit: :bytes`, reject
`estimate < byte_size(content)` as `:byte_estimate_underflow`. For tokens, exact
usage remains external: return full content unchanged, never silently truncate.
Cure receives byte_size, IDs, estimates and validated metadata, **never content**.

`candidate.access` is retrieval evidence. Denied vetoes it even if current check
allows; wrong retrieval principal also vetoes it. This evidence never permits a
candidate by itself. Elixir records those veto drops before encoding survivors;
Cure's candidate type carries no retrieval access field. Current check lookup,
binding and freshness use only the trusted nodes in Cure. Selected output carries
current `access` and the original three-field `retrieval_access` separately.

The host constructs checks and time as one coherent snapshot from its clock,
with `checked_at <= snapshot_at <= now`, and rechecks relevant changes before
injection. `now < snapshot_at` is unavailable context; checks after `snapshot_at`
fail freshness. Snapshot completeness/coherence is a Need, not proved by matching
numbers. A check may be old but only within the trusted `max_age`; the host must
reflect revocations known at snapshot creation. Revocations after the snapshot
are invisible; freshness tolerance does not promise continuing live authority.
There is no future-`updated_at` rule; it is only a ranking operand and may be
omitted when `recency: :input`.

The selected window must match a closed host registry entry by all six fields.
Unknown pair → `unavailable_context/unknown_window`; a known pair with changed
size/unit/estimator/version → `unavailable_context/window_mismatch`. A human
brief registers an explicit pair too. Reservations share its unit; sums larger
than the window fail explicitly. The host supplies estimates under that exact
estimator/unit and rejects mixed estimator output before building candidates.

## Bounds, validation and result

| Bound | Accepted domain |
| --- | --- |
| candidate occurrences / total content / each content | 0..256 / 0..8 MiB / 0..1 MiB, before dedupe/filter |
| trusted provenance list | 0..256 entries, unique `(item_id, version)` |
| ordered refs per node/candidate | 0..16, distinct references |
| path depth | at most 16 nodes, including the starting node |
| total expansion budget | at most 4096 = node entries + outgoing ref occurrences |
| selected count cap / selected actual-content-byte cap | trusted 0..256 / 0..8 MiB, independent of ingress |
| windows / named reservations | 0..32, unique pair / unique name |
| identity and reservation name | 1..1024 valid UTF-8 bytes |
| version / estimator version | 1..2^31-1 |
| estimate, reservation, window size, time, age | integer 0..2^53-1 |
| priority | integer -(2^31)..2^31-1 |

No arbitrary BEAM terms, lazy streams, filesystem reads or floats. Count limits
also bound total identity bytes. Use bounded traversal before policy evaluation;
no truncation. Input is already allocated, so this is not an ingress sandbox.
Arbitrary-precision sums may exceed scalar bounds without overflow or clamping.

Validation order: trusted shape/bounds, duplicate registry/reservation/node keys,
trusted time/window/reservation consistency and graph expansion budget; request
shape/unknown fields and fixed count/byte ceilings; candidates in input order
with schema-order field validation, hash/byte checks and node metadata agreement;
then conflicting duplicate candidates. Exact candidate duplicates remain for
per-occurrence deduplication; conflicting data for one reference removes **all**
selection as a whole-call availability failure. Duplicate context node identities
are unavailable context even when identical. Snapshot binding/permission failures
are per-item decisions, not repaired by normalization.

```elixir
{:ok, %{
  selected: [selected_candidate],
  dropped: [%{index: nonnegative_integer, item_id: id, version: integer,
              reason: :access_denied | :stale_access_check | :over_window |
                      :superseded | :policy, detail: detail_atom}],
  total_estimate: %{size: nonnegative_integer, unit: unit,
                    estimator_id: id, estimator_version: integer},
  reserved_estimate: nonnegative_integer,
  selected_count: nonnegative_integer, selected_bytes: nonnegative_integer,
  window: window, principal: id, tenant: id, evaluated_at: unix_ms
}}
| {:error, {:invalid_input, reason}}
| {:error, {:unavailable_context, reason}}
| {:error, {:invariant_failed, :window | :access | :count | :bytes}}
```

Selected entries retain the complete input content/metadata, add original index,
`kind: :source | :derived`, and `retrieval_access`; `access` becomes the current
three-field access record. Nonempty derivation means `:derived` and untrusted
proposal. The source/hash/version/current-check binding is preserved. Total
estimate excludes reservations; selected bytes sum actual content bytes.
No error carries a usable selected list.

Validation reasons: `{:missing_field, field}`, `{:unknown_field, field}` for safe
schema atoms, `:unknown_field` for arbitrary supplied keys, `{:invalid_field,
field}`, `{:bound_exceeded, bound}`, `:duplicate_window`, `:duplicate_reservation`,
`:duplicate_provenance_node`, `:invalid_snapshot_time`, `:unknown_window`,
`:window_mismatch`, `:reservations_exceed_window`, `:hash_mismatch`,
`:byte_estimate_underflow`, `:candidate_binding_mismatch`, `:conflicting_candidate`.
The first validation fault wins; unknown/missing keys are sorted by safe schema
field order and never echo arbitrary values. Trusted faults use unavailable
context, candidate/request faults invalid input. Expansion overflow is
`{:error, {:unavailable_context, {:bound_exceeded, :provenance_expansions}}}`.

## Selection precedence and bounded provenance (B2, B3)

After global validation, each occurrence receives exactly one disposition:

1. Retrieval denied → `access_denied/retrieval_denied`; otherwise wrong retrieval
   principal → `access_denied/principal_mismatch`.
2. Find its trusted node: absent → `policy/missing_node`; otherwise tenant or
   check binding mismatch → `access_denied/binding_mismatch`; nil own check →
   `access_denied/missing_check`; denied → `access_denied/denied`. Binding wins
   over denial; nil has no fields to compare. Retrieval veto wins over all these.
3. Check after snapshot → `stale_access_check/future_check`; otherwise age larger
   than max_age → `stale_access_check/expired_check`. Exact age is allowed.
4. Higher numeric version in supplied candidates **or nodes** →
   `superseded/newer_version`. No old-version fallback if latest is denied/large.
5. Nonempty derivation while disallowed → `policy/derived_disabled`; otherwise
   consume its provenance verdict: missing referenced node → `policy/missing_node`,
   nil source check → `access_denied/source_unchecked`, source binding mismatch →
   `access_denied/binding_mismatch`, denied → `access_denied/source_denied`, stale
   → `stale_access_check/source_stale`, superseded → `policy/superseded_source`,
   cycle → `policy/cyclic_provenance`, path >16 → `policy/provenance_depth`.
6. In rank order, first eligible dedupe key wins: `{:hash, digest}` if present,
   else `{:ref, id, version}`; domains cannot alias. Later duplicates drop
   `policy/duplicate`, even if the winner later exceeds a packing cap.
7. Greedy admission checks **window, then selected count, then selected bytes**.
   Drop `over_window/insufficient_window`, then `policy/count_limit`, then
   `policy/byte_limit` respectively; skip and continue. Zero caps and zero-cost
   content are legal: count cap still limits zero-byte/zero-estimate entries.

Rank: enabled priority descending, enabled recency descending, then original
input index ascending. Selected follows rank; dropped follows input order.
No optimum packing, maximal cardinality or permutation invariance promise.

Provenance nodes are separate from candidates, contain no raw content, and describe
**all** derivation for their immutable identity. At a node, own binding/access,
freshness and supersession precede its dependencies; its derivation policy also
applies to non-candidate nodes. All ancestors must be permitted even if not
injected. Source results normalize to the source detail atoms above. The first
failed reference in declared order wins, recursively; memo/processing order may
not reorder explanations. No failed reference is replaced by a later successful
one. An externally newer version or omitted derivation is not discoverable;
the host must supply complete provenance and supersession knowledge.

Work accounting is **node entries + declared edge occurrences**, over the entire
trusted graph, including unreachable nodes and references to missing/shared nodes.
Count before evaluation; 4096 is permitted, 4097 fails whole-call before cycle
or depth evaluation. Identical descendant paths never multiply the count.
Use a structural list with exactly the remaining expansion tokens; consume one
for first node expansion and each outgoing edge. Cache node verdict and maximum
successful-path depth by exact reference; each node is evaluated once, in
source-before-dependent order. A bounded cycle-classification pass identifies
cyclic components; cycles get the explicit failure, then their dependants consume
cached failures in declared edge order. Cycle classification and permission
passes each use the same pre-counted bounded node/edge set, never path expansion;
structural node/ref/fuel lists bound every recursive pass. Budget is a graph-size
bound, not a claim that the entire algorithm executes only 4096 BEAM instructions.
Lookup/list traversal costs must also stay finite and be timed on the max graph.

The mandatory worst-case fixture has 16 layers × 16 nodes; each non-leaf points
to all 16 nodes of the next layer: 256 nodes + 3840 references = **4096**.
The over-budget variant adds one reference from a last-layer node to a different
last-layer node (still at most 16 refs per node): **4097**, rejected by the
pre-count before depth processing. Require each call to finish under **5 seconds**
on the pinned local/self-hosted test toolchain, assert one computed verdict per
node and no path expansion. This is a named test bound, not a general latency SLA.
Separate depth fixtures exercise 16 and 17 nodes without hitting graph-size bounds.
