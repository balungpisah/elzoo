## Responsibility and reuse

`workflow/context-selection` chooses one ordered set of permitted, versioned
candidates for C6 child-run artifacts, C7 research, or a human review brief.
It has no state owner or Effects. The caller owns the Run, current authority,
clock, retrieval, byte materialization, estimator, provider submission and usage
reconciliation. No model output becomes a retained fact.

Reuse the accepted `domain/authorization` result at the caller's boundary;
only ALLOW translates to `:allowed`. ASK, DENY and failures cannot authorize
context. A consent record alone is not an access result. The accepted reducer
has exact-write authority, not a general read-ACL schema: the caller defines
and tests its read action mapping. Do not change ELZ-024 to invent one here.
Use ordinary Enum operations for validation/encoding and presentation sorting;
Cure owns the selection decisions. Ash remains an optional consumer action
boundary, not a dependency of this pure bundle. Provider count/tokenizer APIs
(including the studied req_llm candidate) supply estimates externally. Sigil
0.1.4 / bankai 0.4.0 observations motivate reservations and provenance, not a
runtime dependency or copied source. No provider is adopted by this task.

## Proposed API and exact schemas (D1, D2)

`Elzoo.ContextSelection.select(request, context)` returns the result below.
All maps have **exact atom keys**, all listed keys are required, and `nil` is
accepted only where listed. Reject unknown keys, wrong types, improper lists,
non-UTF-8 identities and duplicate keys at an external decoder before map
construction. No coercion, normalization, ambient configuration or defaults.
Identifiers are nonempty UTF-8 binaries, byte-equal and scoped to one tenant.
An identity/hash is a declaration, not authentication or a content certificate.

```elixir
# request (untrusted candidate data; window/policy must be caller selected)
%{
  window: window,
  reservations: [{name, nonnegative_integer}],
  candidates: [candidate],
  now: unix_ms,
  policy: %{
    max_age: nonnegative_ms,
    priority: :descending | :input,
    recency: :newest | :input,
    allow_derived: boolean,
    max_candidates: positive_integer,
    max_bytes: positive_integer
  }
}
# window (all six fields required; no inference from a model name)
%{provider_id: id, model_id: id, size: nonnegative_integer,
  unit: :tokens | :bytes, estimator_id: id, estimator_version: positive_integer}
# candidate
%{item_id: id, version: positive_integer, source: id,
  content: binary, estimate: nonnegative_integer, priority: integer,
  updated_at: unix_ms,
  access: %{principal: id, checked_at: unix_ms, result: :allowed | :denied},
  derived_from: [%{item_id: id, version: positive_integer}],
  content_hash: nil | <<_::256>>}
# context (trusted host inputs, never accepted from a candidate/model)
%{principal: id, tenant: id, windows: [window], access_checks: [check]}
# check: current host-owned access result, bound to an exact candidate
%{item_id: id, version: positive_integer, source: id,
  content_hash: nil | <<_::256>>, principal: id,
  checked_at: unix_ms, result: :allowed | :denied}
```

`candidate.access` is retrieval-time evidence, not current authority. The
host independently re-evaluates permission and supplies `context.access_checks`
for this selection, overriding old retrieval results. It authenticates the
principal/tenant and binds checks to the exact content/version. The selection
must use the current check; it must never fall back to `candidate.access`.
Selected output replaces `access` with that current check's three access fields.
A missing check, wrong principal, or a source/hash binding mismatch fails closed.
Unknown access is represented by a missing check, not a third permission value.

Every candidate is for `context.tenant`; globally ambiguous IDs must be
namespaced by the host. `(item_id, version)` identifies one immutable candidate
within that tenant. The host binds its check to the candidate bytes, source,
version and digest (if present). Hashes are caller-verified SHA-256 over the
exact content bytes; this selector does not hash or verify content integrity.
`nil` means no digest, requiring immutable version binding by the host.

`window` must exactly match one entry in the host's closed `windows` list;
unknown provider/model is `:unknown_window`, a known pair with changed size,
unit/estimator/version is `:window_mismatch`. This admits human briefs through
an explicitly registered provider/model pair as well. Estimates use exactly
that window's unit and estimator version; mixed/unknown estimator output must
be rejected by the caller before creating candidates. Reservations use the
same unit and account for all non-candidate prompt/output overhead. This does
not claim tokenizer accuracy, an actual token bound, or provider success.

**Trust/time limit (D1):** the host supplies one coherent authorization snapshot
and evaluation instant, rechecks after retrieval, and prevents/rechecks relevant
changes before actual injection. A pure selector cannot know about a revocation
that the host omitted, or one that occurs after its snapshot. `max_age` is a
freshness tolerance, not a promise of live permission throughout that interval.
The executable revocation scenario must use the real ELZ-024 ALLOW→DENY result
translation into the second snapshot, retaining the old allowed retrieval
record, and demonstrate exclusion of the item and its derivatives.

## Bounds, errors and precedence

Contract ceilings (policy may tighten only candidate count and total bytes):

| Quantity | Ceiling / domain |
| --- | --- |
| candidates, including duplicate occurrences | 256; policy `max_candidates` 1..256 |
| total candidate content bytes, before filtering/deduplication | 8 MiB; policy `max_bytes` 1..8 MiB |
| content bytes per candidate | 1 MiB (empty permitted) |
| identities / reservation names | 1024 bytes |
| current checks | 256; one per `(item_id, version)` |
| declared windows | 32; one per `(provider_id, model_id)` |
| named reservations | 32; names unique, zero sizes allowed |
| direct provenance refs per candidate | 16; no duplicate refs |
| provenance depth | 16; cycle or deeper chain fails closed |
| version / estimator version | 1..2^31-1 |
| estimate / reservation / window / now / checked_at / updated_at / max_age | integer 0..2^53-1 |
| priority | integer -(2^31)..2^31-1 |

Aggregate identity/reference bytes are additionally bounded by these fixed
counts and per-field limits. Content is materialized binary input, never a
lazy stream, file path to read, or unbounded opaque term. Bound rejection does
not truncate. Input is already allocated; this is not an ingress memory sandbox.
The validator uses bounded traversal before policy evaluation. All arithmetic
uses BEAM arbitrary-precision integers; the sum of individually bounded inputs
may exceed the scalar bound and is still compared exactly, never clamped.

```elixir
{:ok, %{
  selected: [selected_candidate],
  dropped: [%{index: zero_based_input_index, item_id: id, version: integer,
              reason: :access_denied | :stale_access_check | :over_window |
                      :superseded | :policy,
              detail: detail_atom}],
  total_estimate: %{size: nonnegative_integer, unit: unit,
                    estimator_id: id, estimator_version: integer},
  reserved_estimate: nonnegative_integer,
  window: window,
  principal: id, tenant: id, evaluated_at: unix_ms
}}
| {:error, {:invalid_input, reason}}
| {:error, {:unavailable_context, reason}}
| {:error, {:invariant_failed, :window | :access}}
```

`selected_candidate` is the input map with current `access`, plus `index` and
`kind: :source | :derived`. `derived_from == []` means source; a nonempty list
means derived, including tool or model summaries. The host must mark all
actually derived content with complete provenance. The selector cannot infer
hidden derivation from bytes. Every selected derived item retains its exact
references and is explicitly an untrusted proposal, not a factual assertion.
`total_estimate.size` sums selected estimates only; `reserved_estimate` sums
reservations. Their sum must be at most `window.size` on every success.
No selected list is returned with an error.

Validation order: trusted context shape/bounds/duplicate keys first; then
request shape and policy bounds; window resolution; reservation names/sizes;
candidate count/total-byte bounds; candidates in input order with fields in the
schema order above; conflicting duplicate candidate references; finally reserved
sum versus window. Map unknown/missing-key errors follow sorted atom/string key
order; report fixed field names, never supplied content or unknown values.
For invalid key types report `:unknown_field` without retaining the value.

Reasons are `{:missing_field, field}`, `{:unknown_field, field}` (known safe
schema field atoms only), `{:invalid_field, field}`, `{:bound_exceeded, bound}`,
`:duplicate_window`, `:duplicate_access_check`, `:duplicate_reservation`,
`:conflicting_candidate`, `:unknown_window`, `:window_mismatch`, or
`:reservations_exceed_window`. Context validation/window resolution errors use
`:unavailable_context`; other validation errors use `:invalid_input`.
Conflicting data for the same `(item_id, version)` fails the whole call;
byte-for-byte identical duplicate occurrences remain for explained deduplication.

Per-candidate drop precedence, after successful global validation:

1. Own current access missing, denied or misbound → `access_denied`, detail
   `missing_check`, `denied`, `principal_mismatch` or `binding_mismatch`.
2. Current check is in the future, or `now - checked_at > max_age` →
   `stale_access_check`, detail `future_check` or `expired_check`. Equality at
   `max_age` is accepted. Retrieval-time checks cannot override this.
3. A greater version of the same item is present anywhere in the input →
   `superseded`, detail `newer_version`. No fallback to an older version if the
   latest is denied, stale or too large. The maximum is relative to this input;
   the host must supply knowledge of externally superseded versions.
4. Derived disallowed → `policy/derived_disabled`. Missing provenance ref,
   cycle, depth overflow or a superseded source → `policy/missing_source`,
   `policy/cyclic_provenance`, `policy/provenance_depth` or
   `policy/superseded_source`. A denied or stale ancestor uses
   `access_denied/source_denied` or `stale_access_check/source_stale`.
   References are examined in declared order; traversal is depth-first and
   uses a bounded visited path. All ancestors must be current and permitted;
   they need not themselves fit into or be selected for the window. Future
   `updated_at` → `policy/future_item` (after provenance).
5. Deduplicate eligible candidates in rank order. Use `{:hash, content_hash}`
   when non-nil, otherwise `{:ref, item_id, version}`; key domains never alias.
   Later duplicate → `policy/duplicate`. Permissions are checked before
   deduplication; an allowed duplicate cannot launder a denied candidate.
6. Greedy packing in rank order: include if its estimate fits remaining
   capacity; otherwise `over_window/insufficient_window`, then continue to
   later smaller items. A duplicate winner remains the winner even if it
   does not fit; do not try a duplicate with a different estimate.

Ranking: priority descending when enabled, then `updated_at` descending when
recency is `:newest`, then original input index ascending. `:input` disables
that ranking key. Selected output is in this order; dropped output is in input
index order. One disposition per input occurrence, including exact duplicates.
No optimal knapsack, maximal-cardinality or input-permutation invariance claim.

## Cure/Elixir split and laws (D3)

| Work | Owner and grounding |
| --- | --- |
| Validate exact maps, finite bounds, duplicate conflicts, immutable snapshots/window identity; encode/decode | Elixir, scenario tests |
| UTF-8 byte comparison and stable rank preparation using the declared keys | Elixir Enum, scenario/agreement tests |
| Current-check lookup/binding, freshness, latest-version exclusion, recursive provenance, dedupe, greedy include/drop decision | Cure, typed compilation and scenarios |
| Recompute total and aggregate access predicate on actual selected records before success | Cure, selected quantified laws |
| Format output indices/records/drop ordering and estimator tags | Elixir, agreement tests; no policy re-evaluation |
| Authenticate/fetch/recheck, estimate, provider dispatch and usage reconciliation | Caller/Adapters, assumptions; no implementation here |

The production Cure `select` will call `finish` on its actual chosen list.
`finish` recomputes `sum(selected.estimate) + sum(reservations) <= window.size`
and `all_access(selected, snapshot, now, max_age)` from the selected records,
not from an externally supplied total or `safe` flag. Failure is an explicit
internal invariant error with no usable selected output. This is a defensive
runtime decision, not a proof-only assertion. Reservations greater than the
window are a validation error even with zero candidates.

Proposed laws, quantified over all Cure inputs (including malformed values at
that internal boundary), with no hypothesis that the result is safe:

- `window_law`: `window_holds(select(...), reservations, window) = True`.
  `window_holds` is true for refusal; for success it recomputes the estimate
  sum from the selected list plus reservations and compares it with the window.
- `access_law`: `access_holds(select(...), snapshot, now, max_age) = True`.
  True for refusal; on success all selected own access results must be allowed,
  bound to the principal/version/source/hash, non-future and within `max_age`.
  The final implementation must include recursive provenance permission in
  the same aggregate predicate, with exact source lookup and bounded traversal.

Cure's symbolic native arithmetic remains neutral, so the proof uses the
accepted ELZ-024/ELZ-022 inspect pattern: a private lemma cases on the **actual
computed** Boolean and receives its reflexive defining equation. The public
law constructs that evidence itself; callers never provide the claimed
invariant as an axiom or assumption. No disconnected Peano model or finite
arithmetic sampling is substituted. Unlike ELZ-022's scalar admission proof,
the window predicate recomputes the actual list sum, avoiding a separate
unproved scalar-to-list invariant. Native integer operation semantics and the
Cure compiler/kernel remain upstream contracts.

These laws establish safety of successful results, not successful completion,
optimal selection, ranking correctness, absence of spurious internal errors,
hash correctness, authentication, coherent snapshots or provider token limits.
Scenario tests must prevent an always-refusing implementation from passing the
overall acceptance. Final proofs must name the consumed production `select`,
not only the reduced feasibility function. Probe success does not establish the
unimplemented provenance traversal or its totality; that remains implementation
work and must fail closed if Cure cannot check it.

## Planned executable scenarios and negative controls

- Real authorization fixture: retrieval ALLOW, later policy DENY → fresh denied
  snapshot; original candidate still says allowed; no item/derived item escapes.
  ASK and reducer errors translate to no permit; forged principal/check binding
  cannot grant permission. Missing checks never use old retrieval access.
- Freshness at age zero, exact maximum, maximum + 1, future timestamps; changed
  now changes the decision; no wall-clock read inside the selector.
- Direct and transitive derived references, denied/stale/missing/superseded
  ancestors, cycles, maximum-depth and depth + 1; allowed but unselected source
  still permits a derivative; disabled derivation; complete provenance retained.
- Reservation equality/overflow, empty/zero window, exact fit, skip oversized
  then include small, zero estimates, maximum integers and sum beyond 2^53;
  estimates remain estimates and result tags match the supplied known window.
- Latest denied version suppresses old allowed version; duplicate refs with
  conflicting access/content/estimate fail; hash dedup vs fallback and key-domain
  separation; winner over budget does not admit a later duplicate.
- Priority/recency combinations, stable ties, repeated identical calls and
  exact one disposition per occurrence. Independent small Elixir oracle over
  seeded bounded inputs checks the complete selection output (tests, not proof).
- Every fixed/configurable bound at limit and limit + 1; malformed fields and
  multiple-error precedence; no leaking candidate bytes in returned errors.
- Unknown provider/model, missing window, mismatch of unit/estimator/version;
  no default. A provider-limit/undercount response is external to this pure
  Piece: a deliberately low estimate still returns the complete candidate bytes;
  a caller/provider fixture can report its limit error without this Piece
  truncating content or retrying. No real provider accuracy is claimed.
- Compile and clean-audit production Cure (`axioms`, `holes`, `unresolved`,
  `unaudited`, `opaque`, `not_proven_total` empty; no absurd proof).
- Mutate final window failure branch to success, omit reservations, omit one
  selected estimate from the guard, bypass access final guard and weaken age
  checking: require proof rejection at the named law/helper, not parser failure.
  Independent access predicate in law catches a changed guard; mutating both
  guard and specification is not claimed detectable by that proof.
- Export this Piece into a clean standalone application and run copied tests
  with the root Application absent, plus namespace-renamed consumption. New
  scoped tests only; any harness change requires coordinator assignment.

## Decisions requested at early review

- **D1 — snapshot authority:** approve separate trusted current checks overriding
  retrieval-time `candidate.access`, with the stated snapshot/dispatch assumption.
  Literal exclusion of a revocation invisible to all inputs is impossible for
  a pure Piece; this proposal makes that limit explicit instead of asserting it.
- **D2 — concrete missing data:** approve materialized `content`, `updated_at`,
  explicit provider/model/estimator-version registry, trusted principal/tenant,
  and numeric version ordering. The issue does not define byte accounting,
  current principal scope, the window registry, recency timestamp or version order.
- **D3 — proof form:** approve successful-result laws over actual selection plus
  runtime final guards, using native Int operations and inspect lemmas. This is
  not an unguarded arithmetic induction or a proof of provider/tokenizer accuracy.
- **D4 — edge semantics:** approve the exact bounds, drop precedence, no old-version
  fallback, missing-source failure, transitive provenance, dedup-before-packing
  and first-eligible duplicate winner. These are unspecified in the live issue.
- **D5 — scope:** approve the proposed dependency/example closure and coordinator
  ownership of registry/ledger plus any required export-harness wiring. No
  restricted CI/compiler/export file is edited in this stage.

The coordinator decides whether accepted clarifications require a deliberate
issue Contract amendment. This worker does not rewrite the issue or treat this
proposal as permission to weaken an acceptance criterion.
