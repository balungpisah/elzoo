## Contract reading

Two Pieces, one chain: `integration/ai-embedding-openai` → `integration/ai-embedding`
→ `integration/ai-model` (ELZ-079 core); the interface also depends on `core/effect`,
`delivery/effect-intent` and `delivery/retry-timeout`. The interface does not depend on
`integration/ai-text` (a consumer of embeddings copies no text Piece).

### Interface (`integration/ai-embedding`)

The same call path as `integration/ai-text`, for the `embed` operation:

1. `Elzoo.AiEmbedding.configure/1` builds the trusted Config: binding (a module using
   `Elzoo.AiEmbedding.Binding`, fixing the provider account that enters the intent
   key), tenant, provider module and its construction term, the injected credential
   Need (zero-arity function returning `{:ok, key}`), the model allowlist, bounds
   (inputs per call, bytes per input, request bytes), the receive timeout, the norm
   tolerance and the volatile result sink. Fixed for the Config's lifetime.
2. `Elzoo.AiEmbedding.admission/2` takes a `core/effect` declaration (untrusted,
   capability `integration/ai-embedding`, operation `embed`, command schema
   `elzoo/ai-embedding-request` version 1, explicit idempotency key and deadline). Every
   locally decided refusal (`invalid_request`, `unsupported_feature`, `too_large`)
   returns here with **no intent, no credential read and no transport call**.
3. The host starts `Elzoo.EffectIntent` with `adapter_context: config` and advances
   `:dispatch`; `Elzoo.AiEmbedding.Adapter.send_effect/1` calls the Need, the
   provider's pure `translate/2`, exactly one `call/2`, then `decode/2` or
   `classify_failure/1`, then the interface's own checks of the response, the sink and
   the envelope. The Adapter never retries.
4. `Elzoo.AiEmbedding.Retry.next/4`: only `credentials_unavailable` (attested no-send)
   is redispatched; `throttled` and `overloaded` are failed/dispatched/retryable and
   decide `:unresolved` (ELZ-079 amendment 1, family-wide); `unknown` is never retried,
   in every policy mode.

**Request** (the command payload, canonical JSON, schema `elzoo/ai-embedding-request`
v1), exactly these members:

- `"version"`: `1`; `"model"`: 1..256 bytes, in the Config allowlist and known to the
  provider.
- `"inputs"`: 1..`max_inputs` strings, each nonempty valid UTF-8 of at most
  `max_input_bytes` (newlines and tabs allowed; the provider refuses an empty string, so
  the interface does too).
- `"dimensions"` (optional): an integer the provider declares for the model (OpenAI
  `text-embedding-3-*`: 1..native). Absent means the model's native dimension.
- `"input_type"` (optional): `"query" | "document" | "unspecified"` (default
  `unspecified`); see open question 1.
- `"provider_options"` (optional): an object whose keys the provider declares, each
  value passing the provider's validator (R3); anything else `invalid_request`, never
  ignored.

Duplicate keys, unknown members, invalid UTF-8 and a payload over `max_request_bytes`
are refused. `max_request_bytes` is at most 65,536 because `delivery/effect-intent`
bounds its argument bytes at 65,536 (`model.ex`); the canonical payload is those bytes.
So one call carries at most 64 KiB of canonical request JSON; ELZ-082 batches its index
writes within that bound.

**Outcomes** (sink delivery `{:outcome, attempt_id, outcome}` once per attempt):

- `{:completed, %{embeddings: [%{index, vector}], descriptor, usage, provenance}}`;
  `descriptor = %{provider, model, dimensions, dtype: :float32, normalization}` with
  `normalization` `:unit_l2_verified | :none`; `usage` and `provenance` are the core's
  values.
- `{:refused, reason, %{retry_after: seconds | nil}}`, reason one of
  `credentials_unavailable | invalid_request | unsupported_feature | too_large |
  authentication_failed | permission_denied | throttled | overloaded | not_found`.
- `{:unknown, reason}`, reason one of `timeout | transport | malformed_response |
  provider_error`.

**The interface's response checks (owned by the interface, not the provider).** The
provider's `decode/2` returns the raw items `[%{index, vector}]` as the provider listed
them, the provider-reported model, usage and request id. The Adapter then requires:

1. exactly `length(inputs)` items;
2. every index an integer, the set of indices exactly `0..n-1` (no missing, duplicated
   or out-of-range index);
3. every vector a list of exactly `dimensions` numbers (the requested dimension, or the
   model's native one);
4. every element a finite number representable as float32 (`abs(x) <= 3.4028235e38`;
   JSON cannot carry NaN or infinity, so a non-number such as `null` or a string, or a
   value Jason cannot decode, is the realistic defect; integers are accepted and
   converted to floats);

and only then sorts by the validated index and emits it, so input order is list order.
Any defect is `unknown{malformed_response}` (the provider may have charged); never a
shorter or partial list. Then the L2 norm of every vector is computed: when every
`|‖v‖₂ − 1| ≤ norm_tolerance` the descriptor says `:unit_l2_verified`, otherwise the
call **completes** with `normalization: :none` (main's decision; ELZ-082's cosine
binding refuses it). The norm tolerance is a Config setting (default `1.0e-3`, bounds
`(0, 0.1]`).

**Descriptor (stable; ELZ-082 depends on it).** `provider` is the provider's
`capabilities/0` name (`"openai"`), `model` the requested model identifier (the one
in the allowlist), `dimensions` the validated vector length, `dtype: :float32`,
`normalization` as above. Two descriptors are compatible only when all five fields are
equal (`Elzoo.AiEmbedding.Descriptor.compatible?/2`, tested). The provider-reported
model goes to `provenance.provider_model`, not to the descriptor (open question 4).
`input_type` is not part of the descriptor (asymmetric query/document embeddings of one
model are meant to be compared).

**Invariants (as the body).** One call sends at most one HTTP request. Usage absent
from the response is `:unknown`. The credential and the input texts never appear in
results, errors, inspect values, logs, events or EffectIntent state: the completed
envelope carries only an outcome digest and a process-local seal (vectors are delivered
only through the sink); failures are fixed atoms.

**Conformance kit** `Elzoo.AiEmbedding.Conformance` in the interface's `lib/` (as the
text kit: scenario data plus plain check functions, no ExUnit, no test-only dependency,
no provider fixture). Scenarios and stub meanings: `single_input`, `multiple_inputs`,
`out_of_order` (indices listed reversed), `fewer` (one item missing), `more` (an extra
item), `duplicate_index`, `out_of_range_index`, `wrong_length` (one vector one element
short), `non_number` (a `null` element), `beyond_float32` (an element `1.0e39`),
`non_unit` (vectors of norm 2: completed, `:none`), `dimensions` (requested 256,
honored), `usage_omitted`, `malformed_success` (a 2xx that is not the documented list
object), `timeout`, `throttled` (with a 7-second retry-after), `overloaded`,
`server_error`. `check/3` takes the sink delivery and the request count the stub saw
(always 1).

**Outcome mapping.** Same tags, Contract outcomes and delivery triples as the text
interface (table in the `integration/ai-text` README; amendment 1 included). See open
question 2 for where the table lives.

### OpenAI provider (`integration/ai-embedding-openai`)

- **Through `req_llm`'s documented provider-callback API**, as ELZ-079:
  `ReqLLM.Providers.OpenAI.prepare_request(:embedding, model, inputs, opts)` then
  `Req.request/1`. Not the `ReqLLM.embed/3` facade: it drops the status, the
  `x-request-id` header and the raw usage, returns a short list as success (issue
  reuse check) and builds an error value carrying the response body.
- One Elzoo response step is **prepended** (runs before every Req and `req_llm`
  response step): it copies the status, `x-request-id` and `retry-after` (each at most
  256 printable bytes) and the raw body, then halts **every** response. One prepended
  error step halts a transport exception unchanged. So no redirect, no retry, no
  `req_llm` decode, usage or error step runs; the provider decodes OpenAI's documented
  format itself.
- **Retry setting (main's decision, verified in probe p1).** `prepare_request(:embedding)`
  refuses top-level `max_retries` and `receive_timeout` (NimbleOptions: valid options are
  `dimensions, encoding_format, user, provider_options, req_http_options, telemetry,
  total_timeout, fixture`). `ReqLLM.Step.Retry.attach/2` falls back to the request's own
  `:max_retries` option, so the Piece passes `req_http_options: [max_retries: 0,
  receive_timeout: ms]` (plus `plug:` in tests). Observed: a stubbed timeout gave **4**
  requests with no Elzoo step and no `max_retries`, **1** with the halting error step
  alone, and 1 with the full settings; a 500 with the capture step gave 1. Tests assert
  the count (E5) with and without the halting steps' help (a variant where only
  `max_retries: 0` stands).
- Options always passed: `api_key:` from the injected Need (probe: with
  `OPENAI_API_KEY` set in the environment the wire carried only the injected key),
  `encoding_format: "float"` (base64 is not supported in this slice), `dimensions` when
  requested, `user` when given as a provider option.
- **Inputs always sent as an array** (probe: a single string is sent as a JSON string;
  an array of one keeps one response shape).
- **Model table** (capabilities): `text-embedding-3-small` native 1536, reducible
  1..1536; `text-embedding-3-large` native 3072, reducible 1..3072 (OpenAI
  "Vector embeddings" guide; `llm_db` 2026.11.0 reports the same
  `default_dimensions`/`min_dimensions`/`max_dimensions`, checked by a test).
  `text-embedding-ada-002` is not declared (fixed 1536, no `dimensions` parameter,
  superseded); a request for an undeclared model is `invalid_request` at admission.
  The Config allowlist must be a subset of the declared models (construction refuses
  otherwise).
- **Usage** (open question 3): `usage.prompt_tokens` →
  `input_uncached_tokens` (embeddings have no documented prompt cache, convention
  `input_includes_cached: false`); `total_tokens`, when present, must equal
  `prompt_tokens`, otherwise the input counter is `:unknown`; cache read, cache writes
  and output are not reported and stay `:unknown`; no usage object gives source
  `:unknown`.
- **Provenance:** `model_ref{provider: "openai", model_id: requested, wire_surface:
  "embeddings"}`, `provider_model` the response's `model`, `response_id: :absent`
  (embeddings carry no id), `request_id` the `x-request-id` header or `:absent`,
  `provider_piece: "integration/ai-embedding-openai"`.
- **Failure mapping** (statuses documented for `POST /embeddings` in the pinned OpenAPI
  document: 400, 401, 403, 429 `InferenceRateLimited` with optional `Retry-After`, 500,
  503 `InferenceServiceUnavailable`): 400 `provider_invalid_request`; 401
  `authentication_failed`; 403 `permission_denied`; 404 `not_found` (not listed for this
  path; HTTP meaning, recorded as such); 413 `provider_too_large` (same note); 429
  `throttled` (with `retry-after` seconds when present); 503 `overloaded`; 500 and any
  other status, 3xx included, `provider_error`; transport timeout `timeout`; other
  transport failures `transport`. A 2xx that is not `{"object": "list", "data": [...],
  "model": string}` with items `{"object": "embedding", "index", "embedding": [...]}` is
  `malformed_response`.
- **Provider options (R3):** `user` (1..256 printable ASCII). Nothing else.
- **`input_type`:** only `unspecified` declared; `query`/`document` refused
  `unsupported_feature` at admission (open question 1).
- **Install configuration:** README section with `config :req_llm, load_dotenv: false`
  and the ELZ-079 limit text; a two-layout README test (ELZ-079 pattern) until ELZ-091
  provides the field.

## Open questions (for the early review)

1. **`input_type` (the issue's open question).** Recommendation, as the body suggests:
   the interface accepts `query | document | unspecified` (default `unspecified`); a
   provider declares the values it honors; OpenAI declares only `unspecified`, so
   `query` or `document` is refused `unsupported_feature` at admission, before any
   credential read. There is no "hint" mode that a provider may silently drop: a value
   the caller sends is a requirement. A later Voyage or Cohere provider declares
   `query` and `document` and maps them without a Contract change. ELZ-082 sends
   `unspecified` for OpenAI. `input_type` is not part of the descriptor.
2. **Where the failure table lives.** The text and embedding interfaces share the same
   14 tags and delivery triples. `integration/ai-model` (ready) is pure and has no
   Cure decision; `integration/ai-text` must not become a dependency. Recommendation:
   an own Cure decision `Elzoo.AiEmbeddingOutcome` with the same table (type-checked,
   verified at construction as in ai-text), accepting the duplication; the same holds
   for the small Binding, Sink and Retry modules. A family-level extraction would need
   a new Piece ID and is a follow-up, not this task. Alternative: a plain Elixir table
   checked only by the EffectIntent Binding (no Cure file).
3. **Usage for embeddings.** Recommendation as above: `prompt_tokens` →
   `input_uncached_tokens` with `input_includes_cached: false`; cache and output
   counters left absent (so `:unknown`, never zero; `prompt_input_tokens/1` is
   `:unknown` because no cache counters are reported); `total_tokens` must equal
   `prompt_tokens` or the input counter is `:unknown`.
4. **Descriptor model.** Recommendation: the requested (allowlisted) model ID, with
   the provider-reported model in provenance only. Refusing a response whose `model`
   differs would make every alias or snapshot rename an error; equating them silently
   would hide a model switch. The limit is recorded as an assumption (one ID, one
   model).
5. **OpenAPI extract licensing.** The extract is a few schema objects from
   `openai/openai-openapi` (MIT). Recommendation: keep the extract in the provider's
   `test/fixtures/` with the provenance header and the MIT notice inline, and record it
   in the Piece's grounding; no `registry/providers.json` entry (it is test data, not a
   runtime provider). Main to confirm.
6. **Bounds defaults.** `max_inputs` 1..2048 (OpenAI's array limit), default 128;
   `max_input_bytes` 1..65,536, default 32,768; `max_request_bytes` 1..65,536 (the
   EffectIntent argument bound), default 65,536; norm tolerance `(0, 0.1]`, default
   `1.0e-3`; receive timeout 1..600,000 ms, default 60,000.

## Limits (claims deliberately not made)

No live call and no claim about live behaviour, embedding quality, cost, latency or
rate limits (R5). No chunking, storage, similarity, int8 or binary dtypes, base64
encoding, batch-mode submission, other providers or embedding cache. No durable result
retention (volatile sink, as ai-text). Conformance is to the pinned documented format
only.
