## 1. Contract reading

The live issue is the Contract. I read it as one new ready Piece under the
existing deferred handle `domain/money` (no new Piece ID), with this scope:

- **Pure decisions.** Construction from minor units; same-currency add, subtract,
  compare; allocation with explicit residual placement; rounding at a declared
  scale; registry lookup; parse of untrusted alpha and numeric code strings.
- **Values.** A currency is a registry value with alpha code, numeric code and
  minor-unit exponent, never a bare string. An amount is an integer count of
  minor units scaled by that exponent. No Float in any path.
- **Rejections.** `currency_mismatch{left, right}`, `unknown_currency`,
  `malformed_code`, `retired_currency`, `scale_overflow`.
- **Registry.** Closed and versioned. A retired ISO code stays decodable with a
  `retired` mark; retirement never deletes an entry. The registry version is
  the date of the externally sourced ISO dataset committed beside the test.
- **Non-goals.** Exchange rates, locale formatting, journal posting, payment
  providers, usage units.

Where the task body and the ELZ-050 record overlap they agree. The record adds
"AshMoney only where Ash owns the resource": no Ash consumer exists in this
catalogue, so `ash_money` is not exercised here and is recorded as a future
consumer choice, not a dependency.

Decimal 3.2.0: already in `mix.lock` as a transitive dependency of ecto/postgrex/jason,
Apache-2.0, no further dependencies. It supplies exact decimal-string to integer scaling
and the standard rounding modes (`:half_up`, `:half_even`, `:down`, `:up`, `:floor`,
`:ceiling`, `:half_down`); minor-unit arithmetic itself is BEAM integer arithmetic.

**Decision (proposed): Decimal 3.2.0 as the only library provider; ex_money 6.3.0 not
adopted for `domain/money`.** Concrete reasons, each tied to a row above: no
malformed/unknown distinction, no construction-time scale rejection, a Float path, a
CLDR-dated rather than ISO-dated registry, N.A. codes treated as currencies, and a
non-canonical persisted form. ex_money remains named in the README as the compared
candidate, with the observed behaviour, so a consumer that wants its formatting or
exchange-rate features knows the boundary. This follows the record's "decide by
exercise" condition; it is not a rejection of ex_money as a library.

## 3. Proposed design

Piece `pieces/domain/money/`, kind `owned`, providers `cure`, `elixir`, `decimal`.

### Cure (`cure/elzoo/money.cure`, module `Elzoo.Money`) — pure arithmetic and result schema

- `type Exponent = Minor(Int) | UnknownExponent` (retired ISO codes carry no minor unit in
  the ISO historic list); `type Numeric = NumericCode(Int) | NoNumericCode` (XFO, XFU, XRE
  have none); `type Status = Active | Retired(String)` (withdrawal date `YYYY-MM`).
- `rec Currency { alpha: String, numeric: Numeric, exponent: Exponent, status: Status }`
- `rec Amount { currency: Currency, minor_units: Int }`
- `type Placement = First | Last | Spread`; `rec Allocation { parts: List(Amount), residual: Int }`
- `type Rejection = CurrencyMismatch(Currency, Currency) | InvalidRatios(Atom)`
- `type AmountResult = Ok(Amount) | Rejected(Rejection)`; `type Ordering = Less | Equal | Greater`
- Functions (all `@total`): `same_currency`, `add`, `subtract`, `negate`, `compare`,
  `allocate(total, ratios: List(Int), placement)`. Allocation: part i = floor(total × r_i /
  Σr); residual = total − Σparts; placement puts the residual on the first part, the last
  part, or spreads one minor unit per part from the first.

### Elixir (`lib/elzoo/money.ex`, `lib/elzoo/money/registry.ex`, `lib/elzoo/money/codec.ex`)

- `Elzoo.Money.Registry`: generated literal data from the two ISO XML lists (rules in §4);
  `version/0` = `%{active: "2026-09-17", historic: "2026-01-01"}`; `lookup/1`,
  `lookup_numeric/1`, `entries/0`.
- `Elzoo.Money.parse/1` (alpha): exactly three ASCII letters after no trimming, else
  `{:error, {:malformed_code, input}}`; upper-cased lookup, else `{:error,
  {:unknown_currency, code}}`; returns the canonical registry value, retired included.
  `parse_numeric/1`: exactly three ASCII digits, active entries only (ISO reuses numeric
  codes of retired currencies for current ones: 28 cases in the dataset).
- `from_minor_units/2` (Integer only; any other term is `{:error, {:malformed_amount,
  term}}`), `add/2`, `subtract/2`, `compare/2`, `allocate/3` translate to and from the Cure
  records; the mismatch rejection is `{:error, {:currency_mismatch, %{left: alpha, right:
  alpha}}}`.
- Decimal boundary (Decimal 3.2.0): `from_decimal_string/2` exact, rejecting a scale finer
  than the exponent with `{:error, {:scale_overflow, %{code, exponent, scale}}}`;
  `from_decimal/3` rounds a `%Decimal{}` to minor units with a declared Decimal rounding
  mode (C9 sub-minor-unit rates); `to_decimal_string/1` renders `JPY 1000` as `"1000"` and
  `BHD 1234` as `"1.234"`; `round/3` rounds an amount to a coarser scale with a declared
  mode, rejecting a finer scale with `scale_overflow`. Each of these needs the exponent:
  on a retired currency they return `{:error, {:retired_currency, code}}`. Integer
  arithmetic on retired-currency amounts stays available so a journal can replay history.
- `Elzoo.Money.Codec.encode/1` → `"<ALPHA> <minor_units>"` (for example `"BHD 1234"`),
  `decode/1` the inverse through `parse/1` and `from_minor_units/2`. This is the byte-
  stable form appended through `integration/sql`.

### Dataset beside the test

`test/support/iso4217/list-one.xml` (SIX Group, `Pblshd="2026-09-17"`, 47 491 bytes) and
`test/support/iso4217/list-three.xml` (`Pblshd="2026-01-01"`, 30 638 bytes), committed
verbatim, SHA-256 recorded in the README and in piece.json claims. Source URL:
`https://www.six-group.com/dam/download/financial-information/data-center/iso-currrency/lists/`.

## 4. Registry derivation rules (checked by the dataset test in both directions)

1. Active entry: every `CcyNtry` with a `Ccy` element and a numeric `CcyMnrUnts` (178
   codes; 165 with numeric minor units; 3 country rows without a currency are skipped).
2. Excluded: the 13 codes whose minor unit is `N.A.` (XAG, XAU, XBA, XBB, XBC, XBD, XDR,
   XPD, XPT, XSU, XTS, XUA, XXX). They are funds, metals and test codes, not money.
   `parse/1` answers `unknown_currency` for them; the test asserts this for every such row.
3. Retired entry: every `HstrcCcyNtry` alpha code not present as active (8 codes such as
   EUR and TRY appear in both lists and stay active). Numeric code when present; all
   withdrawal dates kept, latest as the mark. 129 retired codes expected.
4. Both directions: every active row maps to one registry entry with equal numeric code
   and exponent, by alpha and by numeric parse; every registry entry is active in list one
   or retired in list three with equal fields; counts match; the version equals `Pblshd`.

## 6. Evidence plan

**Proof (Cure, pinned 20824806).** Candidate laws, each by reduction or list induction,
over the production functions:
- `add_same_currency_closure`: currency of `add` on two amounts in currency c equals c.
- `add_mismatch_names_both`: with `same = False`, `add_with` returns
  `CurrencyMismatch(left.currency, right.currency)`.
- `subtract_mismatch_names_both`, `compare_mismatch_names_both`: same shape.
- `allocate_part_count`: `length(parts) = length(ratios)` (induction on ratios).
- `allocate_closure`: every part carries the input currency (induction).
- Totality and clean audit of the module as the type/contract check.

**Not proved, finite tests with the limitation recorded.** The allocation sum law
(Σparts = total) and add/subtract inverse laws need `x + (t − x) = t` and `div`/`rem`
identities on native `Int`. Pinned Cure keeps native Int equality neutral on symbolic
values (recorded in `workflow/budget` and `domain/authorization` limits);
`Std.Proof.IntOrder` reasons over the inductive `Int = FromNat | NegativeSuccessor`, a
different representation from the native Int at this Port. If the exercise shows one of
the candidate laws does not reduce either, it moves to this list with the reason.

**Test (ExUnit).** Dataset round-trip both directions (§4); `JPY 1000` ↔ `"1000"`,
`BHD 1234` ↔ `"1.234"`, `"1.2345"` BHD and `"1.005"` EUR → `scale_overflow`; `EUR 1.00`
three ways with each placement sums to 100 and the residual lands where stated; JPY and
BHD allocations; negative totals; ratios `[0, 1]`, `[]`, `[-1]` rejected; HRK decodes as
retired with date `2023-01`, HRK arithmetic works, HRK decimal rendering is
`retired_currency`; `"e$r"`, `""`, `" EUR"`, `"EURO"` → `malformed_code`; `"XYZ"` →
`unknown_currency`; `"978"` → EUR, `"999"` → `unknown_currency`; floats and strings as
minor units → `malformed_amount`; mismatch names both codes; a C9-style check that an
amount in one currency cannot be added into another; rounding `EUR 1005` to scale 0 with
`half_even`/`half_up`/`down`; `from_decimal` of a sub-minor-unit rate × quantity;
persistence: append `Codec.encode` payloads for JPY, BHD, EUR and HRK through
`Elzoo.DurableLog.Postgres` on `ELZOO_TEST_DATABASE_URL`, read back, decode, assert equal
amounts and equal bytes, including the digest check of the store; fails closed without the
database. Negative controls: a mutated allocation that drops the residual, a fixed-hundredth
scaler on JPY, and a Float path, each caught by the tests.

**Upstream contract.** Decimal 3.2.0 rounding modes and `Decimal.new/1` parsing (named,
not proved); Elixir 1.20.4 integer arithmetic and binaries; pinned Cure compiler; OTP
29.1.2 `:xmerl` for reading the dataset in the test only; `integration/sql` and
`state/event-log` Contracts for the persistence test (the Piece has no dependency on them;
the test uses them as the named caller boundary).

**Assumptions recorded.** The SIX Group lists are the ISO 4217 maintenance agency's
publication; the committed files equal the download of 2026-11-08 (SHA-256 recorded); no
claim that the registry is current after that date.

**Operational applicability.** telemetry `not_applicable` (pure callable); config
`supported` per call with no hot reconfiguration (rounding mode, residual placement,
scale), evidence `test/elzoo/money_test.exs`; control `not_applicable`.

## 7. Open questions for the early review

1. **Rejection vocabulary additions.** The Contract names five rejections. The design needs
   three more at the input boundary: `malformed_amount` (non-integer minor units, malformed
   decimal string, NaN/Infinity), `invalid_ratios` (empty, negative or all-zero ratios) and
   `unknown_rounding_mode`. Proposed Contract wording change, item 2 "Outputs":
   before `typed rejections (\`currency_mismatch{left, right}\`, \`unknown_currency\`,
   \`malformed_code\`, \`retired_currency\`, \`scale_overflow\`)`; after `typed rejections
   (\`currency_mismatch{left, right}\`, \`unknown_currency\`, \`malformed_code\`,
   \`malformed_amount\`, \`retired_currency\`, \`scale_overflow\`, \`invalid_ratios\`,
   \`unknown_rounding_mode\`)`. If the main coordinator prefers no wording change, I will
   fold the three into the README limits as input-validation rejections and keep the five
   named ones unchanged in meaning.
2. **Meaning of `retired_currency`.** Proposed: emitted only by operations that need the
   minor-unit exponent (decimal string in/out, rounding, `from_decimal`) on a retired code,
   because the ISO historic list carries no minor unit. Integer arithmetic on retired
   amounts stays allowed so `domain/journal` can replay history; refusing retired codes for
   new postings is the journal's decision, as the Contract says. Alternative: refuse
   construction entirely. I recommend the proposal.
3. **N.A. codes excluded** (XAU, XXX, XTS and ten more) answer `unknown_currency`. The
   alternative is a third entry status. I recommend exclusion, recorded in README and test.
4. **Numeric parse covers active codes only**, because ISO reuses retired numeric codes.
   Retired codes decode by alpha only. Recommend as proposed.
5. **Residual placement set** `First | Last | Spread`. ex_money's "separate remainder" is
   expressible by the caller from `residual`. Recommend the three.
6. **Decimal as a direct dependency** in `mix.exs` with `== 3.2.0` and a `decimal` provider
   entry: confirm this metadata change is in scope (the provider table is shared).
