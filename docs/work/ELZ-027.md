## Contract reading

The slice is the pure decision between an already computed due slot and
one admissible occurrence. Due-instant computation stays upstream. The piece
owns three decisions and the data they return:

1. **Identity.** `occurrence id = f(schedule id, generation, scheduled
   instant)`. The scheduled instant is an absolute Unix millisecond value in
   UTC. The id excludes the arrival instant, the node, the process and the
   delivery id. Two activations of one slot compute one id, so the second
   activation is recorded as a duplicate and creates no second occurrence.
2. **Overlap.** Policy `skip`, `queue(n)` or `replace` decides what a live due
   slot does while occurrences are unsettled: skip records `skipped(overlap)`;
   queue admits while fewer than `n` are unsettled and records
   `skipped(queue_full)` beyond that; replace removes the unsettled occurrence,
   records `replaced(old id)` and admits the new one. The bound is at most one
   unsettled occurrence under skip and replace, at most `n` under queue.
3. **Misfire and offline catch-up.** A due slot is a misfire when
   `slot + misfire_grace_ms < now`, with `now` from the clock port passed as an
   argument. Under skip and replace a misfire is recorded as
   `skipped(misfire)` and never becomes an occurrence; under queue it is
   admitted like a live slot, bounded by `n`. This is the Contract sentence
   "due slots that passed while offline become occurrences only under queue"
   made concrete with one declared grace setting instead of an implicit rule.

Settlement `{acknowledged | released, occurrence id}` removes the occurrence
from the unsettled set and records the kind; a settlement for an unknown or
already settled id is `rejected(unknown_occurrence)`, one for an older
generation is `rejected(stale_generation)`. A delivery `{occurrence id,
payload}` is admitted only when both the id and the payload match an
unsettled occurrence; admission is a query that does not change state, so a
retry presents the same id again and keeps its identity. The payload belongs
to the schedule definition, so it is fixed per generation. A redefinition
needs the same schedule id and a strictly greater generation; it supersedes
every unsettled occurrence of the old generation and records their ids. An
equal or smaller generation is `rejected(stale_generation)` and changes
nothing. The last recorded instant is a per-schedule watermark; every decided
slot advances it, and a slot at or below it is a duplicate.

Timezone and DST are declared, not computed: the upstream calculator maps a
wall-clock rule in a declared zone to UTC instants. Two wall-clock slots that
map to two instants (autumn fall-back) are two occurrences; two that map to one
instant (a shifted non-existent spring slot) collapse to one identity. The
tests use fixed Europe/Berlin 2026 transition instants written as UTC
milliseconds, with no tz database dependency.

Non-goals, unchanged from the Contract: cron parsing, transport, job
execution, durable storage, webhook and app-event triggers.

## Evidence plan

Cure laws over step functions with supplied decisions, the pattern used by
`delivery/backpressure` and `delivery/windowed-idempotency`; classification
stays finite test evidence. Selected laws:

| Law | Statement | Grounds |
| --- | --- | --- |
| `identity_excludes_arrival` | `identify(schedule, slot, arrival_a) ≡ identify(schedule, slot, arrival_b)` for all arrival contexts (now, source label) | identity determinism across activations |
| `duplicate_keeps_state` | `slot_step(state, slot, DuplicateSlot()) ≡ state` | two activations yield one occurrence at the step |
| `skip_overlap_keeps_state` | `slot_step(state, slot, SkipOverlap()) ≡ state` | skip bound |
| `queue_full_keeps_state` | `slot_step(state, slot, QueueFull()) ≡ state` | queue bound at capacity |
| `misfire_keeps_unsettled` | unsettled list after `Misfire()` ≡ `state.unsettled` | misfire never admits |
| `fresh_adds_one` | `count(unsettled after Fresh()) ≡ count(state.unsettled) + 1` | queue bound grows by exactly one |
| `fresh_from_empty_is_singleton` | from an empty unsettled list, `Fresh()` yields `[occurrence(schedule, slot)]` | skip bound of one |
| `replace_is_singleton` | unsettled after `ReplaceOverlap(old)` ≡ `[occurrence(schedule, slot)]` | replace bound of one |
| `stale_redefinition_keeps_state` | `redefine_step(state, schedule, RejectedRedefinition(reason)) ≡ state` | unchanged generation cannot replace pending work |
| `rejected_settlement_keeps_state` | `settle_step(state, id, RejectedSettlement(reason)) ≡ state` | stale settlement changes nothing |

Type/contract check: pinned Cure compiles the module; the test audits the
checked environment (no axioms, holes, unaudited, opaque or not-proven-total
items) and runs a production mutation (`SkipOverlap()` admitting) that must
fail at the law with a conversion failure.

Tests (named scenarios, finite evidence):

- two activations of one slot (same slot presented twice, and from two
  arrival contexts) yield one occurrence and one duplicate record;
- restart with an unsettled occurrence: state rebuilt from the retained
  watermark and unsettled list; the re-presented slot is a duplicate; the
  retry delivery keeps its identity and is admitted;
- each policy in a listed scenario: skip overlap, queue(2) fills then
  `queue_full`, replace supersedes with `replaced(old)`;
- generation conflict: equal generation rejected, greater generation
  supersedes unsettled occurrences, settlement of the old id rejected as
  `stale_generation`;
- stale delivery of a settled occurrence rejected; payload mismatch rejected;
- misfire: slots older than the grace are skipped under skip and replace, and
  admitted under queue up to `n` (offline catch-up flooding bounded);
- DST: Europe/Berlin fall-back gives two identities, a shifted spring slot
  gives one; identity encoding is stable;
- seeded random trace against an independent Elixir model of the bounds
  (unsettled count ≤ 1 or ≤ n) and validation of malformed foreign terms;
- a controllable clock: `now` is an argument; a test clock Agent drives it.

Upstream contracts: pinned Cure, Elixir and OTP semantics. Cron correctness,
timezone mapping and clock accuracy are upstream contracts and are named as
such; crontab 1.2.1 is the recommended calculator in README text only.

Assumptions recorded separately: the caller retains state (volatile until
composed with ELZ-009), supplies due slots in ascending order per call,
settles each occurrence once, and uses consumer-side idempotency for repeated
admitted deliveries.

Operational applicability: telemetry `not_applicable` (pure decisions);
config `supported` (policy, queue bound, misfire grace and payload fixed per
generation at construction; a redefinition names a strictly greater
generation, no hot update of an existing generation); control
`not_applicable` (settlement is domain data, not a lifecycle command).

## Open questions for the early reviewer

1. **crontab 1.2.1 as a pinned provider.** The record names crontab as the
   calculation mechanism if selected. The Contract places due-slot
   computation upstream and names cron parsing a non-goal, so the piece
   contains no code that would call crontab. Proposal: do not add a Hex
   dependency or provider pin; name crontab 1.2.1 in the README as the
   recommended upstream calculator and in the assumption grounding.
   Alternative: a test-only provider pin with one DST scenario computed by
   crontab; this needs `mix.exs` and `registry/providers.json` edits.
   Recommendation: the first option.
2. **Dependency declaration.** The record lists `core/envelope` and
   `delivery/windowed-idempotency` as dependencies of the whole entry. The
   piece uses neither source file, so `piece.json` would declare no
   dependencies and the README records the composition (Envelope result
   data and consumer-side idempotency). Declaring unused dependencies would
   copy source a consumer does not use. Recommendation: no dependencies.
3. **Misfire grace as a declared setting.** The Contract does not name a
   grace value. Proposal above: a required non-negative `misfire_grace_ms`
   per schedule definition, so "passed while offline" is explicit and
   testable. Alternative: treat every slot except the latest in one admission
   batch as a misfire, with no setting. Recommendation: the grace setting.
4. **Catalogue status.** `delivery/trigger` becomes `ready` with
   `coverage: subset` (schedule occurrence slice only; webhook and app-event
   slices stay out of scope and are stated in limits). Confirm this matches
   the manifest convention for a partially covered family.
