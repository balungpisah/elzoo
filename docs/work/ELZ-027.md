## Contract reading

The slice is the pure decision between an already computed due slot and one
admissible occurrence. Due-instant computation, timezone mapping, the clock,
transport, job execution and persistence stay outside the piece.

**Inputs per admission call.** The retained state, a list of due slots (UTC
Unix milliseconds) and an arrival record `{now_unix_ms, available_since_unix_ms}`.
`available_since_unix_ms` is the availability boundary of A1: the instant from
which the scheduler was available to admit slots in this activation.
Validation (Elixir boundary, before any transition): slots are integers in
non-decreasing order; every slot is `<= now_unix_ms` (a later slot refuses the
whole batch as `not_due`); `available_since_unix_ms <= now_unix_ms`; a missing
or malformed boundary refuses the call. Nothing is classified when the call is
refused.

**Decision per slot, in order.**

1. `slot <= last_recorded_unix_ms`: `already_recorded{id}`; state unchanged.
   Under the complete-sequence assumption the slot was decided before. This
   is the second activation of one slot.
2. `slot < available_since_unix_ms`: offline catch-up slot. Under `skip` and
   `replace`: `skipped{slot, offline_catch_up}`, watermark advances to the
   slot, unsettled set unchanged. Under `queue(n)`: admitted as
   `occurrence{id, offline_catch_up}` while fewer than `n` are unsettled,
   otherwise `skipped{slot, queue_full}`; watermark advances either way.
3. Otherwise the slot is live and the overlap policy decides: `skip` with an
   unsettled occurrence gives `skipped{slot, overlap}`; `replace` with an
   unsettled occurrence gives `replaced{old id, new id}` and the new one is
   the only unsettled occurrence; `queue(n)` as in step 2 with origin `live`;
   an empty unsettled set gives `occurrence{id, live}`. The watermark
   advances to the slot in every case.

**Identity.** `id = {schedule id, generation, scheduled instant}`; the
encoding `"<generation>:<instant>:<schedule id>"` is unambiguous because the
two numbers come first. Arrival instant, boundary, node, process and delivery
id are not inputs of the identity function.

**Watermark.** `last_recorded_unix_ms` is supplied at construction (for a new
schedule, the activation instant or the definition instant; the caller
decides and records it) and advances to every decided slot. It is per
schedule, not per generation: a redefinition keeps it, so a slot decided under
an older generation is not re-run under the new one. A slot at or below the
watermark is `already_recorded`; the piece cannot tell a duplicate from an
earlier slot the caller never presented, so the caller must present the
complete ordered sequence (assumption, documented).

**Settlement.** `{acknowledged | released, id}` removes a matching unsettled
occurrence and records the kind. An id of an older generation is
`rejected{stale_generation}`; an id that is not unsettled (never admitted,
already settled, replaced or superseded) is `rejected{unknown_occurrence}`.
Both change nothing. Acknowledged and released are both terminal for the
occurrence; neither cancels work already dispatched.

**Delivery admission.** `{id, payload}` is a query: `admitted` only when the
id is unsettled and the payload equals the occurrence payload; otherwise
`rejected{stale_generation | unknown_occurrence | payload_mismatch}`. State
never changes, so a retry presents the same id and keeps its identity.
Consumer-side deduplication of repeated admitted deliveries is the consumer's
choice (README names `encode_id/1` as the key material).

**Redefinition.** A new definition with the same schedule id and a strictly
greater generation replaces the schedule, empties the unsettled set and records
every displaced id as `redefined{old generation, [ids]}`. An equal or smaller
generation is `rejected{stale_generation}`, a different id
`rejected{schedule_mismatch}`, an invalid definition `rejected{invalid_schedule}`;
all three change nothing, so pending work survives. The generation is the
expected-revision check of a configuration write; the piece compares, the
owner serializes and commits (assumption).

**Serialized state ownership.** Deterministic ids do not serialize activations.
The transitions must be applied by one owner at a time: a single process, or a
store with compare-and-set (ELZ-009 when composed). Two concurrent activations
through such an owner yield one occurrence and one `already_recorded`; without
it, two independent evaluations of the same slot each create the same id and
the caller's dedup is on its own. The test exercises the serialized owner and
sequential replay only.

**Timezone and DST** are declared, not computed: the upstream calculator maps
a wall-clock rule in a declared zone to UTC instants. Two wall-clock slots that
map to two instants (autumn fall-back) are two occurrences; two that map to
one instant collapse to one identity. Fixture instants are written as UTC
milliseconds; the test shows identity behaviour for supplied instants, not the
correctness of any timezone mapping.

Non-goals: cron parsing, transport, job execution, durable storage, webhook
and app-event triggers, cancellation of dispatched work.

## Pure model

```
type OverlapPolicy = Skip | Replace | Queue(Nat)          # Nat = Z | S(Nat)
rec Schedule      { schedule_id: String, generation: Int, policy: OverlapPolicy, payload: String }
rec OccurrenceId  { schedule_id: String, generation: Int, scheduled_unix_ms: Int }
rec Occurrence    { id: OccurrenceId, payload: String }
rec ScheduleState { schedule: Schedule, last_recorded_unix_ms: Int, unsettled: List(Occurrence) }
rec Arrival       { now_unix_ms: Int, available_since_unix_ms: Int }
type Origin = Live | CatchUp
type SlotDecision = Admitted(OccurrenceId, Origin) | AlreadyRecorded(OccurrenceId) | NotDue
                  | SkippedOffline | SkippedOverlap | SkippedQueueFull(Origin) | Replaced(OccurrenceId, OccurrenceId)
rec SlotResult    { state: ScheduleState, decision: SlotDecision }
```

The production transition is `admit_slot(state, slot, arrival) -> SlotResult`.
It is written as a chain of total dispatch functions, each taking the Bool it
needs as an argument computed at the call site
(`recorded = slot <= last`, `not_due = now < slot`, `offline = slot < available_since`,
`room(n, xs)` structural on `Nat` and the list). This is the pattern of
`workflow/approval`: laws generalize each Bool to a variable, prove both
branches, and instantiate with the production expression, so the law is about
the production function by definitional equality, not about a supplied
decision. The Elixir boundary calls only `admit_slot`, `settle`,
`admit_delivery` and `redefine`; it never calls a step with its own decision.

## Selected laws (Cure, checked by the pinned compiler)

Quantification: every law is universally quantified over all values of its
parameters; `schedule id`, `payload` are arbitrary strings, `generation`,
`last`, `slot`, `now`, `available_since` arbitrary `Int`, `xs` an arbitrary
list of occurrences, `n` an arbitrary `Nat`. Admissible configurations are
built by reducible constructors `skip_state`, `replace_state`, `queue_state`
so the policy reduces inside the proof. Hypotheses are the stated preconditions;
Cure checks exactly the statement, nothing about classification correctness
of the comparisons themselves beyond their Bool value.

| Law | Statement (all parameters quantified) | Hypotheses |
| --- | --- | --- |
| `within_one_skip` | `Within(one, unsettled(admit_slot(skip_state(sid, gen, payload, last, xs), slot, arrival)))` | `Within(one, xs)` |
| `within_one_replace` | same for `replace_state` | `Within(one, xs)` |
| `within_bound_queue` | `Within(n, unsettled(admit_slot(queue_state(n, sid, gen, payload, last, xs), slot, arrival)))` | `Within(n, xs)` |
| `recorded_keeps_state` | `state_of(admit_slot(state, slot, arrival)) ≡ state` | `slot <= last_of(state) ≡ True()` |
| `not_due_keeps_state` | `state_of(admit_slot(state, slot, arrival)) ≡ state` | `slot <= last ≡ False()`, `now < slot ≡ True()` |
| `offline_skip_keeps_unsettled` | `unsettled(admit_slot(skip_state(...), slot, arrival)) ≡ xs` and watermark `≡ slot` | `slot <= last ≡ False()`, `now < slot ≡ False()`, `slot < available_since ≡ True()` |
| `offline_replace_keeps_unsettled` | same for `replace_state` | same |
| `live_identity_skip` | `unsettled(admit_slot(skip_state(sid, gen, payload, last, []), slot, arrival)) ≡ [Occurrence{identify(sid, gen, slot), payload}]` | the three live-slot hypotheses |
| `live_identity_replace` | `unsettled(admit_slot(replace_state(sid, gen, payload, last, xs), slot, arrival)) ≡ [Occurrence{identify(sid, gen, slot), payload}]` | the three live-slot hypotheses |
| `live_identity_queue` | `unsettled(admit_slot(queue_state(n, ..., xs), slot, arrival)) ≡ [Occurrence{identify(sid, gen, slot), payload} | xs]` | the three live-slot hypotheses and `room(n, xs) ≡ True()` |
| `identity_is_schedule_and_slot` | `id_of(created(state, slot)) ≡ identify(schedule_id_of(state), generation_of(state), slot)` for the production constructor used by every admitting branch | none |
| `stale_redefinition_keeps_state` | `state_of(redefine(state, schedule)) ≡ state` | `greater_generation(state, schedule) ≡ False()` |
| `redefinition_records_displaced` | `displaced(redefine(state, schedule)) ≡ ids(unsettled(state))` and the new unsettled set `≡ []` | `valid ≡ True()`, `same_id ≡ True()`, `greater_generation ≡ True()` |
| `unknown_settlement_keeps_state` | `state_of(settle(state, id, kind)) ≡ state` | `find(id, unsettled(state)) ≡ None()` |
| `stale_settlement_keeps_state` | `state_of(settle(state, id, kind)) ≡ state` | `id.generation < generation_of(state) ≡ True()` |
| `absent_delivery_rejected` | `admitted(admit_delivery(state, id, payload)) ≡ False()` | `find(id, unsettled(state)) ≡ None()` |
| `mismatched_delivery_rejected` | `admitted(admit_delivery(state, id, payload)) ≡ False()` | `find(id, unsettled(state)) ≡ Some(found)`, `text_equal(payload_of(found), payload) ≡ False()` |

Supporting lemmas: `Within indices (n: Nat, xs: List(Occurrence))` with
`within_nil : Within(n, [])` and `within_cons : Within(n, t) -> Within(S(n), [h | t])`;
`room_true_within(n, xs, x, h: room(n, xs) ≡ True()) -> Within(n, [x | xs])`
by induction on `n` and `xs`; `queue_step_within` over the generalized Bool.
The identity laws state that the admitted occurrence carries exactly
`identify(schedule id, generation, slot)` and the schedule payload for every
arrival satisfying the preconditions, so `now`, `available_since` and any
process context cannot enter the identity. `admit_delivery` changes no state
by its type (it returns a decision only).

Limits of the proofs: the Bool comparisons (`<=`, `<` on `Int`, string
equality) are hypotheses, not reduced; the laws cover every state reachable by
the Elixir boundary only together with the boundary's validation (tested); no
law speaks about several calls, durability or concurrency.

## Type/contract check and negative controls

The pinned Cure compiler (`Cure.Compiler.check_source` with the project source
roots) checks the module; the test audits the environment (no axioms, holes,
unresolved, unaudited, opaque or not-proven-total items). Negative controls,
each compiled separately and required to fail at the named law with a
conversion failure:

- production queue placement mutated to admit at capacity (`room(Z, xs) = true`): `within_bound_queue` fails;
- production skip placement mutated to append when an occurrence is unsettled: `within_one_skip` fails;
- production identity mutated (`generation + 1` in `created`): `identity_is_schedule_and_slot` and `live_identity_*` fail;
- production watermark dispatch mutated so an already recorded slot is admitted: `recorded_keeps_state` fails;
- production redefinition mutated so an equal generation replaces pending work: `stale_redefinition_keeps_state` fails.

The Elixir boundary validates foreign terms (record shapes, policy, Peano
bound range, instants, ordering, boundary) and is tested separately.

## Tests (named scenarios, finite evidence)

1. two activations of one slot: sequential replay (second call) and two
   concurrent processes through one serialized test owner (a GenServer in the
   test file) give one `occurrence` and one `already_recorded`; conclusion
   scoped to serialized ownership;
2. restart with an unsettled occurrence: `restore/3` from watermark and
   unsettled ids; re-presented slot `already_recorded`; retry delivery
   admitted with the same id; settlement then clears it; a later duplicate
   delivery rejected as `unknown_occurrence`;
3. skip: overlap skipped, settled then next slot admitted;
4. queue(2): two admitted, third `queue_full`, settlement frees one, next admitted;
5. replace: `replaced{old, new}`, old delivery and old settlement rejected;
6. offline catch-up: slots before the boundary skipped under skip and replace
   (watermark advances), admitted under queue up to `n` with origin
   `offline_catch_up`, excess `queue_full`; a live slot after an offline slot
   in the same batch follows the overlap policy;
7. clock and ordering edges: slot equal to the boundary is live; slot equal to
   `now` is due; slot after `now` refuses the batch; `available_since > now`
   refuses; unsorted batch refuses; equal slots in one batch give one
   occurrence and one `already_recorded`; initial watermark excludes earlier
   slots;
8. generation: equal and lower generation rejected with pending work intact;
   greater generation records every displaced id and empties the set;
   settlement and delivery of displaced ids rejected `stale_generation`;
   watermark kept across redefinition;
9. delivery: payload mismatch rejected; unknown id rejected; admitted delivery
   leaves state unchanged (same term);
10. identity: `identify/3` and `encode_id/1` stable; fall-back fixture (two
    instants, two ids), shifted spring fixture (one instant, one id);
11. configuration: invalid policy, bound outside 1..1024, empty id, negative
    generation, non-binary payload, malformed states refused;
12. seeded random trace over the three policies against an independent
    Elixir model of the unsettled bound and the watermark;
13. Cure audit and the five negative controls.

## Operational applicability

- Telemetry `not_applicable`: pure decisions without lifecycle; the owner
  instruments.
- Config `supported`: policy `skip | replace | queue(n)` with `n` in 1..1024
  (count of unsettled occurrences, no unit), fixed for a generation at
  construction or restore; changed only by `redefine/2` with a strictly greater
  generation, which supersedes pending occurrences; no hot update of an existing
  generation; evidence: scenarios 8 and 11 in the in-bundle test. Payload and
  instants are data, not Config. External serialization of the redefinition
  commit is an assumption.
- Control `not_applicable`: settlement and redefinition are domain data
  transitions, not lifecycle commands; no pause, drain or resume exists.
