## Named job flow (one exemplar)

**Tally job.** A caller submits a Work Item `{job_key, input}` where `input` is
a bounded list of integers; the Assembly durably records the request, enqueues
one Oban job through the ELZ-009 outbox, and an attempt computes the result
with a consumer-supplied **pure** handler (the exemplar handler sums the list;
test handlers inject transient/permanent failures). Completion commits the
result and a `completed` outbox item in one ELZ-009 append. The flow is:

    submit(job_key, input, policy, deadline)
      -> append [requested] + outbox{jobs}                (one ELZ-009 CAS commit)
    relay: pending{jobs} -> Oban.insert(unique job_key) -> ack (only on a persisted job id)
    Oban worker attempt:
      Writer(stream "job/<job_key>") init -> fold Run -> Cure step(StartAttempt)
        -> append [attempt_started{n}]                    (CAS)
        -> handler(input) (pure, no Effect)
        -> Cure step(AttemptCompleted | AttemptFailed)
        -> append [succeeded{n, result}] + outbox{completed}  | [attempt_failed{n}] | terminal record
      -> Oban return :ok | {:error, retry} | {:cancel, terminal}
    cancel(job_key) -> Cure step(CancelRequested) -> append [cancelled] (CAS) -> Oban.cancel_job (best effort)

This is one honest exemplar of durable attempts over a pure computation. It
is not a workflow engine: one Run per Work Item, one step, no branching, no
compensation, no dependencies between jobs.

## Work Item, Run and Attempt (kept distinct)

| Concept | In this Assembly | Identity | Durable where |
| --- | --- | --- | --- |
| Work Item | the submitted request and its acceptance criterion: "a result for `input` is committed before `deadline`" | `job_key` (caller-supplied, 1..160 bytes UTF-8, no NUL; stream = `"job/" <> job_key`) | `requested` record (sequence 1 of the Run stream) |
| Run | the single execution lifecycle fulfilling that Work Item; phase, attempts made, terminal outcome | the Run stream `job/<job_key>`; one Run per Work Item in this exemplar (no re-run after a terminal phase) | ELZ-009 event log records, folded |
| Attempt | one try within the Run | `<job_key>/attempt/<n>`, `n` = 1..max_attempts, assigned by the fold, never by the provider | `attempt_started{n}` / `attempt_failed{n}` / terminal record citing `n` |
| Provider job | Oban's execution vehicle for the Run | Oban `id` and Oban `attempt` | `oban_jobs` row (upstream) |

Oban's `attempt` is **not** the Run's attempt number: an Oban attempt that
dies before `attempt_started` commits consumes an Oban attempt but no Run
attempt, and a rescued Oban attempt begins a new Run attempt that fences the
old one. The Run record is the authority for the attempt budget, deadline and
outcome; Oban is the authority only for when a worker is invoked.

## Records and schemas (R1)

All records are ELZ-009 `state/event-log` records on stream `job/<job_key>`
with `schema_version = 1`, payloads encoded with Jason (opaque bytes to the
log; the digest covers the stored bytes, so canonical JSON is not required).
Fold `kinds` (all state-bearing): `requested`, `attempt_started`,
`attempt_failed`, `succeeded`, `failed`, `exhausted`, `expired`, `cancelled`.
Outbox destinations: `jobs` (relay to Oban), `completed` (left pending for a
downstream consumer; not dispatched by this Assembly).

| Kind | Payload fields (v1) | Written by |
| --- | --- | --- |
| `requested` | `job_key`, `input` (proposed bounds: ≤ 64 ints, each in ±2^53), `max_attempts` (proposed 1..20), `base_backoff_ms`, `max_backoff_ms` (ELZ-006 `policy/1` bounds), `deadline_ms` (absolute Unix ms, > submit time), `submitted_ms` | `submit/4`, expected revision 0 |
| `attempt_started` | `attempt` n, `oban_job_id`, `oban_attempt`, `started_ms` | worker, StartAttempt → BeginAttempt |
| `attempt_failed` | `attempt` n, `class` ∈ `transient`/`permanent`, `retry_after_ms` | worker, AttemptFailed → ScheduleRetry |
| `succeeded` | `attempt` n, `result` (integer), `finished_ms` | worker, AttemptCompleted → RecordSuccess (+ `completed` outbox item) |
| `failed` / `exhausted` / `expired` | `attempt` n (0 if none started), `reason` (bounded atom-string from a fixed table) | worker, matching Record* action |
| `cancelled` | `attempt` n, `requested_by` (opaque bounded string; not authentication) | `cancel/2` |

Fold model (Elixir projection): `%{phase, job_key, input, policy, deadline_ms,
attempts_made, last_attempt, result}`. Unknown kinds, other versions, or a
record inconsistent with the phase (e.g. `attempt_started{n}` with `n ≠
attempts_made + 1`) are ELZ-009 interior corruption via the reducer-failure
path: damaged prefix, Writer refuses (`{:stop, {:replay_damaged, _}}`).

Oban job `args`: `%{"v" => 1, "job_key" => key}` only; the worker never trusts
args beyond locating the Run stream. Unique options: `keys: [:job_key],
period: :infinity, states: :all` on queue `elzoo_jobs` (configurable name).

## Pure decisions in Cure (`workflow/state-machine`, R2)

`Elzoo.JobRun` (`cure/elzoo/job_run.cure`, BEAM `:"Cure.Elzoo.JobRun"`)
reuses `Elzoo.RetryPolicy` from the ready `delivery/retry-timeout` Piece
unchanged: the shell computes `RetryPolicy.decide(policy, attempts_made,
class)` and supplies the resulting `RetryDecision`; `JobRun.step/4` consumes
it. Integer comparisons (deadline vs now, attempts vs budget) stay outside the
quantified laws, exactly as in ELZ-009/ELZ-006: they are test-grounded.

    type RunPhase  = RunRequested | RunActive | RunWaiting | RunSucceeded | RunFailed | RunExhausted | RunExpired | RunCancelled
    type RunInput  = StartAttempt | AttemptCompleted | AttemptFailed | CancelRequested
    type RunAction = BeginAttempt | RecordSuccess | ScheduleRetry | RecordFailure | RecordExhausted | RecordExpired | RecordCancel | NoChange
    rec  RunStep   phase: RunPhase, action: RunAction
    @total @reducible fn step(phase, input, expired: Bool, retry: RetryDecision) -> RunStep

Transition table (terminal = Succeeded, Failed, Exhausted, Expired, Cancelled):

| Phase | Input | Result |
| --- | --- | --- |
| terminal | any | same phase, NoChange |
| Requested / Waiting | CancelRequested | Cancelled, RecordCancel |
| Requested / Waiting | StartAttempt | expired → Expired/RecordExpired; else Active/BeginAttempt |
| Requested / Waiting | AttemptCompleted / AttemptFailed | unchanged, NoChange (no active attempt; stale result) |
| Active | CancelRequested | Cancelled, RecordCancel |
| Active | AttemptCompleted | expired → Expired; else Succeeded/RecordSuccess |
| Active | AttemptFailed | expired → Expired; DecideRetry → Waiting/ScheduleRetry; DecideExhausted → Exhausted; DecidePermanent/Settle/Unresolved → Failed |
| Active | StartAttempt (rescued or duplicate execution; previous attempt's outcome unrecorded) | expired → Expired; DecideRetry → Active/BeginAttempt (n+1, fences n); DecideExhausted → Exhausted; other → Active/NoChange |

For `Active + StartAttempt` the shell supplies `decide(policy, attempts_made,
ClassRetryable)`: an unrecorded attempt of a **pure** handler dispatched
nothing, so it is retryable. This is the only place the handler-purity
assumption enters the decision; an effectful handler would need ELZ-023.

Selected laws (all compiled and audited in the pre-review probe):

| ID | Law (quantified over the unfixed arguments) |
| --- | --- |
| L1–L5 | `succeeded/failed/exhausted/expired/cancelled_absorbing`: `step(T, input, expired, retry) = keep(T)` for each terminal `T` |
| L6–L7 | `cancel_from_active`, `cancel_from_waiting`: phase is Cancelled for every `expired`, `retry` |
| L8–L9 | `expired_never_begins_waiting`, `expired_never_begins_active`: StartAttempt with `expired = True` yields RecordExpired, never BeginAttempt, for every `retry` |
| L10 | `exhausted_never_begins`: Active + StartAttempt + DecideExhausted → Exhausted |
| L11 | `completion_without_attempt_ignored`: Waiting + AttemptCompleted is NoChange for every `expired`, `retry` |
| L12 | `late_success_expires`: Active + AttemptCompleted + expired → Expired for every `retry` |
| L13 | `permanent_not_retried`: Active + AttemptFailed + DecidePermanent → Failed |

Negative controls (must fail compilation): a false law (`succeeded_absorbing`
claiming `keep(RunActive())`), a production mutation (Cancel from Succeeded →
Cancelled) and a second mutation (DecideExhausted on StartAttempt → begin).

The laws do **not** prove the shell's deadline/budget comparisons, the
mapping of actions to records, the fold, CAS behaviour or any provider.

Erasure observed: nullary constructors → atoms; `RunStep` → `{:RunStep,
phase, action}` (e.g. `{:RunStep, :RunWaiting, :ScheduleRetry}`).

## Execution split (OTP / provider)

- **Oban 2.24.2** (upstream, reused): job persistence in `oban_jobs`,
  `FOR UPDATE SKIP LOCKED` claim, retry staging/backoff timing, unique insert,
  `cancel_job`, orphan rescue (`Oban.Lifeline`, time-based). Consumer owns the
  Oban instance, its config, queues and `Oban.Migration` (called directly; no
  Elzoo wrapper).
- **ELZ-009 Store/Writer** (reused unchanged): Run records, CAS on the head
  revision as the only fencing for Run writes, outbox commit and ack.
- **Elzoo-owned shell** (`integration/jobs` + `assembly/durable-job`): the
  relay, the Oban worker translation, the fold, record mapping, deadline and
  budget comparisons, `submit/cancel/status`.
- Per attempt, the worker starts a short-lived `Elzoo.DurableLog.Writer` for
  the Run stream (linked, stopped at return). Concurrent Writers on one stream
  (stale and new attempt) are allowed by the ELZ-009 Contract; the Store CAS
  arbitrates. On `conflict` the worker refolds and re-decides (bounded to
  `max_attempts + 2` rounds, then `{:error, :contended}` to Oban). On
  `indeterminate` the Writer stops; the worker returns `{:error,
  :indeterminate}` and the next Oban attempt rebuilds from the store (no
  reconcile request is persisted; CAS arbitrates any late commit).
- Retry timing: on ScheduleRetry the worker returns `{:error, :retry}` and
  the worker `backoff/1` returns `ceil(RetryTimeout.backoff(policy, n) /
  1000)` seconds (Oban schedules in whole seconds). Oban `max_attempts` =
  Run `max_attempts + provider_slack` (default slack 2) so crashes before
  `attempt_started` do not exhaust the provider first (D-C).
- Exhaustion/terminal: the worker returns `{:cancel, phase}` so Oban stops.

## Provider selection (R5, R10)

Selection checks (job boundary), run in the pre-review probes:

| ID | Check |
| --- | --- |
| J1 | persisted job executes after the executing instance is stopped/killed and a fresh instance starts |
| J2 | attempt count persists across that restart and is not reset |
| J3 | bounded retry reaches a terminal state at the budget |
| J4 | duplicate enqueue is deduplicated, sequentially and concurrently; behaviour when the dedup lock holder rolls back |
| J5 | cancellation of a scheduled and of an executing job |
| J6 | two concurrent claimers never execute one job twice (no rescue) |
| J7 | a stale executor (rescued while alive) cannot record completion over the new attempt |
| J8 | real OS-process death mid-attempt is recovered |
| J9 | enqueue can commit atomically with a caller's domain write |
| J10 | a completed step is not re-executed on retry |

Selection rule (formulated before the probes ran, recorded here with their
results; review it on its merits): choose the provider that passes J1–J8 at
its own boundary with the fewest consumer dependencies; J9/J10 are recorded
because they decide how the Assembly composes, not whether the provider is
usable. If Oban and AshOban both pass, select Oban directly: the Run record
already lives in the ELZ-009 Store, and ADR-0005 forbids requiring Ash for
unrelated pure Pieces or wrapping its APIs. A failed check is recorded, not
weakened.

**Selection: Oban 2.24.2, used directly, disposition `adapt`.** Reuse: queue
persistence, claim, retry staging, uniqueness, cancellation, rescue. Adapt:
Elzoo owns the Run record (budget, deadline, outcome) because Oban's attempt
is per job, its rescue causes concurrent execution (documented upstream:
"may transition jobs that are genuinely executing and cause duplicate
execution"), and its uniqueness answer is not a durable fact under lock
contention (O3). AshOban is not rejected on correctness; its trigger model
would duplicate the Run record as an Ash resource and resets the per-record
budget unless the resource models it (A2). Reactor is rejected for the
attempt boundary (O9) and is not needed for a one-step flow.

### Enqueue: outbox relay, not same-transaction (decision D-B)

S1/S2 show that calling the ELZ-009 Postgres `append` inside a caller
transaction breaks its Contract: `committed` would no longer mean the
provider's COMMIT returned. Supporting that needs a new Store ID with a
different commit-point Contract, so this proposal does **not** do it. The
existing Contract is used instead: `submit` appends `requested` with an outbox
item `jobs`; a relay offers pending items, calls `Oban.insert` with the unique
key, and **acks only when the insert returned a persisted job id** (`id` not
nil), whether new or `conflict?: true` with an id. `conflict?: true, id: nil`
(O3: lock held by an uncommitted inserter) leaves the item pending for the
next offer. A crash between insert and ack re-offers; uniqueness returns the
existing job (S3). Relay delivery is at-least-once; the Run fold makes a
duplicate job harmless (DJ12).

## Persistence, restart and duplicates (R4, R8)

- **Attempt count and absolute deadline persist with the Run**
  (`requested.deadline_ms`, `attempts_made` folded from `attempt_started`).
  No bounded-attempt claim depends on one process lifetime. A restart never
  resets the budget; this is a listed negative scenario (DJ10), and the
  AshOban comparison (A2) shows how a per-job budget does reset.
- Deadline clock: the shell compares `deadline_ms` with the executing node's
  `System.os_time(:millisecond)` (injectable `now_ms/0`). Assumption: bounded
  clock skew between nodes; no store-clock claim (D-D).
- Duplicate submit: `requested` at expected revision 0; `conflict` → re-read:
  same `input`/policy/deadline → `{:duplicate, status}`; different →
  `{:error, :job_key_conflict}`. Duplicate Oban job: folded terminal Run →
  `{:cancel, phase}` without a new record; active Run → StartAttempt (bounded by
  budget). Exactly one terminal record per Run is guaranteed by CAS, not by
  Oban uniqueness.
- Cancellation: `cancel/2` appends `cancelled` by CAS; then best-effort
  `Oban.cancel_job`. An executing attempt's later `succeeded` append conflicts
  and the worker sees the terminal phase. Cancel after success returns
  `{:error, {:terminal, :succeeded}}`. Cancellation cannot undo a committed
  `succeeded` or an outbox item already consumed downstream.

Write/command results exposed by the Assembly:

| Call | Results |
| --- | --- |
| `submit/4` | `{:ok, status}`, `{:duplicate, status}`, `{:error, :job_key_conflict}`, `{:error, {:invalid, field}}`, `{:indeterminate, info}` (ELZ-009 meaning; caller must re-read, never blind resubmit with different input) |
| `cancel/2` | `{:ok, :cancelled}`, `{:error, {:terminal, phase}}`, `{:indeterminate, info}`, `{:error, :not_found}` |
| `status/2` | `{:ok, %{phase, attempts_made, deadline_ms, result, provider: oban_state \| :absent}}`, `{:ok, %{..., stalled: true}}` when the Run is non-terminal but its Oban job is terminal or absent after relay ack, `{:error, :damaged \| :unavailable}` |
| worker return | `:ok`, `{:error, :retry \| :indeterminate \| :contended}`, `{:cancel, terminal_phase \| :damaged \| :unsupported_version}` |

## External Effects (R7)

No dispatched external Effect exists in this exemplar. The handler is a pure,
deterministic function supplied by the consumer (assumption, not enforced);
the only writes are ELZ-009 CAS appends. The `completed` outbox item is left
pending for a downstream consumer (ELZ-011) and is not dispatched here.
Consequently "no re-execution of a dispatched Effect on retry" holds
vacuously for this exemplar and is **not** a general claim: a handler that
performs an Effect is outside this Contract and must use ELZ-023
`delivery/effect-intent` (not adopted). O9 records that Reactor steps inside a
retried job do re-execute, so Reactor does not supply that property either.

## Schema evolution (R3, R6, R9) — decision D-E: explicitly deferred

Chosen option: **defer**, with this Contract. Every Run record carries
`schema_version = 1`, the fold declares `versions: [1]`, and Oban args carry
`"v" => 1`. Any other version is refused, never upcast: a record version is
ELZ-009 interior corruption (damaged prefix; Writer refuses; worker returns
`{:cancel, :damaged}`); an unknown args `v` returns `{:cancel,
:unsupported_version}`. `state/schema-evolution` stays **planned**; no upcast,
golden corpus, frozen reader or `unwritable_version` is claimed, and the P2
catalogue row's "schema upcast" is reported as not delivered.

Why this is the smallest honest option: only one format version exists. A v2
invented only to exercise an upcaster would be a placeholder evolution with no
consumer (AGENTS.md: no placeholder implementations), and its corpus would be
written by a "v1 writer" that never shipped. ELZ-009 already fails closed on
undeclared versions. When the first real format change is needed, its task
must meet R6/R9 in full: a corpus written by each version while current, pinned
bytes, mix check failing on missing/changed/unpinned corpora, a frozen copy of
the older reader, and `unwritable_version` for an older pinned writer.

## ELZ-028 evidence

Question: does Oban 2.24.2's own ownership contract satisfy ELZ-028's lease
invariants? Grounding is per row: **probe** (scratch test executed here),
**source** (read in `deps/oban`, `lib/oban/engines/basic.ex`,
`lib/oban/lifeline.ex`; not executed for that property) or **upstream doc**.

| ELZ-028 invariant | Oban's own contract | Grounding | ELZ-010 composition |
| --- | --- | --- | --- |
| a lease never authorizes a write; the record revision does | Oban fences only its own ack: `WHERE id = ? AND state IN ('executing') AND attempted_at = ?`. Ack returns `:ok` either way; the worker is not told it was fenced. Business writes by the stale worker are not fenced at all | probe O5 (stale ack left job `executing`, attempt 2; stale attempt wrote its `finish` row); source `ack_query/2` | Run writes fenced by ELZ-009 head-revision CAS: stale `completed` at revision 2 → `{:conflict, %{expected: 2, observed: 3}}` (probe S4) |
| stale-owner write fenced by revision, never by timestamp | fence value is `attempted_at` (node-clock timestamp equality), not a revision | source; O5 | revision CAS (S4) |
| a late renewal cannot revive a lease | no renewal/heartbeat in Oban OSS; rescue is purely time-based and also rescues live jobs | upstream doc (Lifeline moduledoc); O5 via `Oban.Engine.rescue_jobs/3`, O10 via Lifeline | not needed for safety: duplicate execution of a pure attempt is accepted and bounded by the Run budget |
| concurrent claims are disjoint | `FOR UPDATE SKIP LOCKED` subquery + `UPDATE … RETURNING` | probe O6 (300/300 once, two producers; finite); source `fetch_jobs/3` | inherited from Oban |
| expiry judged by the store clock | **not satisfied**: `attempted_at` is set from the fetching node's `DateTime.utc_now()`; Lifeline's cut is the rescuing node's `utc_now() - rescue_after` | source only (no clock-skew experiment) | deadline uses node clock as an explicit assumption (D-D) |
| stale/ambiguous (future/unreadable timestamp) fail closed with an attributable release | no status classification; a future `attempted_at` is simply not yet rescued | source inference, not tested | `status/2` reports `stalled`; no automatic takeover |
| terminal state releases atomically | `complete_job` is one guarded UPDATE | source | terminal Run record is one CAS append |

**Verdict:** Oban's own ownership contract does **not** satisfy ELZ-028's
invariants (timestamp fence instead of revision, node clock, no renewal,
time-only rescue of live jobs). ELZ-010 does not depend on a lease for its
safety claims, because Run writes are revision-fenced by the ELZ-009 Store
and attempts are pure; it accepts concurrent duplicate execution after a
rescue. Recommendation (open decision D-F): record on #45 that its trigger
condition is met, and keep it demand-led until an Assembly needs exclusive
execution or an effectful attempt (e.g. C5).

## Limits

No exactly-once execution or delivery: attempts of a pure handler may run
concurrently after a rescue; relay and `completed` offers are at-least-once.
No distributed scheduler, consensus, lease, cron/recurring schedules, workflow
engine, DAG, saga/compensation or Reactor workflow. No schema upcast. No
external Effect is dispatched or reconciled. Deadlines use the node clock.
Oban OSS semantics only (no Pro Lifeline/uniqueness). Finite tests on one local
PostgreSQL are not proofs of all executions, disk durability or replication;
those remain PostgreSQL's and Oban's contracts under the consumer's
configuration.

```cure
# SPDX-License-Identifier: Apache-2.0
mod Elzoo.JobRun
  use Std.Option
  use Elzoo.RetryPolicy

  type RunPhase = RunRequested | RunActive | RunWaiting | RunSucceeded | RunFailed | RunExhausted | RunExpired | RunCancelled
  type RunInput = StartAttempt | AttemptCompleted | AttemptFailed | CancelRequested
  type RunAction = BeginAttempt | RecordSuccess | ScheduleRetry | RecordFailure | RecordExhausted | RecordExpired | RecordCancel | NoChange

  rec RunStep
    phase: RunPhase
    action: RunAction

  @total true
  @reducible
  fn keep(phase: RunPhase) -> RunStep = RunStep{phase: phase, action: NoChange()}

  @total true
  @reducible
  fn expire() -> RunStep = RunStep{phase: RunExpired(), action: RecordExpired()}

  @total true
  @reducible
  fn cancel() -> RunStep = RunStep{phase: RunCancelled(), action: RecordCancel()}

  @total true
  @reducible
  fn begin() -> RunStep = RunStep{phase: RunActive(), action: BeginAttempt()}

  @total true
  @reducible
  fn idle(phase: RunPhase, input: RunInput, expired: Bool) -> RunStep =
    match input
      CancelRequested() -> cancel()
      StartAttempt() ->
        match expired
          True() -> expire()
          False() -> begin()
      AttemptCompleted() -> keep(phase)
      AttemptFailed() -> keep(phase)

  @total true
  @reducible
  fn after_failure(retry: RetryDecision) -> RunStep =
    match retry
      DecideRetry() -> RunStep{phase: RunWaiting(), action: ScheduleRetry()}
      DecideExhausted() -> RunStep{phase: RunExhausted(), action: RecordExhausted()}
      DecidePermanent() -> RunStep{phase: RunFailed(), action: RecordFailure()}
      DecideSettle() -> RunStep{phase: RunFailed(), action: RecordFailure()}
      DecideUnresolved() -> RunStep{phase: RunFailed(), action: RecordFailure()}

  @total true
  @reducible
  fn restart(retry: RetryDecision) -> RunStep =
    match retry
      DecideRetry() -> begin()
      DecideExhausted() -> RunStep{phase: RunExhausted(), action: RecordExhausted()}
      DecidePermanent() -> keep(RunActive())
      DecideSettle() -> keep(RunActive())
      DecideUnresolved() -> keep(RunActive())

  @total true
  @reducible
  fn active(input: RunInput, expired: Bool, retry: RetryDecision) -> RunStep =
    match input
      CancelRequested() -> cancel()
      AttemptCompleted() ->
        match expired
          True() -> expire()
          False() -> RunStep{phase: RunSucceeded(), action: RecordSuccess()}
      AttemptFailed() ->
        match expired
          True() -> expire()
          False() -> after_failure(retry)
      StartAttempt() ->
        match expired
          True() -> expire()
          False() -> restart(retry)

  @total true
  @reducible
  fn step(phase: RunPhase, input: RunInput, expired: Bool, retry: RetryDecision) -> RunStep =
    match phase
      RunRequested() -> idle(RunRequested(), input, expired)
      RunWaiting() -> idle(RunWaiting(), input, expired)
      RunActive() -> active(input, expired, retry)
      RunSucceeded() -> keep(RunSucceeded())
      RunFailed() -> keep(RunFailed())
      RunExhausted() -> keep(RunExhausted())
      RunExpired() -> keep(RunExpired())
      RunCancelled() -> keep(RunCancelled())

  @total true
  @reducible
  fn phase_of(s: RunStep) -> RunPhase = s.phase

  @total true
  @reducible
  fn action_of(s: RunStep) -> RunAction = s.action

  fn succeeded_absorbing(input: RunInput, expired: Bool, retry: RetryDecision) -> Equivalent(RunStep, step(RunSucceeded(), input, expired, retry), keep(RunSucceeded())) =
    reflexive(keep(RunSucceeded()))

  fn failed_absorbing(input: RunInput, expired: Bool, retry: RetryDecision) -> Equivalent(RunStep, step(RunFailed(), input, expired, retry), keep(RunFailed())) =
    reflexive(keep(RunFailed()))

  fn exhausted_absorbing(input: RunInput, expired: Bool, retry: RetryDecision) -> Equivalent(RunStep, step(RunExhausted(), input, expired, retry), keep(RunExhausted())) =
    reflexive(keep(RunExhausted()))

  fn expired_absorbing(input: RunInput, expired: Bool, retry: RetryDecision) -> Equivalent(RunStep, step(RunExpired(), input, expired, retry), keep(RunExpired())) =
    reflexive(keep(RunExpired()))

  fn cancelled_absorbing(input: RunInput, expired: Bool, retry: RetryDecision) -> Equivalent(RunStep, step(RunCancelled(), input, expired, retry), keep(RunCancelled())) =
    reflexive(keep(RunCancelled()))

  fn cancel_from_active(expired: Bool, retry: RetryDecision) -> Equivalent(RunPhase, phase_of(step(RunActive(), CancelRequested(), expired, retry)), RunCancelled()) =
    reflexive(RunCancelled())

  fn cancel_from_waiting(expired: Bool, retry: RetryDecision) -> Equivalent(RunPhase, phase_of(step(RunWaiting(), CancelRequested(), expired, retry)), RunCancelled()) =
    reflexive(RunCancelled())

  fn expired_never_begins_waiting(retry: RetryDecision) -> Equivalent(RunAction, action_of(step(RunWaiting(), StartAttempt(), True(), retry)), RecordExpired()) =
    reflexive(RecordExpired())

  fn expired_never_begins_active(retry: RetryDecision) -> Equivalent(RunAction, action_of(step(RunActive(), StartAttempt(), True(), retry)), RecordExpired()) =
    reflexive(RecordExpired())

  fn exhausted_never_begins() -> Equivalent(RunPhase, phase_of(step(RunActive(), StartAttempt(), False(), DecideExhausted())), RunExhausted()) =
    reflexive(RunExhausted())

  fn completion_without_attempt_ignored(expired: Bool, retry: RetryDecision) -> Equivalent(RunStep, step(RunWaiting(), AttemptCompleted(), expired, retry), keep(RunWaiting())) =
    reflexive(keep(RunWaiting()))

  fn late_success_expires(retry: RetryDecision) -> Equivalent(RunPhase, phase_of(step(RunActive(), AttemptCompleted(), True(), retry)), RunExpired()) =
    reflexive(RunExpired())

  fn permanent_not_retried() -> Equivalent(RunPhase, phase_of(step(RunActive(), AttemptFailed(), False(), DecidePermanent())), RunFailed()) =
    reflexive(RunFailed())
end
```
