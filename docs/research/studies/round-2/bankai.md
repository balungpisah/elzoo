## bankai: Proposals

Verdict **distill**. Reuse as-is fails three checks: (1) Cure/Elixir boundary fit: Bankai is a Gleam escript plus a resident daemon that owns Mnesia tables and a UNIX socket; adopting it means a mandatory host and a Gleam toolchain for every consumer, which AGENTS.md and ADR-0005 rule out; (2) dependency weight and maintenance signal: an exact pin on `aarondb 4.2.0` whose source is not linked from Hex, a sibling `gleamunison` only for SHA-256 and a Unison AST, two contributors, tag commit 2026-10-11; (3) the mechanisms that matter are each under ~200 lines of pure policy that Elzoo must state in its own Contracts anyway. License is not a conflict (Apache-2.0 matches Elzoo-owned source), but no source is copied.

### Admission record: `workflow/dependency-graph` readiness and cycle admission (new task body, demand-led)

1. **Responsibility and caller.** Decide, from a set of Work Items, their typed prerequisite edges, a set of satisfaction facts and `now`, which Work Items are ready, which are blocked and why, and whether a proposed blocking edge may be admitted without creating a cycle. Callers: C5 (`assembly/task-workflow` prerequisites) and C6 (bounded child runs). C7's scheduled research run challenges generality: its prerequisite is a time or trigger fact, not another Work Item.
2. **Interface and invariant.** Inputs: `items{id, lifecycle, deferral}`, `edges{from, to, kind}` where `kind ∈ {blocking, informational, hierarchy}`, `facts{prerequisite id → satisfied|unsatisfied|unknown, source, expiry}`, `now`, `propose_edge{from, to, kind}`. Outputs: `ready(ordered by declared policy)`, `blocked{id, blockers[{target, present, satisfied, reason}]}`, `admit|reject{cycle path}`. State owner: the Assembly that owns the Work Items; this Piece is pure. Invariants: a blocking edge is admitted iff the target cannot already reach the source; a cancelled or closed-without-completion prerequisite never satisfies a blocking edge, only an explicit `satisfied` fact or an accepted completion does; hierarchy edges never block; an `unknown` or expired fact is unsatisfied, never assumed; readiness output is a function of its inputs only (no clock read, no I/O); the explanation is data derived from the same predicates as the decision. Non-goals: execution, claiming, notification, DAG templates.
3. **Reuse check.** libgraph (research row in orchestration-references.md) supplies reachability/topological mechanics; the policy above (what satisfies, what blocks, failure of a prerequisite → block/skip/fail per C5) is Elzoo's. Bankai's `graph.gleam` shows the policy is small; its daemon shows what not to do (step 5). Ash/Reactor dependency resolution is evaluated by ELZ-009/010 for executed steps, not for durable Work Item prerequisites.
4. **Split test.** Cycle admission and readiness share the edge set and satisfaction semantics and stay behind one interface. Ordering policy (priority/FIFO), deferral policy and the external-fact Adapter are separate choices.
5. **Failure and evidence.** Dangerous paths: two concurrent edge additions each pass a snapshot cycle check and each commit its own head, producing a cycle (Bankai M3: validation on a snapshot, CAS on one head); a `Closed` item treated as satisfying (Bankai fixed this as BUG-03); a topological sort that silently appends cycle members instead of failing; a stale or expired external fact treated as satisfied. Proofs: admitted-edge acyclicity and "unknown never satisfies" over the pure reducer. Tests: concurrent admission must either lock both endpoints or re-validate inside one commit; closed-vs-completed; expired fact; explanation equals decision. Upstream: none required for the pure core.
6. **Composition record.** Depends on `core/operator`, the `workflow/work-item` lifecycle vocabulary and, for durable edges, the ELZ-009 boundary; the atomic multi-head commit is a storage Contract, not this Piece's. Facts about external systems arrive through `runtime/adapter` with issuer, expiry and provenance recorded. Data classification: identifiers only.

## Skipped mechanisms and why (2026-11-06)

- Resident daemon, UNIX socket JSON-RPC, MCP stdio server, CLI, agent-setup marker injection: product surface and host; Elzoo does not adopt a mandatory host (AGENTS.md, capability-model "Engine and Pieces").
- aarondb cluster profile (consensus, leases, fences, quorum, BM25/HNSW projections): source not linked from Hex, not audited; `state/replication` and `state/crdt` stay deferred.
- Gleamunison mobile rules sandbox (ADR-0003), Ed25519 fact signing FFI, signed replica envelopes (ADR-0008), HMAC service capabilities (ADR-0009): crypto and protocol specifics; Elzoo would take an upstream library at the `integration/crypto` boundary when an Assembly needs one.
- Molecules (declarative DAG templates): the `(template_hash, idempotency_key)` instantiation rule is already covered by the idempotency sentence above; template storage is `workflow/build-graph` territory, deferred.
- Wisps (TTL scratch tasks), backup preview/restore, `compact`, hierarchical display ids `bk-XXXX.N` and 4-hex derived ids (collision handling is "task already exists"): product choices.
- Lexical term-hash "semantic" similarity and the Ollama embedding backend: `integration/search-data` candidates at best; no evidence of retrieval quality was examined.

## Open questions

1. Should the `workflow/dependency-graph` admission record be published as its own ELZ task now, or folded into the eventual `assembly/task-workflow` task? Its pure core is small; the dangerous path (concurrent edge admission) is a storage-boundary test that only becomes executable after ELZ-009.
2. The `state/lease` fencing sentence implies a token in the Work Item/Run record. Which owner mints it: the lease Piece or the storage boundary? Not decided here.
3. Bankai's `aarondb` dependency has no public source link on Hex; if anyone later proposes it for `state/replication`, that must be resolved first.
4. Not verified: whether Bankai's test suite passes at the tag, whether `reclaim` and `ready --claim` behave as documented under real concurrency, and the exact gleamunison version range compatibility with Gleam 1.19.2 pinned by ELZ-017. None of these affect the distill verdict.
