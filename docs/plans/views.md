### RC-12

Run and Attempt lifecycle with durable approvals

**Product aims:** P01, P02, P03, P05, P06, P07, P08, P11, P13.

**Contract:** Run/Attempt identity, current owner, reciprocal parent-child links, cancellation and effect settlement remain distinct. Persist approval inputs and re-evaluate current authority before dispatch; provider sessions are external references. Boundary with the bot platform track (P13): this job owns Run and Attempt identity, the parent-child links, the Run outcome set, the rule of which Attempt is current and what a cancel names, and approval persistence. At dispatch it calls ready workflow/approval, which already runs the decision again against current context; this job does not write that check a second time. The admitted design keeps these rules. (a) The release event is durable before a dispatch is started. (b) A key is released one time: with a release record the only check is Elzoo.Approval.revalidate/3, and :already_released from release/4 is never a permission. (c) With no release record the Run restores what it has: an approval that has no evidence yet stays an open wait and is not refused; with stored evidence it calls Elzoo.Approval.release/4 with that fresh evidence, for each scope; it passes :retained only after select_retained chose an existing retained consent. (d) revalidate/3 knows nothing about dispatch: :ok is never proof that nothing was sent and never permits a send by itself. (e) When delivery/effect-intent holds a reservation for the action, the action counts as possibly sent: this job starts no new dispatch for it, its outcome comes from the reconciliation of delivery/effect-intent, and this job never makes a replacement action for it. ### RC-68

Pattern step protocol: inputs, one request with actions, outcomes

**Product aims:** P13. Bot platform track; see docs/plans/bot-platform.md.

**Contract:** The one shared shape between a pattern and the engine, as data and pure validation.
