# Wave 7 — Remember and know

## Status and scope

This document is planning input for Wave 7 (`Remember and know`) of the P13 track in [bot-platform.md](bot-platform.md). It promotes nothing to ready and publishes no Piece task. [release-plan.json](release-plan.json) remains the one canonical planning source; handles are provisional until publication, and the coordinator assigns the ELZ IDs then. The coordinator publishes the levels below after the owner answers Q1–Q10, and records the answers.

Wave 6 is accepted: its root consumer acceptance [ELZ-323](../../tasks/ELZ-323-wave6-count-and-see-acceptance.md) and its closure record ([ELZ-326](../../tasks/ELZ-326-wave6-closure-note.md), in [the Wave 6 plan](bot-platform-wave6.md)) are merged on `main`, so the serial rule of [bot-platform.md](bot-platform.md) lets Wave 7 be registered. The coordinator reports that the owner approved Wave 7 for planning (2026-11-22). This plan treats the pruned Wave 7 row of [bot-platform.md](bot-platform.md) ("Subsequent waves (Waves 6–9)") as a proposal, checks each handle against the ready manifests, and keeps a new Piece only for missing policy. Where a ready Piece lacks something that clearly belongs to it, the plan extends it in place under its ID (rule of 2026-11-14; `AGENTS.md` section 4).

Wave 7 means two things. A bot **remembers**: facts and preferences about a tenant, a space, an end user or a bot are kept as scoped records with provenance, written only through a declared policy, recalled within bounds, and forgotten or erased on request. And a bot **knows**: a tenant's documents are parsed, chunked, embedded and indexed durably, retrieved by meaning and by words under the tenant's permissions, and an answer cites the exact text it used.

The plan proposes **4 new Pieces and 1 in-place extension across 4 dependency levels**, from 16 candidate handles, plus one provider prerequisite (conditional on Q1) and a mandatory root consumer acceptance. Two departures from the pruned baseline, each argued in "All candidate handles":

1. `integration/search-text` is not a new Piece. It is a lexical query added in place to `integration/search-data`, over the same chunk rows, tenant filter, permitted-source filter and candidate shape. The same in-place task adds a source delete, a version guard and an optional row-security floor, which forgetting, erasure and re-ingest need.
2. `assembly/knowledge-ingest` is a durable Assembly of bounded jobs over `integration/jobs` with Piece-owned tables, not a RunEngine Run of a service principal. An embedding outcome is larger than the engine's payload bound, and a Unit's 256 lifetime actions would cap a document's embedding calls.

The recorded limits of earlier waves stay recorded limits. For Wave 7:

- **Identity provider: not needed.** Memory scopes, ingest callers and retrieval take opaque tenant, space, subject and principal IDs that `integration/token-verify`, `domain/principal` and `domain/membership` already supply. The ingest caller is a host-vouched `:service` principal; no Wave 7 job authenticates a person.
- **Live providers: not needed.** The root acceptance uses scripted embedding and model providers. Retrieval and answer quality are not measured.
- **Live public MCP endpoint and connectors: not needed.** No Wave 7 job calls an MCP server, fetches a URL or reads an outside database; documents arrive as `state/artifact` versions.
- **Audit capture: not needed.** No Wave 7 job adds an admin command; memory writes that need a person go through `workflow/approval`.

## Source boundaries checked (at `main` `2447871f`)

These facts were read from the ready manifests, READMEs and sources at `main` `2447871f`. They are facts, not claims that a Wave 7 composition has been exercised.

- [integration/search-data](../../pieces/integration/search-data/README.md) is a PostgreSQL/pgvector exact cosine chunk store over a consumer Repo: `new/3`, `Migration.install/1`, `put_source/4` and `query/2`. A declaration is immutable per index identity and is checked again on every operation. `put_source/4` takes 1..65,536 chunks (at most 1 MiB each, 8 MiB in total) and atomically deletes all old rows of the tenant and source and inserts the new version under a transaction-scoped advisory lock; there is "no monotonic-version or latest-version policy". `query/2` takes only a query embedding and at most 256 permitted source references per call; the tenant and permitted-source list apply in the SQL `WHERE` before ranking, and each candidate carries `item_id, version, source, content, content_hash, derived_from, access, distance, source_digest, start_byte, end_byte`. Its limits say "No ANN, ranking quality, source authentication, retention/deletion policy, monotonic-version policy, embedding calls or exactly-once guarantee". There is no lexical query and no way to remove a source. Its `content` column is `bytea`, and its `Migration.install/1` runs at run time through its own transaction, not inside an Ecto migration. An index created without a column cannot gain it, since the declaration is immutable and the table is created with `CREATE TABLE IF NOT EXISTS`. Its `transaction/3` refuses a call when `repo.in_transaction?()` is true, so a host cannot wrap it in `state/tenant-isolation`'s `transact/3`; its tables are not under row security.
- [integration/text-chunking](../../pieces/integration/text-chunking/piece.json) chunks one frozen UTF-8 source of at most 1 MiB, bound to its SHA-256, through `text_chunker 1.0.1`, as `:plaintext` or `:markdown`. Its limits say "No semantic quality, language detection or extraction from PDF, DOCX or HTML bytes; format selects separators only".
- [integration/ai-embedding](../../pieces/integration/ai-embedding/README.md) bounds one call by its 65,536-byte canonical request: 32 ASCII chunks of 2,000 graphemes, 10 of three-byte text, 8 of four-byte text. A throttle or overload is not redispatched, and "a caller retries only with its own ground, for example a new logical request reference accepting that the first request may have been processed". The result sink is volatile: "after a restart only the settled status remains". [integration/ai-embedding-openai](../../pieces/integration/ai-embedding-openai/piece.json) reports `prompt_tokens` as `input_uncached_tokens`.
- [assembly/run-engine](../../pieces/assembly/run-engine/piece.json) bounds a payload or outcome at 65,536 JSON bytes and a Unit at "64 active/256 lifetime occurrences" ([choices](../choices.md#payload-and-record-caps)). One unit-norm float32 vector of 1,536 dimensions is about 32.6 KB as compact JSON with shortest round-trip digits (about 22.6 KB at a provider's roughly 10 significant digits), so two vectors with the outcome wrapper reach the payload bound, and a batch of 32 is about 1 MB.
- [workflow/context-selection](../../pieces/workflow/context-selection/piece.json) selects candidates over a host-owned current access snapshot, freshness, supersession and caps. Its limits say "No retrieval, tokenizer, summarization, persistent memory, truth, provider accuracy …". [workflow/prompt-assembly](../../pieces/workflow/prompt-assembly/README.md) already has a `memory` part, `%{id: id, content: marked_map}` "already selected by `workflow/context-selection`", placed as one memory block and dropped last-item-first.
- [workflow/untrusted-content](../../pieces/workflow/untrusted-content/piece.json) marks content with trust class `untrusted` or `derived`; `encode/1` gives its neutral map, which carries the UTF-8 content; marking "grants no authority and prevents no injection". [workflow/typed-decision](../../pieces/workflow/typed-decision/piece.json) asks a model for a value of a schema, with bounded repair; "An answer that matches the schema is not a correct answer".
- [state/conversation](../../pieces/state/conversation/piece.json) is pure, at most 64 messages and associations, with no persistence. No ready Piece keeps facts across conversations.
- [state/tenant-isolation](../../pieces/state/tenant-isolation/README.md) gives a forced restrictive tenant floor (and an optional exact space-list floor) through `Migration.protect/2`, which issues its DDL with `Ecto.Migration.execute/1` and so runs only inside an Ecto migration, and `transact/3`, whose scope takes tenant IDs of 1..128 bytes. [domain/metering](../../pieces/domain/metering/piece.json) is the Wave 6 precedent for a Piece that protects its own tables and runs its statements through `TenantIsolation.transact/3` itself (`pieces/domain/metering/lib/elzoo/metering.ex`), and refuses an isolation level other than READ COMMITTED ([choices](../choices.md#the-durable-wave-6-pieces-need-read-committed)).
- [state/artifact](../../pieces/state/artifact/piece.json) stores tenant-owned versioned bytes (at most 16 MiB a version by default), verifies the SHA-256 on every get, and enforces recorded access terms; `media_type` is an opaque bounded tag.
- [state/retention-erasure](../../pieces/state/retention-erasure/piece.json) is a per-subject vault with crypto-shredding by `erase/2`. Its task ELZ-279 left out "tombstones or expiry for `state/artifact` and `integration/search-data` objects". [integration/pii-redaction](../../pieces/integration/pii-redaction/piece.json) replaces found values by `[pii:kind:ref]` in tokenize mode through an injected vault Need; it finds listed patterns only (known values, email, card, phone), with "no names, addresses, national IDs".
- [runtime/async-work](../../pieces/runtime/async-work/piece.json) runs bounded volatile local computation with a monotonic deadline and cancel; it reports no progress, and it is used inside `assembly/run-engine` for `local_work`. [assembly/durable-job](../../pieces/assembly/durable-job/piece.json) is "One exemplar: one Run per Work Item, one pure step; no workflow engine, DAG, saga, cron, distributed scheduler, lease or external Effect", and [assembly/http-job](../../pieces/assembly/http-job/piece.json) is one bounded JSON publication at a fixed HTTP origin. [integration/jobs](../../pieces/integration/jobs/piece.json) states that "Lifeline rescue is time-based and can re-run live jobs (upstream)". [runtime/os-isolation](../../pieces/runtime/os-isolation/piece.json) is "Not security isolation: no sandbox, container, seccomp, path confinement or network isolation".
- [domain/principal](../../pieces/domain/principal/README.md) has the kinds `:human`, `:service` and `:agent`. [integration/egress-policy](../../pieces/integration/egress-policy/piece.json) is the outbound URL policy that the Wave 5 plan names for later web and database connectors.
- Dependencies: `floki 0.38.5` (MIT, no dependencies of its own) is in `mix.lock` only as a transitive dependency (`md 0.12.2` of `cure` needs `floki ~> 0.33`); it is not in `mix.exs` or `registry/providers.json`, and no Piece uses it. No PDF or DOCX reader is locked.
- PostgreSQL: built-in full-text search needs no extension. The local PostgreSQL 16.16 has 29 text search configurations, including `simple`, `english` and `indonesian`, and ships `pg_trgm` and `unaccent` as trusted extensions. CI uses the image `pgvector/pgvector:0.8.7-pg16-bookworm` and runs only `CREATE EXTENSION vector` ([workflow](../../.github/workflows/symbolic-check.yml), [setup](../../.agents/setup)); that the image ships `pg_trgm` was not checked here.
- Catalogue: of the 16 Wave 7 handles only `assembly/data-pipeline` has a row (`deferred`, summary "Build graph, content cache, dataframe", job RC-39, `deferred-example`, stage `examples-later`). RC-39's Contract is "Later bounded artifact upload/transform flow; initial contract excludes the broader build graph and dataframe family unless separately delivered", and its acceptance is "Upload interruption, integrity mismatch, duplicate transformation, cancellation and retention tested in composition".

**`integration/search-data` in place (jobs `integration/search-text`, source delete, version guard, floor), conditional on Q2 and Q7.**
- *Dependencies:* ELZ-082, ELZ-270 (the floor, under Q7 A), ELZ-285 (the `elzoo_app` test role). *New external dependency:* none under Q2 A; under Q2 B the `pg_trgm` prerequisite. Under Q7 A the copy closure of search-data gains `state/tenant-isolation`, also for a binding without the floor.
- *Contract sketch (Q2 A):* the declaration gains an optional key `text_search: %{config: name}`, where `name` (1..63 bytes) is a text search configuration that `Migration.install/1` finds in `pg_ts_config`; it is part of the persisted declaration, so a binding cannot change it, and an index installed without it needs a new index identity to gain it. With the key, install adds a plain `tsvector` column and a GIN index, and `put_source/4` fills the column in the same `INSERT` with `to_tsvector($config::regconfig, convert_from(content, 'UTF8'))` (content is `bytea`, and `convert_from` is not immutable, so a stored generated column cannot be used). A UTF-8 database encoding becomes an operator Need, which install checks and refuses otherwise. `query_text/2` takes `%{tenant, text, k, allowed_sources, principal, checked_at, max_content_bytes, statement_timeout_ms}` with `text` 1..4,096 UTF-8 bytes parsed by `websearch_to_tsquery` (no syntax error is possible). The tenant and at most 256 permitted sources apply in the `WHERE` before ranking, as in `query/2`. Rows order by `ts_rank_cd` descending, then the same tie order as `query/2` (source reference in C collation, version, chunk index). The same top-k content bound applies, and each candidate has the same fields, with `rank` in place of `distance`. A query whose tsquery is empty (stop words only) returns `{:ok, []}`. An index without the key refuses `text_search_disabled`. *Delete and version guard:* `delete_source/4` takes the tenant, source and the version being removed; under the same advisory lock as `put_source/4` it removes every row of that tenant and source and records a delete mark of that version in a Piece-owned table, and returns `{:committed, count}` (0 when absent), so it is idempotent. `put_source/4` gains an option `if_newer: true`: under the same lock and in the same transaction it refuses `stale_version` when the stored version of the source is higher than the new version, or its delete mark is equal or higher; an equal stored version is replaced as today, so a repeated write of one version succeeds. Without the option it behaves as today. *Floor (Q7 A):* a new `Migration.protect/2` of search-data, called from the consumer's Ecto migration `up/0` after the index is installed (as `domain/metering`'s install is), protects the chunk table and the delete-mark table with `state/tenant-isolation` (tenant column, no space column), and a binding with the optional key `tenant_isolation: %{prefix: p}` (`p` matching `^[a-z_][a-z0-9_]{0,62}$`) runs every statement through `TenantIsolation.transact/3` with scope `%{tenant: t}`; a new `verify/1` of search-data runs `TenantIsolation.verify/3` over its protected tables, and the host calls it before serving, as tenant-isolation's README asks (a binding is a plain value with no process, so no operation knows it is the first). The run-time `Migration.install/1` refuses a caller's transaction and an Ecto migration runs in one, so the protecting migration runs after the run-time install (a stated Need). Under the floor a tenant ID is 1..128 bytes (the scope rule), not search-data's 1..1,024. A binding without the keys behaves as today, and the existing tests do not change. The prefix-local declaration registry is deployment-wide and stays unprotected (a stated limit).
- *Acceptance:* lexical hit and miss; a stop-word-only query; tenant and permitted-source filtering before ranking (a better-ranked row of another tenant or of a source not permitted is not returned); the tie order; the content-bound overflow as in `query/2`; `text_search_disabled`; an unknown configuration refused at install; a second install with another configuration refused; delete of a present and of an absent source; a delete racing a `put_source/4` behind a barrier is serialized; after a delete neither query returns the source; two guarded writes of versions 1 and 2 behind a barrier leave version 2 whichever commits last, a guarded write of a deleted version is refused while a higher version is accepted, and a guarded repeat of the stored version succeeds; under the floor, as `elzoo_app`, a T1 scope sees no T2 row and a T2 write is refused (SQLSTATE 42501), and `verify/1` over an unprotected table reports the missing floor; the caller-transaction refusal for the new operations. Negative controls: drop the tenant predicate from `query_text/2` (the cross-tenant case fails on a binding without the floor, and passes on one with it, which shows that the floor catches it); drop the advisory lock from `delete_source/4` (the race case fails); read the stored version outside the lock (the guarded race case fails).
- *Kept open:* trigram similarity as a match member (Q2 B); a configuration per query; an ANN index; a fusion helper; highlight snippets as a candidate key; a space-list floor.

**`state/memory-record` (absorbing `domain/memory-scope` and `workflow/memory-write-policy`), conditional on Q4–Q6.**
- *Dependencies:* ELZ-033, ELZ-030 (`workflow/context-selection`, for the recall case's tests), ELZ-137 (`workflow/untrusted-content`), ELZ-270, ELZ-285. *New external dependency:* none.
- *Contract sketch:* `Migration.install/1`, called from the consumer's Ecto migration `up/0` (as `domain/metering`'s is), installs records and tombstones tables protected with the tenant floor; statements run through `TenantIsolation.transact/3`. A scope (Q4 A) is one of `{:tenant}`, `{:space, id}`, `{:subject, id}` or `{:bot, id}`. A record is `{tenant, memory_id, scope, kind, content, provenance, written_by, writer_kind, written_at_ms, expires_at_ms | nil, supersedes | nil}`. `kind` is `:fact`, `:preference` or `:summary`. `content` is a `workflow/untrusted-content` marked value of 1..4,096 bytes, stored and returned with its trust class. `provenance` is 1..16 references `{kind, id}`, with `kind` from `:run | :message | :artifact | :person`. `writer_kind` is the `domain/principal` kind of the writer, `:human`, `:service` or `:agent`; a model's proposal is written under the Run's agent principal. IDs are 1..128 bytes without NUL or control characters. The pure `check_write/2` takes a host policy, a map from `{scope kind, kind, writer_kind}` to `:allow | :ask | :deny`, and one proposal. It returns `:allow`, `{:ask, :policy}` or `{:deny, reason}`; an unlisted triple is `{:deny, :unlisted}`, and the Piece has no default policy (Q6). `write/4` runs `check_write/2` itself and writes only on `:allow`, or on `:ask` when the call carries an approval reference for the proposal's canonical SHA-256 digest; the host obtains that approval through `workflow/approval`, and the Piece checks only the digest, so the reference is host-vouched (a stated limit). A write is idempotent by `(tenant, memory_id)`: equal canonical bytes give `:duplicate` and other bytes `{:error, :conflict}`. A record is immutable; `supersedes` names a current record of the same scope, and a record has at most one successor (`already_superseded`). `recall/3` takes `principal`, `checked_at`, 1..16 scopes, optional kinds, `max_records` 1..256, `max_bytes` and `now_ms`. It returns the current records of those scopes (not superseded, not forgotten, not expired at `now_ms`), newest first. Each entry is a `workflow/context-selection` candidate (`item_id` the memory ID, `version: 1`, `source` `memory:<id>`, `content` the marked value's UTF-8 text, `content_hash` its SHA-256, `derived_from: []` because recall has applied supersession, `access` restating `principal` and `checked_at` with `result: :allowed`, as search-data does) together with the neutral marked map for the `memory` part of `workflow/prompt-assembly`. `forget/3` (Q5 A) deletes a record's content row and keeps a tombstone `{memory_id, scope, forgotten_at_ms, actor_ref, reason}`; a forgotten ID is not written again (`forgotten`). `erase_subject/3` forgets every record of `{:subject, id}` in bounded batches and returns the forgotten memory IDs of each batch with a cursor, so the host can delete their search-data sources; it is idempotent. Refusals: shape, then the caller's open transaction, before any query; then the isolation check, which is the first query of a transaction, refuses a level other than READ COMMITTED before any write. Fixed error atoms never echo an ID or content. The Piece has no embedding, search, extraction or model call.
- *Acceptance:* write, duplicate and conflict; allow, ask and deny, and an unlisted triple; an ask, then a write with the approval of the exact digest, while an approval of another digest is refused; supersede once, and two concurrent supersedes of one record behind a barrier commit one; recall by scope and kind, expiry at the exact `now_ms` boundary, superseded and forgotten records left out, newest-first order, and the count and byte bounds at their edges; after a forget a direct read of the tables finds no content, the tombstone stays and the ID cannot be reused; `erase_subject/3` removes only that subject's records; the marked trust class survives a round trip; cross-tenant isolation as `elzoo_app`; the caller-transaction and isolation refusals. The recall candidates pass `workflow/context-selection` unchanged. Negative controls: drop the expiry predicate from recall; let forget keep the content row; skip `check_write/2` in `write/4` (the deny and ask cases fail).
- *Kept open:* more scope members (for example `{:conversation, id}`); more kinds; per-record access labels; a TTL sweep; content sealed in the vault (Q5 B) as an optional mode; recall by meaning in place, beside the composition of Q10 B.

**`workflow/citation`.**
- *Dependencies:* ELZ-033, ELZ-030 (the selected item shape), ELZ-115 (`core/payload-schema`, for the cited-answer schema). *New external dependency:* none.
- *Contract sketch:* `schema/0` gives the `core/payload-schema` value of a cited answer version 1, `%{text, citations: [%{item_id, quote}]}`, for `workflow/typed-decision` to ask for. The pure `check/3` takes one decoded answer, the items that were given to the model (each `%{item_id, source, version, content}`, with `start_byte` when the item is a chunk) and a policy `%{min_citations: 0..32}`. Rules: 0..32 citations; each `item_id` is one of the given items by exact bytes; `quote` is 1..1,024 UTF-8 bytes that occur in that item's content as exact bytes (the first occurrence counts); a repeated `{item_id, quote}` pair is refused. It returns `{:ok, %{citations: [%{item_id, source, version, start_byte, end_byte}]}}`, with offsets in the source when the item has `start_byte` and in the item otherwise. Otherwise it returns `{:error, reason}` in the fixed order `malformed`, `too_many`, `duplicate`, `unknown_item`, `quote_not_found`, `uncited`. Errors never echo content. The Piece checks that the quoted text is in the cited source; it does not check that the answer is true or that the quote supports it (rule 8: a citation is evidence of where the text came from, not of truth).
- *Acceptance:* every rule at its edge; a quote that differs only by Unicode normalization is not found; a quote that occurs twice resolves to the first occurrence; source offsets of a chunk whose `start_byte` is not 0; `min_citations` at its boundary; malformed answers in the fixed error order. Negative control: skip the substring check, and the fabricated-quote case fails. The answer is model output (untrusted input), so the task keeps the local small gate and gets the full review (`AGENTS.md` sections 5 and 6).
- *Kept open:* inline markers in `text` as a citation key; quotes that span two items; a near-match mode as a policy member.

### Level 2 — the parser (after its prerequisite merges and `main` is green)

**`integration/document-parse`, conditional on Q1.**
- *Dependencies:* the `floki` prerequisite (under Q1 A–C), ELZ-081 (the output fits `integration/text-chunking`). *New external dependency:* `floki` (adopted by the prerequisite).
- *Contract sketch (Q1 A):* the pure `parse/3` takes bytes, a media type and options. The media types form a closed version 1 set: `text/plain`, `text/markdown` and `text/html`. Input is 1..8 MiB, and options may narrow the bound. It returns `%{text, format: :plaintext | :markdown, media_type, source_sha256, text_sha256, parser: %{id, version, library}}`. Plain text and Markdown must be valid UTF-8 (no transcoding); one leading BOM is removed and CRLF becomes LF. HTML is parsed with `Floki.parse_document/1`. The text of `script`, `style`, `template`, `noscript` and `head` is left out, except the `title`. Block elements give paragraph breaks, whitespace is collapsed, entities are decoded and attributes are dropped. A declared charset other than UTF-8 is refused. Text over 1 MiB (the text-chunking ceiling) is refused `text_too_large`, and empty text `empty_text`. No URL is fetched, no entity is resolved from outside and no script runs. Fixed errors: `unsupported_media_type`, `too_large`, `invalid_utf8`, `unsupported_charset`, `parse_failed`, `empty_text`, `text_too_large`. Its output is untrusted content (rule 9); the caller marks it.
- *Acceptance:* each media type; BOM and CRLF; text inside `script` and `style` never appears in the output; nested blocks; entities; malformed HTML as Floki parses it; non-UTF-8 bytes and a `windows-1252` charset refused; input at 8 MiB and one byte over; output at the 1 MiB edge; deeply nested HTML and random bytes always give a result or a fixed error, never a raise, with timings recorded as observations, not a time guarantee. Negative controls: keep `script` text; drop the input bound. Untrusted input: local small gate and full review.
- *Kept open:* PDF, DOCX and other members of the media-type set with their providers (Q1 B, C); headings and links as result keys; other charsets.

### Level 3 — knowledge ingest (after document-parse and the search-data extension merge)

**`assembly/knowledge-ingest`, conditional on Q1, Q8 and Q9.**
- *Dependencies:* the document-parse task, the search-data task, ELZ-010 (`integration/jobs`), ELZ-023 (`delivery/effect-intent`), ELZ-080 (`integration/ai-embedding`), ELZ-081, ELZ-096 (`state/artifact`), ELZ-270, ELZ-285. *New external dependency:* none.
- *Contract sketch:* `Migration.install/1` installs an ingest table, one row per `(tenant, source_ref, version)`, and a staged-chunk table, both under the tenant floor. `submit/3` takes a host-vouched caller `%{tenant, actor}` (a `:service` principal) and `%{source_ref, version, artifact: %{artifact_id, version}, media_type, chunking, index}`, where `media_type` is from document-parse's set. It is idempotent by `(tenant, source_ref, version)`: equal bytes give the existing ingest, other bytes `{:error, :conflict}`. The ingest row and its first unique Oban job are inserted in one transaction, and an equal re-submit of an ingest that has no live job enqueues it again. Each step is one bounded job:
  1. *Prepare:* `state/artifact` `get` (hash verified), `parse/3` and `chunk/4`, then insert the staged chunks, unique by chunk index. Chunking options are refused when `chunk_size` is more than a quarter of the ai-embedding Config's bytes per input (default 32,768), so four-byte text fits; a chunk whose one-input canonical request the Config's bounds still refuse (escaped characters, long grapheme clusters) fails the ingest `chunk_too_large`. Then one embed job per batch is enqueued, each batch sized by measuring the canonical ai-embedding request. The chunker's no-separator path is quadratic, so the step's time is an observation and a Lifeline re-run of a live step can happen; the staged-row uniqueness makes it harmless.
  2. *Embed:* one ai-embedding request through the effect-intent owner. A completed outcome writes its vectors to the staged rows and records the attempt's usage. Under Q9 A a throttled or overloaded outcome (dispatched and retryable: the first request may have been processed and paid) starts a new attempt with a new request reference after its `retry_after` (or a declared backoff), up to a declared `max_attempts` (1..5, default 3); each attempt is recorded with its usage when reported, and then the ingest is `failed{embedding}`. An `unknown` outcome is never retried automatically (track rule 4, and ai-embedding's "`unknown` is never retried"): the batch and the ingest fail `failed{embedding_unknown}`, and only an explicit `resubmit/3` by the host starts a new attempt. A refusal is `failed{embedding_refused}`. The step that settles the last batch takes the ingest row `FOR UPDATE` before it enqueues the index step, so exactly one index step is enqueued.
  3. *Index:* when every batch has completed, `put_source/4` with `if_newer: true` writes the complete version, so the version check and the write are atomic under search-data's lock; `stale_version` (a higher version is indexed, or the source was deleted at this version or later) makes the ingest `superseded`; a repeat of this version's own write succeeds. An indeterminate result repeats the step (a whole replacement is safe to repeat). Then the staged rows are deleted.

  `cancel/3` marks the ingest cancelled; a later step that sees it stops and deletes the staged rows, and an indexed version is not touched. `status/3` gives the state (`requested`, `preparing`, `embedding` with done and total batches, `indexed`, `failed` with a reason, `cancelled` or `superseded`) and each attempt's usage, which the host records in `domain/metering`. A re-run of a step by Oban's Lifeline is idempotent: staged rows are unique, and a completed batch is skipped. Removing a document is the host's `delete_source/4` at the newest version, and an in-flight ingest of that version or an older one then ends `superseded`. Refusals: shape, then the caller's open transaction, then the isolation level. The ingest makes no Run, no exactly-once Effect claim and no claim about retrieval quality.
- *Acceptance (RC-39's integrity, duplicate-transformation and cancellation cases for this flow):* an artifact hash mismatch is `failed{artifact_integrity}`; a duplicate submit; a crash between the ingest insert and its job is impossible by the shared transaction, and a re-submit re-enqueues a stranded ingest; a crash after an embedding completes and before its vectors persist re-embeds the batch, and exactly one version is indexed; a node killed mid-ingest resumes to `indexed`; cancel during embedding gives no `put_source/4` and no staged rows; two index steps of versions 1 and 2 racing behind a barrier, and a Lifeline re-run of an older index step, leave version 2 indexed; the index step repeated after its write committed ends `indexed`; a `delete_source/4` during an in-flight ingest is not undone by it; a throttled outcome gives a new attempt, and after `max_attempts` the ingest fails; an unknown outcome fails the batch with no new attempt until `resubmit/3`; a refused outcome; the last two batches settling at once enqueue one index step; batches of four-byte text stay within 65,536 bytes; cross-tenant isolation as `elzoo_app`; status counts at each step. Negative controls: write without `if_newer` (the race case fails); drop staged uniqueness (the duplicate-transformation case fails); retry an unknown outcome automatically (the unknown case fails). Durable, effects, unknown outcomes and concurrency: local small gate and full review.
- *Kept open:* reuse of a stored vector for an unchanged chunk digest and descriptor (`state/cache`); connectors as submitters; more media types through document-parse; a progress heartbeat if a step ever becomes unbounded; scheduled re-ingest through `state/scheduler`; metering inside the Assembly.

### Level 4 — mandatory Wave 7 root consumer acceptance (no Piece output)

Mirrors ELZ-286 and ELZ-323. It depends on every Wave 7 task above, and on ELZ-024, ELZ-030, ELZ-080, ELZ-081, ELZ-082, ELZ-096, ELZ-127, ELZ-137, ELZ-140, ELZ-141, ELZ-267, ELZ-270, ELZ-278, ELZ-279, ELZ-285 and ELZ-299. It is a V1B job. It exercises the public interfaces together on real disposable PostgreSQL with pgvector. The application connection is the `elzoo_app` role, and the test fails, not skips, if the role is missing or bypasses row security. It adds no Piece, runtime, provider or generic test framework, and a Piece failure is a separately scoped repair. Conditional on Q1, Q2, Q3, Q5, Q6, Q7 and Q10.

1. **Ingest:** two tenants each put an HTML and a Markdown document as `state/artifact` versions, and knowledge-ingest indexes them with a scripted embedding provider. Each attempt's usage is recorded in `domain/metering`. A restart mid-ingest still indexes once; a new version supersedes; a removed document is deleted with `delete_source/4` and is no longer retrieved.
2. **Retrieve:** a vector query and a lexical query for T1 are fused by reciprocal rank in the harness (Q3 A) into context-selection priorities. A source revoked in the current permission snapshot is vetoed. As `elzoo_app` under T1's scope, no T2 chunk is visible and a T2 write is refused (SQLSTATE 42501).
3. **Answer with citations:** a RunEngine Run of `workflow/typed-decision` over the cited-answer schema, with a scripted model, answers from the selected items. `workflow/citation` resolves each quote to a source, version and byte range. A scripted answer that cites an item it was not given, or a quote that is not in the item, is refused, and the host does not show it as cited.
4. **Remember:** a typed-decision Run proposes memories from a conversation. The host policy allows a model's subject-scope fact and asks for a tenant-scope fact. An approval through `workflow/approval` lets that exact proposal be written, and an edited proposal needs a new approval. The next Run's recall returns the subject's memories newest first; context-selection selects within the window, and prompt-assembly puts them in the memory block as marked content. A memory that reads like an instruction stays inside its marked block (rule 9).
5. **Recall by meaning (Q10 B):** each written memory is also indexed in a search-data memory index as the source `memory:<id>`, and a query by meaning finds it.
6. **Forget and erase:** forgetting one memory removes it from recall and from the memory index. Erasing a subject runs memory-record `erase_subject/3`, `delete_source/4` for each memory ID it returns, and `state/retention-erasure` `erase/2`, so the `[pii:kind:ref]` tokens that `integration/pii-redaction` wrote into memory content no longer open. pii-redaction finds listed patterns only, so crypto-shredding covers only the values it found; the rest is deleted with the record.
7. **Negative controls, one at a time:** connect without `SET ROLE` (the group 2 isolation case must fail); skip the citation check in the harness (the group 3 refusal must fail); write a model proposal without the policy (the group 4 ask must fail); skip `delete_source/4` in forget (group 6 must fail). Restore each before the final passing run.

Limits to state: scripted providers, so no claim about embedding, retrieval, ranking or answer quality; no rerank provider (Q3); no live web, database or drive connector; a citation shows that the quoted text is in the source, not that the answer is right; dead tuples, WAL and backups keep deleted content until PostgreSQL reclaims them; the search-data declaration registry and the ready Store tables are not under row security; pinned test identities, not an identity provider; a meaning query covers at most 256 permitted sources, so under Q10 B one query covers at most 256 memories and a tenant with more documents needs several queries; the RunEngine Stores of the harness run on the owner connection unless ELZ-327 is merged at publication.

## Provider prerequisites and open questions

**Provider prerequisites.** Under the recommended answers there is one: adopting `floki 0.38.5` as a direct dependency (Q1 A). Under Q2 B there is a second, `pg_trgm` in CI and `.agents/setup`. Under Q1 B or C there are more: a poppler `pdftotext` system package in CI and `.agents/setup`, or a parsing-service container in CI and its adapter. Each is its own task with the full check, and it merges before the Piece that needs it. No Ash, OpenTelemetry, rerank or connector dependency is adopted.

**Owner questions.**

1. **Q1 — Which document formats, and which parser** (`integration/document-parse`; knowledge-ingest's media types).
   - A: plain text, Markdown and HTML; HTML through `floki 0.38.5` (MIT, pure Elixir, already locked as a transitive dependency), adopted as a direct dependency by its own task.
   - B: A plus PDF through poppler's `pdftotext`, run with `runtime/os-isolation`; a system package Need in CI and `.agents/setup`, and the PDF parser runs unsandboxed.
   - C: A plus PDF, DOCX and other office formats through a parsing service (for example Apache Tika server) in its own container, behind a provider adapter with `integration/http`; a container service in CI.
   - D: no parser in Wave 7; ingest takes UTF-8 text and Markdown only, and document-parse is deferred.

   *Recommendation: A.* It covers web pages and exported help articles with a maintained library that is already in the lock. PDF parsers have a long history of memory-safety faults, and `runtime/os-isolation` is not a sandbox. So when a consumer asks for PDF, C (a container) is the safer first provider, added in place as a new media-type member.
2. **Q2 — Lexical search** (the search-data extension).
   - A: PostgreSQL built-in full-text search in place on search-data, with one text search configuration declared per index (for example `simple`, `english` or `indonesian`); no extension.
   - B: A plus `pg_trgm` similarity for typos and partial words; a provider prerequisite adds the extension to CI and `.agents/setup` and merges first.
   - C: a separate `integration/search-text` Piece with its own table.

   *Recommendation: A.* Words and stems cover keyword search with no new extension. C copies each source and search-data's filters; trigram matching stays addable as a match member.
3. **Q3 — Fusion and reranking** (root acceptance; `integration/ai-rerank`).
   - A: the host fuses the vector and lexical ranks by reciprocal rank into context-selection priorities; no rerank provider.
   - B: a provider-neutral `integration/ai-rerank` interface and one provider adapter, with its credential and pinned format.

   *Recommendation: A.* Reciprocal-rank fusion is a few lines of host code over two ranked lists; a rerank provider is a new paid call per query, and it waits until a consumer measures a need.
4. **Q4 — Whom a memory belongs to** (`state/memory-record`).
   - A: a closed tagged scope set, `{:tenant}`, `{:space, id}`, `{:subject, id}` (an end user or principal) and `{:bot, id}`; one scope per record; recall names the scopes the caller may read.
   - B: subject scope only.
   - C: free host labels.

   *Recommendation: A.* Bots need tenant knowledge and per-user preferences alike. A closed set can gain members, and free labels would leave erasure by subject undefined.
5. **Q5 — How a memory is forgotten and erased** (`state/memory-record`).
   - A: forget deletes the content row and keeps a tombstone with opaque IDs; subject erasure forgets every record of the subject; the host writes personal values through `integration/pii-redaction` tokenize mode with the `state/retention-erasure` vault, so crypto-shredding covers them as the 2026-11-20 erasure decision says.
   - B: every memory content is sealed in the vault under its subject key.
   - C: append-only memory with no delete.

   *Recommendation: A.* Memory is state, not a log, so deleting it is allowed. B makes every recall depend on the KEK Need, and C cannot honour a forget request.
6. **Q6 — Who may write a memory** (`state/memory-record`; root acceptance).
   - A: a host policy per scope kind, kind and writer kind (`:person`, `:service`, `:model`), with deny for an unlisted triple. The acceptance policy: a model may write subject-scope facts and preferences; a model's tenant, space or bot memory needs a person's approval (ASK); a person may write.
   - B: only people and services write; no model-proposed memory.
   - C: a model's proposals are written without a policy.

   *Recommendation: A.* Model output is a proposal (rule 3), and a tenant-wide memory changes every user's bot. C breaks rule 3, and B gives up extraction.
7. **Q7 — Row security on search-data** (the search-data extension).
   - A: an optional tenant floor in place: when a binding names a `state/tenant-isolation` prefix, install protects the chunk table and every statement runs under the tenant scope; a binding without it is unchanged.
   - B: keep the SQL tenant filter only, as a stated limit.

   *Recommendation: A.* Knowledge chunks and memory indexes hold tenant content, and the floor guards against a forgotten filter, as it does for the Wave 6 tables. search-data refuses a caller's transaction, so the floor can only come from inside the Piece.
8. **Q8 — `assembly/data-pipeline` (RC-39) and knowledge ingest.**
   - A: knowledge-ingest gets its own new Piece ID; RC-39 stays a deferred example for a later data workload (dataframes, a build graph).
   - B: knowledge-ingest takes RC-39's `assembly/data-pipeline` ID with a narrowed Contract; it then inherits RC-39's V1 release, its P08 aim and its dependencies (RC-13, RC-14, RC-42), which the job would have to restate.

   *Recommendation: A.* RC-39's row names a generic build-graph and dataframe family and is an examples-later row; a knowledge ingest is a specific Contract, and the name should say so.
9. **Q9 — An embedding call that is throttled or overloaded** (`assembly/knowledge-ingest`). An `unknown` outcome is never retried automatically under every option: track rule 4 says "A timeout after dispatch is an unknown outcome and never gets an automatic retry", and the batch fails until the host calls `resubmit/3`.
   - A: a new attempt with a new request reference after the provider's `retry_after` or a declared backoff, up to a declared `max_attempts` (1..5, default 3); each attempt is recorded with its usage.
   - B: no new attempt; the ingest fails and the host resubmits.

   *Recommendation: A.* A throttle or overload is the provider's own signal to try later, which is the caller's own ground that `integration/ai-embedding` asks for; a new attempt accepts that the first request may have been processed and paid, recorded attempts keep that cost visible, and B makes every host write the same loop.
10. **Q10 — Recall by meaning** (root acceptance).
    - A: recall by scope, kind and recency only.
    - B: as A, and each written memory is also embedded into a search-data memory index (one embedding call per write), so a query by meaning finds it; no Piece changes.

    *Recommendation: B, as a composition in the root acceptance.* Recency alone misses an old relevant fact; the composition needs only the in-place source delete, which forgetting needs anyway. One query covers at most 256 memory sources (search-data's permitted-source bound), so the host queries the newest 256 or several sets.
